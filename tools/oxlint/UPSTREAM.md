# Локальные правила Oxlint

- Источник: [dmmulroy/anti-slop](https://github.com/dmmulroy/anti-slop).
- Ревизия: `c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b`.
- Скопирован только [src/rules/no-conditional-empty-object-spread.ts](https://github.com/dmmulroy/anti-slop/blob/c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b/src/rules/no-conditional-empty-object-spread.ts), без изменений, в [rules/no-conditional-empty-object-spread.ts](/tools/oxlint/rules/no-conditional-empty-object-spread.ts).
- Лицензия исходника — MIT, [LICENSE](/tools/oxlint/LICENSE). Вход плагина и тесты принадлежат проекту.

Правило не имеет автофикса: отсутствие ключа может отличаться от значения `undefined`. Сначала проверь потребителей объекта; если отсутствие значимо, добавляй свойства отдельными присваиваниями под исходным условием. Если `undefined` допустим и присутствие ключа незначимо, используй прямое optional-поле с сохранением исходного условия.

## Обновление

1. Выбери upstream-ревизию и разреши её в полный Git SHA. Скачай новый исходник отдельно от рабочей копии.
2. Сравни закреплённый upstream-исходник, локальную копию и новую ревизию. Перенеси нужные изменения с сохранением локальных правок; конфликты поведения и новые правила согласуй с владельцем. Не заменяй весь каталог исходниками anti-slop.
3. Обнови SHA, ссылку, сведения о локальных изменениях и лицензию, если upstream её изменил. При обновлении Oxlint закрепи одинаковые точные версии `oxlint` и `@oxlint/plugins` и обнови lock-файл.
4. Из корня выполни `pnpm test:lint`, затем [порядок проверки Oxlint](/docs/development.md#oxlint-для-агентов) и подходящие проверки затронутого кода. Заимствованный исходник исключён из форматирования; собственные вход и тесты проверяются как проектный код.

Bootstrap устанавливает закреплённые зависимости, но не обновляет локальные правила. Skill `install-anti-slop` не используется: он предназначен для установки полного набора, а здесь подключено одно правило.

При изменении набора внешних skills в `skills-lock.json` синхронно обновляй их адресные исключения в `.oxlintrc.json`, `oxfmt.config.ts` и `.prettierignore`. Собственные skills проекта остаются в проверках и форматировании.
