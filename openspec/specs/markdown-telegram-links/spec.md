# markdown-telegram-links Specification

## Purpose

Помогать читателю узнавать Telegram-ссылки в редакционном Markdown по общему значку сайта, сохраняя авторский смысл подписи, назначение ссылки и пригодность публичного Markdown для внешних читателей.

## Requirements

### Requirement: Telegram-ссылки имеют общее HTML-оформление

HTML редакционного Markdown сайта SHALL показывать перед подписью Telegram-ссылки один штатный значок Telegram. Правило SHALL действовать независимо от раздела и формы Markdown-ссылки, включая ссылки по определению и автоссылки. HTTP(S)-адреса `t.me`, `telegram.me` с необязательным `www.` и ссылки `tg:` SHALL распознаваться по адресу, а не подписи. Значок SHALL быть декоративным и доступным без JavaScript.

#### Scenario: Одинаковая ссылка встречается в разных разделах

- **WHEN** разные редакционные материалы содержат Telegram-ссылку обычной записью, по определению или как автоссылку
- **THEN** их HTML показывает одинаковый значок перед подписью без дополнительной авторской разметки

#### Scenario: Ссылка ведёт на сообщение или приглашение

- **WHEN** Telegram-ссылка ведёт на сообщение, тему обсуждения, приглашение или использует deep link
- **THEN** она получает значок и сохраняет авторские адрес и подпись

#### Scenario: Название Telegram находится на другом домене

- **WHEN** слово Telegram есть только в подписи, пути или части имени постороннего домена
- **THEN** такая ссылка не получает оформление Telegram

### Requirement: Только однозначная подпись ника теряет начальный знак

HTML SHALL удалять начальный `@` только из подписи, целиком состоящей из простого текста `@username`, совпадающего без учёта регистра с username прямой HTTP(S)-ссылки Telegram. Адрес SHALL иметь единственный сегмент username, необязательный завершающий `/`, без query и fragment. Регистр подписи SHALL сохраняться. Другие подписи, включая вложенное форматирование и видимый URL, SHALL сохранять свой текст.

#### Scenario: Подпись повторяет username адреса

- **WHEN** простая подпись равна `@Resident_Name`, а ссылка ведёт на прямой адрес `resident_name`
- **THEN** HTML показывает `Resident_Name`, сохраняя исходные URL и `title`
- **AND** подпись без начального `@` отображается без изменений

#### Scenario: Автор задаёт собственное название

- **WHEN** подпись описывает назначение ссылки, содержит форматирование или называет другой username
- **THEN** HTML добавляет значок, сохраняя всю авторскую подпись

#### Scenario: Адрес содержит дополнительное назначение

- **WHEN** подпись начинается с `@`, но адрес ведёт на сообщение, приглашение, deep link либо содержит query или fragment
- **THEN** начальный `@` и остальные символы подписи сохраняются

### Requirement: Оформление сохраняет смысл и доступность ссылки

Telegram-оформление SHALL сохранять назначение ссылки, `title`, вложенную разметку и возможность перехода с клавиатуры. Доступное имя SHALL передавать видимую подпись после допустимой нормализации; значок SHALL NOT заменять её общим названием сервиса. Обработка SHALL NOT менять обычные и файловые ссылки, буквальные примеры кода, упоминания сущностей или цели якорей документа.

#### Scenario: Длинная авторская подпись содержит выделение

- **WHEN** Telegram-ссылка содержит несколько слов и выделенный фрагмент
- **THEN** подпись сохраняет выделение, переносится по обычным правилам текста и остаётся доступным именем ссылки
- **AND** значок не озвучивается и не становится отдельной остановкой фокуса

#### Scenario: В документе соседствуют разные виды разметки

- **WHEN** рядом с Telegram-ссылкой находятся обычная ссылка, ссылка на PDF, упоминание сущности и пример ссылки в коде
- **THEN** общее оформление Telegram меняет только Telegram-ссылку; остальные элементы сохраняют своё назначение и поведение

### Requirement: Markdown companion сохраняет авторскую ссылку

Публичный Markdown companion SHALL сохранять авторские текст, URL и `title` Telegram-ссылки. HTML-значок и нормализация начального `@` SHALL NOT попадать в companion или редакционный исходник. HTML и companion SHALL вести к одному авторскому назначению.

#### Scenario: Читатель открывает другое представление материала

- **WHEN** HTML показывает нормализованный ник со значком, а читатель открывает Markdown companion того же материала
- **THEN** companion содержит обычную Markdown-ссылку с авторской подписью, включая начальный `@`, если он был в исходнике, и тем же URL и `title`
- **AND** companion не содержит служебного SVG или CSS-атрибутов оформления ссылки
