# component-runtime-delivery Specification

## Purpose

Ограничивать доставку специального клиентского кода липких таблиц и подписей состояния сервисов страницами с соответствующими компонентами, сохраняя их поведение при навигации.

## Requirements

### Requirement: Свежий вход получает только нужный спецкод

При свежем прямом входе страница без липких таблиц SHALL NOT получать их специальный клиентский код; страница без подписей состояния сервисов SHALL NOT получать специальный код уточнения этих подписей. Это ограничение SHALL NOT исключать общий код состояния шапки и сводки главной, предусмотренный [status-lifecycle](/openspec/specs/status-lifecycle/spec.md).

#### Scenario: Страница без обоих компонентов

- **WHEN** в новом документе напрямую открыта страница без липких таблиц и без подписей состояния сервисов
- **THEN** их специальный код отсутствует в доставленном JavaScript, включая зависимости общего entry
- **AND** общая шапка продолжает работать по действующим требованиям

#### Scenario: Страница содержит один вид компонента

- **WHEN** в новом документе напрямую открыта страница только с одним из этих видов компонентов
- **THEN** доступен спецкод этого вида, а спецкод отсутствующего вида не доставляется

### Requirement: Компоненты сохраняют поведение при всех способах входа

Липкие таблицы и подписи состояния сервисов SHALL сохранять предусмотренное поведение при прямом входе, клиентском переходе и навигации назад/вперёд, включая первый переход со страницы без этих компонентов. Подписи SHALL отражать состояние на момент предусмотренного подключения по [status-lifecycle](/openspec/specs/status-lifecycle/spec.md), без изменения правил общего статуса.

#### Scenario: Первое посещение страницы с компонентом

- **WHEN** читатель напрямую открывает страницу с компонентом либо впервые переходит к ней клиентской навигацией со страницы без него
- **THEN** липкий заголовок таблицы корректно отражает состояние прокрутки, если таблица присутствует
- **AND** подпись сервиса отражает состояние на момент подключения, если она присутствует

#### Scenario: Возврат по истории

- **WHEN** читатель уходит со страницы с компонентом и возвращается назад или вперёд
- **THEN** компонент остаётся работоспособным в восстановленном документе
- **AND** при новом подключении подписи сервиса действует контракт пересчёта из [status-lifecycle](/openspec/specs/status-lifecycle/spec.md#requirement-клиент-уточняет-только-предусмотренные-элементы-при-подключении-страницы)

### Requirement: Повторная навигация не накапливает активные ресурсы

Повторное посещение страниц с компонентами SHALL NOT создавать дубли их lifecycle listeners или активных обработчиков. После ухода на страницу без липких таблиц SHALL освобождаться их обработчики scroll/resize и запланированная работа обновления геометрии. Уже загруженный модуль и единственные lifecycle listeners SHALL NOT требовать выгрузки из документа после посещения страницы с компонентом.

#### Scenario: Повторные переходы между таблицами

- **WHEN** читатель несколько раз переходит между страницами с липкими таблицами и возвращается по истории
- **THEN** активен один комплект табличных обработчиков, а повторное подключение не умножает обновления

#### Scenario: Уход на страницу без таблиц

- **WHEN** после страницы с липкими таблицами подключена страница без них
- **THEN** табличные обработчики scroll/resize отключены, отложенная табличная работа отменена и геометрия ушедших таблиц больше не обновляется
- **AND** сохранение уже загруженного модуля в документе не нарушает контракт доставки при свежем прямом входе

#### Scenario: Несколько подписей сервиса

- **WHEN** на странице присутствуют несколько подписей сервисов или читатель повторно посещает такие страницы
- **THEN** подключение уточняет все предусмотренные подписи и не создаёт дубли lifecycle listeners
