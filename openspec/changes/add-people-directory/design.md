# Устройство справочника

## Context

`loadPeopleData()` уже собирает полный реестр, сортирует профили по имени и даёт доступ по `bySlug`. `/people/index.md` и JSON используют полный набор. В реестре публичных поверхностей входом раздела сейчас служит Markdown, а в хлебных крошках профиля «Люди» пока не ссылка.

## Goals / Non-Goals

Редактор должен видеть состав страницы и порядок карточек в одном месте. Перестановка карточек не меняет сведения о человеке, порядок записей полного реестра или связи упоминаний. Модель штатного расписания и история должностей для этого не нужны.

## Decisions

- Хранить подборку в одном редакционном YAML рядом с данными раздела, вне набора Markdown-профилей. В нём — slug ведущей персоны, заголовок организации и упорядоченный список slug. В отличие от флага и числового веса в каждом профиле, перестановку двух людей видно в одном diff. Должности, имена, портреты и URL брать из доменной модели по `bySlug`; не загружать обратные ссылки ради карточек. Проверять структуру через Zod, неизвестные и повторные ссылки считать ошибками сборки. См. [границы данных](/docs/decisions/013-raw-domain-public-data-boundary.md).
- Начальный порядок: Юрий Кизилов отдельно; в ОК «Комфорт» — Геннадий Мозгов, Кирилл Щемелинин, Денис Кочергин, Светлана Ткачёва, Андрей Корняков, Максим Сорочинский, Надежда Махрова, Екатерина Куренкова, Елена Бахаруева, Ярослав Кира. Сергей Минаков остаётся только в полном наборе. Это редакционный выбор, а не сортировка по старшинству.
- Отдать статический HTML в штатном layout. Использовать общие стили страницы и локальную CSS-сетку по [ADR-034](/docs/decisions/034-native-css-architecture.md). Одна ссылка на карточку, фото или инициалы рядом с полным именем; карточка без рамки и фоновой заливки, с видимым клавиатурным фокусом. Верхние края фото и имён выровнены даже при длинной должности. Инициалы относятся только к списку: правила фото на отдельном профиле не меняются.
- Зарегистрировать HTML-вход через [реестр публичных поверхностей](/docs/decisions/011-public-surface-registry.md), убрать утверждения об отсутствии HTML-хаба. Использовать существующий `peoplePath()` для навигации. Сохранить адреса и полноту машинных представлений; для `/people/` сверить обычную HTML-выдачу и выдачу Markdown по `Accept`.

## Risks / Trade-offs

- Должность могла измениться → сверять спорные сведения в исходном профиле; справочник берёт исправления оттуда.
- После удаления или переименования профиля карточка может вести в никуда → сборка должна сообщить проблемный slug, а не молча исключить человека.

## Migration Plan

Опубликовать подборку, маршрут и ссылки на него одним изменением. Миграция профилей не требуется; откат возвращает прежнюю навигацию, сохраняя их URL.
