# Design

## Context

Мотивация и границы — в [proposal](/openspec/changes/adopt-astro-fonts/proposal.md). Изменение затрагивает два приложения, общий UI и тестовые хосты, а также порядок загрузки и fallback шрифтов.

Текущее подключение:

- [global.css](/apps/www/src/styles/global.css) содержит девять `@font-face`: три начертания по три subsets. [FontPreloads.astro](/packages/ui/src/FontPreloads.astro) отдельно импортирует три кириллических WOFF2 и подключается в `BaseLayout.astro`.
- [standalone-error.css](/packages/ui/standalone-error.css) подключает только Cyrillic Fira Sans 600 и PT Serif 700. Media 404 использует только русские заголовок и ссылку, без preload.
- [NotFoundView.astro](/packages/ui/src/NotFoundView.astro) использует буквальные имена семейств; остальные production-потребители в основном читают `--font-body` и `--font-heading`.
- Четыре визуальных стенда `apps/www` импортируют production foundation через `tests/config/visual-foundation.css`; стенды `packages/ui` имеют свою копию шрифтовых объявлений в `tests/visual-foundation.css`.
- [font-budget.test.ts](/apps/www/src/lib/tests/font-budget.test.ts) разбирает ручной CSS и imports preload-компонента; его источник проверяемых определений нужно заменить.

Применимые решения:

- [ADR-034](/docs/decisions/034-native-css-architecture.md): app-owned tokens и foundation, scoped UI и минимальный standalone foundation media.
- [ADR-020](/docs/decisions/020-separate-media-error-app.md): независимая media 404, локальные assets под `/_media/`, без клиентских скриптов.
- [Font Budget](/docs/design/design-code-shelkovo.md#font-budget): действующие семейства, начертания и пределы загрузки.

Исследование 3 октября 2026 года, Astro 7.3.5 / unifont 0.7.5:

- Штатный `fontsource()` возвращает нужные веса, WOFF2 и метки subsets. SHA-256 каждого из девяти полученных файлов совпал с файлом установленных `@fontsource/*@5.3.0`.
- `local()` разрешает package imports и передаёт `unicodeRange`, но не передаёт `meta.subset`. Выборочный preload по `subset: 'cyrillic'` не выбирает его файлы.
- `npm({ remote: false })` читает локальный entry CSS, но возвращает CDN-адреса файлов, не передаёт метки subsets и при стандартном `index.css` получает только 400. Он не заменяет локальный источник для этой задачи.
- На production главная в Headless Chrome 147 на macOS, viewport 390×844, без ограничения сети/CPU, загрузила шесть WOFF2; затем новость использовала их из кеша. В обоих просмотрах observer не зарегистрировал layout shifts. Эти наблюдения не заменяют сравнение production-сборок на медленной сети.
- Локальные базовые шесть файлов занимают 121 608 байт, дополнительные три `latin-ext` — 116 160 байт. Это размеры файлов, без HTTP-заголовков.

## Goals / Non-Goals

**Goals:**

- Передать разрешение шрифтов, генерацию CSS и preload штатному API Astro, сохранив контроль над фактической загрузкой.
- Подключать общие определения на этапе сборки; semantic font tokens остаются у хостов согласно ADR-034.
- Подтвердить поведение fallback и отсутствие сетевой и визуальной регрессии на воспроизводимых сценариях.

**Non-Goals:**

- Собственный font provider, CSS-парсер, runtime-загрузчик шрифтов или новый пакет для управления ими.
- Перенос глобальной темы `apps/www` в `packages/ui`, изменение preload других ресурсов и общий performance-аудит сайта.

## Decisions

### 1. Штатный Fontsource-провайдер и самостоятельная раздача assets

Использовать `fontProviders.fontsource()` с явными весами, `styles: ['normal']`, `formats: ['woff2']`, `display: 'swap'` и нужными subsets. Astro скачивает файлы при сборке и размещает их внутри существующего `build.assets`: `/static/fonts/` для www и `/_media/fonts/` для media.

Для www сохраняются Fira Sans 400/600 и PT Serif 700, subsets `latin`, `cyrillic`, `latin-ext`. Для media — только Fira Sans 600 и PT Serif 700, subset `cyrillic`. Совпадение байтов, проверенное при исследовании, — исходная точка приёмки этой миграции, а не обещание неизменности удалённого каталога.

Альтернативы:

- Оставить ручной CSS и вынести общие определения: сохраняет фиксированные npm-файлы, но оставляет ручное управление fallback и preload.
- `local()` с небольшим адаптером метаданных: сохраняет npm-воспроизводимость, но требует собственного кода ради ограничения текущего API. При выбранном приоритете штатного сопровождения отклонён.
- NPM-провайдер: отклонён по результатам проверки выше.

Сборка с пустым кешем зависит от Fontsource API/CDN. Существующий cacheDir обоих приложений находится в `node_modules/.astro` и уже охвачен Astro cache в CI. Внешний доступ нужен build-процессу; расширять браузерный `font-src` для Fontsource не требуется.

Установленный Astro подавляет ошибки разрешения metadata и может вернуть пустую или неполную семью. Общий head-компонент проверяет публичный `fontData` по обязательной матрице общих определений через Zod и останавливает prerender при отсутствии face или WOFF2-источника. Это server-side защита сборки, без собственного провайдера, CSS-парсера или клиентского runtime; ошибки скачивания файлов Astro пробрасывает штатно.

### 2. Общие определения и два минимальных набора подключения

Поместить общий build-time модуль определений в `packages/ui`, экспортировать набор для www и набор для media без копирования описаний семейств. Общий Astro-компонент подключения выводит два `<Font>`; production-хост выбирает preload, визуальные стенды используют те же определения семейств.

Использовать отдельные generated family variables, например `--font-fira-sans` и `--font-pt-serif`. В `apps/www/src/styles/tokens.css` сохранить семантические `--font-body` и `--font-heading`, направив их на generated variables. Standalone foundation media задаёт эти две роли для своего хоста. `NotFoundView.astro` читает semantic variables с системным fallback для standalone-использования.

Так generated unlayered CSS Astro не конкурирует с app-owned определением тех же переменных в слое `tokens`. Хешированные имена реальных `@font-face` не фиксируются в потребителях или тестах.

В www preload задаётся средствами `<Font>` по кириллице и нужным весам: Fira Sans 400/600, PT Serif 700. В media сохраняется подключение без preload. Визуальные стенды не требуют preload, но должны получить соответствующие Fonts API config и head-компонент вместе с CSS.

После перевода всех хостов удалить заменённые объявления, `FontPreloads.astro` и его export. Удалить неиспользуемые Fontsource-зависимости только после проверки production- и fixture-потребителей. Проверить `sideEffects` пакета UI: build-time модуль не должен включать глобальные стили или инициализацию в клиентский JS.

### 3. Оптимизированный fallback с проверкой русского текста

Включить штатные `optimizedFallbacks`. Для PT Serif сохранить завершающую цепочку `Georgia, serif`; для Fira Sans использовать `system-ui`, чтобы Astro подбирал метрики к системному интерфейсному шрифту. Astro добавляет оптимизированные локальные fallback перед этой цепочкой; внешний вид во время загрузки может измениться.

Сохранить `font-display: swap`: загруженный шрифт продолжает определять итоговую типографику. `optional` изменил бы поведение первого посещения и мог бы оставить всю страницу в системном шрифте при медленной загрузке.

Проверять fallback на кириллических заголовках с переносами, обычном тексте, цифрах и интерфейсном весе 600. Отсутствие подходящего локального шрифта должно оставлять рабочий generic fallback. Наличие generated CSS само по себе не доказывает уменьшение сдвигов.

### 4. Приёмка по поведению и стоимости загрузки

Перед изменением сохранить production-сборки обоих приложений и результаты `pnpm bundle:analyze`; затем сравнивать их с новыми сборками на одинаковых URL и настройках браузера. Точные страницы и условия записать вместе с результатами в PR.

Сетевой и визуальный охват: главная, статья новости, материал базы знаний, `/815/compare/`, www 404 и media 404. Для визуальных стендов выполнить существующие проверки затронутых хостов. Сравнивать мобильную и desktop-ширину; браузерные проверки выполнить в Chromium и WebKit при доступности окружения, ограничения указать в PR.

Для ключевых текстовых страниц проверить:

- Холодный кеш и ограниченную сеть: появление текста, завершение шрифтовых запросов, font-attributed layout shifts и LCP. Зафиксировать viewport, браузер, сеть и CPU; для числового сравнения сделать три одинаковых прогона и привести медиану и диапазон.
- Управляемую задержку шрифтов в локальном preview: видимый fallback до ответа, переносы и геометрию после загрузки. Отдельно отказ шрифтов: читаемость и работоспособность ссылок/кнопок.
- Тёплый кеш и переход через ClientRouter: отсутствие повторной передачи файлов и потери font variables.
- Страницу без расширенной латиницы и локальный пример с требующим её символом: отсутствие лишнего `latin-ext` в первом случае и загрузку только нужного начертания во втором.

Обычная страница укладывается в базовые шесть WOFF2, media 404 — в свои два. Предзагрузки не включают Latin/latin-ext и не создают второй запрос того же файла. Проверить также HTTP-доставку по действующим asset-префиксам и CSP.

Сравнивать не только WOFF2, но и объём встроенного font CSS, сжатого HTML и внешнего CSS: `<Font>` размещает CSS в документе, включая объявления fallback. Итоговая типографика и размеры шрифтовых файлов должны сохранить baseline; дополнительные байты generated CSS нужно явно показать в результатах вместе с поведением текста. Обнаруженную устойчивую регрессию времени появления текста, LCP или сдвигов сначала исправить в рамках подхода; если потребуется смена подхода, вернуть решение владельцу. Улучшение fallback подтверждать наблюдаемым результатом; при равенстве результатов зафиксировать равенство.

Постоянную проверку Font Budget адаптировать к общим определениям и preload-политике, сохранив проверку запрещённых весов. Она не должна зависеть от буквальных хешей, позиции CSS в файлах или наличия сети. Полную разовую сетевую приёмку не превращать в постоянный обход всех страниц в CI.

## Risks / Trade-offs

- Недоступность Fontsource при холодной сборке → использовать штатный cache; проверить чистую сборку и отсутствие тихого выпуска страниц без нужных font faces. При проблеме деплоя сохранять ранее собранный artifact.
- Изменение удалённых файлов независимо от npm lock → документировать источник и кеш, сравнить файлы и типографику при миграции; не заявлять npm-воспроизводимость Fonts API.
- Дополнительный inline CSS и различия fallback между платформами → измерить сжатый HTML и загрузку, проверить русский текст и оба браузерных движка, сохранить generic fallback.
- Потеря шрифтов в визуальных стендах после удаления CSS → переводить config, head и foundation каждого хоста вместе; проверить существующие визуальные сценарии.
- Нарушение изоляции media или подключение лишних начертаний → отдельный минимальный набор, проверка двух файлов на media-origin и отсутствия клиентского runtime.

## Migration Plan

1. После разрешения реализации сохранить baseline и связать issue с коммитом согласованных артефактов по [проектному workflow](/AGENTS.md#согласование-и-передача).
2. Перевести config, head и font consumers обоих приложений и визуальных стендов; удалить заменённые подключения и обновить проверки с документацией.
3. Пройти структурную, runtime- и diff-приёмку. Синхронизировать spec, архивировать change и открыть один PR с результатами сравнений.
4. Деплоить штатные artifacts www/media вместе с изменением. Откат возвращает весь PR и предшествующие согласованные artifacts обоих приложений, включая CSS и font assets.
