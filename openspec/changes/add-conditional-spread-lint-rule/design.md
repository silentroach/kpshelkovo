# Design

## Context

Мотивация и границы — в [proposal](/openspec/changes/add-conditional-spread-lint-rule/proposal.md). Сейчас `/.oxlintrc.json` содержит только test override; `pnpm lint`, pre-commit и CI используют одну конфигурацию. Установлен Oxlint 1.86.0, в manifest указан диапазон. Node.js 24 поддерживает TypeScript-вход локального плагина без отдельной сборки.

Исходное правило самодостаточно: импортирует только `defineRule` и типы из `@oxlint/plugins`. Оно выявляет spread внутри объекта с условным выражением, в любой ветке которого стоит пустой объект; не проверяет произвольное условное построение данных и не предлагает автофикс.

## Goals / Non-Goals

**Goals:**

- Использовать один источник правила для полной проверки, staged-файлов и CI.
- Сохранить поведение условий, отсутствие ключей там, где оно значимо, и порядок вычислений при исправлении объектов.
- Оставить минимальную локальную интеграцию, пригодную для последующих осознанных обновлений.

**Non-Goals:**

- Не создавать установщик или систему синхронизации anti-slop, новый пакет workspace либо отдельный lint-процесс.
- Не расширять синтаксический охват исходного правила и не вводить автоматическую замену на `undefined`.
- Не менять публичные форматы, редакционные данные и набор агентских skills.

## Decisions

### Локальный плагин с одним правилом

Скопировать `src/rules/no-conditional-empty-object-spread.ts` из `dmmulroy/anti-slop` на ревизии `c44ef22ca116d0ba62a3ff663a0bd13a3f3fa40b` в `/tools/oxlint/rules/`. Сохранить исходник без проектного рефакторинга, рядом разместить upstream MIT LICENSE и `UPSTREAM.md` с источником, SHA, исходным путём и порядком обновления. Собственный `/tools/oxlint/index.ts` экспортирует только это правило; зарегистрировать его через `jsPlugins` в существующем JSON config под именем `local`.

Полный набор и npm-форк не нужны для одного правила. Собственная реализация с нуля добавила бы сопровождение уже решённой задачи. Локальное копирование соответствует модели upstream; обновление — сравнение закреплённого исходника с выбранным полным SHA, просмотр diff, сохранение локальных изменений и повторная проверка. Автоматического обновления при bootstrap нет.

### Версии и исключения

Закрепить `oxlint` и `@oxlint/plugins` на `1.86.0`, не обновляя остальные инструменты. Включить `local/no-conditional-empty-object-spread` как `error`, сохранив test override и остальные проверки.

Заимствованный исходник исключить из lint и форматирования адресно, чтобы локальная копия оставалась сравнимой с upstream; собственный вход и тесты продолжить проверять. Сохранить существующие исключения generated-интеграции и учесть внешние skills в lint/format, включая явно переданные staged-пути. Не исключать проектный код или собственные агентские инструкции. Не менять CI: он уже вызывает полную `pnpm lint`.

### Ручное исправление без изменения контрактов

Сначала выполнить агентский вызов с безопасным `--fix`; остаток нового правила разобрать вручную. Для каждого случая проверить исходное условие и потребителей объекта: truthiness, наличие ключа, сериализацию, spread поверх defaults и вызовы сторонних API.

- Если отсутствие ключа незначимо и допустим `undefined`, использовать прямое optional-поле, сохранив исходную фильтрацию пустых значений.
- Если отсутствие значимо, собирать объект отдельными присваиваниями под исходным условием; не заменять паттерн общим helper ради обхода правила.
- Сохранить порядок вычислений и перезаписи свойств; не расширять типы и схемы ради механической замены.

Это следует [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md): публичный формат не меняется при внутреннем рефакторинге. Для Markdown AST отдельно сверить контракт сторонних типов и потребителей optional-полей.

### Проверки и инструкции

Добавить короткую проверку поведения правила и отсутствия автофикса с штатным `RuleTester`; подключить её к существующему CI lint-пути либо уже запускаемым тестам без отдельного универсального harness. Одноразовыми CLI fixtures проверить фактическую загрузку плагина на TS, JS и поддерживаемых скриптовых блоках Astro/Svelte, а также staged-вызов. Не сохранять общий smoke-обход сайта.

В `/AGENTS.md` и `/docs/development.md` закрепить команды из корня с `--format=agent`, порядок безопасного `--fix` → ручные исправления → форматирование → lint без записи. Прямые адресные вызовы используют тот же формат. `pnpm lint` и CI остаются без автофикса; `--fix-suggestions` и `--fix-dangerously` не входят в стандартный порядок.

## Risks / Trade-offs

- Изменение присутствия ключа или truthiness → ручная сверка потребителей и короткие регрессионные тесты значимых случаев, существующие тесты публичных DTO и Markdown.
- Плагин работает на AST, а не по всем семантически эквивалентным конструкциям → тестировать исходный синтаксический охват, не обещать запрет всех способов условного добавления полей.
- Исключения не сработают при явном списке staged-файлов → проверить реальные lint-staged и formatter-вызовы, не ограничиваться полной проверкой каталога.
- Замены могут затронуть shared-код → проверить связанные разделы; сравнить bundle-отчёты, если меняются клиентские импорты или сборка.

## Migration Plan

После разрешения сохранить артефакты в рабочей ветке и связать коммит с issue по проектному процессу. Подключить правило, исправить все его замечания, выполнить форматирование и приёмку. Завершение — архив change и PR по [ADR-038](/docs/decisions/038-openspec-development-workflow.md); delta specs отсутствуют, поскольку продуктовые требования не меняются. Откат возвращает весь PR: конфигурацию, локальное правило, зависимости, исправления и инструкции.
