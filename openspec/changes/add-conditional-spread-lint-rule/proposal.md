# Proposal

## Why

Проект уже запрещает условные spread с пустым объектом в собственных правилах TypeScript, но Oxlint их не выявляет. В рамках [#973](https://github.com/silentroach/kpshelkovo/issues/973) владелец выбрал первый узкий этап: подключить только `no-conditional-empty-object-spread` из `dmmulroy/anti-slop`.

## What Changes

- Добавить локальный плагин Oxlint с одним заимствованным правилом, MIT-лицензией и точной upstream-ревизией.
- Включить правило как ошибку в действующей конфигурации, сохранив остальные проверки, pre-commit и CI.
- Закрепить одинаковые точные версии `oxlint` и `@oxlint/plugins` и обновить lock-файл.
- Исправить замечания этого правила во всём проверяемом workspace без изменения поведения, массовых отключений и исключения проектного кода.
- Документировать обновление локального правила и агентский порядок `--format=agent`: безопасный `--fix`, ручные исправления, форматирование, повторная проверка.
- Не подключать остальные правила anti-slop, `oxc/no-accumulating-spread`, Effect-группу или `install-anti-slop`; набор skills не менять.

## Capabilities

### New Capabilities

Нет. Изменение инструментов разработки использует `skip_specs: true`.

### Modified Capabilities

Нет. Публичные контракты и требования основных specs сохраняются.

## Impact

- Конфигурация Oxlint, зависимости и lock-файл, новый каталог `/tools/oxlint`, инструкции `/AGENTS.md` и `/docs/development.md`.
- Исправления затрагивают приложения, пакеты и тесты: поиск уже выявил случаи в Markdown AST, публичных DTO, JSON-LD, discovery и `.astro`. Точный список определит линтер после подключения.
- У правила нет автофикса: отсутствие свойства и свойство со значением `undefined` требуют проверки контракта каждого объекта.
- Production-приёмка не требуется. Этот этап не выполняет первоначальный полный объём #973; PR использует `Refs #973`, а дальнейший объём issue согласуется отдельно.
