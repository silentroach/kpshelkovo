# Spec Delta

## Purpose

Потребители детальной сметы могут связать опубликованные факты с первоисточником и корректно разрешать ссылки при обновлении набора данных.

## ADDED Requirements

### Requirement: Версия публичного формата

JSON по `/815/regulation/data/estimate-details-2026.json` SHALL явно указывать `schema_version`. Действующий формат с нормализованным реестром источников SHALL публиковаться как версия `"2"`, чтобы потребитель мог определить поддерживаемый способ чтения ссылок.

#### Scenario: Чтение версии

- **WHEN** потребитель получает детальную смету в действующем формате
- **THEN** ответ содержит `schema_version: "2"` и корневой реестр `sources`

### Requirement: Разрешимость ссылок и трассируемость

`source_refs` у работ, ресурсов, контрольных итогов и, если указаны, внутри `needs_check` SHALL содержать ID записей `sources` того же документа. Каждый указанный ID SHALL разрешаться; набор с неразрешимой ссылкой SHALL отклоняться до публикации. Источник SHALL сохранять указание PDF, страницы и фрагмента, а также имеющуюся цитату либо её структурированные позиции. Одинаковые по полному публичному содержимому источники SHALL публиковаться одной записью реестра.

#### Scenario: Общий источник нескольких фактов

- **WHEN** несколько фактов и пояснение `needs_check` ссылаются на один и тот же публичный источник
- **THEN** их ссылки ведут к одной записи `sources`, по которой можно восстановить PDF, страницу, фрагмент и опубликованное представление цитаты при её наличии

#### Scenario: Неразрешимая ссылка

- **WHEN** ссылка факта или `needs_check.source_refs` указывает на отсутствующую запись `sources`
- **THEN** проверка публичного набора завершается ошибкой до его публикации

### Requirement: Область действия идентификаторов

ID источника SHALL интерпретироваться только вместе с `sources` из того документа, где он получен. ID не является постоянным идентификатором первоисточника между обновлениями набора, в том числе при неизменном `schema_version`.

#### Scenario: Одинаковый ID в разных ответах

- **WHEN** потребитель сравнивает два обновления набора, содержащие одинаковый ID источника
- **THEN** каждую ссылку он разрешает через реестр соответствующего ответа; совпадение ID само по себе не подтверждает совпадение источников

### Requirement: Повторяемость публикации

Повторная генерация JSON из неизменного набора с тем же порядком данных SHALL давать одинаковый результат, включая ID источников и ссылки на них. Это не гарантирует сохранение ID при изменении содержимого или порядка данных.

#### Scenario: Повторная генерация без изменений

- **WHEN** один и тот же упорядоченный набор повторно публикуется в том же формате
- **THEN** сгенерированный JSON совпадает побайтно
