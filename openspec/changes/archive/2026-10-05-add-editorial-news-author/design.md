# Design

## Context

Мотивация и границы — в [proposal](/openspec/changes/archive/2026-10-05-add-editorial-news-author/proposal.md). Тип `editorial` уже проходит raw-схему, доменную модель и публичные адаптеры. `NewsMeta` общий для карточек и обоих заголовков статьи; автор JSON-LD собирается на странице статьи. Helper `newsArticleSchema` уже допускает отсутствие автора.

## Goals / Non-Goals

- Применить правила видимости на границах представлений, сохранив полноценного автора в доменной записи по [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md).
- Использовать существующий `kind`; дополнительный флаг видимости и новый тип автора не нужны. Единственная согласованная смена автора опубликованной статьи — `/news/2026/10/land-tax/`.

## Decisions

- Добавить минимальный `/apps/www/src/data/news/authors/editorial.yaml`. Выбор `author: editorial` закрепить в редакционных инструкциях, сохранив обязательное явное поле. Подстановка автора загрузчиком затронула бы историческую атрибуцию.
- Передать `kind` в `NewsMeta` и пропускать только элемент авторской подписи при `kind === 'editorial'`. Это покрывает все существующие вызовы; фильтрация в каждой карточке или CSS-скрытие создавали бы лишние точки управления. Карточки передают дату и автора; страницы статей — также сведения о части посёлка и источник. Владелец подтвердил при ревью PR #930, что добавлять эти поля в карточки не нужно.
- При сборке JSON-LD страницы передавать отсутствие автора для того же типа. Остальное сопоставление типов сохранить. Общий JSON-LD-helper менять не требуется.
- JSON и Markdown продолжают читать исходного доменного автора. Отдельный флаг для каждого формата не нужен: различия полностью определены [контрактом](/openspec/specs/news-authorship/spec.md).
- Использовать существующие test helpers и Astro container для редакционной новости и контрольных авторов. Не добавлять искусственную статью в публикуемые данные.

## Risks / Trade-offs

- Скрытие всей строки метаданных может убрать дату и источник → проверять отдельную подпись вместе с сохранением остальных сведений.
- Фильтрация автора в загрузчике может лишить JSON и Markdown атрибуции → проверять эти представления на той же редакционной записи, что HTML и JSON-LD.
- Существующие fixtures иногда используют имя «Редакция» вместе с ID `ig` → в проверках различать ID, имя и тип; поведение определяется типом, а реальные исторические записи сохраняются.

## Migration Plan

Обычная статическая сборка публикует новую запись автора, обновлённые шаблоны и `author: editorial` у `/news/2026/10/land-tax/`. Остальные статьи, авторы `ig`/`ig-global`, их URL и историческая JSON-LD-выдача сохраняются. Результат проверяется на fixtures и статье о земельном налоге. При откате вернуть изменения данных и шаблонов вместе; если к тому времени появились другие статьи с `author: editorial`, сохранить для них запись автора либо отдельно согласовать их атрибуцию.
