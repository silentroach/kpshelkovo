# Design

## Context

Причина изменения — в [proposal](/openspec/changes/archive/2026-11-06-preserve-status-kind-in-backlinks/proposal.md#why).

- [Адаптер статуса](/apps/www/src/lib/status/mentions.ts) создаёт одинаковый `source.kind: 'incident'` для обоих видов событий. Общий граф и проекции людей и мест передают это значение дальше.
- После [PR #1265](https://github.com/silentroach/kpshelkovo/pull/1265) HTML и Markdown мест получают правильный вид через исходный dataset статуса. HTML, Markdown и JSON людей используют только backlinks.
- При проверке production 6 ноября 2026 года у людей было 11 обратных ссылок статуса, все на инциденты. Проверка только опубликованных профилей не обнаруживает ошибку: нужны тестовые плановые работы.
- Подход следует [ADR-012](/docs/decisions/012-entity-mention-graph.md): адаптер источника передаёт готовый контекст, общий граф не загружает доменные datasets. Публичную границу определяет [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md); владелец разрешил прямое обновление контракта без обратной совместимости.

## Goals / Non-Goals

**Goals:**

- Передавать вид из исходной записи через существующий `kind` до представлений и публичного DTO.
- Для подписи вида использовать сам backlink; данные статуса в карточке места остаются источником периода, состояния и отбора материалов.

**Non-Goals:**

- Переименование `/status/incidents/`, исходных файлов, доменного типа `StatusIncident` и всего словаря статуса.
- Изменение жизненного цикла статуса, состава HTML-подборок и правил создания обратных ссылок.
- Включение HTML-блока упоминаний людей: `showBacklinks = false` сохраняется, отдельная задача [#1284](https://github.com/silentroach/kpshelkovo/issues/1284).

## Decisions

### 1. Источник передаёт настоящий вид

Добавить `maintenance` в виды общего графа и людей; в адаптере статуса присваивать `source.kind` из `incident.kind`. Один и тот же source используется для упоминаний и `affected_places`, поэтому оба способа связи получают одинаковый вид и дедуплицируются вместе. Фаза, дата и заголовок не участвуют в выборе вида.

Альтернатива — восстанавливать вид отдельной загрузкой статуса во всех потребителях, как сейчас делают места. Она оставляет неполные данные в графе и добавляет зависимость каждому представлению. Второе поле рядом с `kind` тоже не требуется: нужное различие помещается в существующее поле.

### 2. Форматирование опирается на backlink

Расширить существующие словари видов людей и мест подписью «Плановые работы», согласованной с `formatStatusKind` и [глоссарием](/GLOSSARY.md#статус-сервисов). В Markdown места брать подпись вида из backlink независимо от наличия дополнительного dataset статуса. Периоды и состояния продолжает предоставлять действующая логика мест; HTML-подборка уже берёт верный вид из статуса.

Отдельный универсальный форматтер или переработка графа для этого не нужны: достаточно существующих адаптера, типов и словарей.

### 3. Публичный контракт обновляется напрямую

Адаптер people JSON публикует фактический `kind`. Расширить перечисление в [schema.ts](/apps/www/src/lib/people/schema.ts), от которого строятся JSON Schema и OpenAPI в [discovery.ts](/apps/www/src/lib/people/discovery.ts), и объяснить различие в описании схемы и [llms.ts](/apps/www/src/lib/people/llms.ts).

Прежняя классификация плановых работ как `incident` не поддерживается: переходные поля, флаги, дублирующий endpoint и преобразование обратно в `incident` не вводятся. Потребители внутри проекта и их проверки переходят на новый контракт вместе с генератором.

## Risks / Trade-offs

- Нынешние данные людей не покрывают плановые работы → проверить полный путь от адаптера статуса до Markdown и JSON на тестовых записях обоих видов, с заголовками, не подсказывающими вид. HTML проверить у мест; у людей проверить форматтер скрытого блока и сохранение его скрытости.
- Изменение вида входит в ключ дедупликации графа → проверить одну связь при повторе упоминания и сочетании текста с `affected_places`, а также разные короткие записи с общим адресом календарного месяца.
- Упрощение подписи Markdown места может затронуть соседние метаданные → сохранить проверки периода и состояния инцидентов, отсутствия дополнительной подписи о завершении у работ и доступного назначения короткой записи.

## Migration Plan

Сборка публикует новый JSON, его схему, OpenAPI и документацию одним выпуском. Редакционные записи уже содержат правильный `kind`, миграция данных не нужна. При откате возвращается изменение целиком с повторной сборкой.
