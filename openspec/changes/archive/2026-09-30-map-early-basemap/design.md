# Design

## Context

Мотивация — в [proposal](/openspec/changes/archive/2026-09-30-map-early-basemap/proposal.md). Astro-страница уже получает `selectMapPlaces(await loadPlaces())`, но передаёт Svelte только URL JSON и fallback. Клиент ждёт данные и SDK через `Promise.all`, затем импортирует кластеризатор и создаёт `YMap`. `getPlaceBounds` использует только основные координаты; `fitPlaces` сразу после создания повторно задаёт bounds и адаптивные margin.

Действующие решения: [ADR-028](/docs/decisions/028-markdown-first-places-map.md) сохраняет статический сайт, клиентский renderer и единую видимую выборку; [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md) задаёт границы данных. Требования — в [delta](/openspec/changes/archive/2026-09-30-map-early-basemap/specs/site-maps/spec.md), [site-maps](/openspec/specs/site-maps/spec.md), [place-map-visibility](/openspec/specs/place-map-visibility/spec.md) и [parcel-map](/openspec/specs/parcel-map/spec.md).

## Goals / Non-Goals

**Goals:**

- Вынести начальную геометрию кадра из сетевого критического пути, не меняя её алгоритм.
- Разделить готовность подложки и готовность объектов без новой архитектуры загрузчиков.

**Non-Goals:**

- Не переписывать общий runtime SDK, не удалять ожидание стабильного layout и не оптимизировать все карты сайта.
- Не делать работоспособность слоя участков при отказе JSON мест новым контрактом: сохранить текущую обработку ошибок всего setup и готовность панели после успешного подключения объектов.

## Decisions

### Bounds из сборки, а не фиксированный кадр или полный payload

Передавать компактный `initialBounds` в props `PlaceMap` из Astro. Переиспользовать текущие padding, округление и локальный fallback через helper, доступный на сервере и клиенте без загрузки browser-only зависимостей. При необходимости сузить вход helper до координат, а не собирать искусственные `PlaceMapItem` из доменных мест. Скрытые места и дополнительная геометрия не участвуют. Сохраняется публичная точность координат не более восьми знаков.

Фиксированный кадр посёлка не подходит для включённых мест за его пределами. Передача всех мест в HTML дублирует JSON и увеличивает страницу. Новый endpoint bounds не нужен: он вернул бы сетевую зависимость.

### Независимые загрузки, одна карта

Запустить загрузку SDK и мест параллельно, а динамический импорт кластеризатора — сразу после готовности SDK, параллельно с ожиданием стабильного layout и загрузкой мест. Модуль кластеризатора при исполнении наследует классы SDK, поэтому его импорт до готовности SDK небезопасен. Сразу присоединить обработку отказов, чтобы раннее отклонение независимого promise не стало необработанным. По готовности SDK и стабильного контейнера создать единственный `YMap` с build-time bounds и актуальным адаптивным margin, не ожидая кластеризатор. Обычный кадр должен быть установлен до отображения, а не сначала без отступов, затем повторным `fitPlaces` после JSON.

После готовности мест и кластеризатора подключить listener, маркеры и геометрию. Динамический импорт сохраняется; переход на статический импорт мог бы утяжелить начальный чанк. Не вводить очередь задач, универсальный менеджер фаз или отдельные экземпляры карты. Для существующих прямых вызовов компонента в тестах/с местами оставить совместимый путь вычисления bounds, когда новый prop не передан.

### Камера и действия не зависят от позднего обычного ответа

Убрать повторное начальное вписывание после подключения обычных маркеров. Resize и явные действия карты сохраняют текущие правила. Прямые ссылки `h` и `p` обрабатываются после готовности нужных объектов: приоритет `p`, очистка неизвестных значений, временная подсветка места, выбор участка и отмена остаются прежними. Не переносить таймер подсветки на момент создания ещё пустой подложки.

Готовность панели слоёв и порядок штатного действия Яндекса не расширять за пределы этой задачи. Ошибки SDK, JSON или импорта сохраняют существующее оповещение и очистку setup, даже если подложка уже успела появиться. Уничтожение компонента останавливает актуальную карту; поздние результаты не создают новую карту, не добавляют объекты и не меняют URL.

## Risks / Trade-offs

- Ранний показ делает промежуток без маркеров заметным → это намеренный постепенный показ, без новой загрузочной панели.
- Bounds HTML и JSON могли бы разойтись → вычислять оба из общей видимой выборки одной сборки; сохранить текущий алгоритм и проверить пустой набор и точки вне посёлка.
- Поздний `fitPlaces` может сбросить ручной кадр → initial fit выполнить до объектов; регрессия с ручным перемещением до ответа JSON.
- Параллельные promises могут завершиться после ухода или отказа → обработчики отказов с момента запуска и существующие проверки destroyed на каждом асинхронном продолжении, тесты задержанных ответов.
- Кэш браузера может скрыть задержку → ручная проверка с холодным кэшем и искусственной задержкой JSON/чанка, без обещания фиксированного выигрыша в миллисекундах.

## Migration Plan

План опубликован в draft PR ветки `perf/map-early-basemap`, владелец разрешил реализацию в отдельной сессии. Эта сессия реализует задачи в той же ветке, обновит отчёты бандлов, проведёт приёмку, sync/archive и переведёт PR в готовый к ревью. Изменение доставляется обычной статической сборкой без миграции контента или JSON; откат возвращает весь PR вместе с bounds-prop и порядком setup.
