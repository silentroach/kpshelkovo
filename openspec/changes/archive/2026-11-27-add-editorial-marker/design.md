# Маркер в редакционном Markdown

## Context

Реплики уже проходят через общий HTML-рендер сайта. Их публичные `.md`, как и статьи, разбирают исходный Markdown через `parseMarkdownFragment` и сериализуют полученное дерево. Между этими путями нельзя подменять исходник строкой с `**`: тогда HTML уже не отличит маркер от обычного полужирного.

## Goals / Non-Goals

Единый синтаксис для текста и единое оформление отмеченной фразы. Поля YAML, редакторские пометки между репликами и поисковая подсветка остаются самостоятельными механизмами.

## Decisions

- **Одна грамматика для обоих выходов.** Распознавать парные `==` при разборе inline-содержимого в `@shelkovo/markdown`: HTML использует remark, Markdown-фрагменты разбираются отдельно. Переиспользовать одно правило и сохранить дочерние узлы фразы. Подходящее представление в mdast: `strong` с HTML-подсказкой `hName: 'mark'` и отдельным классом оформления. Тогда штатный сериализатор выдаёт полужирный, а типограф получает текстовые узлы внутри `<mark>`. Это универсальная авторская разметка без зависимостей от записей сайта, по [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md) и [ADR-008](/docs/decisions/008-markdown-ast-generation.md).
- **Границы фразы.** Пара действует в пределах одного inline-контекста, не пересекает границу абзаца. Ссылки и обычное форматирование могут находиться внутри. Код и адрес ссылки буквальны; пустая, незакрытая или экранированная пара не даёт штриха. Не заменять подстроки регуляркой во всём документе: она захватит примеры кода и проигнорирует структуру Markdown.
- **Оформление.** `wide-nib.webp` показывает выбранную форму широкого пера. После просмотра длинной фразы владелец попросил смягчить цвет и дать штриху больше места слева. Рисунок повторяется на каждой строке (`box-decoration-break: clone`); выход за край текста задаётся `border-image-outset`, без изменения метрик и переносов. Стилизуем только редакционный класс по [ADR-034](/docs/decisions/034-native-css-architecture.md): общее правило для `mark` заденет подсветку поиска.

## Risks / Trade-offs

- Промежуточная обработка упоминаний опирается на позиции в исходнике. Проверить фразу со ссылкой и с `@slug` непосредственно перед закрывающей парой.
- Ровная сплошная заливка потеряет характер пера, а крупная текстура помешает чтению. Сверять с эталоном в обычном размере, особенно на коротком хвосте перенесённой фразы.

## Migration Plan

Миграция архива не нужна. Для приёмки использовать уже размеченный владельцем фрагмент встречи с юристом. При откате согласовать с владельцем снятие разметки с опубликованных фраз.
