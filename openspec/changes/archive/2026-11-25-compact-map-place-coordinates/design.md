# Пара координат на границе JSON карты

## Context

Публичный справочник и файлы слоёв используют один `PlaceMapPublicItemDto` и адаптер `toPublicPlace`. Браузер переводит DTO во внутренний `PlaceMapItem`; редакционные записи и Markdown-карточки используют собственные модели.

## Goals / Non-Goals

Изменить только представление основной точки в JSON карты. Не менять редакционные записи, Markdown, геометрию дорог и участков или внутренний тип координат.

## Decisions

- В общем адаптере формировать пару `[lng, lat]` с действующей точностью. Проверять длину и диапазоны на сборке по [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md), не добавлять Zod в браузер. `PlaceMap` разбирает типизированную пару в существующий объект.
- Не сохранять два формата и не читать старый объект. Адреса JSON остаются прежними. В описании публичной выдачи указать порядок и пример миграции; проверить связанные страницы обнаружения по [ADR-011](/docs/decisions/011-public-surface-registry.md).

## Risks / Trade-offs

- Оба числа координат Шелково допустимы в диапазоне широты, поэтому проверка диапазонов не ловит перестановку. Тест с известной точкой и проверка прямой ссылки фиксируют порядок.
- Потребители публичного JSON должны перейти с обращения к `lat` и `lng` на элементы пары. Клиент и JSON публикуются одной сборкой; проверить политику кеширования существующих адресов перед выпуском.
