## Context

Мотивация и область изменения — в [proposal.md](proposal.md). Решение выбрано при обсуждении [#762](https://github.com/silentroach/kpshelkovo/issues/762). Владелец разрешил реализацию и уточнил, что настройка и подтверждение тарифа Яндекс Карт находятся вне текущей задачи; фактическое поведение и рекламные запросы остаются предметом проверки.

После реализации и архивирования прямые запросы владельца при ручном ревью [PR #763](https://github.com/silentroach/kpshelkovo/pull/763) уточнили оформление подложки, расположение штатных элементов и замену резервной ссылки компактного события. Решения ниже включают эти согласованные уточнения в том же PR; повторные проверки отражаются отдельно от завершённой приёмки исходной реализации.

В `apps/www/src/lib/yandex-maps/runtime.ts` уже есть общий загрузчик JS API v3, ожидание готовности, восстановление после ошибки и сохранение стилей при Astro-навигации. Его используют общая карта мест, `PlacePreview` и `SettlementMap`. `NewsEventCard` отдельно загружает `map-widget/v1/`; `lib/news/view.ts` вычисляет для iframe сдвиг центра, компенсирующий растяжение и обрезку фона.

`PlacePreview` уже решает большую часть задачи неподвижной карты: `behaviors: []`, географический маркер, fit контуров, обновление часов, серверная fallback-ссылка, ожидание подложки и штатного действия, cleanup при удалении элемента. Он начинает работу сразу при подключении к DOM. В карточке поселка сейчас монтируется `SettlementMap` с отключённым интерактивом; на узком экране эта шапка скрыта.

Действующие основания:

- [ADR-028](../../../../docs/decisions/028-markdown-first-places-map.md) — сущности мест, JS API v3, контуры и поведение превью.
- [ADR-017](../../../../docs/decisions/017-csp-inline-exceptions-for-astro-yandex-maps.md) — CSP для Яндекс Карт.
- [ADR-033](../../../../docs/decisions/033-integrated-tariff-comparison-section.md) и [ADR-034](../../../../docs/decisions/034-native-css-architecture.md) — app-owned логика Compare и стили.
- [Дизайн-гайд](../../../../docs/design/design-code-shelkovo.md) — карта под media-hero, композиция места и выразительная календарная карточка.
- [ADR-039](../../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md) — общий runtime интерактивных карт и неподвижных превью, границы общего компонента и сохранение фоновой композиции.

## Goals / Non-Goals

**Goals:**

- Переиспользовать существующий runtime и механизм превью внутри `apps/www`, сохранив доменные данные у текущих владельцев.
- Удалить независимую загрузку iframe и декоративный режим полнофункционального renderer-а там, где достаточно общего неподвижного превью.
- Сохранить внешний вид фоновых карт и доступность служебных элементов без вмешательства в рекламный DOM Яндекса.

**Non-Goals:**

- Универсальный renderer со всеми фильтрами, кластерами, попапами и настройками всех разделов; отдельная система очередей, пулов или кэширования карт.
- Смена картографического провайдера, Static API, генерация изображений на сборке и объединение географических моделей разделов.
- Настройка и подтверждение тарифа Яндекс Карт: они не являются условием реализации, приёмки или закрытия #762.

## Decisions

### 1. Один JS API и граница ответственности за рекламу

Все встроенные карты используют `loadYandexMaps` и существующий `PUBLIC_YANDEX_MAPS_API_KEY`. Сохраняем JS API v3, конкурентную загрузку через общий promise и работу после клиентских переходов. Интерактивные renderer-ы мест и Compare продолжают отвечать за свои сценарии; общий runtime не получает доменную логику.

Безрекламный показ зависит от условий подключения продукта JavaScript API. Само наличие ключа и замена iframe на JS API не подтверждают отсутствие рекламы. Настройка и подтверждение тарифа для нынешнего ключа находятся вне #762 и не блокируют её реализацию или закрытие.

По проверенным при подготовке change 18 сентября 2026 года [условиям подключения](https://yandex.ru/legal/maps_api/ru/) и [описанию тарифов JavaScript API](https://yandex.ru/dev/tariffs/doc/ru/jsapi/prices) бесплатный ключ не даёт гарантии безрекламного показа. Код не скрывает полученную рекламу стилями, перекрытиями или вмешательством в DOM. Локальная приёмка фиксирует фактический показ и рекламные запросы; отсутствие рекламы в одном прогоне не подтверждает тариф и не гарантирует её отсутствия в будущем. Отдельный iframe и Static API отклонены: владелец выбрал единый JS API для интерактива и превью.

### 2. Общий механизм неподвижного превью

Выделить из `PlacePreview` небольшой app-owned Astro-компонент с custom element в `apps/www/src/components/maps/`. Он использует общий runtime и получает только данные конкретного показа: координаты, кадрирование, оформление подложки, внешний URL и DOM-шаблон маркера. Контуры и расписание передаются только там, где они нужны. Типы лежат отдельно от исполняемого кода.

Адаптеры разделов готовят входные данные и внешний HTML:

- `PlacePreview` — текущая иконка или стандартная точка, все области, расписание и прежняя логика fallback. Полный объект `Place` остаётся у адаптера; общий компонент не загружает справочник мест.
- `NewsEventCard` — обычный `ui-map-marker`, координаты места и фоновое кадрирование. Расписание, объектная иконка и контуры сюда не передаются.
- Карточка поселка — точка с существующим тарифным оформлением и кадрирование шапки. `SettlementMap` остаётся renderer-ом интерактивной карты сравнения; ставшие ненужными ветки его декоративного режима удаляются после проверки всех вызовов.

Общими становятся создание и уничтожение карты, подложка, отключение жестов, наблюдение за размером и готовностью. Существующие helpers геометрии и часов переиспользуются без второй реализации. Выделение общего превью не требует нового workspace-пакета или зависимости.

Для верхней резервной ссылки события `MapPreview` предоставляет именованный слот `fallback`: адаптер задаёт исходный URL и оформление, общий механизм управляет видимостью по готовности подложки и штатного действия и передачей фокуса.

### 3. Сохранение карты фоном

Сохраняем размеры и композицию компактного события, фон desktop-шапки поселка, положение информации, приглушённость подложки и географически верную точку. Карточка места сохраняет собственный географический блок. Эталон внешнего вида — локальные страницы до изменения с согласованными уточнениями ручного ревью: у события подложка получает `opacity: 0.4`, экранная позиция маркера — `anchor: [0.75, 0.45]`, а нижний ряд действий содержит только ICS.

Карта заполняет фактический контейнер. Нужный кадр задаётся через `location` и `margin`; координаты маркера не смещаются ради дизайна. Приглушение делается штатной [`YMapDefaultSchemeLayer.customization`](https://yandex.ru/maps-api/docs/js-api/map/customization.html), поддерживающей насыщенность, светлоту и прозрачность объектов подложки. Общие `opacity`, фильтры и маски не применяются к контейнеру со служебным интерфейсом.

В шапке поселка нижний переход в фон страницы применяется к canvas, блоку атрибуции и штатной кнопке с привязкой к общей высоте карты. У атрибуции и кнопки нижняя граница маски остаётся на 30%, чтобы они были различимы. Копирайт выровнен по левому краю названия поселка. Маркер не затухает.

По прямому уточнению владельца нижний блок атрибуции события получает `opacity: 0.4`. При наведении или фокусе атрибуция события и нижние штатные элементы поселка возвращаются к полной видимости. Владелец выбрал эти CSS-эффекты после обсуждения п. 4.1.3.1 условий Яндекса; это решение проекта, а не подтверждение разрешения со стороны Яндекса. Удаление штатной кнопки владелец отклонил, поскольку SDK не предоставляет переключателя её отключения.

Логотип, атрибуция, условия и штатная кнопка остаются внутри видимого контейнера, поверх фонового оформления и вне зон перекрытия текстом. Позиции служебных блоков настраиваются документированными параметрами [`YMap`](https://yandex.ru/maps-api/docs/js-api/ref/index.html#YMapProps), включая `copyrightsPosition`; фактический состав блока `distributionPosition` проверяется на настоящем SDK. Увеличение и обрезка целой карты ради скрытия служебных элементов не используются.

В компактном событии штатная OpenMaps остаётся сверху справа. В шапке поселка, `/map/` и интерактивной карте Compare она расположена снизу справа. В узком контейнере responsive CSS переносит атрибуцию и условия над нижней штатной кнопкой; элементы не скрываются и не перекрывают друг друга.

`behaviors: []` отключает жесты карты. Сохраняем проверенное в `PlacePreview` разрешение вертикального touch-scroll, а ссылки и кнопки оставляем интерактивными. Весь контейнер карты с доступными действиями не получает `aria-hidden` или `pointer-events: none`.

### 4. Простая отложенная инициализация

Использовать `IntersectionObserver`: каждое неподвижное превью запускается один раз при приближении к viewport. После начала инициализации наблюдение за видимостью этого экземпляра прекращается; уход за экран не уничтожает уже созданную карту. Скрытая адаптивной вёрсткой шапка ждёт реального показа. Размер контейнера резервируется существующей вёрсткой.

Сохраняем cleanup при удалении элемента и защиту от завершения устаревшей асинхронной инициализации. Отдельный планировщик, приоритеты, лимиты числа экземпляров и циклы выгрузки при прокрутке не нужны. Интерактивная `/map/` запускается при открытии; в Compare действует существующее управление показом карты.

### 5. Действия и отказоустойчивость

Во время ожидания карты, при ошибке и без JavaScript исходный внешний URL доступен как обычная HTML-ссылка. В компактном событии она расположена сверху справа и использует исходный `mapUrl`, который может вести на организацию или маршрут. После готовности подложки и штатного действия ссылку заменяет native OpenMaps на текущий кадр; если резервная ссылка была в фокусе, он передаётся штатному действию. Исходный URL после готовности не дублируется. Серверная ссылка на место остаётся в сведениях события, нижний ряд действий содержит только ICS.

В карточке поселка сохранённый `location.mapUrl` либо существующая ссылка из координат остаётся отдельным действием и после готовности карты. Здесь штатный переход на текущий кадр не заменяет исходное назначение.

В карточке места сохраняется контракт `place-card-presentation`: исходная ссылка видна до готовности подложки и активного штатного действия, при ошибке и без JavaScript; после готовности резервная ссылка скрывается без потери клавиатурного фокуса. В фоновых картах сведения и HTML-действия доступны без перекрывающего их сообщения о загрузке.

### 6. CSP и долговечное решение

После удаления iframe проверить всех оставшихся потребителей `frame-src https://yandex.ru` и убрать разрешение только при отсутствии потребителей. Разрешения JS API сверить с настоящими сетевыми запросами; синхронизировать `ops/nginx/security.conf`, пояснения в `ops/nginx/CSP.md` и затронутые настройки сервера. Источники для работающего SDK сохраняются по ADR-017.

Общее подключение и два режима JS API закреплены в [ADR-039](../../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md), связанном с ADR-028 и индексом решений. Дизайн-гайд описывает сохранённую фоновую композицию и отдельное оформление подложки; технические параметры конкретного компонента остаются в коде.

## Risks / Trade-offs

- **Неподвижная карта всё ещё загружает полноценный движок** → единый runtime и отложенная инициализация сокращают дублирование и раннюю работу; реальный эффект измеряется, снижение веса заранее не обещается.
- **Служебный интерфейс SDK тесно размещается в компактном событии** → проверить настоящую карту на узкой и широкой странице, подобрать кадр и штатное положение элементов в существующей композиции.
- **Подложка и штатная кнопка готовы в разное время** → переиспользовать проверку готовности и HTML-fallback существующего превью; отдельно проверить ошибку, no-JS и клавиатурный фокус.
- **Настоящий SDK может отличаться от mock-теста** → для локальной приёмки нужен доступ API с используемого локального origin и фиксация фактического показа и рекламных запросов. Недоступность API означает незавершённую проверку, а не успешный результат; подтверждение тарифа для неё не требуется.

## Migration Plan

1. До правок снять локальный визуальный и сетевой baseline новости с картой события, места и desktop-карточки поселка. Использовать одинаковые страницы, браузер, размеры окна и настройки кэша при сравнении.
2. Подготовить общее превью на основе `PlacePreview`, подключить события и карточку поселка, удалить iframe-builder и ставшие ненужными декоративные ветки после проверки вызовов.
3. Согласовать CSP и документацию с фактическими запросами SDK, выполнить тесты и локальную приёмку.
4. После завершения реализации и проверок синхронизировать основные specs и архивировать change в ветке реализации перед итоговым PR с `Closes #762`.

**Приёмка завершается локально; обязательная production-проверка не требуется.** Проверить настоящие карты всех пяти поверхностей, несколько событий на странице, узкий экран, изменение размера, прокрутку, действия, блокировку API, no-JS и повторную Astro-навигацию. Записать наличие или отсутствие рекламы, сравнить количество запросов, переданные байты SDK и рекламные цепочки с baseline; отсутствие iframe само по себе не доказывает отсутствие рекламы. Результат описывает наблюдаемое поведение сервиса, а не подтверждает тариф. Автоматизированные проверки поведения дополняют, а не заменяют этот прогон.

Откат реализации возвращает её код, CSP и документацию одним revert. Внешние настройки продукта в кабинете Яндекса находятся вне этого изменения и отката репозитория.
