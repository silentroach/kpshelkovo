# Design

## Context

Мотивация и объём — в [proposal.md](/openspec/changes/archive/2026-11-08-add-tariff-tldr/proposal.md). Согласованы URL `/815/tldr/`, пункт «Вкратце», H1 «Вкратце о новом тарифе», одна колонка, умеренные выделения и поиск по содержимому.

Исходник: [сообщение собственника](https://t.me/shelkovoecoclub/34238/52130) от **11 августа 2026 года**. Полный текст доступен через [публичное представление Telegram](https://t.me/shelkovoecoclub/52130?embed=1&mode=tme); в HTML дата поста — `2026-08-11T14:29:10+00:00`. Отметка `edited` не сообщает дату последней правки.

Найденные точки интеграции:

- [SiteNav.astro](/apps/www/src/components/site/SiteNav.astro) содержит обе версии меню. Текущая группа вычисляется из `compareCurrent || regulationCurrent`; новый маршрут нужно включить явно.
- [Правила отзывов](/apps/www/src/lib/reviews/rules.ts) уже читают один Markdown через `?raw`, извлекают H1 средствами AST и отдают содержимое HTML и companion. Это ближайший образец, без новой коллекции.
- [BaseLayout](/apps/www/src/layouts/BaseLayout.astro) автоматически объявляет `<путь>/index.md`; поисковое содержимое подключается отдельно через `SearchDocument`.
- В [поисковых разделах](/apps/www/src/lib/search/sections.ts) есть Compare и регламент, но нет общего раздела «Тариф 815».

Design нужен для согласования контента, меню, поиска и доставки одной страницы. Нового архитектурного механизма здесь нет.

## Goals / Non-Goals

**Goals:**

- Использовать один редактируемый Markdown для текста, его атрибуции и публичных представлений.
- Применить существующие рендер, типографику, поисковую разметку и статическую доставку.
- Сохранить различие между датированной авторской цитатой и собственными текстами сайта.

**Non-Goals:**

- Общий движок произвольных страниц, новая CMS или коллекция ради одной записи.
- Пересказ, сокращение, фактологическая актуализация цитаты, новые выводы и дополнительные разделы статьи.
- Новый дизайн меню, новые шрифты, анимации, Telegram embed или клиентский код страницы.
- Отдельный JSON API, разделовый `llms.txt` или новый тип обратных ссылок в графе упоминаний.

## Decisions

### 1. Один Markdown и небольшой серверный helper

Предлагаемый источник — `/apps/www/src/data/tariff-tldr.md`: H1, короткий NOTE с атрибуцией, затем цитата обычным Markdown blockquote со всеми абзацами и списком. Frontmatter для этой единичной страницы не нужен. Заголовок и body извлекаются через AST по простому образцу правил отзывов; дополнительная логика того образца для секций правил сюда не переносится.

Серверный модуль `/apps/www/src/lib/tariff-tldr/` хранит минимальные route/content helpers. HTML проходит через `@/lib/markdown/render`; для ссылочных упоминаний подключается общий `SiteMentionRegistry`. Companion строится из того же Markdown средствами AST и app-level подготовки, раскрывает mentions в публичные ссылки. Эти решения следуют [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md) и [правилам Markdown](/packages/markdown/README.md).

Альтернативы: строка внутри `.astro` усложняет редактуру; отдельная content collection с raw/domain/public-моделями не нужна для фиксированного документа без структурированного набора данных.

### 2. Границы корректуры и атрибуция

Вверху, сразу после H1:

```markdown
> [!NOTE]
> **[Сообщение от 11 августа 2026 года](https://t.me/shelkovoecoclub/34238/52130)**
>
> Цитата одного из собственников в чате «Shelkovo Eco Club — соседи».
```

Внешнее имя автора и профиль человека не добавляются: согласована атрибуция «одного из собственников». Дата относится к исходному посту; она не заменяется датой публикации страницы или последней сборки.

Корректура ограничена ошибками: например, «обьекты» → «объекты», «в течении дня» → «в течение дня», «не понятно» → «непонятно» с необходимой пунктуацией. Скрытые случайные символы можно убрать. Факты, суммы, расчёты, оценки, абзац о ключевой ставке и относительные указания времени сохраняются. Спорную фактическую правку нужно обсудить с владельцем.

Оформление: существующее перечисление становится Markdown-списком; несколько исходных начальных фраз выделяются полужирным. Новые подзаголовки не сочиняются. Исходное курсивное пояснение можно набрать обычным шрифтом с полужирной вводной фразой. Штатная типографика применяется как часть разрешённого оформления, без изменения общих правил.

До корректуры сохранить исходный текст для сверки по [редакторскому протоколу](/docs/development.md#редакторское-ревью-текстов-сайта). `humanizer-ru` используется в точечном режиме; цитата защищена от стилистического переписывания. `editorial-reviewer` получает оригинал, чистовик и эти ограничения, а также все новые UI/SEO/discovery-тексты.

### 3. Ссылки выбираются по контексту

Ссылки ставятся на существующие слова, преимущественно при первом полезном упоминании. Для мест подходит `[авторская фраза](@slug)`: этот синтаксис сохраняет слова. Раскрытие ссылок не требует подключения страницы как нового источника backlinks, что допускает [entity-mentions](/openspec/specs/entity-mentions/spec.md).

Подтверждённые кандидаты: «Титаник» — `/map/titanic/`, пляж — `/map/beach/`; абзац об обосновании цены можно связать с `/815/regulation/`, учитывая, что это калькулятор и разбор, а не сам исходный документ.

Точное место ссылки на регламент проверить при подготовке текста. Для п. 3.12 найден разбор юриста, но не сам договор; для оферты опубликованы документы с датой 9 июня, тогда как автор пишет об августе; «Доп. соглашение № 1/2026» не найдено. Эти результаты не позволяют подменять названные документы похожими материалами. У ВЗУ есть несколько карточек мест. Если соответствие не удаётся подтвердить, оставить соответствующие слова без ссылки; публикация не зависит от ссылки на каждое упоминание.

### 4. Страница для последовательного чтения

`BaseLayout`, стандартный page header и `ui-prose` с единой левой осью для заголовка, атрибуции и цитаты. Ширина колонки и типографические роли берутся из [дизайн-гайда](/docs/design/design-code-shelkovo.md#3-typography): основной текст Fira Sans 17 px / 1.65, выделения 600, H1 PT Serif 700. По уточнению владельца атрибуция использует компактный тёплый NOTE по образцу оригинала оферты в KB: заголовок-ссылка с датой и штатным Telegram-значком, ниже пояснение 14 px / 1.5. Подложка и граница повторяют существующий рецепт KB; PDF-значок не добавляется, shared стили NOTE не меняются.

Цитата семантически остаётся blockquote; локальное оформление убирает у её внешней оболочки декоративную плашку, большую кавычку и длинную боковую линию. Основную структуру дают абзацы и интервалы. На телефоне та же колонка занимает доступную ширину с полями. Рецепт страницы кратко фиксируется в дизайн-гайде; CSS ограничивается этой страницей по [ADR-034](/docs/decisions/034-native-css-architecture.md).

Из [референса Бирмана](https://ilyabirman.ru/reference/) используются типографическая иерархия, группировка близостью и ссылки внутри текста. Многоколоночный словарный набор подходит справочнику, но мешал бы последовательному чтению этой цитаты. Альтернатива с большой карточкой цитаты добавляет обрамление длинному тексту без полезной роли.

### 5. Навигация и поиск

В обеих ветках `SiteNav.astro` добавить «Вкратце» перед сравнением, вычислить `tldrCurrent` существующим `getCurrent` и включить его в признак текущей группы. По дополнительному согласованию владельца `/815/tldr/` служит входной страницей раздела без переноса на `/815/`. Её полные крошки: «Главная → Тариф 815»; у сравнения и регламента перед собственным уровнем добавляется родитель «Тариф 815» со ссылкой на `/815/tldr/`. Вложенные страницы продолжают ту же цепочку. HTML-крошки и BreadcrumbList используют одинаковую иерархию. Существующие адаптивные правила и URL страниц сохраняются; ссылка на несуществующий `/815/` не создаётся.

Передать в `BaseLayout` `SearchDocument` с `scope: 'page'`, заголовком из Markdown и разделом `tariff` / «Тариф 815», добавленным в существующий список разделов. В поисковый body входят заголовок, атрибуция и видимый текст; общая навигация остаётся вне него. Новый результат использует обычные snippets, ссылки и подсветку. Метаданные не получают искусственную дату «обновления».

Это пополнение содержательного корпуса. Специальные веса, алиасы и изменения ранжирования не нужны. HTML имеет собственный canonical и обычную внешнюю индексацию; companion следует действующей политике `noindex, follow`. Title/description оформляются по [page-meta](/docs/page-meta.md) и обозначают материал как цитату собственника.

### 6. Публичный Markdown и доставка

Добавить `/apps/www/src/pages/815/tldr/index.astro` и `index.md.ts`, использовать `createMarkdownResponse`. Зарегистрировать HTML и companion небольшим фрагментом рядом с helpers страницы в [общем реестре](/apps/www/src/lib/public-surface/index.ts), добавить именованную ссылку в корневой `llms.txt`. Для `describedby` используется корневой путеводитель. Основание — [ADR-011](/docs/decisions/011-public-surface-registry.md).

В nginx подключить адрес к существующим правилам HTML/Markdown negotiation, alternate/discovery-заголовков, MIME и кеширования по [ADR-009](/docs/decisions/009-markdown-accept-negotiation.md). Проверить доставку собранного сайта через nginx, а не только ответ Astro helper. Действующий CI уже доставляет site-конфиг; сверить совместимость с [workflow](/.github/workflows/ci.yml). Сам deploy-поток не меняется.

Альтернатива без companion оставляла бы объявленную `BaseLayout` ссылку неработающей либо потребовала бы отдельного исключения для обычной текстовой страницы.

## Risks / Trade-offs

- Датированный рассказ можно принять за текущую сводку → дата с годом и атрибуция видны до первого абзаца, сохраняются в companion и описании страницы.
- Ссылка может незаметно подменить редакцию договора или конкретное место → проверять цель и контекст, при неоднозначности оставлять слова без ссылки.
- Подсветка группы меню не появится от одного добавления ссылки → включить маршрут в расчёт текущей группы и проверить оба представления.
- HTML доступен, но companion или поиск забыты → включить их в один change и проверить фактический production-индекс и HTTP-доставку.

## Migration Plan

Данные пользователей не мигрируют. Страница, меню, индекс, discovery и конфигурация доставки публикуются одним изменением после приёмки. Откат возвращает этот комплект целиком. Основные specs синхронизируются и change архивируется в ветке реализации до PR по проектному workflow.
