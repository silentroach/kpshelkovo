# Proposal

## Why

Поиск номеров участков сейчас делает отдельный запрос Pagefind только по точному фильтру, а затем соединяет его результаты с текстовой выдачей. Холодный поиск номера загружает заметно больше файлов индекса, чем обычный текстовый запрос; владелец предпочёл искать участки полнотекстово, включая короткие номера, без требования точного совпадения и принудительного приоритета участков.

Изменение продолжает [#804](https://github.com/silentroach/kpshelkovo/issues/804) в текущей ветке `feat/parcel-map-search` и существующем [PR #810](https://github.com/silentroach/kpshelkovo/pull/810). Оно следует за [архивированным change `index-parcels-with-pagefind`](../2026-09-23-index-parcels-with-pagefind/proposal.md), не переписывая его историю.

## What Changes

- Добавить короткие основные номера и короткие варианты подтверждённых алиасов в поисковый текст записи участка. Полный и короткий код должны находиться в общем Pagefind-поиске; префиксные и числовые совпадения больше не исключаются особым правилом точности.
- Для запросов с обозначением участка использовать один обычный полнотекстовый запрос Pagefind вместо параллельных запросов текста и фильтра по номеру. Участки участвуют в общей релевантной выдаче без отдельного закрепления перед страницами; результат по-прежнему различает части и ведёт по основному коду на карту.
- Не индексировать служебную подпись раздела «Участки» как поисковое слово каждой записи: тематический запрос об участках не должен получать тысячи случайных совпадений. Проверить релевантность и холодный трафик до/после на одинаковой локальной production-сборке.
- **Изменение поведения:** отменить требование точного совпадения и обязательного места участка перед текстовыми страницами. Номерные префиксы и цифровые фрагменты могут давать обычные результаты Pagefind; отдельного гарантированного расширения до всех участков по фрагменту нет.
- Сохранить действующие данные и правила подтверждённых алиасов, прямых ссылок и геометрии. Вопрос об удалении алиасов из доменной модели остаётся отдельным продуктовым решением.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `search`: поиск по полному и короткому обозначению остаётся доступным, но участки становятся обычными полнотекстовыми результатами без отдельного точного совпадения, приоритета и случайных совпадений по служебной подписи раздела.

## Impact

- Сборка записей Pagefind в `apps/www/scripts/build-search-index.ts`, клиент `apps/www/src/lib/search/client.ts` и его тесты; при необходимости только затронутые DOM- и production-проверки поиска.
- Действующая [спецификация поиска](../../../specs/search/spec.md) и [ADR-041](../../../../docs/decisions/041-parcel-records-and-exact-search.md); `parcel-map`, редакционная модель участков и правила обновления источников не меняются.
- Новых зависимостей, маршрутов, внешних запросов и публичных JSON нет. Измерение сравнивается с опубликованными в PR #810 результатами предыдущего change, а не подменяет их.
