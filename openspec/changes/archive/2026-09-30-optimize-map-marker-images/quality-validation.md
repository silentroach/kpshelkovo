# Визуальная приёмка маркеров

Task 3.1, 30 сентября 2026 года. Сеть и объём передачи — отдельная task 3.2.

## Итог

- **Adaptive — FAIL:** при root24 браузер продолжал выбирать уменьшенный источник. На настоящей карте у Foodtruck при DPR1 / максимальном hover рисунок занимал 72.384 × 64.326 CSS px, но загружался вариант 72 px. В парных снимках он мягче полноразмерного baseline; потеря деталей видна также в серии root24 / DPR2. Это основание для предусмотренного fallback, а не разрешение снизить качество.
- **Окончательный full-only — PASS в выполненном адресном повторе:** на :14335 проверены все семь рисунков при DPR1/2/3 и root16/root24. Ухудшения относительно полноразмерного baseline в просмотренных парах не обнаружено. Загружаются те же семь полноразмерных WebP; `srcset` и `sizes` отсутствуют на всех собранных живых изображениях.
- Подтверждённых release-blocking дефектов final нет. Это не заявление о повторном выполнении всей прежней матрицы: desktop zoom, закрытые состояния и узкая раскладка проверены на прежнем full-only baseline, но после удаления атрибутов не повторялись. Владелец остановил дальнейшие длительные прогоны; новые не запускались.

## Что выполнено на final

- Production-сборка :14335 после перехода на fallback; baseline :14336 содержит единственный `144w` кандидат. Использован настоящий SDK Яндекс Карт, без mock подложки или маркеров.
- Шесть успешных серий `final-dpr{1,2,3}-root{16,24}-open-real-raster`, по 75 записей каждая. Все семь: Apple, Animals, Foodtruck, Titanic, Construction, Fish, Kpp.
- Обзорная карта: обычное состояние, настоящий wheel zoom до graphic scale `1.300`, hover и клавиатурный `:focus-visible`; Tab + Enter открывает соответствующую карточку. Клавиатурный тест начинается с предшествующего элемента, затем выполняется настоящий Tab; это не полный обход всех offscreen-маркеров.
- Настоящее отдаление карты до `0.625` с кластеризацией сохранено отдельно. Все семь рисунков при минимальном graphic size сняты как **isolated minimum CSS probe** на живом маркере: это не семь видимых маркеров при реальном минимальном zoom.
- Семь живых SDK-превью: normal/hover/focus. «Рядом» на карточках `village-checkpoint`, `titanic`, `beach`: normal/focus, объединение действительно содержит все семь рисунков, Tab + Enter открывает нужные карточки. Открытие внешнего popup из превью проверено на DPR1/root16, не на каждом DPR.
- Во всех шести сериях DPR совпадает с плотностью PNG (`pngWidth / innerWidth`), root действительно `16px` или `24px`. Полноразмерные пути совпадают с baseline: `Apple.DmgdUoLt`, `Animals.uaszdH8e`, `Foodtruck.CR2UB4CH`, `Titanic.Dy7FzEBK`, `Construction.CHv7cYO9`, `Fish.C4LRg0Ap`, `Kpp.oDHkH3JZ` — все `.webp`.
- Адресная сверка DOM не нашла отличий фильтров, object-fit, исходных width/height, статусов, hover/focus и видимости часов. В двух обычных кадрах КПП размер отличается на 0.960/1.440 CSS px: сохранённый scale `1.030` против `1.000` после SDK-приближения к кластеру. Это не сравнение при одинаковом zoom; в максимальных focus-парах различие не проявляется. Пиксельное совпадение всей карты не заявляется.
- Визуально просмотрены парные final/baseline contact sheets максимального focus всех семи рисунков во всех шести условиях, превью DPR3/root24, минимальные CSS probes и ближайшие ссылки DPR1/root16. Нет заметного изменения деталей, пропорций, теней, обрезания рисунков или focus-ring. Дополнительные сохранённые кадры не выдаются за индивидуально просмотренные.

## Ранее выполненное full-only покрытие

- `full-dpr{1,2,3}-root16-open-real-raster` и `full-dpr{1,2,3}-root24-open-real-raster`: полные успешные серии по 75 записей.
- Настоящий desktop zoom 125% при исходном DPR1/2/3: полные `full-dpr{1,2,3}-root16-open-native1.25-real-raster`, DPR **1.25/2.5/3.75**, innerWidth **1024** вместо **1280**, `visualViewport.scale=1`. Использован `chrome.tabs.setZoom`; preference-only попытки, CSS zoom и pinch не засчитываются. Ранее оборванный DPR2 повтор завершён в этой сессии.
- Stress root24 + 125%: `full-dpr1-root24-open-native1.25-real-raster`, все 75 записей; ранее оборванная серия завершена в этой сессии. Root24 + 125% на DPR2/3 не выполнялся.
- Реальные расписания Foodtruck/Kpp: mixed и closed при DPR1/2/3 на обзорной карте и в живых превью, по 17 записей в каждой full-only серии. Закрытость определяется временем до навигации, не подменой DOM. Визуально просмотрены закрытые focus-превью DPR2: grayscale, часы и рамки сохранены. Остальным пяти рисункам закрытое состояние не выдумывалось.
- `full-points-real-raster`: 390px/DPR2, четыре карточки и обзорная карта, без горизонтального overflow; отдельно foodtruck на обзорной карте и kpp в превью переходят closed → open штатным таймером без reload, `sameMap=true`. Это точечное покрытие, не проверка каждого рисунка на узком экране.
