# Proposal

## Why

В [#118](https://github.com/silentroach/kpshelkovo/issues/118) интерфейс соединяет заголовок секции с обрезанным excerpt Pagefind через двоеточие: хвост заголовка выглядит повтором, а продолжение абзаца — искусственным предложением. Владелец выбрал ограниченное исправление: отделить контекст секции от фрагмента, сохранив сам основной excerpt и поведение переходов после #124.

## What Changes

- Показывать heading context отдельным текстовым блоком над основным excerpt внутри той же ссылки результата; не собирать `заголовок: фрагмент`.
- Сохранить текст и highlights основного excerpt без дописывания исходного текста, удаления заголовочных суффиксов или восстановления начала предложения.
- Сохранить выбор однозначного соответствующего якоря, canonical fallback и передачу поискового контекста по действующему контракту #124.
- Ограничить визуальную правку существующим компонентом результата: без новых шрифтов, палитры, движения и общего редизайна.
- Явно оставить обрезку Pagefind ограничением согласованного объёма. Первоначальное ожидание issue о целых связных фразах этим изменением полностью не выполняется; собственного sentence/block-aware генератора и нового определения обрезки не будет. Многоточие не добавляется вслепую.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `search`: отдельное представление heading context без грамматической склейки с основным excerpt и без изменения его текста.

## Impact

- Компонент и существующие fixtures: `/apps/www/src/components/search/SearchDialog.svelte`, `/apps/www/src/components/search/tests/SearchDialog.test.ts`; короткое правило композиции в `/docs/design/design-code-shelkovo.md` одновременно с будущей UI-правкой.
- Дополняется [search](/openspec/specs/search/spec.md), без ослабления требований безопасности, primary excerpt, якоря, доступности и ленивой загрузки. Поисковый клиент, ranking, корпус, aliases, версия Pagefind, Markdown-render и инфраструктура остаются прежними.
- Приёмка реализации: адресные fixture-тесты и ручное сравнение семи запросов issue с контролями, длинной транскрипцией и Markdown-картой на сопоставимых production-сборках. Автоматическая матрица реального контента из PR #136 не возвращается.
- Проверка после публикации на production не является условием завершения этого плана; штатная локальная production-приёмка предшествует PR и архивированию. Перед будущим закрытием #118 основная сессия обновляет резюме issue согласованным ограниченным результатом, а не заявлением о гарантии целых фраз.
- Эта очередь разрешает только planning artifacts и их валидацию: без реализации, commit, push, PR и запуска dev. Порт `4321` принадлежит работе по #903; для будущей браузерной проверки согласуется отдельная среда/очередь.
