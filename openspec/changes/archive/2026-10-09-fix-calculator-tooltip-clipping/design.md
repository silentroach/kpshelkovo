# Design

## Context

Мотивация — в [proposal](/openspec/changes/archive/2026-10-09-fix-calculator-tooltip-clipping/proposal.md). В `/apps/www/src/pages/815/regulation/index.astro` подсказка абсолютно позиционирована относительно кнопки шириной 1rem. Ограничение ширины не учитывает положение кнопки. Ниже 64rem scroll-контейнер обрезает подсказку; увеличение z-index не исправляет clipping.

Advisor предложил перенести containing block к существующей внешней секции. Browser-эксперимент на production со временным CSS подтвердил подход в Chromium: на 320/390px подсказка остаётся читаемой при перемещении кнопки к обоим краям. Отдельное искусственное уменьшение высоты shell подтвердило отсутствие overflow-clipping по screenshot. Блокировка скриптов и touch/focus сохранили раскрытие. Исходники проекта в эксперименте не менялись; это доказательство подхода, не приёмка будущего diff.

Применимы [ADR-034](/docs/decisions/034-native-css-architecture.md) и [дизайн-гайд](/docs/design/design-code-shelkovo.md): route-owned CSS и сохранение горизонтальной прокрутки таблицы. Новый ADR не нужен.

## Goals / Non-Goals

- Исправить локальное CSS containment всех трёх видов объяснений отсутствующих значений без новых импортов, компонентов и JavaScript.
- Сохранить связь через `aria-describedby`, hover/focus, сенсорное раскрытие и работу без JS.
- Не добавлять автоматический выбор сверху/снизу у вертикального края viewport и точное горизонтальное следование кнопке: для исправления #150 они не нужны.
- Не менять расчёт, общий `.ui-sticky-table-shell` и desktop-оформление от 64rem.

## Decisions

- Ниже 64rem задать существующей `.reglament-sections__inner > section`, оборачивающей header и scroll-shell, `position: relative; min-width: 0`.
- У `.reglament-missing-help` использовать `position: static`; tooltip оставить absolute с `left: 0; top: auto; width: min(18rem, 100%)` и вертикальным отступом 1.35rem, сохраняющим высоту кнопки и зазор.
- Статическая вертикальная позиция сохраняет связь со строкой; горизонтальная позиция задаётся секцией вне clipping ancestor. `min-width: 0` не даёт grid растянуть секцию по минимальной ширине таблицы: прокручивается shell, а не документ.
- Одно `right: 0` отвергнуто: после прокрутки обрезание переходит налево. Перенос containing block без `min-width: 0` тоже недостаточен: эксперимент на 320px показал прокрутку документа и левое обрезание.
- JS clamp, portal и библиотека positioning не нужны: CSS-кандидат подтверждён. `!important` из browser-эксперимента в проектный CSS не переносить.
- Постоянную регрессию проверять на реальной странице и существующей browser-конфигурации; отдельный общий fixture/framework не добавлять. `toBeVisible()` и размеры сами по себе не доказывают отсутствие clipping. В текущей смете нет отсутствующей периодичности: браузер проверяет реально представленные объяснения и автоматически включает остальные при их появлении; неиспользуемую ветку проверяем адресным ревью эквивалентности разметки и применения общего CSS. Это не исполненный SSR-кейс и не браузерное доказательство этой ветки. Владелец согласовал корректировку приёмки в текущей сессии; delta остаётся для всех отсутствующих значений.

## Risks / Trade-offs

- Подсказка перестаёт следовать кнопке по горизонтали → сохраняется вертикальная связь со строкой и доступное описание; проверить читаемость реально представленных объяснений и адресно сопоставить неиспользуемую ветку с общим CSS.
- Изменяется containment секции → проверить, что документ не получает горизонтальный overflow, таблица прокручивается внутри shell и sticky headers не регрессируют.
- Production-эксперимент выполнен в Chromium, Safari не проверен → приёмка итогового CSS должна явно указывать браузерный охват; использовать доступный WebKit для адресного контроля при наличии.
- Последняя строка секции может пересекать следующий блок → проверить фактическую читаемость и отсутствие clipping, не менять глобальное overflow ради подсказки.

## Migration Plan

- После локальных browser-проверок, подходящих тестов, typecheck/сборки и reviewer синхронизировать delta, архивировать change и открыть PR с `Closes #150`.
- Откат — возврат PR целиком. Данные, зависимости и deploy не меняются.
