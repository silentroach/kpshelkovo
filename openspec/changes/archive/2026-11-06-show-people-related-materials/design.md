# Design

## Context

Причина и согласованный объём — в [proposal](/openspec/changes/archive/2026-11-06-show-people-related-materials/proposal.md). На момент подготовки плана [страница профиля](/apps/www/src/pages/people/[slug]/index.astro) уже загружала backlinks, но `showBacklinks = false` скрывал карточный список с группами и выдержками. [Тест страницы](/apps/www/src/lib/people/tests/profile-page.test.ts) закреплял это временное отключение.

[Карточки мест](/apps/www/src/components/places/PlaceRelatedLinks.astro) используют компактные списки ссылок. Их [селектор](/apps/www/src/lib/places/related.ts) решает собственные задачи: приоритет явно затронутых мест, три новости/статуса и случайная подборка KB. У людей источники шире, а семантики `affected_places` нет.

[ADR-012](/docs/decisions/012-entity-mention-graph.md) оставляет публичные представления за доменами поверх общего графа. [ADR-034](/docs/decisions/034-native-css-architecture.md) задаёт локальное владение стилями и общесайтовые tokens. Нового архитектурного решения для этой проекции не требуется.

## Goals / Non-Goals

**Goals:**

- Отдельная build-only HTML-проекция существующих ссылок без изменения доменных данных.
- Узнаваемое оформление по [рецепту карточки места](/docs/design/design-code-shelkovo.md#карточка-места) с локальным компонентом профиля.

**Non-Goals:**

- Расширение источников упоминаний, извлечение цитат вокруг имени, ручное ранжирование, пагинация и полный HTML-архив.
- Изменение отбора мест, их приоритетных сообщений, Markdown/JSON и поисковой релевантности.

## Decisions

### 1. Отбор выполняется только для HTML

Добавить небольшой селектор в `apps/www/src/lib/people/related.ts`: собрать ссылки из `PERSON_MENTION_SECTIONS` в новый массив, отсортировать и взять первые шесть. Использовать существующий `PersonMentionRef`, без новой публичной модели. Единственность ссылки на материал уже обеспечивает граф; одинаковые заголовки разных источников не объединять.

Хронология определяется `mentionedAt`: публикация для новостей и отзывов, начало для мероприятий и статуса, обновление карточки для «Сарафана». Ссылки из описаний людей и мест не имеют даты и следуют после датированных источников. Используется дата, уже предоставленная адаптером источника; у обновлённой карточки «Сарафана» она может быть позже публикации новости.

Сравнивать моменты времени; равенства разрешать через `compareRuText` по заголовку, разделу и `sourceId`, как в подборке мест. `sortKey` не использовать: у статуса он отражает последнее изменение, которое может поднять старый инцидент выше новой новости. Будущая дата участвует в том же порядке; отдельного приоритета фаз нет.

Срез по каждой группе дал бы больше шести материалов или скрытые квоты. Ограничение в загрузчике повредило бы полный Markdown и JSON. Поэтому `personBacklinkGroups` и полные backlinks остаются для существующих потребителей, а селектор вызывается страницей профиля.

### 2. Метаданные берутся из готовой ссылки

Компонент использует `htmlUrl`, `title`, существующие `formatPersonBacklinkKind` и `formatPersonBacklinkDate`. Дата получает исходное `datetime`; отсутствие даты оставляет только вид материала. Динамические строки проходят действующую типографику.

У людей показывается дата начала записи статуса. Период, состояние и приоритетные плашки места решают задачу доступности объекта; они не нужны для указателя упоминаний человека. Дополнительная загрузка статуса ради полного совпадения метастрок добавила бы связь между слоями без пользы для согласованного блока. Выдержки остаются в полных представлениях: это пересказ источника, который не всегда объясняет роль человека.

### 3. Оформление повторяет компактный рецепт мест

Добавить `apps/www/src/components/people/PersonRelatedLinks.astro` с локальным scoped CSS и подключить после основного блока профиля. Компонент получает уже отобранные ссылки, выводит именованную секцию, заголовок и один `ul`. Пустой массив не создаёт разметку секции или её отступы. Удалить выключатель, старую разметку и ставшие ненужными стили карточек.

Использовать тот же визуальный рецепт, что у `PlaceRelatedLinks`: тонкая верхняя граница, поле сверху `1.5rem`, `ui-section-label` в `text-muted`, отступ до списка `0.625rem`, между записями `0.875rem`; ссылки Fira Sans 400, `1rem` / 1.5, метаданные `0.875rem` / 1.5 с отступом `0.25rem`. Ссылки используют `site-text-link`, тонкое подчёркивание, цвет действия при наведении и видимый фокус. Ширина следует текстовому содержимому профиля; длинные названия и метаданные переносятся целиком.

Общий рецепт закрепить в дизайн-гайде и связать с разделом мест; убрать из гайда упоминание карточных рамок ссылок профиля. Общими остаются действующие tokens и примитивы. Универсальный компонент с настройками групп, приоритета, лимитов и метаданных здесь не нужен: для двух коротких доменных представлений локальная разметка проще, а совпадение вида проверяется рядом в браузере.

Простое включение старого блока оставило бы отличающиеся карточки и полный список. Вынос в `packages/ui` не соответствует app-owned данным и отсутствию второго приложения-потребителя.

### 4. Статическая выдача и исключение из поиска

Подборка целиком формируется в Astro без гидратации и сохраняет `data-pagefind-ignore="all"` существующего блока. Это вспомогательная навигация: заголовки чужих материалов не становятся содержимым профиля для поиска. При проверке исключения следовать [правилам поиска](/AGENTS.md#локальные-инструкции); клиентские импорты и условия загрузки страницы не меняются.

## Risks / Trade-offs

- Сортировка по последнему изменению статуса исказит хронологию → использовать `mentionedAt` и проверить старую запись с поздним обновлением.
- Случайная мутация backlinks сократит другие представления → создавать новый массив и проверить сохранность входа, Markdown и JSON при числе ссылок больше лимита.
- Одинаковые заголовки инцидентов плохо различимы → сохранять даты и вид; подробности доступны по ссылке.
- Локальные стили двух компонентов могут разойтись → закрепить один рецепт в дизайн-гайде и сравнить профиль с карточкой места на широком и узком экранах.
- Старые или недатированные материалы могут не попасть в шесть ссылок → это согласованный предел HTML-подборки; полные представления сохраняют все источники.

## Migration Plan

Обычная статическая сборка и публикация. Миграции данных нет. Откат возвращает изменение HTML-представления и документации целиком; граф и публичные форматы сохраняются.
