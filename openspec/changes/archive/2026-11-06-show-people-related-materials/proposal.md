# Proposal

## Why

В [#1284](https://github.com/silentroach/kpshelkovo/issues/1284) житель не видит в HTML-профиле материалы сайта с упоминанием человека, хотя ссылки уже доступны в Markdown и JSON. Согласован компактный единый список до шести материалов, оформленный как связанные материалы карточек мест.

## What Changes

- Показывать после сведений о человеке раздел «Где упоминается»: один список из всех подключённых разделов, общий лимит — шесть материалов.
- Выбирать самые свежие материалы по дате источника; недатированные помещать после датированных. При равных датах сохранять устойчивый порядок.
- Выводить название-ссылку и строку с видом материала и доступной датой. Использовать компактное оформление списков мест, без карточных рамок, выдержек и раскрытия остальных ссылок.
- При отсутствии материалов скрывать весь раздел вместе с заголовком и разделителем.
- Закрепить оформление в дизайн-гайде и проверить его рядом с карточкой места.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `people-profile-presentation`: видимая компактная хронология упоминаний, отбор шести материалов, пустое состояние и согласованное с местами оформление.

## Impact

- HTML-маршрут `/people/[slug]/`, его представление связанных материалов и адресные тесты в `apps/www/src/lib/people/tests/`.
- [Дизайн-гайд](/docs/design/design-code-shelkovo.md): общий визуальный рецепт связанных ссылок людей и мест.
- Источником остаётся существующий граф по [entity-mentions](/openspec/specs/entity-mentions/spec.md). Его группировка, полный Markdown и JSON людей, правила отбора материалов мест сохраняются; лимит применяется только к HTML-подборке профиля. Подборка исключена из Pagefind.
- Новые зависимости, клиентский JavaScript и публичные адреса не нужны. Приёмка выполняется локально до PR; отдельная production-приёмка не требуется.
