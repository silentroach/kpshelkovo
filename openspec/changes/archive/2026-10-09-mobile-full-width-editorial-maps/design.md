# Design

## Context

Мотивация — в [proposal](/openspec/changes/archive/2026-10-09-mobile-full-width-editorial-maps/proposal.md#why). Объём согласован после explore/advisor. В сессии реализации 9 октября 2026 года владелец разрешил реализацию, затем согласовал прямые углы растянутых карт и узкое исправление мобильного переноса заголовка новости. После приёмки владелец явно разрешил commit, push и перевод PR из draft в готовый к ревью.

- `ui-page` ограничивает ширину через `--page-padding: clamp(1rem, 3vw, 2rem)`; `.news-article-layout` и `.kb-body` добавляют по `1.25rem`. До `40rem` ограничение `ui-prose` в `39.06em` не сужает материал дополнительно.
- `/apps/www/src/components/maps/editorial-map.css` импортирует общую рамку `/apps/www/src/components/maps/map-frame.css`, которую также используют превью мест. Подпись уже поддерживает `overflow-wrap: anywhere` и фокус ссылки.
- `/apps/www/src/lib/markdown/editorial-maps.ts` обрабатывает карты в списках, цитатах и сносках: ширину нельзя менять общим descendant-селектором всех карт.
- Владение CSS определяют [ADR-034](/docs/decisions/034-native-css-architecture.md) и [ADR-042](/docs/decisions/042-feature-owned-map-frame-css.md). Новый ADR не нужен.

## Goals / Non-Goals

**Goals:** ограничить новую геометрию двумя существующими контекстами и экранным media query; подтвердить её реальным layout браузера.

**Non-Goals:** менять общий файл рамки, радиусы вложенных карт, высоту, renderer, JavaScript, импорты или условия загрузки; вводить универсальный full-bleed примитив, измерение viewport в JS либо скрытие overflow всей страницы.

## Decisions

### Локальный CSS с отрицательными отступами

В `editorial-map.css` добавить правила внутри `@media screen and (width < 40rem)` (640 CSS-пикселей при базовом размере 16px). Для `.news-article-layout .ui-prose > .ui-editorial-map` и `.kb-body .ui-prose > .ui-editorial-map` использовать `width: auto` и `margin-inline: calc(-1 * (var(--page-padding) + 1.25rem))`. Это компенсирует известные отступы обоих контекстов и оставляет текст на месте. Существующая рамка сохраняется; у самого figure, его прямого `editorial-map` (включая `:last-child` без подписи) и панели подписи задать `border-radius: 0`. Вложенные карты сохраняют прежние радиусы.

Прямой дочерний комбинатор исключает вложенные карты. В том же экранном диапазоне выровнять `.ui-editorial-map__caption` по центру в обоих контекстах, без ограничения по вложенности и без изменения переноса и ссылок. `screen` исключает влияние мобильного правила на печать.

Общий `map-frame.css` не подходит: его изменение затронуло бы места. `100vw` с отдельным позиционированием не нужен при известной структуре отступов и усложняет контроль переполнения. Перестройка DOM или JS-измерение не даёт пользы для согласованных простых случаев.

### Аварийный перенос мобильного заголовка новости

Браузерная проверка выявила прежнее переполнение новости на 320px: длинное слово в H1 задаёт min-content неявной grid-колонки больше доступных 248px. По консультации advisor и разрешению владельца в scoped CSS news route добавить `overflow-wrap: anywhere` для `.news-article-header__content .ui-page-title` только внутри существующего `@media screen and (width < 40rem)`. Это устраняет источник расширения без изменения grid, размера шрифта и отступов. Переносы абзацев на ранее переполненном экране пересчитываются по исправленной ширине; заданные отступы остаются прежними. Широкий экран, печать и hero-заголовок не затрагиваются. Проверить также новость без карты.

### Документация и проверка без нового тестового механизма

Одновременно с CSS дополнить раздел [«Встроенная карта с подписью»](/docs/design/design-code-shelkovo.md#встроенная-карта-с-подписью) мобильным правилом для редакционных карт, прямыми углами растянутых карт, исключением вложенности и сохранением desktop/печати. В правиле заголовков зафиксировать аварийный перенос обычного заголовка новости на мобильном экране.

Существующий `/apps/www/src/components/maps/tests/editorial-map-style.test.ts` проверяет перенос и фокус, но happy-dom не доказывает геометрию браузерного layout. Нужна короткая браузерная проверка реальной `/news/2026/09/alternative-access/` и временного KB fixture через штатный Markdown pipeline, с прямой картой и картами в списке, цитате и сноске. Fixture не публиковать и убрать после проверки. Не добавлять постоянный smoke-обход сайта или отдельный универсальный harness ради этой правки.

## Risks / Trade-offs

- Зависимость от `1.25rem` у двух контейнеров → проверить оба раздела и границу media query; при будущей смене отступов пересмотреть компенсацию вместе с layout.
- Длинная подпись, рамка или округление могут дать переполнение → измерить bounding rect и `scrollWidth/clientWidth`, проверить перенос и клавиатурный фокус, не маскировать дефект через page overflow hidden.
- Мобильные правила могут случайно попасть в печать или другие карты → использовать `screen`, ограничить селекторы контекстами news/KB и сравнить print и незатронутые виды карт.

## Migration Plan

Миграция данных не требуется. После разрешения реализации CSS и дизайн-гайд входят в одно изменение; откат возвращает эти правки вместе. Для приёмки достаточно локальной сборки и браузера, без обязательной production-проверки.
