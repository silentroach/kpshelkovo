# Proposal

## Why

В [issue #479](https://github.com/silentroach/kpshelkovo/issues/479) production теряет `Content-Type` и `Link`, которые обработчики Astro задают для статических API-документов. Причина общая для prerendered endpoints: файл сохраняет тело, но не метаданные ответа; по согласованию с владельцем исправление охватывает все такие endpoints сайта, а не только 15 URL исходной проверки.

## What Changes

- Сборка получает заголовки фактических prerendered-ответов через штатный `staticHeaders` API Astro и выпускает отдельный nginx-фрагмент с точными `location =` для всех статических endpoints `apps/www`, включая конкретные пути из `getStaticPaths`.
- Охват включает JSON/Schema/OpenAPI, каталоги API, индексы навыков, Markdown, llms/robots, RSS, ICS и vCard. Не вводится список разрешённых разделов или ограничение количества URL.
- Основной nginx-конфиг подключает фрагмент; заменённые ручные правила удаляются или сужаются. HTML, файлы из `public/`, инфраструктура и правила для сохраняемых старых статических ресурсов остаются ручными.
- Источник объявленных `Content-Type`, `Link`, `Content-Disposition`, `X-Robots-Tag` и `Vary` — фактические ответы. Кеширование, security headers и дополняющие связи, которые сейчас задаёт только nginx, сохраняют действующую политику; один заголовок не получает конфликтующих источников.
- Schema и OpenAPI сравнения тарифов получают тот же набор discovery-ссылок, что уже использует основная JSON-лента этого раздела.
- Deploy устанавливает фрагмент вместе с конфигурацией и восстанавливает предыдущий комплект при неуспешном `nginx -t`.
- Автоматические проверки подтверждают полное покрытие prerendered endpoints и поведение каждого семейства форматов; 15 URL из issue остаются обязательной API-выборкой, но не границей генерации.

URL, тела документов, DTO и схемы не меняются. Не добавляются SSR, runtime-сервер, внешние зависимости или универсальный генератор всего nginx. Новые discovery-связи не придумываются за пределами двух отсутствующих Compare `Link`; существующие связи nginx не теряются при передаче locations генератору.

## Capabilities

### New Capabilities

- `static-api-response-metadata`: метаданные всех статических endpoints сохраняются при публикации, включая media type, discovery-связи и заголовки скачивания.

### Modified Capabilities

Нет. Действующие specs не описывают публикацию этих HTTP-метаданных.

## Impact

- `apps/www`: локальная Astro-интеграция, два обработчика сравнения тарифов, тесты всех семейств endpoints и отчёты клиентских бандлов после изменения сборки.
- `ops/nginx` и `.github/workflows/ci.yml`: include, безопасная установка и откат фрагмента, проверка конфигурации.
- `/docs/decisions/`: отдельный ADR для генерации locations статических endpoints из фактических ответов; он уточнит ручную границу nginx из ADR-011, не переносит в генератор весь реестр поверхностей.
- Артефакт конфигурации остаётся вне публичного `dist/www`.
- Первоначально PR #908 содержал только план. 2 октября 2026 года владелец разрешил реализацию, затем уточнил: продолжать в той же ветке и PR. Согласование привязано к коммиту `0662523a7ce2bfb5237f68dee6881d2f7379df1f` в issue. После успешной приёмки разрешены commit, push и перевод PR из draft для ревью ботом.
- PR требует локальной/CI-приёмки и ревью. После merge и деплоя необходимо проверить `GET` и `HEAD` всех 15 URL из issue и представителей остальных семейств: media type с параметрами, `Link`, заголовки скачивания и индексирования, отсутствие дублей, прежние cache-control и security headers. PR использует `Refs #479`; issue закрывается после production-проверки. Change можно синхронизировать и архивировать после приёмки реализации до публикации: оставшаяся проверка опубликованного результата хранится в issue и PR.
