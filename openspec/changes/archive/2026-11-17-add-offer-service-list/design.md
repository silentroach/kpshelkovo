# Design

## Context

Мотивация и границы: [proposal](/openspec/changes/archive/2026-11-17-add-offer-service-list/proposal.md), [issue #1360](https://github.com/silentroach/kpshelkovo/issues/1360). Владелец уточнил, что распознанный перечень нельзя редактировать; требуется только отдельное табличное представление. 17 ноября 2026 года владелец разрешил реализацию.

### Проверенные источники

- Шесть файлов `/apps/www/src/data/kb/ok/offer/*.md` содержат одинаковое приложение № 1: 9 круглогодичных, 5 зимних, 12 летних пунктов. Сверка worker подтверждена основным агентом; SHA-256 блока после нормализации пробелов: `efc4ec8561e89a54ec0263339ec22661af9771c5ced0b6fb14e100bce4471bdc`.
- Визуально просмотрена страница 7 [оригинала Шелково Парк](https://media.kpshelkovo.online/kb/ok/offer/2026-07-07/shelkovo-park.pdf#page=7). На ней колонки «№», «Перечень и состав услуг», «Периодичность», три сезонные группы и отдельная нумерация в каждой. Состав работ и периодичность подтверждают распознанный текст.
- PDF относится к редакции от 09.06.2026; дата `2026-07-07` в URL является датой архивного снимка. Проверена доставка: HTTP 200, `application/pdf`, 8 754 879 байт, SHA-256 `fbddf1ad951409b72b028c9961a1959d1ccb1b937683cb7b6eeaef33b8588f5d`.
- Остальные пять PDF визуально не проверялись; установлено совпадение их Markdown-копий. Изображение страницы 7 и PDF сохранены локально во временном каталоге среды `opencode/offer-services/`; повторное получение возможно по ссылке выше.

### Текущий код

KB использует один Markdown-источник по [ADR-015](/docs/decisions/015-markdown-first-knowledge-base.md). GFM уже подключён в `/packages/markdown/src/render.ts`, однако `assertNoMarkdownTables` отклоняет таблицы; сериализатор `/packages/markdown/src/generate.ts` также запрещает их. Raw HTML отбрасывается.

HTML KB строит `/apps/www/src/pages/kb/[...slug].astro` через общую app-обёртку. Companion строит `/apps/www/src/lib/kb/markdown.ts`: парсит body, обрабатывает редакционные блоки и переписывает KB-ссылки. Нормализация mentions сохраняет исходную строку с точечными заменами, а не сериализует всё дерево; её взаимодействие с ячейками нужно проверить сквозным тестом.

## Goals / Non-Goals

**Goals:**

- Сохранить один авторский Markdown для HTML и companion; использовать существующие GFM и AST.
- Ограничить включение HTML-таблиц базой знаний и сохранить безопасный вывод.

**Non-Goals:**

- Отдельная модель услуг, извлечение данных из оферт при каждой сборке, новая директива или специальный маршрут.
- Сортировка, фильтры, отдельный клиентский механизм таблиц и разрешение raw HTML.

## Decisions

### 1. Явное разрешение таблиц только для HTML KB

Добавить опцию `allowTables` в пакетный renderer и app-wrapper; по умолчанию оставить запрет. Включать опцию в общем HTML-маршруте KB, без проверок конкретного slug. GFM-узлы проходят штатный безопасный рендер; заголовки колонок имеют семантику `th` и `scope="col"`. Оформление и оболочка для прокрутки принадлежат приложению.

Обсуждение с `advisor` подтвердило этот вариант после сверки PDF. Цена состоит в изменении двух представлений и их проверках; отдельная подсистема услуг не нужна.

В ходе приёмки владелец дополнительно попросил стики-шапки, как в остальных таблицах сайта. Повторная консультация с `advisor` подтвердила применение общих `ui-sticky-table-shell ui-sticky-table-surface`, `ui-sticky-table` и `ui-sticky-table-head` на первой строке. От `64rem` оболочка имеет `overflow: visible`, заголовки закрепляются с общим `--site-sticky-offset`. Ниже сохраняется локальный горизонтальный scroll, а `th` статичны. В печати закрепление отключено. Для правильных углов при прилипании KB условно выводит существующий `StickyTableScript` только при наличии сгенерированного маркера таблиц в HTML; новые скрипты и lifecycle не создаются.

Рассмотрены альтернативы:

- Обычная отдельная страница списками использует текущий механизм, но не выполняет просьбу о таблице.
- Отдельный Astro-маршрут с копией данных потребовал бы отдельно поддерживать KB-навигацию, поиск и companion.
- Новый синтаксис таблиц или разбор текста услуг по тире добавил бы собственный формат и зависимость от пунктуации.
- Глобальное разрешение таблиц изменило бы незатронутые разделы.

Решение сохраняет слои [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md). Нужна синхронная правка описанного запрета в README Markdown-пакета и локальных правилах KB; запрет таблиц во внутренних документах и публичных companions остаётся.

### 2. Преобразование таблицы в списки на уровне AST

Добавить в `@shelkovo/markdown` небольшой helper: одна строка таблицы становится пунктом маркированного списка, внутри значения получают подписи из заголовков колонок. Переносить узлы ячеек, сохраняя ссылки, выделения и inline-код; номер из первой колонки остаётся данными. Пустая ячейка сохраняет свою позицию и подпись, а не сдвигает следующие значения.

KB вызывает helper после `parseMarkdownFragment`, до финальной сериализации и переписывания ссылок. Запрет таблиц в `serializeMarkdownDocument` остаётся защитной проверкой. Это соответствует [ADR-008](/docs/decisions/008-markdown-ast-generation.md). HTML не парсится обратно, Markdown не собирается строковым шаблоном.

### 3. Страница воспроизводит документ

Новый источник: `/apps/www/src/data/kb/ok/service-list.md`, адрес `/kb/ok/service-list/`. Исходные формулировки из существующей расшифровки переносятся в три таблицы по сезонным группам; меняется только разделение номера, услуги и периодичности по ячейкам. Не сокращать, не объяснять и не исправлять документ стилистически. Если найдётся сомнительное распознавание, вынести его владельцу отдельно перед изменением текста.

При приёмке владелец уточнил оформление: убрать повторный полный заголовок приложения внутри страницы и конечные точки в колонке «Периодичность»; сделать жёлтым вводное пояснение о приложении, убрать прежний блок оригинала с PDF-ссылкой и добавить `[TOC]`. Сезонные подзаголовки становятся H2; прочие слова, номера и условия сохраняются.

По окончательному уточнению владельца в индексе создаётся группа «Услуги», а названия обеих страниц совпадают с её ссылками: «Услуги, включённые в тариф за обслуживание» и «Дополнительные платные услуги и подключения». Адреса остаются прежними; миграция и совместимые названия не нужны. Вводная фраза «Приложение № 1 к публичным договорам с ОК Комфорт» связывает слова «публичным договорам» с `/kb/ok/#публичные-оферты`. После примерки WARNING владелец одобрил компактную пометку: NOTE с подписью и SOURCE-абзацем даты редакции, бледно-жёлтый фон исходного блока оригинала, текст 16 px / 1.5 обычного веса, поля 12×16 px. Для NOTE с SOURCE в KB используется структурный CSS-рецепт, без выбора по slug. После него `[TOC]`. Отдельный блок PDF-оригинала убран по прямому указанию владельца; оригиналы доступны через список договоров, PDF учитывается в `sources`, дата также видна в пометке. Сами строки таблиц защищены от humanizer/infostyle, кроме одобренного удаления конечных точек периодичности. Добавить ссылку в `/apps/www/src/data/kb/ok/index.md`; приложения внутри оферт сохраняются.

Brief: житель хочет быстро найти услугу и её периодичность. Основа композиции: обычный заголовок KB, пометка об исходных договорах, оглавление, сезонные подзаголовки и плотные читаемые таблицы. Использовать существующие шрифты, цвета и разделители из [дизайн-гайда](/docs/design/design-code-shelkovo.md#tables); длинные ячейки переносятся, при нехватке места прокручивается только таблица. В статье дополнительных платных услуг также добавлено `[TOC]` по просьбе владельца. Проверить клавиатуру, экран 320 px и печать. Для справочного документа маркетинговые hero, изображения и движение не нужны.

### 4. Промпт обновляет обе публикации

После обработки всех оферт `/prompts/oferta.md` требует:

- сравнить приложения № 1 всех документов; отличия не сводить молча к одному варианту;
- обновить отдельную страницу, сохранив исходный текст, порядок, номера, группы, периодичность и условия;
- сверить структуру по PDF, обновить редакцию, источник и ссылку в индексе;
- проверить HTML и companion на полноту и одинаковые данные.

## Risks / Trade-offs

- Разная периодичность в будущих офертах → промпт останавливает обновление общего перечня до решения владельца.
- Потеря ячейки или ссылки при преобразовании → адресные тесты AST и сквозная проверка KB.
- Пересказ оригинала при редактуре → защищённые строки документа, одноразовая сверка всех 26 пунктов; редакторское ревью собственных пояснений отдельно от оригинала.
- Разрастание области поддержки → default-запрет вне KB, локальный CSS, условное переиспользование существующего sticky script. До подключения сохранён baseline bundle, после сравниваются актуальные отчёты.
- Параллельная работа в общей папке → править только файлы задачи, перед реализацией сверить актуальные правки. Во время планирования владелец перевёл другого агента в отдельный workspace; после этого дерево содержит только артефакты этого change.

## Migration Plan

Рендер, companion, материал, промпт и рабочие инструкции выпускаются одним PR после согласования и проверок. Существующие оферты и PDF не мигрируют. Откат возвращает весь PR. Основные specs синхронизируются и change архивируется после приёмки реализации.
