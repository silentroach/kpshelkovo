# Design

## Context

Причина изменения описана в [proposal](/openspec/changes/archive/2026-10-19-add-caption-only-map-points/proposal.md). Общий [renderer](/apps/www/src/components/maps/editorial-map.ts) всегда создаёт кружок для `Point`, а подпись размещает отдельным элементом. Строгие схемы пока не принимают признак скрытия кружка.

Сохраняем границы [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md): raw, доменная модель и публичная геометрия имеют собственные схемы и явные адаптеры. Новый ADR не требуется.

## Goals / Non-Goals

**Goals:**

- Использовать существующий `Point` и общий renderer, чтобы подписи одинаково работали на всех редакционных картах.
- Передавать новый режим через все существующие границы данных без изменения координат.

**Non-Goals:**

- Автоматическое размещение подписей вдоль линий, устранение пересечений, новые SDK-объекты и специальные стили для одного места.
- Переработка геометрии участков или остального интерфейса карты.

## Decisions

### Явный необязательный флаг

Добавить `captionOnly?: boolean` в свойства редакционной точки и доменную модель. `true` допустим только для `Point` с непустой `iconCaption` и без `iconContent`; `false` сохраняет обычный маркер. Наличие поля у линии или области отклоняется. Проверка непустоты не меняет авторский текст. `marker-color` можно сохранить, но в этом режиме он ничего не рисует: существующий импорт геометрии в наборы иногда добавляет цвет автоматически.

Протянуть поле через raw-схему, mapper, `EditorialFeature`, HTML data-схему, публичную схему, `toPublicEditorialGeometry` и `fromPublicEditorialGeometry`. Проверять согласованность режима на существующих границах Zod. Общий renderer пропускает создание кружка при `captionOnly: true`, сохраняя подпись и её нынешнее положение. CSS менять не требуется.

Рассмотрены варианты:

- Оставить кружок: не требует программных изменений, но не выполняет пожелание о надписи без точки.
- Прозрачный цвет: сохраняет белую рамку и тень, поэтому не подходит.
- Скрывать все кружки с подписью: меняет уже опубликованные схемы и цифровые маркеры.

Advisor исследовал эти варианты и рекомендовал явный флаг; консультация `ses_eab38de3effe7ddcMjiH2WU4cF`. Цена решения ограничена существующей цепочкой данных и renderer.

### Применение к дорожке

В [геометрии места](/apps/www/src/data/places/park-forest-lake.geojson) включить режим у точки с подписью «Будущий проход к парку» и удалить ненужный цвет этой точки. Конец дорожки уже укорочен до `[37.73927397, 55.06358008]`; окончательный отступ проверить визуально. Начало между участками проверено по публичным контурам с действующей поправкой слоя участков; сохранить его и остальную плавную линию.

## Risks / Trade-offs

- Потеря флага на одной из границ вернёт кружок → проверить сквозной путь raw → domain → public → client и HTML data.
- Подпись может пересечься с маркером озера на узком экране → проверить реальную карточку при 390 px и общую карту с видимыми участками при 1664 px.
- Одновременная сборка и dev могут обновить общий кеш зависимостей → выполнять production-сборку после остановки dev.

## Migration Plan

Миграция существующих геоданных не нужна. После разрешения реализации добавить поддержку флага и применить его к дорожке в той же ветке. Выполнить проверки и показать свежий скриншот до публикации; запрос владельца ограничивает работу локальным результатом. При последующем разрешении публикации синхронизировать specs и архивировать change по штатному workflow. Откат возвращает поддержку режима и его использование вместе.
