# Proposal

## Why

Ссылка из новости или сообщения должна сразу показывать нужные слои общей карты, не заставляя читателя включать их вручную. Задача [#1170](https://github.com/silentroach/kpshelkovo/issues/1170) добавляет начальную настройку слоёв через URL; решения и реализация разрешены владельцем в рабочей сессии.

## What Changes

- Параметр `l` включает один или несколько слоёв через запятую: `infra`, `shf`, `shv`, `shp`, `shr`; `parcels` включает все части участков.
- Повторяющиеся параметры объединяются. Неизвестные и пустые значения игнорируются без сообщений об ошибках и переписывания URL.
- Запрошенные слои дополняют обычное состояние и слои прямых целей `p`, `h`, `set`. Сам параметр не управляет камерой.
- Параметр действует только при открытии; ручные переключения не меняют `l`, а поздние ответы не отменяют ручное выключение.
- **BREAKING**: идентификатор слоя `infrastructure` заменяется на `infra` в исходных данных, схемах, коде и публичном JSON, без обратной совместимости. Категория `infrastructure` и подпись «Инфраструктура» сохраняются.
- Не входят: синхронизация ручного состояния с URL, новые слои, изменение камеры, переработка панели и категорий мест.

## Capabilities

### New Capabilities

- `map-layer-links`: начальное включение слоёв общей карты через URL, совместное применение с прямыми целями и независимое ручное управление.

### Modified Capabilities

- `parcel-map`: включение частей по `l` и сохранение дополнительных частей при прямом переходе к участку.
- `place-map-visibility`: включение инфраструктуры по `l` и публичное значение `mapLayer: infra`.

## Impact

- Общий компонент карты и URL-helper в `/apps/www/src/components/places/`; отдельной мобильной реализации не требуется.
- Схемы и проверки видимости в `/apps/www/src/lib/places/`, поля `map_layer` мест, публичный `/map/data/places.json`, связанные тесты и локальные инструкции.
- Потребители публичного JSON должны использовать новое значение `infra`; старое значение не принимается схемами. Клиент и данные публикуются согласованно в одной сборке.
- Новые зависимости, внешние запросы и изменения инфраструктуры не нужны. Проверки выполняются до PR; отдельная production-приёмка не требуется.
