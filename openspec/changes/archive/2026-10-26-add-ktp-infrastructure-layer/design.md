# Design

## Context

Мотивация и согласованный объём описаны в [proposal](/openspec/changes/archive/2026-10-26-add-ktp-infrastructure-layer/proposal.md). Текущий `show_on_map` отбирает весь опубликованный набор для JSON, Markdown, наборов, соседей и начального кадра. Он не подходит для временно выключенного слоя. Категория `infrastructure` уже существует, но включает памятник; категория и принадлежность инженерному слою имеют разный смысл.

`PlaceMap.svelte` получает опубликованные места одним JSON, создаёт их маркеры и кластеризатор. Участники `set` вынесены из обычных кластеров, дополнительная геометрия раскрывается по hover/focus/highlight/set. Начальный кадр передаёт `/apps/www/src/pages/map/index.astro`; независимость подложки от загрузки мест сохраняется.

Действующие решения: [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md), [ADR-028](/docs/decisions/028-markdown-first-places-map.md), [ADR-039](/docs/decisions/039-shared-yandex-maps-runtime-and-preview.md), [ADR-012](/docs/decisions/012-entity-mention-graph.md). Новый архитектурный механизм или отдельный ADR не нужны.

## Goals / Non-Goals

**Goals:**

- Встроить переключаемую инфраструктуру в существующую карту без второй сущности КТП и без второго загрузчика мест.
- Сохранить опубликованный справочник, привычный прямой фокус, наборы и обычные ссылки маркеров.
- Связать исторические материалы с новыми карточками без переписывания фактов.

**Non-Goals:**

- Параметр слоёв URL, сохранение переключателей между визитами и новый интерфейс «Поделиться»; URL-функция находится в #1170.
- Перенос КПП или памятника в новый слой, фильтрация «Рядом» по слоям, схемы питания и связи КТП с обслуживаемыми участками.
- Публикация исходных фотографий: в комментариях доступны их описания, сами изображения в GitHub не загружены.

## Decisions

### 1. Явная принадлежность слою

Добавить optional `map_layer: infrastructure` во frontmatter, `mapLayer` в явную доменную модель и клиентский/public DTO. Отсутствие поля означает обычное место; существующие записи не мигрируют. Все КТП получают `show_on_map: true`, `category: infrastructure`, `map_layer: infrastructure`, `marker: ktp`, `status: existing`.

Такое поле не связывает видимость с названием, slug или видом маркера. Альтернатива по категории дешевле на одно поле, но превращает редакционную классификацию в переключатель всех существующих и будущих объектов этой категории. `show_on_map: false` исключён: он запрещает участие в опубликованном наборе и именованных наборах.

Существующий JSON сохраняет legacy поля (`html_url`, `status_label`, `opening_hours`); новое поле использует camelCase. Обновить конечную Zod-валидацию payload, связанные schema/discovery-описания, если они перечисляют поля. Код Zod не добавляется в браузер.

### 2. Полный набор отделён от отображаемого

Сохранить `selectMapPlaces` как фильтр публикации. Для начального кадра отдельно выбрать обычные места; при их отсутствии использовать текущий локальный fallback. JSON, Markdown-индекс и JSON-LD продолжают перечислять весь опубликованный набор, включая КТП. `getNearbyPlaces` не менять.

В `PlaceMap.svelte` хранить один флаг инфраструктуры, изначально `false`. Общий предикат видимости использовать для кластерных features, отдельных маркеров набора и дополнительной геометрии. Не менять координаты, историю или камеру при ручном переключении. При скрытии активного маркера не оставлять невидимую геометрию или потерянный клавиатурный фокус. Переключатель добавить в нынешнее меню «Слои» рядом с «Участками», без нового механизма панели.

### 3. Прямые цели и наборы

Допустимый `h` для инфраструктуры включает слой до фокуса. После таймера `h` очищается штатным helper, слой остаётся включён. Приоритет `p` сохраняется; карточка `/map/<slug>/` остаётся отдельной страницей, а её кнопка «Показать на общей карте» ведёт на `?h=<slug>`.

Набор включает инфраструктуру при наличии её опубликованных мест, но вписывает только участников. Повторно использовать текущую идею явной отмены для частей: выключение инфраструктуры во время ожидания набора запрещает позднее включение и отменяет pending fit. После повторного ручного включения участники получают прежнее оформление; снятие набора не выключает слой. Не вводить URL-персистентность переключателя.

### 4. Источники и карточки КТП

Источник каждой записи: соответствующий комментарий [#1116](https://github.com/silentroach/kpshelkovo/issues/1116), материалы получены 25.10.2026. Координаты сохраняются в порядке `lat`, `lng`, без выдуманной дополнительной точности:

- `ktp-13`: 55.060896, 37.738451. КТП №13; на двери 400 кВА; изготовитель «КУБАНЬЭЛЕКТРОЩИТ», тип ПН-400, заводской №05739, выпуск 11.2023.
- `ktp-15`: 55.065643, 37.740351. КТП №15; «КУБАНЬЭЛЕКТРОЩИТ», заводской №05736, выпуск 11.2023. Мощность не устанавливать по нечётко прочитанному обозначению.
- `ktp-16`: 55.067389, 37.744332. КТП №16; дополнительных надёжно прочитанных паспортных параметров нет.
- `ktp-00628`: 55.062971, 37.742962. Название «КТП, заводской №00628»; ПАНЭНЕРГОМЕТ, тип КТПН-П-К/К 400/10/0,4, 400 кВА, выпуск 2023. Поселковый номер не установлен, заводской с ним не смешивается.
- `ktp-1933`: 55.061823, 37.730124. КТП №1933; 400 кВА по надписи на двери; пометка «Россети» по сообщению пользователя, без утверждения документально проверенной собственности.
- `ktp-2050`: 55.062962, 37.717187. КТП №2050; название/логотип «Россети» на корпусе.
- `ktp-2051`: 55.058973, 37.719339. КТП №2051; название/логотип «Россети» на корпусе.
- `ktp-2079`: 55.062028, 37.724490. КТП №2079; табличка «Россети Московский регион».

Summary кратко объясняет объект; body сохраняет полезные паспортные сведения, доступные в комментариях. По уточнению владельца в карточках не показывать дату получения данных, служебную фразу о ней, ссылки на источник или тикет. Ссылки на источники остаются только во внутренних материалах change. Не переносить в публичный текст внутренние идентификаторы наборов фотографий или перечни всех неизвестных параметров. Мощность и прочие параметры атрибутировать надписям/табличке, чтобы планы модернизации из старых материалов не воспринимались как уже выполненные работы.

Публикация координат этих объектов одобрена владельцем запросом на их добавление. Точность сверх переданных значений не обещается; принадлежность и обслуживаемые территории из координат не выводятся.

### 5. Маркер

Исходный PNG сохранить в принятом каталоге UI-маркеров без удаления пользовательского `ktp.png` до проверки переноса. Подготовить lossless WebP с прозрачностью, очисткой ореола, полями и плотностью по ADR-028. Добавить enum `ktp`, константу изображения, реестр, exports, visual catalog и компонентный тест. Применить существующие масштаб, контур и тень. Для строки слоя использовать отдельно предоставленный владельцем `wnp.png`, подготовив компактный WebP по образцу иконки участков; исходник сохранить отдельно от публичного растра. Проверить `sideEffects` пакета и фактический состав бандлов; новых обязательных import effects нет.

### 6. Упоминания в существующих материалах

Заменять только однозначные названия в Markdown body на labelled mentions с прежним видимым текстом:

- `/apps/www/src/data/news/articles/2026/05/ktp-upgrade.md`: два упоминания КТП-1933.
- `/apps/www/src/data/status/incidents/2026/05/electricity-park-outage-2026-05-05.md`: КТП-1933.
- `/apps/www/src/data/status/incidents/2026/09/electricity-river-park-outage-2026-09-10.md` и `/apps/www/src/data/status/incidents/2026/09/electricity-river-park-outage-2026-09-11.md`: КТП №1933.
- `/apps/www/src/data/status/incidents/2026/10/electricity-village-outage-2026-10-17.md`: КТП №2079.

КТП-2012 и КТП-2059 пока не имеют карточек; ненумерованные подстанции не связывать по догадке. Plain-text title/summary/SEO и архивные выжимки не получают mentions. Текст цитат не переписывать. Существующий graph автоматически создаёт backlinks; новый обработчик не нужен.

## Risks / Trade-offs

- Выключенная инфраструктура остаётся в JSON и «Рядом»: это согласованное различие публикации и отображения; проверить обе выборки отдельно.
- Фильтрация только кластеров оставила бы маркеры набора/геометрию: один предикат видимости и интеграционные сценарии для `h`/`set` предотвращают расхождение.
- Поздний ответ набора способен включить отменённый слой: хранить явное выключение, как сейчас для частей, и проверить отложенным ответом.
- Новый растр используется также в компактных превью и карточках: проверить маркер на разных подложках и увеличенном шрифте, без новых шрифтов и глобальных стилей.
- Mock SDK не подтверждает реальный рендер: после разрешения локального dev-стека проверить настоящую карту на узком и широком экране; ограничение явно сообщить, если такого разрешения нет.

## Migration Plan

Выпустить код, контент и обновлённые specs одним PR с `Closes #1116`; #1170 оставить открытым. Существующие карточки и URL не меняются. Перед PR синхронизировать specs и архивировать change в той же ветке; откат выполняется возвратом всего PR.
