# Пометка как элемент транскрипции

## Context

Сейчас каждый элемент `segments` проходит через поиск спикера, проверку времени и назначение якоря. HTML и Markdown читают эту последовательность; Markdown также использует реплики для счётчиков и диапазона времени части. Основание для сохранения адресации: [ADR-014](/docs/decisions/014-meetings-transcript-first-archive.md).

## Goals / Non-Goals

Обе версии транскрипции должны читать пометку с одного и того же места в YAML. Существующие реплики сохраняют формат и адресацию. Вычитка, перенос старых `speaker: note` и удаление неразборчивой речи остаются за владельцем. Реализация не меняет редакционные данные, включая локальный черновик встречи.

## Decisions

- Редактор вставляет в `segments` запись `- note: Запись прерывается`. Для длинной подписи подходит обычная YAML-строка со свёрткой `>-`. Ключ `note` выбран вместо `break`: редактор может пояснить, что несколько человек говорят одновременно, даже если запись не прерывалась. Подпись представляет собой простой текст, без спикера, ссылок и обязательных временных границ.
- Расширить raw-схему и доменную модель в существующих слоях по [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md). У части есть упорядоченные элементы для чтения; для подсчёта, диапазона, проверки хронологии и назначения якорей используются только реплики. Каждая часть по-прежнему содержит речь, первая реплика начинается в `00:00:00`. Пометка не сбрасывает предыдущее время. Специальная обработка спикера с именем `note` переписала бы смысл существующих данных и оставила бы обязательный таймкод.
- В HTML подпись стоит по центру на ширину обеих колонок, между тонкими декоративными линиями. Цвет и кегль как у вторичного текста, без подчёркивания. Для длинной подписи ширина текста ограничена: линии укорачиваются и проходят по бокам через середину блока. Естественный перенос добавляет строки, ограничения высоты нет. В дереве доступности остаётся сам текст. Согласованные примеры: [короткий](/openspec/changes/archive/2026-11-26-add-meeting-transcript-breaks/preview/desktop.png), [длинный на компьютере](/openspec/changes/archive/2026-11-26-add-meeting-transcript-breaks/preview/long-desktop.png) и [на телефоне](/openspec/changes/archive/2026-11-26-add-meeting-transcript-breaks/preview/long-mobile.png). [Снимок тестовой сборки](/openspec/changes/archive/2026-11-26-add-meeting-transcript-breaks/preview/implemented-mobile.png).
- В полном Markdown части выводить пометку отдельным пунктом с выделением курсивом через AST. Порядок сохраняется, пояснение не получает префикса реплики, имени или ссылки на таймкод. В индексе и описании по-прежнему считаются только реплики.
- Существующий атрибут `data-pagefind-ignore="all"` на элементе пометки исключает её из поиска и сниппетов. Правила индексирования обычных реплик не меняются.

## Risks / Trade-offs

- Пометка могла бы сдвинуть суффиксы одинаковых таймкодов или скрыть ошибку порядка. Сверить адреса и проверку убывающего времени по репликам с пометкой между ними.
- Без автора и времени подпись легко принять за продолжение реплики при линейном чтении. Выводить её самостоятельным элементом и проверять порядок чтения без CSS.

## Migration Plan

Миграции данных нет. Поддержку формата можно выпустить до появления первой пометки. Если позже понадобится откат, сначала проверить, появились ли в данных элементы нового формата.
