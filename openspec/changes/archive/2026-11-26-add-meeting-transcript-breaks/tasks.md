# Редакторские пометки в транскрипции

## 1. Формат и чтение данных

- [x] 1.1 Добавить вариант `note` в raw-схему и модель части, сохранить порядок элементов. На тестовых данных проверить, что у пометки нет спикера, что пустая подпись и смешанная запись с `note` и полями реплики отклоняются и что одних пометок недостаточно для публикации части.
- [x] 1.2 Проверить в тестах mapper, что сравнение времени между репликами работает через пометку, а вставка пометки перед повторяющимся таймкодом сохраняет якоря.
- [x] 1.3 Обновить [правила подготовки встреч](/apps/www/src/data/meetings/AGENTS.md): показать YAML-пример ручной вставки `note` и пояснить, что расстановку делает редактор при вычитке. Сверить пример с raw-схемой; рабочие YAML встреч не редактировать.

## 2. Публикация в HTML и Markdown

- [x] 2.1 Вывести пометку отдельным элементом списка в HTML и описать её в [дизайн-гайде](/docs/design/design-code-shelkovo.md#транскрипции-встреч). На тестовом фрагменте сверить короткую и длинную подписи с примеркой на компьютере и телефоне: линии по бокам, подпись читается один раз, текст не обрезан.
- [x] 2.2 Вывести подпись в полном Markdown части через AST. Тестом на смешанной последовательности проверить порядок и буквальный текст пометки, адреса соседних реплик и отсутствие изменений в счётчиках и диапазоне времени.
- [x] 2.3 Исключить пометки из индекса и сниппетов. Сравнить выдачу на одной тестовой странице до и после: запрос по пометке и контрольный запрос по реплике. Запустить проверки поиска.

## 3. Приёмка

- [x] 3.1 Выполнить `pnpm typecheck`, тесты встреч, сборку и `pnpm openspec:validate`. Сверить вывод для встречи без новых пометок и убедиться, что change не изменил данные встреч.
- [x] 3.2 Провести ревью актуального diff с `reviewer`, обозначив предшествующие правки текущей рабочей ветки. Исправить подтверждённые замечания и проверить затронутые сценарии.

## Результаты приёмки

- На отдельной сборке тестовой встречи длинная подпись занимает четыре строки при ширине экрана 1440 и 390 пикселей, пять строк при ширине 320 пикселей. Переполнения нет; в дереве доступности каждая пометка встречается один раз. Рабочие YAML для этой проверки не менялись.
- До правки индекса «участников говорят одновременно» находил тестовую встречу по пометке. После правки встреча по этому запросу исчезла, а «что нам делать» продолжает находить её по реплике, без пометок в отрывке.
- Встреча без пометок: все 577 HTML-реплик совпали с исходной сборкой, Markdown первой части совпал побайтно. Прошли `pnpm typecheck`, `pnpm test`, сборка сайта и 13 тестов `test:search-quality`.
- Независимое ревью не нашло регрессий в реализации. В модели пояснено, какая последовательность включает пометки, а какая нужна только для реплик. Ссылки на снимки приведены к архивному пути.
