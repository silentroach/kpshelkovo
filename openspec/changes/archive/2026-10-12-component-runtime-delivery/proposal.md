# Proposal

## Why

В [issue #848](https://github.com/silentroach/kpshelkovo/issues/848) отмечена доставка кода липких таблиц и подписей состояния сервисов через общий runtime даже страницам без этих компонентов. Нужно исключить эту доставку при свежем прямом входе, сохранив поведение компонентов и общей навигации.

## What Changes

- Перенести подключение существующих installers из общего runtime к обработанным Astro script entries соответствующих компонентов и шаблонов.
- Сохранить эффект липких заголовков таблиц, клиентское уточнение подписей сервисов и их работу при прямом входе, клиентских переходах и навигации назад/вперёд.
- Сохранить идемпотентность listeners и освобождение активных табличных ресурсов после ухода со страницы с таблицами.
- Измерить изменение общего entry и фактической доставки JavaScript; улучшение Core Web Vitals не является обещанным результатом.
- Не менять `home/status`, общую шапку, правила status lifecycle и остальной runtime; не добавлять generic lazy-loader, Svelte `onMount` или новый ADR.

## Capabilities

### New Capabilities

- `component-runtime-delivery`: доставка спецкода липких таблиц и подписей сервисов только страницам с соответствующими компонентами, с сохранением поведения и жизненного цикла при навигации.

### Modified Capabilities

Нет. Существующие требования `status-lifecycle` и `site-navigation` сохраняются; новая capability задаёт границу доставки, а не меняет расчёт статусов или правила навигации.

## Impact

- Общий [site-runtime](/apps/www/src/scripts/site-runtime.ts), [StatusServiceState](/apps/www/src/components/status/StatusServiceState.astro), небольшой Astro entry для таблиц и шаблоны регламента, услуг, активов и страницы поселка сравнения.
- Существующие installers, адресные DOM/browser-тесты и актуальные [YAML-отчёты бандлов](/docs/bundle/) используются для приёмки.
- URL, API, данные, CSS, визуальный эффект, зависимости, CSP и deploy-поток не меняются.
- Приёмка локальная: production-проверка для завершения change и закрытия issue не требуется. Публикация и реализация возможны только после отдельного разрешения владельца; сейчас создаются только planning artifacts.
