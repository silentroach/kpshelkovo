# Proposal

## Why

При первом открытии поиска строка «Загружаем поиск…» появляется немедленно, даже если модуль готов через несколько миллисекунд, и вызывает короткий скачок высоты окна. На живом сайте в Chromium наблюдались около 126 мс показа при холодной загрузке и около 3 мс с прогретым кешем; во втором случае строка всё равно попала в один кадр.

## What Changes

- Показывать индикатор загрузки интерфейса только после 200 мс ожидания, если текущий открытый диалог ещё загружается.
- До порога полностью скрывать строку, не занимать ею место и не объявлять ожидание скринридеру; окно и фокус в поле ввода предоставлять сразу.
- Убирать показанный индикатор сразу по готовности, отменять отложенный показ при завершении, ошибке, закрытии или переходе на другую страницу. Старое ожидание не должно влиять на новое открытие.
- Ошибку загрузки показывать и объявлять сразу по действующему контракту восстановления.
- Объём ограничен ожиданием клиентского модуля диалога. Состояние «Ищем…» после ввода запроса, debounce, загрузка Pagefind, корпус и ранжирование не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `search`: быстрое открытие без кратковременного индикатора и скачка высоты от его строки; отложенный индикатор при заметном ожидании интерфейса.

## Impact

- Основная точка изменения — [загрузчик диалога](/apps/www/src/scripts/site-runtime.ts); регрессионные проверки — [существующие тесты загрузчика](/apps/www/src/scripts/tests/site-runtime.test.ts).
- Сохраняются немедленное открытие серверной оболочки, ввод до гидрации, передача введённого запроса, возврат фокуса и [контракт восстановления](/openspec/specs/client-load-recovery/spec.md). Архитектура ленивого поиска соответствует [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md).
- Приёмка — тесты времени показа и жизненного цикла, проверки поиска и браузерная сверка production-сборки с быстрым и принудительно задержанным импортом. Отдельная приёмка на production не требуется.
- Связанная задача — [#885](https://github.com/silentroach/kpshelkovo/issues/885), с наблюдениями исследования и решением владельца о задержке 200 мс.
- По указанию владельца сначала публикуется PR с артефактами change в ветке `fix/delay-search-loading-indicator`; реализация продолжится в этой же ветке и PR в отдельной сессии. До выполнения задач PR остаётся черновиком и ссылается на issue через `Refs`.
