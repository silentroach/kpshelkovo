# Design

## Context

[Главная](/apps/www/src/pages/index.astro) уже получает момент сборки и готовит адаптивные WebP для двух панорам. Клиент выбирает день или ночь по освещённости в Шелково; без JavaScript показывается вариант, выбранный при сборке.

## Goals / Non-Goals

- Подготовить адаптивные изображения только для выбранного комплекта и сохранить правила кадрирования из [дизайн-гайда](/docs/design/design-code-shelkovo.md#главная).
- Не менять расчёт освещённости, клиентские скрипты, расписание публикации или nginx.

## Decisions

- Выбрать дневную, ночную и социальную версии вместе в серверной части `index.astro` по одному снимку времени сборки. Для московского месяца использовать существующий `dateTimeFromISO` из `@shelkovo/format`. Два набора файлов лежат рядом в `src/assets/home`. Прямой выбор импортов сохраняет хешированные URL и не требует генерировать симлинки или подменять файлы в рабочей копии.
- Взять зимние исходники из `~/Downloads/winter-images.zip`: два PNG 2048×682 и JPEG 1200×630. Для панорамы оставить существующие промежуточные ширины, а последнюю брать из исходника, не увеличивая её до 2172 px. Для обложки использовать JPEG качества 85 без изменения размеров и передавать подходящее описание по [правилам метаданных](/docs/page-meta.md#обложка-главной).
- Переиспользовать ежедневную публикацию сайта, как у статических страниц статуса ([ADR-031](/docs/decisions/031-status-incident-lifecycle.md)). [Сборка `www`](/apps/www/turbo.json) уже отключает кэш результата Turbo, поэтому смена даты не требует нового ключа кэша. Кэш обработки изображений Astro можно сохранить.

## Risks / Trade-offs

- Изменение видно после успешной публикации, не ровно в полночь. Если ночной деплой не пройдёт, останется предыдущий статический комплект.
- Оригиналы обоих комплектов входят в артефакт сборки. Посетитель загружает изображения только выбранного комплекта.
- Снег меняет фон навигации и сводки. Проверить читаемость и кадр на телефоне и широком экране для обеих зимних панорам.

## Migration Plan

Обычная сборка и публикация, без миграции данных. Для отката достаточно вернуть изменение и опубликовать сборку повторно.
