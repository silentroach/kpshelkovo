# Proposal

## Why

В контактах сайта Telegram уже узнаётся по фирменному значку, а те же ссылки внутри редакционного Markdown выглядят обычными ссылками. Владелец попросил сделать оформление общим для Markdown, чтобы списки участников и контакты читались одинаково во всех разделах.

## What Changes

- HTML-рендер сайта автоматически добавляет штатный декоративный значок к Telegram-ссылкам, включая ссылки на сообщения и приглашения.
- У простой текстовой подписи `@username` удаляется только начальный `@`, если она совпадает с username прямого HTTP(S)-адреса без параметров и fragment. Регистр подписи сохраняется; ник без `@` уже подходит.
- Авторские фразы, форматированные подписи, подписи-URL и текст ссылок на сообщения, приглашения или deep links сохраняются. Адрес назначения и `title` остаются авторскими.
- Доступное имя продолжает передавать подпись ссылки; значок не подменяет её словом «Telegram». Оформление работает без клиентского JavaScript.
- Публичные Markdown companions сохраняют текст, адрес и `title` ссылки без SVG и HTML-нормализации ника.

## Capabilities

### New Capabilities

- `markdown-telegram-links`: единое HTML-оформление Telegram-ссылок в редакционном Markdown, узкая нормализация подписи ника и сохранность авторского содержания в остальных представлениях.

### Modified Capabilities

Нет.

## Impact

- Общая точка подключения — [app-wrapper Markdown](/apps/www/src/lib/markdown/render.ts). Поведение распространяется на его потребителей: справки, новости, события, статусы, профили людей, места, «Сарафан», отзывы, «У кого есть» и Markdown-фрагменты других разделов.
- Понадобятся небольшой HTML-only AST-transform приложения, общий источник геометрии значка в `packages/ui`, app-owned стили generated content, адресные тесты и обновление [справочника Markdown](/packages/markdown/README.md) и [дизайн-гайда](/docs/design/design-code-shelkovo.md).
- Обнаружение Telegram использует существующий `isTelegramUrl` из `@shelkovo/url`. Новые runtime-зависимости, внешние запросы и клиентский JavaScript не требуются.
- Связанный issue не предоставлен. Владелец 28 октября 2026 года согласовал контракт и разрешил реализацию: «да, запускай реализацию, прям тут тоже, я потом все это вместе закомичу запушу сам». Работа выполняется локально в текущей рабочей копии `master`; ветки, worktree, issue, коммиты, push и PR не создаются. Публикацию выполняет владелец.
- Это самостоятельное общее изменение Markdown-рендера. Редактура памятки о празднике и данных карт ведётся параллельно основной сессией.
- Production-приёмка не требуется: контракт проверяется на рендере, companions и локальной production-сборке до PR.
