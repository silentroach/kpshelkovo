# Design

## Context

Мотивация — в [proposal](/openspec/changes/archive/2026-10-07-disable-hanging-quotes/proposal.md#why). Короткий дизайн нужен, поскольку удаление пересекает строковое ядро, два AST-адаптера, CSS приложения и защитные тесты.

- Основная сессия проверила исходники и все готовые `dist/www/**/*.html` через parse5: 370 страниц, 3213 элементов `h1`–`h6`, 0 заголовков с начальной кавычкой `«`, `„`, `“`, `"`, `'` или `‘`. В исходниках такие заголовки найдены только в тестах. Это разовое свидетельство для решения, а не требование к будущему контенту.
- В строковом ядре включено `ru/optalign/quote`; `ru/html/quoteContext` исправляет контекст скрытых HTML-тегов через `alignHtmlQuotes`. AST-адаптеры повторяют коррекцию в `alignTreeQuotes`. Реальный случай — цитата внутри `strong` и ссылка внутри абзаца на `/news/2026/08/guest-passes-disputed-debt/`; прежняя приёмка зафиксирована в [отчёте](/docs/research/date-range-typography-2026-10-07/README.md).
- Границы пакетов и CSS определены [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md) и [ADR-034](/docs/decisions/034-native-css-architecture.md). Изменение укладывается в них; в ADR-003 потребуется убрать только устаревшую обязанность коррекции контекста дерева.

## Goals / Non-Goals

**Goals:** убрать обработку контекста кавычек целиком, сохранив общую безопасную границу text → HTML → AST и правила [date-labels](/openspec/specs/date-labels/spec.md).

**Non-Goals:** новый режим выравнивания, второй экземпляр Typograf, переработка Markdown-pipeline, миграция редакционного контента или расширение правил диапазонов через несколько текстовых узлов.

## Decisions

### Один Typograf без оптического выравнивания

Выбран отказ от эффекта на всех поверхностях, включая обычные абзацы. Сохранение выравнивания только в заголовках потребовало бы отдельного режима без подтверждённого реального случая; сохранение текущих обходов оставило бы цену поддержки необязательного эффекта.

- В [ядре](/packages/typography/src/index.ts) удалить включение `ru/optalign/quote`, относящийся к его start-очистке фильтр конструктора, `QUOTE_CONTEXT_RULE`, его регистрацию, `alignHtmlQuotes`, импорт `TypografContext` и `TYPOGRAPHY_BLOCK_TAGS`.
- Для сохранения границ ссылок отключить штатное `common/punctuation/quoteLink`: без optalign-обёртки оно выносит кавычки из `<a>«текст»</a>`, тогда как AST-пути сохраняют их внутри ссылки. Это обнаружил существующий тест согласованности HTML и AST; достаточно настройки одного Typograf.
- В [AST-адаптерах](/packages/markdown/src/typography.ts) удалить `alignTreeQuotes`, его вызов после rehype-обхода, Satteri `after` и ставшие мёртвыми импорты. Удалить `/packages/markdown/src/typography.types.ts`, который содержит только `TypographyNodeReplacement`.
- Удалить классы `typograf-oa-*` из `TYPOGRAPHY_WRAPPER_CLASSES`, очистки сгенерированных обёрток и [global.css](/apps/www/src/styles/global.css). Сохранить распознавание `nowrap-date-range` и узкую очистку его обёртки для повторного HTML-прохода в очереди после защиты кода, комментариев и атрибутов.

### Безопасность и даты остаются отдельной обязанностью

Сохраняются `formatText`, `formatTextHtml`, `formatDynamicHtml`, text-only `ruleFilter`, экранирование, safe tags для защищённых элементов, буквальных entities и start tags с кавычками/угловыми скобками в атрибутах. Эти защиты нужны и без optalign. Правила диапазонов, `TYPOGRAPHY_SKIP_TAGS`, безопасный `htmlToHast`, краевые пробелы и пропуск уже обёрнутых дат в AST сохраняются. Обычное преобразование прямых кавычек в типографские продолжает работать.

Регистрация оставшихся правил по-прежнему выполняется ядром: проверить `sideEffects` обоих пакетов и сохранение инициализации в production-сборке; строковый клиентский вход не должен получить Markdown/Satteri. Удаление quote-only регистрации само по себе не делает всё ядро свободным от побочных эффектов.

### Проверять полезное поведение, сокращая матрицу косметики

В тестах обоих пакетов убрать варианты, отличающиеся лишь контекстом висячей кавычки, и обновить HTML-ожидания. Сохранить проверки диапазонов, обычных кавычек, буквальной разметки/entities, неизменности атрибутов и защищённого кода, пробелов, ссылок/выделения, согласованности HTML с rehype/Satteri и повторных проходов без вложенных дат. Одного адресного примера цитаты внутри выделения/ссылки достаточно для отсутствия optalign-разметки; отдельная новая матрица не нужна.

В приложении адаптировать `events-view.test.ts`, `homepage.test.ts`, `render.test.ts`, `ContactReviews.test.ts` и `meetings/mapper.test.ts`: сохранить проверки безопасности, диапазонов и нормального преобразования кавычек, изменив ожидаемый HTML. README обоих пакетов и дизайн-гайд описывают итоговые API/CSS hooks; датированный отчёт предыдущей приёмки остаётся историческим свидетельством.

## Risks / Trade-offs

- Удаление общей очистки вместе с оптическим эффектом может вложить date spans или изменить защищённый HTML → сузить очистку до дат и подтвердить повторные проходы, атрибуты и код существующими тестами.
- Переразметка inline-текста может повлиять на зазоры, переносы и печать → адресно проверить реальную статью `guest-passes-disputed-debt` на desktop/mobile и в печатном режиме; проверить перенос и копирование диапазона на реальной странице с датами. Временный узкий образец допустим, если нужный перенос на странице не воспроизводится. Постоянный smoke-обход сайта не нужен.
- Кавычки перестанут выступать за левый край и в абзацах → это согласованная цена удаления эффекта; обычные кавычки, текст, ссылки и выделение сохраняются.

## Migration Plan

После разрешения реализации изменить ядро, адаптеры, CSS, тесты и рабочую документацию вместе. Сравнить исходные bundle-отчёты с результатом `pnpm bundle:analyze`; эта production-сборка одновременно служит основой локальной приёмки. Данные не мигрируются: HTML пересоздаётся сборкой. Откат возвращает изменение целиком, чтобы сгенерированная разметка и её CSS оставались согласованными.
