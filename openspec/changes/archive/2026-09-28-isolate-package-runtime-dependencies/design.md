# Design

## Context

Мотивация и расширение объёма владельцем — в [proposal.md](proposal.md). Сборка использует Astro 7, Vite 8 и Rolldown 1.2.5. В сохранённом отчёте общий geo-чанк занимает 5 796 байт, 2 540 байт Brotli; это размер всего файла, а не обещанная экономия каждой страницы.

`packages/geo/src/index.ts` одновременно реализует расстояния через Turf и солнечные функции через SunCalc. Главная импортирует `isSunlight` в `lib/home/hero.ts`; сравнение импортирует `calculateDistance` в `SettlementsExplorer.svelte` и косвенно через `compare/lib/rating.ts`. `mercator.ts` и `polygon-label.ts` уже выделены по вычислительным задачам. Во всех семи библиотеках `packages/*` поле `sideEffects` отсутствует.

Применимые решения:

- [ADR-003](../../../../docs/decisions/003-markdown-pipeline-layering.md): общие правила типографики принадлежат Markdown-пакету, а приложение использует свои адаптеры.
- [ADR-033](../../../../docs/decisions/033-integrated-tariff-comparison-section.md): сравнение остаётся частью общего приложения и build-потока.
- [ADR-034](../../../../docs/decisions/034-native-css-architecture.md): компоненты пакета владеют scoped CSS, media использует отдельный минимальный foundation.

## Goals / Non-Goals

**Goals:**

- Дать сборщику независимые модули вычислений при сохранении именованных импортов через `@shelkovo/geo`.
- Описать фактическую семантику импорта каждой библиотеки, сохранив необходимые эффекты.
- Закрепить проверяемое правило для новых пакетов и последующих изменений существующих.

**Non-Goals:**

- Менять алгоритмы расчёта, библиотеки, версии зависимостей или публичные пути импорта.
- Перестраивать Markdown-инициализацию, UI-компоненты, правила поиска или интерфейс страниц.
- Управлять именами/числом чанков, вводить бюджет размеров или постоянный smoke-обход сайта.
- Объявлять корневой workspace и приложения `apps/*` библиотеками без побочных эффектов.

## Decisions

### Модули по вычислительным задачам и один публичный API

Перенести `calculateDistance` в `packages/geo/src/distance.ts`, солнечные функции и их константы — в `solar.ts`. В `index.ts` оставить явные реэкспорты этих функций, существующих геометрических функций и типов. Существующие потребители и тесты продолжают пользоваться прежним API. Разделять тесты только ради совпадения с новыми именами файлов не требуется.

Проверка в памяти на настоящих исходниках `geo`, `hero.ts` и `rating.ts`, с динамической точкой входа сравнения, показала:

- Общий исходный модуль сохраняет SunCalc и Turf в одном чанке, в том числе при объявлении его без побочных эффектов.
- Раздельные реализации с корневыми реэкспортами изолируют библиотеки без изменения импортов потребителей.
- Дополнительное объявление модулей `geo` без побочных эффектов удаляет оставшийся неиспользуемый фрагмент `mercator.ts`.

В эксперименте использован `moduleSideEffects: false` через API Rolldown; при реализации метаданные задаются в `package.json` и проверяются штатной production-сборкой. Дополнительные subpath exports не дают нужной сейчас возможности. Ручное разнесение SunCalc и Turf по чанкам сохраняет обе статические зависимости общего модуля и не решает задачу загрузки.

### `sideEffects` по фактическому поведению пакетов

Значение `false` разрешает исключить неиспользуемый модуль целиком; оно относится к выполнению импорта, а не объявляет все вызовы экспортированных функций чистыми.

- `format`: `false`. Форматтеры и обёртки Luxon не меняют глобальные настройки при импорте.
- `geo`: `false`. Вычисления находятся в экспортированных функциях; верхний уровень содержит локальные константы.
- `ical`: `false`. Создание локальных `TextEncoder` и `Intl.NumberFormat` обслуживает экспортированную функцию сериализации.
- `seo`: `false`. Экспортируются константы и функции сборки metadata.
- `url`: `false`. Экспортируются функции, использующие локальные регулярные выражения.
- `ui`: `["**/*.css"]`. `standalone-error.css` импортируется ради оформления media-404; CSS сохраняется. Компоненты, реэкспорты иконок и данные маркеров используются через их экспорты. Проверка сборки должна также подтвердить сохранение scoped CSS и ресурсов используемых компонентов.
- `markdown`: `["./src/index.ts", "./src/typography.ts"]`. `typography.ts` при импорте регистрирует правила через `Typograf.addRule`, меняя общий реестр библиотеки. Корневой `index.ts` сохраняет путь к этой инициализации, включая импорт пакета без использования экспортов. Остальные модули разрешено исключать, когда они не нужны.

Небольшой эксперимент с Rolldown подтвердил необходимость учесть входной файл Markdown: пометка только модуля регистрации не сохраняет эффект при удалении импорта корневого файла, объявленного чистым. Поэтому blanket `false` и список лишь из `typography.ts` отвергнуты. Перенос регистрации на первый вызов изменил бы момент инициализации и не нужен для этого изменения.

### Правило для дальнейшей разработки

В разделе «Правила workspace» корневого `AGENTS.md` добавить одно правило:

> При создании библиотеки в `packages/*` или изменении её импортов и инициализации проверь побочные эффекты при импорте и синхронно обнови `sideEffects` в `package.json`: `false`, если пакет нужен только ради используемых экспортов; список путей для CSS и обязательной инициализации, включая входы, которые должны её запускать; `true`, если пакет пока нельзя безопасно ограничить списком. Учитывай цепочки импортов и реэкспортов, проверяй сохранение эффектов и исключение ненужного кода в production-сборке.

Правило применяется по факту создания пакета и изменения его поведения; отдельный реестр пакетов или автоматический запрет значений не вводится. Обоснование стандартных метаданных и результаты проверки остаются в change, без отдельного ADR.

### Проверка результатов

Сохранить исходные отчёты `pnpm bundle:analyze`, повторить анализ после изменения и сравнить состав клиентского графа и размеры готовых файлов. Для `/` и `/815/compare/` проверить Network в независимых браузерных контекстах: главная получает солнечные вычисления без Turf и геометрических вычислений, сравнение — расстояния без SunCalc. Переходы между страницами проверяются отдельно: уже загруженный код предыдущей страницы не считается новой лишней загрузкой.

Существующие тесты проверяют функции географии, панораму, расстояния, типографику и остальные библиотеки. Дополнительно разово собрать маленький потребитель Markdown через настоящие метаданные пакета и проверить регистрацию обоих правил Typograf при импорте корневого входа. Это проверка результата изменения, не новый постоянный тест сборочного инструмента.

Собрать `www` и `media`; проверить реальные CSS и шрифты media-404, scoped CSS используемых общих компонентов, маркеры карты, форматирование дат и текста на репрезентативных страницах. Результаты и размеры записать в PR, актуальные YAML — в Git. Новые тесты создавать только при обнаружении поведения, не покрытого существующими проверками.

## Risks / Trade-offs

- Неверное объявление чистоты удалит необходимую инициализацию или стили → сохранить явные исключения Markdown/UI и проверить их в собранных потребителях.
- Метаданные общих пакетов могут изменить другие клиентские чанки → сравнить весь отчёт и выполнить проверки обоих приложений, а не только двух исходных страниц.
- Изменения хешей или размера `rendered` не равны сетевой экономии → сравнивать реально загружаемые файлы и их Brotli-размеры; не фиксировать численный выигрыш до замера.
- Сохранение побочных эффектов Markdown ограничивает его tree shaking → это честное описание текущего поведения; независимую переработку его инициализации можно обсуждать отдельно.

## Migration Plan

После согласования сохранить исходные измерения, выполнить перенос geo-функций, добавить метаданные и правило, затем пройти проверки и ревью. Пакетные импорты, данные и deploy не требуют миграции. Откат возвращает вместе структуру geo, манифесты, правило и снимки бандлов. Production-приёмка не требуется.
