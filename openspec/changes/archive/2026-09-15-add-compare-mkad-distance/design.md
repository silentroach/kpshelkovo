## Context

- Мотивация и границы: [proposal.md](proposal.md), issue [#744](https://github.com/silentroach/kpshelkovo/issues/744).
- Настольная карточка и мобильный паспорт находятся в `apps/www/src/pages/815/compare/settlements/[slug]/index.astro`; они переключаются на ширине `64rem`.
- `getRing(lat, lng)` в `src/compare/lib/rating.ts` уже считает `max(расстояние от центра Москвы − средний радиус МКАД, 0)`. Расчёт используется в сортировке и соответствует метрике рейтинга, Markdown и JSON.
- `formatDistance()` уже задаёт округление и знак приблизительности. Его поведение покрыто тестами `packages/format/src/index.test.ts`; метрика расстояния покрыта `src/compare/lib/rating.test.ts`.
- Решение следует [ADR-033](../../../../docs/decisions/033-integrated-tariff-comparison-section.md) о доменной границе сравнения и [ADR-034](../../../../docs/decisions/034-native-css-architecture.md) о локальных стилях. Новый ADR не нужен.

## Goals / Non-Goals

- Цель: вычислить значение один раз при статической сборке страницы и использовать его в обоих вариантах расположения.
- Новые компоненты, поля YAML, клиентские вычисления и отдельный географический helper не нужны.

## Decisions

- Вызвать `getRing()` по координатам поселка в frontmatter и отформатировать результат через `formatDistance()`. Повторно реализовывать формулу или подключать маршрутизацию не нужно: пользователь попросил вывести уже доступную оценку.
- На компьютере добавить `<p>` с существующим классом `settlement-fact-detail` после условной строки расстояния от Шелково. Новый вывод не связывать с условием `distanceFromShelkovo > 0`: он нужен и базовому поселку, и для нулевой оценки.
- В мобильном паспорте добавить то же значение после адреса и имеющегося расстояния, сохранив компактную подачу блока. Отдельная настольная карточка на телефоне скрыта, поэтому правка только hero не выполнит пользовательскую задачу для мобильных читателей.
- Подпись: `{formatDistance(distanceFromMkad)} от МКАД`. Для пояснения использовать обычный `title`: «Примерная оценка по координатам, без учёта дорог». Отдельный интерактивный tooltip не требуется.
- По последующему уточнению владельца нормализовать начальную тильду расстояния от Шелково через `.replace(/^~?/, '~')` после `formatDistance()`. В HTML подготовить текст один раз для обоих блоков, в Markdown применить то же преобразование. Это сохраняет округление и добавляет ровно один знак, не расширяя общий API форматирования.
- Markdown и JSON уже публикуют эту метрику. Проверить соответствие вычислений, учитывая существующее округление рейтинга до десятых и отображения до десятков километров; расширять их схемы не требуется.

## Risks / Trade-offs

- Приближённый радиус МКАД не даёт длину пути по дороге и точное расстояние до ближайшей точки кольца. Общий формат и пояснение сохраняют смысл оценки.
- Дополнительная строка увеличит высоту карточки. Проверить обычный поселок с длинным адресом и Шелково на компьютере, затем оба мобильных блока на узком экране.

## Migration Plan

- Обычная статическая сборка и deploy; миграции данных нет. Откат возвращает правку страницы.
- Обязательная production-приёмка не нужна: достаточно проверок сборки и локальной браузерной проверки до PR. После выполнения задач синхронизировать spec и архивировать change в той же ветке.
