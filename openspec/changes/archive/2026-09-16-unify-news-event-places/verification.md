# Проверка unify-news-event-places

Дата: 16 сентября 2026 года. Разрешение реализации относится к артефактам коммита `d946b10e`; [отметка в #749](https://github.com/silentroach/kpshelkovo/issues/749#issuecomment-5702527988). Реализация продолжает [PR #750](https://github.com/silentroach/kpshelkovo/pull/750).

## Результат

- Все 14 требований и 27 сценариев двух specs сопоставлены с реализацией и проверками ниже.
- Разрешение места выполняется один раз через полный базовый dataset. Общая карта использует `selectMapPlaces`; карточки и реестр упоминаний получают все места.
- `pnpm typecheck` — успешно.
- `pnpm test` — успешно: 1247 тестов приложения в 192 файлах, ещё 94 теста shared-пакетов.
- После заключительного упрощения public DTO повторно прошли 73 профильных теста и typecheck.
- `pnpm build` — успешно: 330 страниц, 224 страницы в индексе Pagefind. Финальная сборка и разовая сверка миграции выполнены повторно после ревью.
- `pnpm openspec:validate` — успешно до архивирования и после завершения архивной задачи. Основные specs синхронизированы; все 16 задач выполнены, PR #750 обновлён с `Closes #749`.
- `pnpm skills:check` — успешно. Проектные инструкции обновлены в исходниках; upstream-интеграция не менялась.
- Изменённые файлы отформатированы oxfmt/Prettier; `git diff --check` проходит.

Первый полный прогон обнаружил устаревший dev-store Astro: три изменённые статьи отсутствовали в `.astro/data-store.json`, хотя build-store и собранный сайт содержали их. Dev-store обновлён через программный `sync({ cacheDir: './.astro' })`, затем полный прогон прошёл. Изменений инфраструктуры тестов для обхода этой ошибки не потребовалось.

## Сценарии news-event-places

Тесты лежат под `apps/www/src/`.

- **Известное место** — `lib/news/tests/event-places.test.ts`: разрешение видимой и скрытой сущности, сохранение ссылки на объект, внешний URL и координаты iframe.
- **Неизвестное место** — тот же файл: ошибочная ссылка отклоняется с id статьи и slug события. Loader ищет исключительно в places, поэтому slug другого типа не разрешается через общий mention registry.
- **Старый inline-формат** — `lib/news/tests/raw-schema.test.ts`: `location` и `coordinates` отклоняются по отдельности и вместе с `place`. Ошибка Astro при пробной синхронизации до миграции содержала статью `2026/05/apple-garden` и путь `events.0`.
- **Место пока неизвестно** — `event-places.test.ts`, `components/news/tests/event-card.test.ts`: нет географических полей JSON/JSON-LD/ICS, ссылки на место и карты; календарная ссылка остаётся.
- **Встреча в беседке** — `event-places.test.ts`, `event-card.test.ts`, браузерная проверка `ok-meeting-june`: уточнение рядом с каноническим названием и в ICS DESCRIPTION; URL статьи сохраняется.
- **Уточнение без сущности** — `raw-schema.test.ts`: отдельные отрицательные случаи для отсутствующего места и пробельного уточнения.
- **Событие в скрытом месте** — `event-card.test.ts` для обоих вариантов карточки и браузерная проверка Green Dreams: внутренняя ссылка, внешний переход и iframe доступны; общей карты место не пополняет.
- **Исправление места** — `event-places.test.ts`: переименование, адрес и координаты переходят в domain event, JSON, JSON-LD и ICS, URL и UID события сохраняются. HTML-тест получает актуальный объект места через те же props.
- **JSON события с местом** — `event-places.test.ts`, `lib/news/tests/public-contract.test.ts`, `lib/news/discovery.test.ts`: Zod-контракт и согласованность JSON Schema/OpenAPI, прежние типы и новые поля.
- **Структурированные данные без адреса** — `event-places.test.ts`: JSON-LD без выдуманного адреса; парный случай с адресом.
- **Миграция календаря** — `lib/news/calendar.test.ts`, `event-places.test.ts` и разовая сверка всех пяти файлов: прежние URL/UID, LOCATION/GEO/X-APPLE-STRUCTURED-LOCATION, escaping описания и уточнения, сохранённый URL статьи.
- **Место только в событии** — `event-places.test.ts`: backlink создаётся при пустом body и попадает в Markdown карточки. Собранные companions четырёх новых мест содержат ссылки на исходные статьи.
- **Повторная связь** — тот же тест: два события и упоминание в body дают одну source ref.
- **Посадка яблонь** — разовая сверка frontmatter и сборочного JSON: `apple-garden`, точка `55.063710, 37.724333`, уточнение «возле спортивной площадки»; остальные поля события сохранены.
- **Встреча и праздничные события** — разовая сверка исходников до/после и сборки: четыре новых slug, исходные координаты, раздельные ресторан и КПП, отдельный фруктовый сад, отсутствие новых мест на общей карте. У шествия место обозначает старт; описание маршрута сохранено.

## Сценарии place-map-visibility

- **Место включено** — `lib/places/tests/raw-schema.test.ts`, `map-public.test.ts`: нормализация `true`, включение в общую выборку и одинаковый набор JSON/Markdown. HTML `/map/` использует эту же выборку для ItemList, количества и fallback.
- **Место не включено** — те же тесты для `false` и отсутствующего поля, смешанной и пустой выборок. Маркеры, контуры, bounds и кластерные features строятся только из опубликованного JSON; скрытых сущностей в нём нет.
- **Доступ к скрытой карточке** — `lib/places/tests/place-page.test.ts`, разовая проверка HTML/Markdown/canonical/sitemap/`data-pagefind-body` всех четырёх мест. Браузерный поиск `Green Dreams` возвращает `/map/green-dreams/` и связанную статью.
- **Переход из видимой карточки** — `place-page.test.ts`: ссылка с каноническим `h` присутствует только у видимого места.
- **Прямой фокус скрытого места** — `components/places/tests/PlaceMap.test.ts`, `place-map-url.test.ts`: скрытый/неизвестный slug очищается без фокуса камеры, query/hash/history state сохраняются; браузерная сверка ниже.
- **Место за прежними границами** — `raw-schema.test.ts`: удалённые координаты при `true`, `false` и отсутствии поля; `geometry.test.ts`: удалённый контур тоже допустим.
- **Некорректные координаты** — `raw-schema.test.ts`: отсутствие, строка, NaN и выход за мировые диапазоны отклоняются; сами мировые границы принимаются. `geometry.test.ts` проверяет выход контура за диапазон.
- **Разные места в одном здании** — `lib/places/tests/load.test.ts`: два slug с одинаковыми координатами остаются отдельными объектами. Сборка подтвердила отсутствие коллизий с людьми.
- **Единственное удалённое место** — `components/places/tests/place-map-geometry.test.ts`: bounds вокруг точки `2.35, 48.85`, а не посёлка.
- **Несколько мест** — тот же файл: bounds охватывает местную и удалённую точки. Скрытые места исключены до передачи данных renderer-у.
- **Пустая карта** — `place-map-geometry.test.ts`, `map-public.test.ts`: локальный fallback и пустые публичные наборы; HTML-fallback берётся только из видимой выборки.
- **Состав карты после миграции** — разовое сравнение всех 13 файлов с `HEAD` до реализации: единственное изменение их данных — `show_on_map: true`; slug и координаты совпадают с собранным map JSON. Четыре новых места скрыты.

## Браузерная проверка

Собранный `dist/www` проверен в Chromium через `agent-browser`, сессия `places-749`, адрес `http://localhost:14335`. Сессия закрыта после проверки.

- Общая карта загрузила настоящую подложку Яндекс Карт, прежние точки и кластеры. Набор всех 13 slug дополнительно сверен по JSON; число видимых DOM-маркеров зависит от кластеров.
- `?h=green-dreams&from=acceptance#map` и `?h=unknown-place&from=acceptance#map` дали одинаковый набор маркеров без подсветки; URL стал `?from=acceptance#map`.
- `?h=apple-garden&from=acceptance#map` центрировал и подсветил ссылку `/map/apple-garden/`; через пять секунд `h` исчез, остальные части URL сохранились.
- Карточка Green Dreams открывается из события клавишей Enter после фокуса ссылки. В карточке доступна внешняя карта и отсутствует действие «Показать на общей карте».
- Карточка события показывает название ресторана и «в беседке». Внешняя ссылка открыла `https://yandex.ru/maps/?pt=37.755599,55.074958&z=18&l=map` в новой вкладке.
- Iframe загрузился с канонической долготой и существующим смещением центра по широте для фоновой карты. Варианты с местом и без него дополнительно проверены Astro-container тестами.
- Проверены desktop и ширина 390 px; горизонтального переполнения нет.
- На `127.0.0.1` API общей карты не загрузился; при том же build на `localhost` проверка прошла. Код карты для этого не менялся.

## Ревью и оставшаяся приёмка

- Просмотрен весь актуальный diff и новые файлы. Удалено лишнее преобразование map URL в public DTO: URL уже валидирован и сформирован сущностью места.
- Не добавлены новые зависимости, loader мест, исторические снимки или промежуточная модель события. Дедупликация использует существующий `createEntityMentionSourceRefs`.
- Проверены проектные инструкции, ADR-012/028, описание JSON, публичный news-feed skill, JSON Schema/OpenAPI и llms discovery. ADR-013 соблюдён без изменения его правил. Пример визуальной проверки события переведён на новую domain model.
- Новые summary сверены с опубликованными статьями и согласованным design. Месячная и годовая выжимки сохраняют прежний смысл; их менять не потребовалось.
- Блокирующих расхождений со scope и specs не найдено. Остаются человеческое ревью PR и merge владельцем; обязательная production-приёмка не нужна по согласованному design.
