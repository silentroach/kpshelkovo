# Как получать и показывать дороги

## Context

У [Центральной улицы в OSM](https://www.openstreetmap.org/way/1357820677) есть общие узлы с десятью безымянными проездами. В окрестностях КПП встречаются `service`, `unclassified` и `track`: фильтр по названию или только по `residential` потерял бы улицы. На [карте НСПД](https://nspd.gov.ru/map) в слое «Сооружения» нашлись автомобильные дороги, но проверенные объекты имеют площадные контуры. Из них нельзя прочитать линию проезда и связи на перекрёстках.

## Goals / Non-Goals

Редактор обновляет данные по образцу [снимка НСПД](/docs/parcel-updates.md#кадастр): сначала смотрит изменения, потом принимает выгрузку. Будущий планировщик получает исходную сеть, карта — линии для показа. Разметка обслуживаемых улиц, проверка права проезда и построение маршрутов относятся к планировщику.

## Decisions

1. **Один источник и явный охват.** По запросу редактора получать через [Overpass](https://overpass-api.de/) линии `way[highway]` в прямоугольнике и все их узлы одним запросом. Основной API редактирования для этой цели не подходит по [правилам OSM](https://operations.osmfoundation.org/policies/api/).

   Для первого просмотра взять `55.048…55.077 N, 37.701…37.758 E`: сюда входят участки всех четырёх частей и точки КПП. Западная граница важна для Фореста: его участки доходят до `37.70443 E`. Пробный запрос 25 ноября 2026 года вернул 347 линий до отбора автомобильных дорог; все ссылки на узлы разрешились. Сохранить границы со снимком, проверить подъезды и проезды между частями, показать весь результат владельцу. Уточнять охват по его замечаниям.

2. **Линии и узлы вместо готовой картинки.** Из ответа брать линейные `way` автомобильных классов `highway`, включая частные подъезды и дороги без названия. Не брать площадки `area=yes`, строящиеся дороги, чисто пешеходные и велосипедные пути. Полевые и лесные проезды `highway=track` исключать даже при разрешённом автомобильном доступе: при просмотре первой выгрузки владелец указал на полевые линии южнее Центральной улицы. Грунтовое или щебёночное покрытие у улицы само по себе не основание для исключения. `access=private` описывает доступ, а не отсутствие дороги. Сохранять OSM ID, исходный порядок узлов, их координаты и дорожные теги линий и узлов, в том числе ограничения и шлагбаумы. Для принятой дороги сохранять узлы и за границей запроса: обрезка или склейка изменила бы исходную сеть. Остальные объекты и сведения о пользователях OSM для снимка не нужны.
3. **Получение и принятие разделены.** Предлагаемая команда `pnpm roads:update` готовит кандидата вне рабочего снимка и печатает сравнение по OSM ID; `--snapshot <файл>` проверяет и принимает именно просмотренный файл без второго запроса. Метаданные и дорожные записи помещаются в один файл: после проверки его можно заменить целиком. Связи сравниваются по ссылкам на узлы, геометрия — также по их координатам, а не по версии `way`. Стабильный порядок записей не скрывает изменений и не меняет порядок узлов внутри дороги. Отчёт указывает ID затронутых дорог, в том числе при изменении общего узла; при проверке КПП и проездов между частями разрыв можно принять без исправления.
4. **Два представления одного снимка.** Загрузчик приложения проверяет вход по [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md). Из исходной сети сборка готовит компактную геометрию для карты. Она загружается с сайта при включении инфраструктуры как внутренний ресурс карты, без нового справочного API ([ADR-011](/docs/decisions/011-public-surface-registry.md)). В конфигурации дорог хранится своя пара метров на восток и север; её подбирают при визуальной сверке с подложкой. Использовать тот же `createDisplayOffset`, что и для [участков](/apps/www/src/lib/parcels/map-public.ts), и округлять результат по [правилу публичных координат](/openspec/specs/public-coordinate-precision/spec.md). Поправка участков к дорогам не прибавляется.
5. **Существующая сцена карты.** Показ зависит от фактического состояния слоя, в том числе при открытии `/map/?l=infra`. Добавить обычные линии в общую карту по [ADR-039](/docs/decisions/039-shared-yandex-maps-runtime-and-preview.md), без объектов справочника мест, подписей, обработчика нажатия или второго переключателя. На карте указывать [© OpenStreetMap contributors](https://www.openstreetmap.org/copyright), у распространяемых данных — источник и [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). Штатная атрибуция Яндекса остаётся доступной.

6. **Контур показа независим от выгрузки.** Используем [редакционный GeoJSON](/apps/www/src/data/territory/shelkovo.geojson) на основе [границы Шелково в OSM](https://www.openstreetmap.org/relation/18726399), без старой деревни. Показываем дороги строго внутри, без внешних подъездов к КПП. На сборке пересекаем линии с полигоном и только потом применяем поправку. Новые точки принадлежат геометрии показа, а не сети OSM. Отбор целых `way` по одному узлу не подходит: он захватывает внешние продолжения и может пропустить сквозную дорогу.

## Risks / Trade-offs

- Достоверный разрыв в OSM и потерянная часть ответа выглядят похоже на рисунке. Сообщение Overpass о тайм-ауте или нехватке памяти (даже при HTTP 200), пустая выборка или ссылка на отсутствующий узел останавливают приём. Две целые линии без общей точки принимаются. Значительные исчезновения из формально корректного ответа будут видны редактору до замены.
- У края выборки могут оказаться соседние дороги или длинное продолжение улицы. В первом просмотре показать их владельцу вместе с охватом, не угадывать границы обслуживания по классу дороги.
- Если между частями OSM соединяет улицы только полевыми проездами, после отбора связи не будет. Роль этого проезда можно уточнить в задаче планировщика по местным сведениям; линии не соединяем по догадке.
- Если пользователь выключил инфраструктуру до загрузки линий или файл недоступен, остальные объекты карты остаются доступны. Запоздалый ответ не должен снова включать дороги.
