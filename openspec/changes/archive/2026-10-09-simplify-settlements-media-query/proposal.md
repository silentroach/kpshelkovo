# Proposal

## Why

Каталог посёлков вручную хранит мобильное состояние и управляет media-query подпиской, хотя Svelte предоставляет штатный реактивный `MediaQuery`. Задача [#904](https://github.com/silentroach/kpshelkovo/issues/904) сокращает служебный код без изменения поведения.

## What Changes

- Ручная подписка заменяется штатным `MediaQuery`.
- Ширина определяет начальный показ карты один раз; затем `showMap` остаётся независимым пользовательским состоянием.
- Сохраняются начальная серверная разметка, резервирование места, момент готовности контролов и обновление подписей при resize.
- Не меняются renderer карты, CSS-адаптивность, URL-состояние или способ ручной гидратации.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: это совместимый рефакторинг. `skip_specs: true`; действующие требования карт остаются в [site-maps](/openspec/specs/site-maps/spec.md), без нового дублирующего контракта.

## Impact

- `/apps/www/src/compare/components/SettlementsExplorer.svelte`, профильные component/browser проверки и отчёты `/docs/bundle/`.
- Новые зависимости не нужны. Новый клиентский импорт требует сравнения бандлов до/после в этой ветке.
- Основная приёмка проверяет hydration, resize, ручной выбор и cleanup; mock SDK не считается проверкой настоящей карты. Если она потребуется, dev запускается только после явного разрешения владельца.
- Отдельная production-приёмка не нужна; PR закрывает #904 после подтверждения сохранности поведения.
