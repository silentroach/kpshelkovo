# Proposal

## Why

Метрика автоматически включается в production-сборке, а существующий выключатель предназначен только для Lighthouse. Владелец хочет временно отключить счётчик и впоследствии вернуть его через конфиг без изменения интеграции.

Связанный тикет: [#1031](https://github.com/silentroach/kpshelkovo/issues/1031).

## What Changes

- Добавить версионируемый переключатель Метрики на этапе сборки и в этом изменении установить его в выключенное состояние.
- Читать флаг только при сборке: клиентский runtime не импортирует и не запрашивает конфиг.
- При отключении не публиковать маркер счётчика и `noscript`-пиксель, не запускать загрузку, просмотры и цели Метрики.
- Сохранить production-only подключение и принудительное отключение для Lighthouse.
- Согласовать сводку Lighthouse и документацию с фактическим состоянием аналитики.
- Не менять Яндекс Карты, параметры счётчика, CSP и не добавлять пользовательский или runtime-переключатель.

## Capabilities

### New Capabilities

- `site-analytics`: управление подключением Метрики при сборке и согласованное отключение всех способов отправки аналитики.

### Modified Capabilities

Нет.

## Impact

- Конфигурация приложения, `BaseLayout.astro`, адресные тесты и документация включения/отключения.
- Lighthouse workflow и ADR-004, который сейчас предполагает обязательную Метрику в production.
- Клиентский runtime уже прекращает работу с Метрикой без маркера счётчика; его переработка не нужна.
- Новых зависимостей и внешних запросов нет. Разрешения CSP сохраняются для обратимого включения.
- Проверки выполняются на локальной production-сборке. Production-приёмка не является условием закрытия тикета; эффект на опубликованном сайте наступит после merge и обычного deploy.
