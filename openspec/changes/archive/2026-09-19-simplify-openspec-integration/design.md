# Упрощение генерации и проверок

## Context

См. [proposal.md](proposal.md). [ADR-038](../../../../docs/decisions/038-openspec-development-workflow.md) закрепляет штатную интеграцию и изоляцию личного профиля. На момент подготовки change скрипт генерировал инструкции через `init` и `update`, сравнивал их с временным эталоном, а bootstrap повторял генерацию для `check`.

После `spec cleanup` фактический набор совпадает с шестью workflows штатного `core`, но скрипт всё ещё добавляет `verify`. Правила отбора specs уже находятся в корневом `AGENTS.md`; ссылки на удалённый `openspec/AGENTS.md` устарели.

## Goals / Non-Goals

- **Goals:** оставить минимальную обвязку для воспроизводимой генерации из локального пакета и убрать отдельный механизм сравнения инструкций.
- **Non-Goals:** менять внешний набор skills, схему `spec-driven`, согласование изменений или интеграцию других агентов.

## Decisions

- Генерировать через один `pnpm exec openspec init --tools opencode --profile core --no-animation` во временном проекте. Штатный `core` заменяет ручной список; `update` сразу после `init` и собственный JSON профиля удаляются. Язык артефактов уже задан рабочим `openspec/config.yaml`.
- Сохранить временные `XDG_CONFIG_HOME` и `XDG_DATA_HOME`, очистку временных файлов и перенос только сгенерированных OpenSpec-инструкций в рабочую копию. Прямой запуск с личным профилем может изменить набор или способ доставки инструкций.
- Удалить режим `check`, `checkGenerated`, соответствующий package script, вызовы из bootstrap и CI и тесты изменённых, отсутствующих и лишних инструкций. Короткая проверка изоляции личного профиля остаётся; сравнение рабочей копии с эталонной генерацией не переносится в другой скрипт или тест.
- Сохранить структурную валидацию и проверки внешних skills. Актуальность сгенерированных инструкций проверять при обновлении пакета через регенерацию и ревью diff. Обновить действующие правила и инструкцию обслуживания вместе с delta spec.
- Установить `minimumReleaseAge: 2880` в `pnpm-workspace.yaml`: во время реализации владелец выбрал два дня вместо трёх. OpenSpec 1.13.1 уже старше двух дней, поэтому обычная установка и CI проходят без разовых обходов и исключений для пакета.

## Risks / Trade-offs

- Несогласованное ручное изменение инструкций больше не блокируется отдельной CI-проверкой → штатная регенерация и ревью generated diff входят в приёмку обновлений.
- Новый `core` может расшириться в будущих релизах → состав и совместимость с проектными правилами проверяются при обновлении закреплённой версии.
- Двухдневный порог применяется ко всем зависимостям workspace; это согласованное изменение общей политики установки.

## Migration Plan

- Обновить точную версию до 1.13.1, упростить интеграцию, регенерировать и проверить результат, затем синхронизировать spec и архивировать change.
- Проверить повторяемость генерации и изоляцию профиля, выполнить `pnpm openspec:validate`, `pnpm test:agent-tooling`, `pnpm skills:check` и ревью всего diff изменения.
- Production-приёмка не требуется: меняются локальные инструменты разработки. Откат возвращает пакет, lock-файл, обвязку, инструкции и документацию вместе.
