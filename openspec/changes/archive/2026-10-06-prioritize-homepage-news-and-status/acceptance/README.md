Первые два снимка сохраняют опубликованный состав сервисов. В двух смешанных примерах только в браузере подставлены перебой электричества, работы на дамбе, будущие работы по воде и будущий перебой интернета. Статьи на всех снимках — из репозитория; редакционные данные не менялись.

## Подтверждённый результат

- Вариант A: описание ведущей видно всегда, дополнительных — только ниже `48rem`. От `48rem` дополнительные заголовки используют **Fira Sans 400, 17 px, line-height 1,75, `text-wrap: pretty`**; ниже порога — **PT Serif 700, 21 px**. Семантика H2 сохранена. Ведущее описание использует `ui-copy` 17/16 px с line-height 1,75.
- В сводке маркер остаётся внутри общей строки ссылки. Подпись состояния использует 82% светлого цвета, декоративная черта `|` — 35%; черта скрыта от screen reader, пробелы находятся снаружи её элемента. Доступное имя: «Дамба Идут работы».
- Ранее прошли **24/24** сочетания: 1440/390/320 px, день/ночь, пустое/активное/будущее/смешанное состояние. После последней типографической правки адресно проверены 1440, 768, 767, 390 и 320 px, длинные заголовки и фокус обоих дополнительных desktop-заголовков. Переполнения и перекрытия меню нет.
- При resize 767↔768 без JS описания переключаются `[все]` ↔ `[только ведущее]`, дополнительных data/JS-запросов нет. Набор шрифтов не увеличился: те же шесть WOFF2. Возможная загрузка другого responsive-srcset панорамы не относится к запросам для адаптации описаний.
- Метаданные — **14 px**, высота целей сервисных ссылок — **30 px** или больше. Новости сохраняют начало на **533,8 px** при 1440 и **321 px** при 390/320. Прежние проверки короткой/пустой ленты, H1 и сохранения серверного снимка без JS после начала/конца окна остаются действительными.
- Контраст в худшем проверенном варианте с четырьмя длинными будущими подписями на 320 px ночью: **подпись 5,38:1**, **рамка сервиса 4,976:1**. Для расчёта снимали фон с сохранённым градиентом и учитывали композицию подписи с alpha 0,82 в каждом пикселе её текстовых прямоугольников. Контраст непрозрачного `currentColor`-контура новостных ссылок к фону — **10,14:1**; исходный дефект исправлен.
- Структуру payload проверяет схема при SSR-генерации. Клиент разбирает доверенный встроенный JSON без runtime Zod; отсутствующий script, пустой или синтаксически повреждённый JSON сохраняет серверную сводку.
- После переноса проверки прошли **19/19 runtime-сценариев** и два круга ClientRouter. Дубли обработчиков, таймеры и запросы данных сводки не появились; ошибок JS нет. Холодная главная загружает одну панораму, соседний `/reviews/rules/` — без модулей главной. CSS и четыре снимка остались прежними.

## Ограничения

- Проверен Chromium; другие движки и реальные устройства в эту приёмку не входили.
- Сохраняется известное частичное отсечение примерно 4 px нижнего контура первого дополнительного заголовка после Tab на 320 × 844. Текст и основная часть фокуса видны; полностью скрытого фокуса нет.
