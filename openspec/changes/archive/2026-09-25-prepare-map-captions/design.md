# Design

## Context

Причина изменения — в [proposal.md](proposal.md). Редакционный `iconCaption` проходит через `parseEditorialGeometry` к трём поверхностям: HTML-атрибут Markdown-карты, `MapPreview` карточки места и `/map/data/places.json` общей карты. В черновой реализации PR #860 общий renderer уже выводит подпись через `textContent` без клиентского Typograf, но серверная подготовка подписи изменила публичное значение. До merge владелец выбрал сохранить авторскую строку без типографики на всех трёх поверхностях. Отдельный импорт `formatPlaceStatus` через `places/view` и `status/view` ранее удерживал тяжёлые зависимости в чанке `/map/`; выполненную оптимизацию этого пути нужно сохранить.

В исходной базе шаблоны новости и KB подключали `editorial-map-element` безусловно, хотя серверный `renderMarkdown(..., { editorialMaps: true })` уже определяет наличие итоговых `<editorial-map>`. Обе страницы используют Astro ClientRouter; условное подключение в PR #860 нужно сохранить. Применимы [ADR-003](../../../../docs/decisions/003-markdown-pipeline-layering.md) для правил типографики сайта, [ADR-013](../../../../docs/decisions/013-raw-domain-public-data-boundary.md) для редакционного и публичного представлений, [ADR-028](../../../../docs/decisions/028-markdown-first-places-map.md) для мест и JSON карты и [ADR-039](../../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md) для запуска Markdown-карты и повторной навигации.

## Goals / Non-Goals

**Goals:**

- Убрать Typograf/YAML из клиентской цепочки подписей, сохранив авторский текст и безопасный вывод на всех трёх поверхностях.
- Сохранить проверку конечных данных до сериализации и самостоятельность публичного JSON от внутренней модели; без повторной схемной проверки в браузере.
- Не загружать код редакционной карты на статьях без карты, сохранив немедленный запуск всех карт на статьях с картами.

**Non-Goals:**

- Дробить `/map/data/places.json` на слои (#858) или менять навигационный Markdown-индекс и опубликованные карточки (#859).
- Оптимизировать клиентскую загрузку обычного превью без геометрии (#847), скрытые превью (#844), время готовности внешнего SDK или первый экран `/map/` (#393).
- Пересматривать редакционные правила Typograf либо типографировать скрытые описания и исходные блоки `map`.

## Decisions

### Дословная подпись без отдельного display-представления

Не типографировать `iconCaption` и не вырезать из него HTML-подобные фрагменты. Удалить добавленные в черновой реализации helper `formatPlainText`, отдельный `prepareEditorialGeometry` и их тесты. Остальные способы применения типографики в `@shelkovo/markdown` не менять.

Передавать исходную коллекцию в `editorial-maps-html.ts`, `PlacePreview.astro` и `toPublicEditorialGeometry` без текстового адаптера. Проверки конечных HTML payload и публичного DTO действующими Zod-схемами до публикации оставить. В `/map/data/places.json` использовать прежнее имя `properties.iconCaption` с буквальным исходным значением — без параллельного поля. `fromPublicEditorialGeometry` переносит эту строку в геометрию карты, а общий renderer ставит её в `textContent` без типографа и HTML decoder-а.

Альтернатива — типографировать в raw mapper-е или отдельном display-представлении: обе добавляют обработку неизменяемой авторской строки ради лейбла. Асинхронный клиентский импорт Typograf сохраняет тяжёлый код; удаление HTML-тегов или замена `&amp;` меняют содержание подписи. Дословная передача с выводом через `textContent` не требует ни дополнительного helper-а, ни несовместимого изменения публичного JSON.

### Убрать остаточный тяжёлый импорт общей карты

После переноса подписей проверить клиентский граф всех затронутых страниц. Если `/map/` продолжает получать Typograf через `formatPlaceStatus` → `places/view` → `status/view`, готовить необходимый статический текст места при построении payload карты, а не импортировать серверный view-модуль в `PlaceMap.svelte`. Время открытия/закрытия, viewport, кластеры и действия пользователя остаются динамическими: их нельзя вычислить при сборке. Выбор конкретного display-поля должен оставаться минимальным и не подменять публичные коды lifecycle-статуса; конечный payload по-прежнему проверяется при сборке. Совместимость остальной клиентской карты, включая сопутствующий Luxon из этого пути (#843), проверить фактическим отчётом, но не включать общий рефакторинг дат в change.

Альтернатива — вынести `formatPlaceStatus` в лёгкий клиентский модуль: это уменьшило бы граф импортов, но оставило бы подготовку неизменного текста в браузере вопреки принятой границе. Перенос всего JSON в HTML-пропсы также не нужен: добавляет HTML и меняет способ загрузки карты ради одной строки.

### Подключение редакционной карты только к материалам с картой

Использовать результат уже выполненного серверного Markdown-render-а для признака наличия сгенерированного `<editorial-map>` в конкретной новости или KB-странице. Подключать существующий bundled script регистрации custom element только для такого материала; не дублировать парсинг исходного Markdown и не использовать клиентский обход DOM для принятия решения о наличии карты. Условную вставку проверять по **собранному** HTML: способ размещения Astro `<script>` и deduplication могут отличаться от вида шаблона. При необходимости вынести script в небольшой Astro-компонент, который рендерится условно. Стили карты условно подключать только тогда, когда это действительно устраняет лишнюю доставку без влияния на общие стили; не превращать CSS в самостоятельную миграцию.

Альтернатива — безусловный маленький скрипт с проверкой `document.querySelector('editorial-map')` перед динамическим импортом. Он защищает от тяжёлого чанка, но каждую текстовую страницу всё равно заставляет загружать и запускать проверку присутствия, уже известного при сборке. Безусловное подключение готовой регистрации сохраняет текущую проблему #841.

## Risks / Trade-offs

- Публичный `iconCaption` остаётся точной копией исходной строки → убрать прежнее объявление несовместимости в PR, документации и specs. Не выдавать будущий #859 за уже выполненную миграцию внешних потребителей.
- Буквальные entity-последовательности и псевдотеги могут исполниться при небезопасном выводе → точечные тесты `textContent`, отсутствия DOM-узлов разметки и сохранения исходника, в том числе для публичного JSON.
- Удаление импорта renderer-а может лишь переместить Typograf/YAML в иной чанк → проверить `pnpm bundle:analyze` и сетевые запросы на `/map/`, странице места, новости с картой, обычной новости и простом превью; сравнивать суммарную передачу, не складывать модульные `rendered` как байты сети.
- Условный Astro-скрипт может не соответствовать ожиданиям на выходе сборки или при ClientRouter → проверить отсутствие map-кода в HTML/Network без карты и восстановление нескольких карт при переходах; если условный tag всё равно подключается, применить условный компонент вместо отказа от требования.

## Migration Plan

Опубликовать дословные HTML-данные и JSON совместно с клиентским кодом, который больше не типографирует подпись. До объединения PR исправить текст о публичном контракте, выполнить локальную сборку, поведенческие проверки и сравнение бандлов; отдельная production-приёмка не требуется. При откате вернуть вместе клиентское форматирование и входы renderer-а. Разделение JSON по #858 и изменение агентского индекса по #859 остаются самостоятельными изменениями с собственной проверкой совместимости.
