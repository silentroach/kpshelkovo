# Proposal

## Why

Подтверждённые проблемы вне текущей задачи теряются в переписке, и следующему исполнителю приходится повторять исследование. [Issue #1168](https://github.com/silentroach/kpshelkovo/issues/1168) предлагает сохранять такие находки через проектный skill `backlog`; в обсуждении также согласована более узкая граница обязательного OpenSpec для небольших собственных skills.

## What Changes

- Разрешить короткий путь для небольших собственных skills и их подключения, если они используют существующий процесс и действующие разрешения. Изменения полномочий, согласований или владельцев информации требуют change.
- Добавить `backlog` в общий проектный каталог skills и подключить его через правила работы с побочными находками.
- Подтверждённые находки сохранять самостоятельно в пределах действующих разрешений: сначала искать существующий issue, затем добавлять новый контекст или создавать задачу через `project-issues`.
- Сохранять свидетельства и проверенное состояние, отделять факты от гипотез, возвращать ссылку в итог основной задачи. Ошибки собственной реализации и необходимые для текущей задачи исправления остаются в её объёме.

## Impact

- Агентские инструкции: `/AGENTS.md`, `/docs/development.md`, новый `/.agents/skills/backlog/SKILL.md` и разрешение его каталога в `/.gitignore`.
- Существующий bootstrap определяет собственные skills по отслеживаемым Git-файлам; новый skill подключается этим же способом.
- По указанию владельца тесты и сценарные прогоны исключены из приёмки этой задачи. Приёмка включает сверку инструкций с требованиями, проверку подключения skill, структурную валидацию и ревью diff.
