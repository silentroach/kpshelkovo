# Design

## Context

Мотивация и общий тикет описаны в [proposal](/openspec/changes/archive/2026-11-05-add-explicit-search-sections/proposal.md). Применимы [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md), [ADR-018](/docs/decisions/018-markdown-first-useful-contacts.md), [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md) и [ADR-034](/docs/decisions/034-native-css-architecture.md). Публичное поведение поиска карт уже задано в [search](/openspec/specs/search/spec.md); новая delta добавляет поведение отзывов.

[Рендер карт](/apps/www/src/lib/markdown/editorial-maps-html.ts) резервирует `editorial-map-N`, помещает ID на `h3` в подписи именованной карты и исключает клиентский host через `data-pagefind-ignore="all"`. [global.css](/apps/www/src/styles/global.css) компенсирует положение подписи отступом прокрутки, зависящим от высоты карты. Ссылка-якорь heading скрывается в [editorial-map.css](/apps/www/src/components/maps/editorial-map.css).

У [ContactReview](/apps/www/src/lib/contacts/types.ts) есть источник, дата, оценка и summary; mapper сортирует записи по дате. Разовый просмотр данных при планировании нашёл 95 отзывов без повторяющихся URL источника внутри одной карточки. Количество и результат этой проверки не являются постоянным требованием.

## Goals / Non-Goals

**Goals:**

- Перенести существующую цель карты на саму карту и упростить её HTML/CSS.
- Получать стабильную цель отзыва из существующей идентичности источника.
- Использовать обычные `sub_results` и общий выбор соответствующего фрагмента после первого change.

**Non-Goals:**

- Отдельные поисковые документы карт/отзывов, особые веса или принудительное первенство секции.
- Новый редакционный формат карт, массовая правка отзывов или расширение публичных DTO.
- Автоматическое ограничение секции закрывающим тегом контейнера: Pagefind делит текст по последовательности якорей.

## Decisions

### 1. Существующий ID карты переходит на `figure`

Сохранить вызов и порядок `reserveId`, включая разведение коллизий с авторскими headings, шаблонными ID и одноимёнными картами. Разместить получившийся ID на `figure`; для карты с непустым именем добавить `data-pagefind-title` с тем же plain-text именем. Подпись остаётся обычным `figcaption` с прежним текстом и внешней ссылкой при наличии. Карта без имени сохраняет прежнее отсутствие именованной поисковой секции.

Удалить `h3`, стили нейтрализации heading и скрываемого heading permalink, когда у них не остаётся потребителей. Вместо отступа, вычисляемого из высоты карты, использовать обычный отступ цели под закреплённую шапку на `figure[id]`. Холодный переход должен попадать к началу карты до загрузки SDK; геоданные и runtime-текст остаются исключены из поиска.

Альтернатива оставить `h3` не даёт пользы новой возможности и сохраняет обход прокрутки. Менять опубликованный ID при переносе не требуется.

### 2. ID отзыва зависит от URL источника

Добавить к readonly-модели отзыва `anchorId`, который серверный mapper вычисляет из исходного URL: префикс `contact-review-` и первые 16 hex-символов SHA-256. Хеширование выполняет `node:crypto` только на сервере; небольшой contacts-owned helper может разделяться mapper-ом и Zod-проверкой уникальности ID. Использовать один алгоритм, без индекса массива, даты, оценки и summary в идентичности.

Zod-граница карточки проверяет уникальность полученных целей среди её отзывов и выдаёт понятную ошибку при повторе источника/ID. Отдельное редакционное поле не добавляется. Альтернатива с порядковым номером ломает ссылки при сортировке; обязательные ручные ID потребовали бы миграции всех отзывов ради выводимого значения.

Идентичность привязана к точной строке URL: замена самого источника может изменить якорь. Перестановка или правка выжимки при прежнем источнике не меняет его. В публичные JSON/Markdown представления новое внутреннее поле автоматически не копируется; источник и текст отзыва остаются прежними.

### 3. Секция отзыва начинается на индексируемой выжимке

В [ContactReviews](/apps/www/src/components/contacts/ContactReviews.astro) поместить `id` и `data-pagefind-title` на существующий блок summary внутри обёртки `data-pagefind-body`. При production-проверке выяснилось, что Pagefind 1.6.0 не сохраняет якорь на самом элементе opt-in body: текст находится, но `anchors` пуст. Отдельная обёртка делает summary обычным дочерним якорем, не меняя индексируемого текста. Название секции: «Отзыв от <дата с годом>», дата берётся из `publishedIso` через действующий formatter. Имя автора не выдумывается. Это поисковый контекст; новый постоянный заголовок в карточке не нужен.

Служебное название и дата не добавляются в body; оценка, ссылка-оверлей и метаданные продолжают находиться вне индексируемой выжимки. Добавить локальный отступ прокрутки под шапку. Ссылка результата сайта остаётся внутренней; существующая ссылка карточки отзыва на внешний источник сохраняет своё действие.

Не менять общие правила выбора якоря. Если primary excerpt пересекает отзывы и не совпадает с единственной секцией, результат ведёт на canonical карточки. Более точный переход не оправдывает замены показываемого текста.

### 4. Проверки охватывают фактические переходы

Fixtures проверяют сохранность ID карты и коллизий, plain-text имя, отсутствие данных SDK в body, стабильность review ID при перестановке/правке текста, разные источники в одну дату и отказ при дублирующей цели. Проверка production-индекса подтверждает, что новый title сам по себе не создаёт совпадение по служебному слову или дате.

Ручной поиск выбирает существующую карту по её названию и конкретную работу, названную только в отзыве «Сарафана». Сравнить с baseline после первого change; проверить `hash`/`h`, реальную цель, подсветку, внешний источник отзыва и canonical fallback. На 390 и 1280 px проверить положение под шапкой, холодный переход и клиентскую навигацию; для изменённого общего CSS сверить новости и KB.

## Risks / Trade-offs

- Снятие heading может повлиять на вес текста. Проверить реальные запросы до/после; новые веса «на всякий случай» не добавлять.
- Несколько соседних отзывов могут попасть в primary excerpt. Сохранить canonical fallback, а не принудительный выбор одного из них.
- Источник отзыва может быть заменён. Это явная смена его идентичности; постоянное хранение редиректов для якорей не вводится.
- Карта может работать иначе вне разрешённого origin. Production-индекс и статическую цель проверять отдельно; реальный SDK проверять на `localhost:4321` по [правилам среды](/docs/development.md#проверка-настоящих-карт) после явного разрешения запуска dev.

## Migration Plan

Выполнить после `add-search-excerpt-ellipsis`. Существующие строки ID карт переносятся без изменения; review ID вычисляются при чтении данных без редакционной миграции. После этого выполняется `restore-search-data-retry`. Проверки, sync/archive, итоговый PR и откат общие по [плану первого change](/openspec/changes/archive/2026-11-05-add-search-excerpt-ellipsis/design.md#migration-plan).
