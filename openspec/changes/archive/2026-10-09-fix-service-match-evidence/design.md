# Design

## Context

Мотивация — в [proposal](/openspec/changes/archive/2026-10-09-fix-service-match-evidence/proposal.md). `full-2026.ts` служит общим источником сопоставлений для HTML услуг, публичного JSON и Markdown. Существующие адаптеры уже поддерживают `partial`; решение требуется на уровне данных, а не каждого представления.

## Goals / Non-Goals

**Goals:** исправить классификацию в общем источнике и подтвердить её распространение в публичные представления.

**Non-Goals:** искать новый первоисточник, менять модели источников, схемы, услуги, детальную смету или расчёты.

## Decisions

- Для `summer-road-gutters-cleaning` использовать `partial`, существующую русскую подпись и примечание «частично сопоставлено», по образцу соседних записей. Сохранить источник, ID, связи и пояснение: нынешнее доказательство не подтверждает тождество объектов работ.
- Не добавлять runtime-классификатор по тексту: семантическая редакционная оценка остаётся в данных. Не требовать дословного совпадения для других записей.
- Действующие [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md), [ADR-030](/docs/decisions/030-normalized-estimate-detail-sources.md) и [ADR-008](/docs/decisions/008-markdown-ast-generation.md) сохраняются; нового архитектурного решения нет.
- Сводки пересчитываются автоматически: ожидаются 5 явных и 14 частичных сопоставлений. Обновить только относящиеся к ним ожидания; спорная запись не должна попадать в перечень «нужно сверить» по одному частичному статусу.

## Risks / Trade-offs

- Несогласованность представлений → проверить реальный JSON endpoint, service-map Markdown и собранную HTML-строку.
- Лишний объём регрессии → адресная проверка одной связи и имеющихся сводок, без snapshot полного generated документа.

## Ownership and Verification

- Исполнитель владеет `/apps/www/src/data/reglament/full-2026.ts`, существующим тестом данных, `/apps/www/src/lib/reglament/tests/full-public.test.ts`, `/apps/www/src/lib/reglament/markdown.test.ts` и его snapshot.
- Страница калькулятора и controller-тесты принадлежат #173 и не меняются. HTML-потребители и адаптеры остаются без правок.
- Артефакты change и sync/archive ведёт оркестратор. Любое расширение границ сначала возвращается ему.
- Приёмка: адресные тесты, typecheck, сборка, валидация OpenSpec и reviewer всего diff. Обычный деплой; откат возвращает change целиком.
