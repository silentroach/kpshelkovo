# Design

## Context

Мотивация — в [proposal](/openspec/changes/fix-open-status-timeline-geometry/proposal.md). SSR таймлайна передаёт отдельно фактический конец и дневную геометрию, ограниченную моментом сборки. Парсер сохраняет различие, но гидратация предпочитает геометрический конец даже при отсутствии фактического. Один укороченный span используется и для события, и для зелёных промежутков.

Действующие границы — [status-lifecycle](/openspec/specs/status-lifecycle/spec.md) и [ADR-031](/docs/decisions/031-status-incident-lifecycle.md): клиент уточняет только предусмотренные элементы в предусмотренные моменты, без запросов и таймеров.

## Goals / Non-Goals

- Исправить выбор конца в `/apps/www/src/lib/status/timeline.dom.ts`, используя существующую поддержку открытого интервала в `timeline.ts`.
- Не менять SSR-атрибуты, группировку, lazy-loading, начало геометрии, календарь или публичные DTO.
- Случай заданного будущего конца с устаревшей геометрией остаётся вне задачи: он не воспроизведён в #955 и требует отдельной оценки.

## Decisions

- Отсутствие фактического конца означает открытый span независимо от сохранённого геометрического конца. Для заданного конца сохраняется существующий приоритет дневной геометрии с fallback на фактический конец.
- `endMs` передаётся напрямую, включая `undefined`; новый helper или условная сборка optional-объекта не нужны.
- Удаление всех геометрических границ отвергнуто: оно меняет дневное представление завершённых событий. Простой обмен приоритетами двух значений тоже не исправляет открытый случай.
- Проверить настоящий SSR → DOM → lazy-loading путь на разных серверном и клиентском временах. Дополнить существующие короткие DOM-проверки открытого и завершённого интервалов; общий test harness не добавлять.

## Risks / Trade-offs

- Дневные маркеры завершённых событий могут регрессировать → контроль с различающимися фактическим и геометрическим концами.
- Группа с открытой записью может выглядеть завершённой → отдельный короткий сценарий группы; сервер уже оставляет её фактический конец отсутствующим.
- Один DOM fixture без сохранённой геометрии не ловит ошибку → integration regression использует настоящий Astro-компонент и штатное первое ленивое подключение.

## Migration Plan

- Изменение не требует миграции данных. После профильных тестов и ревью синхронизировать specs, архивировать change и открыть PR с `Closes #955`.
- Откат — возврат PR целиком, без изменений данных и инфраструктуры.
