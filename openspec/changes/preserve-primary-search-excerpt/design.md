# Design

## Context

Мотивация — в [proposal](/openspec/changes/preserve-primary-search-excerpt/proposal.md). `resultRow` в `/apps/www/src/components/search/SearchDialog.svelte` заменяет основной excerpt первым якорным. `/apps/www/src/lib/search/client.ts` предварительно исключает безъякорные секции и сортирует якорные по внутренним оценкам Pagefind. UI-тест закрепляет эту подмену.

Решение уже принято в [search](/openspec/specs/search/spec.md), требование «Переход из выдачи сохраняет контекст совпадения»; архитектура — [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md). Delta specs не нужны: `skip_specs: true`.

Документация Pagefind описывает `excerpt` и `sub_results` с отдельными секционными окнами, но не гарантирует равенство основного и секционного excerpt. Исследование production обнаружило подходящий положительный пример для `тариф` и посторонние галерейные excerpts для `асфальт форест` и `фудтрак`. Это не заменяет baseline точной базы.

## Goals / Non-Goals

- Исправить пару показанный контекст/цель перехода, не выбирая собственный «лучший» snippet.
- Сохранить веса, корпус, порядок документов, галереи и механизм подсветки.
- Не менять обработку сетевого отказа #899, склейку #118 и ранжирование длинных документов #122.

## Decisions

- Всегда сохранять основной `excerptHtml`; при его отсутствии оставить существующие `matchContext` и description fallback.
- Подрезультат соответствует основному фрагменту только при равенстве непустых excerpt после существующей нормализации пробелов. Сравнивать до UI-декодирования, сохраняя `<mark>` и entities.
- Учитывать все соответствующие `sub_results`, включая безъякорную секцию. Несколько записей одного URL дают одну цель; разные цели с одинаковым excerpt означают неопределённость и canonical fallback. В частности, canonical-секция и якорь не считаются однозначным якорным совпадением.
- Удалить отбрасывание безъякорных секций и сортировку по внутренним `weighted_locations`/`balanced_score`. Сохранить допустимые URL одного документа, безопасный текст, поисковые `h` и порядок Pagefind. Нынешних типов достаточно; новый DTO не требуется.
- Контекстный заголовок секции добавлять только при выбранном соответствующем якоре; основной заголовок страницы сохранять.
- Нечёткое сравнение, пересечение слов и собственный подсчёт highlights отвергнуты: они превращают исправление в новый ранжирующий алгоритм и могут снова выбрать посторонний контекст.

## Risks / Trade-offs

- Разные окна excerpt сохранят canonical даже для полезной секции → это консервативный fallback; положительный пример совпадающего якоря проверить отдельно.
- Одинаковый текст нескольких секций не локализуется по excerpt → canonical при нескольких целях, включая безъякорную.
- Изменение неверного теста может скрыть регрессию URL/безопасности → сохранить отдельные проверки same-document, `h`, entities, `<mark>` и fallback контекста.

## Migration Plan

- До изменения записать локальный baseline запросов `асфальт форест`, `фудтрак`, `тариф`; после — сравнить на том же корпусе и условиях. Дополнительно проверить длинный документ и Markdown-карту без введения постоянной контентной матрицы.
- После адресных тестов, search-quality, typecheck, подходящей сборки и reviewer архивировать change без изменений основных specs и открыть PR с `Closes #124`.
- Откат — возврат PR целиком; поисковые данные и версия Pagefind не мигрируют.
