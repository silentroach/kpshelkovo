## Context

Мотивация — в [proposal.md](proposal.md). `MapPreviewElement` включает `pinchZoom` только для `PlacePreview`; capture-обработчик wheel переключает `scrollZoom` для Ctrl+wheel. Простое добавление `drag` в один список недостаточно: следующий wheel перезапишет список, а сенсорный ввод может начать двигать карту вместо страницы.

Подход следует [ADR-028](../../../docs/decisions/028-markdown-first-places-map.md), [ADR-034](../../../docs/decisions/034-native-css-architecture.md) и [ADR-039](../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md). Штатный `drag` подтверждён [документацией Яндекс Карт](https://yandex.com/maps-api/docs/js-api/map/index.html) и установленными типами SDK.

## Goals / Non-Goals

- **Goals:** добавить мышиное перетаскивание в существующий режим интерактивного превью, сохранив pinch, прокрутку и lifecycle.
- **Non-Goals:** собственная геометрия drag, сенсорное перетаскивание одним пальцем, новые контролы и независимые комбинации режимов.

## Decisions

- Переименовать внутренний opt-in `pinchZoom` в `interactive`: единственный потребитель включает теперь pinch и mouse drag. Публичных DTO это не касается. Отдельные флаги для комбинаций, которых нет у потребителей, не нужны.
- Использовать штатный `drag` SDK. Перед обработкой нажатия SDK определить тип ввода через capture `pointerdown`: основная кнопка с `pointerType === 'mouse'` разрешает drag, сенсорный ввод оставляет pinch без drag. Это работает и на гибридных устройствах; глобальная проверка fine/coarse pointer недостаточна.
- Wheel-обработчик должен сохранять разрешённые для текущего ввода базовые behaviors и добавлять `scrollZoom` только для Ctrl+wheel. Логику выбора списка держать локально у инициализации одного превью.
- Захват движения и завершение отпусканием оставить SDK; проверить mouseup внутри и за пределами карты. Новые движения без нажатия не должны продолжать drag. Слушатели приложения освобождать существующим `AbortController`; `touch-action: pan-y` сохраняет прокрутку одним пальцем.
- Приёмка — компонентные регрессии и настоящий SDK на локальной production-сборке: удержание/движение/отпускание, последующий pinch и wheel, смена мыши на touch, Astro-переходы и неподвижные фоновые карты. Обязательная проверка после публикации в production не требуется.

## Risks / Trade-offs

- Wheel может сбрасывать drag → единый выбор behaviors и последовательный тест drag → wheel → drag.
- Drag может перехватить touch-свайп на ноутбуке с сенсорным экраном → различать ввод по событию и проверить mouse → touch.
- Отпускание за рамкой может оставить активный жест → проверить с настоящим SDK, не ограничиваться mock-ом и границами контейнера.
