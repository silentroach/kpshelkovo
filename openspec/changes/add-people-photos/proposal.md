# Proposal

## Why

Профили людей сейчас показывают имя, должность и контакты, но не помогают узнать человека в лицо. В [issue #800](https://github.com/silentroach/kpshelkovo/issues/800) предложено добавить портреты; для части существующих профилей фотографии уже опубликованы на [сайте ОК Комфорт](https://ok-komfort.ru/company/).

## What Changes

- Добавить необязательную фотографию в данные профиля: публичный media URL, фактические размеры и необязательный источник с названием и ссылкой.
- Показывать портрет справа вверху страницы человека, сохраняя полный кадр. На узком экране размещать его после имени и должности, перед контактами и описанием. Размер подобрать по вёрстке, ориентир — около 220 px на широком экране.
- Показывать указанный источник под фотографией. Для снимков с сайта компании использовать подпись «Фото: ОК Комфорт» со ссылкой на страницу компании.
- Подготовить и опубликовать в нашем S3 шесть портретов для существующих профилей; список и исходные URL зафиксированы в `design.md`.
- Добавить фотографию и источник в Markdown-карточку и JSON-ленту людей, URL фотографии — в структурированные данные `Person.image`; синхронизировать описание публичного формата.
- Закрепить правила публикации портретов: раздел-владелец `people`, неизменяемые датированные ключи и подготовленные JPEG без метаданных.

Границы изменения: отдельные страницы существующих людей и их публичные представления. Общий HTML-каталог людей, новые профили, фотографии рядом с упоминаниями, галерея и изменение социальных превью в объём не входят. Профили без фотографии остаются текстовыми, без заглушек.

Владелец согласовал перечисленные решения и запросил PR с change для чтения до реализации. На этом этапе разрешены подготовка и публикация плановых артефактов; разрешение реализации требуется после их просмотра.

## Capabilities

### New Capabilities

- `people-photos`: необязательный портрет в карточке человека, атрибуция источника, стабильный публичный media URL и согласованное представление фотографии в Markdown, JSON и структурированных данных.

### Modified Capabilities

Нет. Существующая `place-card-presentation` служит ориентиром расположения, её требования не меняются.

## Impact

- Данные и HTML: `apps/www/src/data/people/`, raw-схема, доменные типы и mapper в `apps/www/src/lib/people/`, страница `apps/www/src/pages/people/[slug]/index.astro`.
- Публичные форматы: `/people/<slug>/index.md`, `/people/data/people.json`, JSON Schema, OpenAPI, описание раздела для агентов и JSON-LD профиля. Поле фотографии добавляется как необязательное, существующие поля и URL сохраняются.
- Хранилище: новые объекты в `kps-public` под `people/<slug>/<snapshot-date>/portrait.jpeg`; на сайте используются только ссылки `https://media.kpshelkovo.online/...`.
- Рабочие правила: новый ADR о портретах, актуализация документации хранилища и проектного `public-media-publisher`, инструкций данных людей и дизайн-гайда.
- Новых зависимостей и клиентского JavaScript для портретов не требуется. При реализации проверяется разрешение media-origin в действующей CSP.
