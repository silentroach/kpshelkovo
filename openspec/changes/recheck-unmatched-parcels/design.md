# Design

## Context

См. [proposal.md](proposal.md). Существующий импорт в `apps/www/src/lib/parcels/genplan-page.ts` извлекает `window['houses_data']` и сохраняет исходную кадастровую строку, статус и цену; площадь в рабочем JSON не хранится. Исследовательская [процедура](../../../docs/parcel-updates.md) ошибочно предписывает брать площадь из статичного `<p class="square">`. Для R63 в текущем HTML это 9,73 сотки, а `square_value` встроенного каталога, обновлённая метка и исследовательский снимок от 22 сентября дают 9,25 сотки; в принятой геометрии НСПД контур `:2893` имеет площадь 925 м². Аналогичное расхождение статичной подписи и каталога есть у R65.

В [PR #824](https://github.com/silentroach/kpshelkovo/pull/824) после первого разбора перечислен остаток 361 обозначение (42 с указанными номерами, которых нет в снимке, и 319 без номера), при сохранении точных дат снимков и причин. Эти числа — точка сверки, не требование к результату нового прохода. Связи по-прежнему принадлежат `matches.yaml`, а действующие объекты — принятому НСПД-снимку.

[ADR-041](../../../docs/decisions/041-parcel-records-and-exact-search.md) требует подтверждённой редакционной связи и запрещает угадывать её при импорте. [ADR-013](../../../docs/decisions/013-raw-domain-public-data-boundary.md) сохраняет проверку данных на входе. Долговременный контракт уточнён в [delta spec](specs/parcel-updates/spec.md).

## Goals / Non-Goals

**Goals:**

- Исключить ошибку выбора площади в исследовании при расхождении статичного HTML с данными генплана.
- Дать воспроизводимую оценку локальных невязок рисунка, кадастровых меж и площадей, не превращая её в автоматическую эвристику импорта.
- Повторно проверить прежний остаток и записать только установленные связи, включая R63.

**Non-Goals:**

- Выводить из визуальной связи официальную историю перенумерации исходного кадастрового номера.
- Массово создавать участки там, где в НСПД пока присутствуют лишь общие земли, или связывать два участка по одной близкой площади.
- Добавлять `square_value` в рабочую модель предложений ради разового исследования либо строить постоянный GIS-инструмент.

## Decisions

### 1. Различать три представления площади

При исследовании получить из принятой страницы встроенный `houses_data`: идентификатор, `cadastral_number`, `square_value` и дату получения. Проверить нужные значения Zod, не копируя персональные поля. Статичный `<p class="square">` и видимую после загрузки подпись считать отдельными представлениями, сверять с каталогом по `id`. Если они противоречат, для сравнения с НСПД брать `square_value` каталога, который управляет обновлением метки; записывать расхождение и его происхождение, а не сообщать старую подпись как актуальную площадь. Площадь НСПД брать отдельно из принятой геометрии. При отсутствии или непригодности `square_value` выяснить актуальное значение по источнику либо не использовать площадь как положительное основание связи.

Альтернатива — добавить поле в штатный генпланный snapshot — неоправданна: импорт не использует площадь для статуса, цены или геометрии, а проблема возникает только в ручном пространственном разборе. Защита — исправленная инструкция и проверка примера с противоречащими представлениями при повторном исследовании.

### 2. Оценивать совпадение участка целиком, а не абсолютное наложение пикселей

Перепроверить текущие изображения, CSS и параметры привязки, разделить опорные и независимые локальные контрольные участки по существующей процедуре. На увеличении нескольких соседних участков показывать исходный JPG, контуры НСПД и метки; сравнить последовательность, форму и межи участков, примыкание к дороге, уже связанные коды и возможные раздел/объединение. Небольшое смещение нарисованных границ относительно геометрии — ожидаемая невязка двух подложек, а не автоматический отказ. Если смещение меняет выбор между соседними объектами, искать дополнительные контрольные точки или оставить случай нерешённым. Поправка визуализации Яндекс Карт к исходной геометрии не применяется.

Разница площади менее одной сотки — ориентир для индивидуального допуска при однозначном совпадении границ и окружения, не автоматический порог. Даже точное совпадение площади не доказывает связь при нескольких кандидатах, общих землях или признаках раздела; большие расхождения требуют отдельного объяснения. Для R63 пример сочетает единственный контур между прямо связанными соседями и совпадение площади `9,25 сотки = 925 м²` по данным каталога.

Альтернатива — выбрать полигон по попаданию метки или ближайшему центру — не даёт защиты от соседнего участка и ошибки привязки, поэтому не используется.

### 3. Повторный проход по всему остатку без обещания заполнить карту целиком

Получить текущий остаток штатным разрешением связей и сверить с перечнем PR: случаи с исходным номером вне снимка и без номера, четыре части, отсутствие HTML-меток и конфликты. Если живые данные изменились, принять полную партию источника по действующей процедуре до нового анализа. Сначала проверить R63 и прочие одиночные случаи с небольшой невязкой или подозрением на устаревшую подпись; затем оставшиеся группы, включая крупные общие контуры. Для каждого кода указать связь с местными контрольными точками и объяснением площади/границ либо оставить проверяемую причину неопределённости и недостающее свидетельство. Не переоткрывать без причины уже установленные соответствия; проверять их, если новый источник вступает с ними в конфликт.

Подтверждения записывать в `matches.yaml`, а затем применять штатным импортом с повторным запуском для проверки идемпотентности. Изображения и временный HTML наложения остаются исследовательскими артефактами вне набора участков; в PR показывать итоги и читаемые увеличения для ручной приёмки. Архив прежнего change сохраняет фактический результат первого прохода.

## Risks / Trade-offs

- Встроенный каталог и HTML могут снова противоречить друг другу → фиксировать оба значения и не приписывать кадастровому источнику значение застройщика.
- Приближённая привязка может попасть на соседнюю межу → независимый контроль района, увеличения и проверка порядка соседей; неоднозначность остаётся нерешённой.
- У групп на общих землях отдельные контуры могут отсутствовать → не производить номера и не обещать устранить весь остаток без нового проверенного снимка.

## Migration Plan

Изменить процедуру, перепроверить остаток и применить только подтверждённые связи существующим импортом. В случае ошибочной редакционной связи вернуть соответствующую запись реестра и результат импорта через Git; кадастровые координаты и прежний архив не менять.
