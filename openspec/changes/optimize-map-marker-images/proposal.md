# Proposal

## Why

При холодном открытии `/map/` семь PNG-маркеров передают 200 173 байта, больше собственного JavaScript страницы. [Issue #887](https://github.com/silentroach/kpshelkovo/issues/887) предлагает сократить этот трафик без изменения рисунков, поведения и прогрессивного запуска карты; lossless WebP уже даёт проверенную экономию 29,7%.

## What Changes

- Подготовить lossless WebP шириной 72, 120 и 144 px для каждого маркера, сохранив редакционные `*-source.png` без изменений. Полноразмерные варианты сохраняют исходные размеры и декодированные RGBA-пиксели.
- Использовать нативный `srcset` с одинаковым фиксированным `sizes` во всех потребителях общего реестра: обзорная карта, превью места, ближайшие места и визуальный каталог. Размер выбора рассчитан на максимальную графику, выражен в `rem` и не обновляется вслед за zoom.
- Сохранить отображаемые размеры, пропорции, центрирование, тени, статусы, ссылки и взаимодействие с картами.
- Проверить качество и суммарные загрузки; если адаптивность не проходит приёмку, использовать только полноразмерные lossless WebP, без дальнейшего подбора вариантов.
- Обновить необходимые импорты, экспорты, проверки, документацию runtime-ресурсов и отчёты клиентских бандлов.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- Нет изменений требований. Действующие контракты [site-maps](/openspec/specs/site-maps/spec.md), [place-card-presentation](/openspec/specs/place-card-presentation/spec.md) и [place-nearby-navigation](/openspec/specs/place-nearby-navigation/spec.md) сохраняются. Используется `skip_specs: true`: формат растра и набор разрешений — детали реализации, а не новые возможности продукта.

## Impact

- Затронуты `packages/ui/src/markers`, экспорты `packages/ui/package.json`, потребители в `apps/www/src/components/places` и `apps/www/src/pages/map/[slug]/index.astro`, соответствующие тесты и визуальный каталог UI.
- Используется существующая доставка хешированных статических ресурсов. Новый runtime-конвертер, зависимости приложения, PNG-fallback и параллельные запасные запросы не нужны.
- Не меняются рисунки, подложка, слои, движок, шрифты, момент запуска и первый экран карты; lossy-кодирование исключено.
- Приёмка проводится на production-сборке, включая сеть и браузер; отдельная проверка уже опубликованного production-сайта не является условием завершения. Dev-сервер не используется для оценки production-бандла.
- Сейчас публикуется только план в draft PR. Реализация продолжится в отдельной сессии на той же ветке после явного разрешения владельца на подготовленные артефакты. До реализации issue не закрывается, change не архивируется.
