# Design

## Context

См. [proposal.md](proposal.md). `editorial-map-element.ts` и интерактивное `map-preview.ts` используют общий `map-gestures.ts`: `drag` включается перед `pointerdown` только для мыши, `pinchZoom` остаётся для touch, а `touch-action: pan-y` сохраняет прокрутку страницы. Фоновые превью не подключают этот helper. Подход продолжает [ADR-039](../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md) и [ADR-034](../../../docs/decisions/034-native-css-architecture.md).

В локальном пробнике на странице статьи с настоящим SDK: два пальца при одном `pinchZoom` не сдвинули маркер; разрешение штатного `drag` после появления второго активного касания сдвинуло его на 48 px без прокрутки страницы. Одиночное касание не переместило карту, вертикальный свайп прокрутил страницу. Это подтверждает технический путь в Chromium, но не заменяет проверки после реализации на целевых устройствах.

## Goals / Non-Goals

**Goals:** использовать штатный жест SDK для двухпальцевого перемещения без нового интерфейса, сохраняя действия мыши, трекпада и прокрутку статьи.

**Non-Goals:** собственный расчёт сдвига карты, изменение поведения статичных превью, изменение resize-правил Markdown-карты и места.

## Decisions

- Отслеживать активные touch `pointerId` внутри экземпляра интерактивной карты. На втором касании разрешать штатные `drag` и `pinchZoom`, на первом — только `pinchZoom`; мышиная основная кнопка сохраняет нынешний `drag`. На отпускании/отмене касания и при потере фокуса возвращать `pinchZoom`, когда пальцев меньше двух. Очистка слушателей остаётся в существующем `AbortController`. Это не позволит одиночному горизонтальному свайпу двигать карту, что происходит при постоянном `drag` даже с `touch-action: pan-y`.
- Сохранить `touch-action: pan-y` и существующий capture-переключатель `wheel`: CSS продолжает отдавать вертикальный свайп странице, а SDK обрабатывает одновременное движение двух пальцев. Не включать `drag` безусловно и не добавлять кнопку режима или overlay.
- Применить правило в общем helper-е только к его существующим интерактивным потребителям; фоновые превью с `behaviors: []` остаются неподвижными. Для места сохранить текущий повторный fit на resize, для Markdown — выбранный читателем кадр после ручного жеста.
- Дополнить принятое уточнение о gesture в ADR-039 при реализации, чтобы действующее архитектурное описание не утверждало «touch только pinch».

## Risks / Trade-offs

- Второй палец может появиться или исчезнуть во время движения → разрешать drag по числу активных touch-контактов, сбрасывать при отпускании любого из двух, `pointercancel` и `blur`; проверить переходы touch → mouse и жест с началом на маркере.
- Настоящий SDK и мобильный браузер могут иначе разрешать одновременные `drag`/`pinchZoom` → проверить двухпальцевый сдвиг, pinch, однопальцевую прокрутку и отсутствие случайного перехода по ссылке на локальной сборке с SDK, а не полагаться только на mock-тесты.
