# Design

## Context

Мотивация и область описаны в [proposal](/openspec/changes/mobile-breadcrumbs/proposal.md). Владелец выбрал вариант «Тихий фон» в локальном `/breadcrumbs-preview.html` 8 октября 2026 года. Это согласование визуального решения; разрешение на реализацию подготовленного change запрашивается отдельно.

В [Breadcrumbs](/packages/ui/src/Breadcrumbs.astro) уже есть скрытие текущей страницы до `40rem`, но следующее правило `.breadcrumbs-item { display: flex }` его перекрывает. Корневые страницы с единственным родителем «Главная» скрывают весь `nav`. Компонент формирует один список и schema.org microdata, поддерживает `linkLast` и промежуточные подписи без ссылки.

Потребители находятся в разных обёртках: обычный `ui-page-header`, профиль человека, карточка места, сравнение поселков и новость с обложкой или без неё. Общий компонент отвечает за путь, а геометрию страницы определяет приложение. Границы CSS следуют [ADR-034](/docs/decisions/034-native-css-architecture.md); отдельный ADR для этой правки не нужен. Дизайн-документ нужен из-за общего компонента и нескольких видов заголовков.

## Goals / Non-Goals

**Goals:**

- Перенести выбранный вид на все текущие страницы с крошками и сохранить полную цепочку для широкого экрана и структурированных данных.
- Отделить правила списка от app-owned геометрии полноширинной полосы, используя SSR-разметку и CSS.
- Сделать переносы и родительские переходы устойчивыми к длинным названиям, масштабу текста и отключённому JavaScript.

**Non-Goals:**

- Перестройка иерархии разделов, редактура названий, изменение URL или координат памятника.
- Изменение широкого представления, основной навигации и содержимого страниц.
- Скролл крошек, раскрывающиеся родители, пользовательский выбор оформления и новые анимации.

## Decisions

### 1. Точные параметры выбранного варианта

- Мобильный режим: ширина экрана меньше `40rem` (640 CSS px при стандартном базовом размере). От этого порога полная горизонтальная цепочка сохраняет действующее оформление.
- На телефоне скрыты главная и текущая страница, включая текущую страницу с `linkLast`. Остальные элементы сохраняют порядок и прежние ссылки. Промежуточная подпись без URL остаётся подписью.
- Первая видимая крошка без стрелки и отступа. Вторая и все последующие начинаются на новой строке с одинаковым отступом `0.75rem` (12 px), без нарастания. Перед ними сохранён декоративный знак `›`.
- Название переносится под собственным текстом; стрелка стоит у первой строки и не входит в доступное имя.
- Fira Sans 400, размер `0.875rem`, межстрочный интервал `1.25rem`. Вертикальные поля ссылки `0.125rem` дают строке с однострочным названием высоту 24 px. Уменьшать размер текста ради компактности не нужно.
- Цвет ссылок в покое: действующий `--color-text-muted`, `oklch(46% 0.02 135)`. При hover и видимом фокусе использовать основной цвет ссылки и подчёркивание; клавиатурный фокус должен иметь отчётливый контур.
- Подложка: `oklch(98% 0.003 125)`, полноширинная, сразу под нижней границей меню. Внутренние поля сверху и снизу по `0.75rem` (12 px). Без рамки, тени и скругления.
- Первая ссылка совпадает по горизонтали с заголовком. После полосы до заголовка сохраняется интервал `1.25rem` (20 px) обычного стека заголовка. Страницы с отдельным hero сохраняют свою композицию заголовка ниже полосы.
- Пустой мобильный путь не создаёт подложку, поля или пустой элемент стека. На телефоне главная остаётся доступна через название сайта в шапке.

Для трёх однострочных родителей полоса занимает 96 px вместо 104 px у исследованного зелёного варианта. Эта величина описывает пример, а не ограничивает высоту длинных названий.

### 2. Один список, адаптивная видимость через CSS

Сохранить один SSR-список общего компонента. Корректно отметить главную, текущий пункт и первый мобильный элемент; убрать конфликт порядка правил, который сейчас возвращает текущую страницу на телефон. Полная цепочка остаётся в microdata, а скрытые элементы исключаются из мобильного фокуса и accessibility tree через `display: none`.

Не заводить отдельные мобильные данные и вторую копию навигации. Это сохраняет единый порядок, `linkLast`, позиции schema.org и исключение крошек из Pagefind. Контракты перехода к месяцу и дню в [events-calendar](/openspec/specs/events-calendar/spec.md) и существующих родителей в [knowledge-base](/openspec/specs/knowledge-base/spec.md) остаются действующими.

### 3. Полноширинная полоса принадлежит оформлению приложения

Scoped CSS компонента владеет списком, переносами, стрелками и видимостью. Фон передаётся из app-owned токена `--color-breadcrumb-surface` с выбранным значением; токен и раздел хлебных крошек в [дизайн-гайде](/docs/design/design-code-shelkovo.md) добавляются одновременно с реализацией.

Ширину до краёв экрана и примыкание к меню обеспечить в текущих обёртках заголовков через общие site-level правила и минимальные локальные поправки. На обычной странице полоса компенсирует внешние и внутренние поля header, а её текст сохраняет прежний inset. Проверить начало полосы относительно меню, не переносить отрицательные поля макета без проверки конкретной обёртки.

У новости с обложкой крошки находятся внутри `.news-hero__layout`, у новости без обложки в `.news-article-breadcrumbs`; у профиля и карточки места есть свои контейнеры. Эти случаи входят в реализацию. Подложка должна быть непрозрачной над фотографией и не перекрывать заголовок, портрет, карту или действия. Общий layout, маршруты и данные не требуют отдельного механизма переноса DOM, измерения ширин или клиентской гидратации.

### 4. Почему выбран этот вид

- Простое скрытие крайних пунктов устраняет повтор заголовка, но оставляет случайные переносы длинного пути.
- Горизонтальную прокрутку владелец отклонил. Ссылка только на ближайшего родителя убирает полезные переходы к другим уровням, например сразу к месяцу мероприятия.
- Нарастающий отступ заменён одинаковым по решению владельца: следующие строки сохраняют доступную ширину.
- Зелёная полноширинная заливка с полями 16 px слишком выделяла вспомогательную навигацию. Выбран почти нейтральный фон, приглушённые ссылки и симметричные поля 12 px.
- Вариант без подложки остаётся исследованной альтернативой; для реализации выбран именно «Тихий фон». Переключатели из макета на сайт не переносятся.

## Risks / Trade-offs

- Полноширинный фон может выйти за viewport или оставить зазор под шапкой в нестандартной обёртке. Проверить реальные страницы всех затронутых разделов, включая news hero, профиль, место и сравнение; не маскировать переполнение глобальным `overflow-x: hidden`.
- Вертикальный путь занимает место, пропорциональное числу родителей. Сохранить согласованную раскладку; уменьшение контраста фона не заменяет читаемость текста и доступность ссылок.
- Исчезновение самого `nav` может оставить пустую обёртку и gap на странице-разделе. Проверять весь верх страницы, а не только видимость списка.
- Более спокойные ссылки всё ещё должны быть различимы. Проверить контраст не ниже 4.5:1, видимый фокус и реальные переходы с клавиатуры.
- Существующий визуальный тест проверяет скрытие корневой цепочки, но не скрытие текущего элемента вложенной страницы. Добавить адресную проверку этой регрессии и геометрии нескольких родителей; сохранение microdata проверять отдельно от внешнего вида.
- Печатные представления `/kb/` и `/news/` продолжают скрывать навигацию и её фон по [content-print](/openspec/specs/content-print/spec.md).

## Migration Plan

По просьбе владельца сначала открывается draft PR с планом для ревью. После согласования реализация продолжается в отдельной сессии в ветке `design/980-mobile-breadcrumbs` и дополняет тот же PR компонентом, нужными обёртками, токеном, дизайн-гайдом, тестами и синхронизированной спецификацией.

Макет сохранён в [preview.html](/openspec/changes/mobile-breadcrumbs/preview.html) рядом с change; публичная копия из `apps/www/public/breadcrumbs-preview.html` удалена при подготовке планового PR. Если для повторного просмотра она создаётся заново, её нужно убрать перед завершением реализации. Контекст следующей сессии и результаты исследования — в [handoff.md](/openspec/changes/mobile-breadcrumbs/handoff.md). Отдельной миграции данных и production-приёмки нет. Откат возвращает весь PR.
