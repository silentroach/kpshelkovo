# Proposal

## Why

Обозначение E35 в Шелково Ривер осталось вне карты: генплан даёт одну позицию площадью 10 соток и исходный номер `50:33:0010101:2482`, которого нет в принятом снимке НСПД; на этом месте находятся два отдельных контура по 500 м². Действующая модель допускает несколько обозначений для одного кадастрового участка, но не одно обозначение для нескольких участков. Исходная задача разбора несопоставленных обозначений — [#823](https://github.com/silentroach/kpshelkovo/issues/823); этот change отдельно расширяет модель для установленного случая E35.

## What Changes

- Разрешить подтверждённую связь одной позиции генплана с несколькими **самостоятельными** нынешними кадастровыми участками. Хранить номера, площади и исходные геометрии каждого без вымышленного общего кадастрового номера; одного попадания метки и совпадения общей площади для подтверждения недостаточно.
- Показывать такую позицию на карте одной подписью и несколькими контурами, выделять их вместе при выборе или переходе по коду. На время выделения показывать подсказку «Разбит на несколько участков». Поиск возвращает одну строку обозначения с переходом к этой группе контуров.
- На повторном импорте проверять наличие всех подтверждённых контуров и отсутствие пересечений связей; не показывать усечённую группу при потере одного контура или изменении исходной ссылки. Сведения предложения генплана относить к позиции целиком, не дублируя цену и статус как отдельные предложения по каждому кадастровому номеру.
- После проверки свидетельств E35 сохранить связь с обоими контурами через реестр и применить её штатным обновлением. Уточнить определения в глоссарии и архитектурное решение об идентичности редакционной записи.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `parcel-records`: запись с кодом генплана может ссылаться на несколько отдельных кадастровых участков с сохранением их индивидуальной идентичности и источника сведений о предложении.
- `parcel-updates`: проверка и повторное применение связи одного обозначения с несколькими нынешними контурами, поведение при неполной группе.
- `parcel-map`: одна подпись, одна ссылка и совместное выделение всех контуров подтверждённой позиции.
- `search`: один результат для позиции с несколькими контурами вместо результатов, выдаваемых за один кадастровый участок.

## Impact

- Затрагиваются реестр подтверждений и обновлятор `apps/www/src/lib/parcels/`, Markdown-записи в `apps/www/src/data/parcels/`, публичный геометрический feed и индексация обозначений; текущие записи с одним кадастровым номером и формат публичной ссылки `/map/?p=<полный-код>` сохраняются.
- Долговечные определения и причины модели потребуют уточнения `GLOSSARY.md` и [ADR-041](../../../docs/decisions/041-parcel-records-and-exact-search.md). Для новых контуров используются только уже принятые снимки НСПД; временное наложение остаётся исследовательским артефактом.
- Приёмка до PR: OpenSpec-валидация, проверка E35 и регрессий одиночных участков, typecheck, тесты, сборка и ревью полного diff. Проверка на production для завершения change не требуется.
