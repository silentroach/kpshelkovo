# Design

## Context

См. [proposal.md](proposal.md). Сегодня `map-frame.css` явно импортируется редакционной картой и страницей места, но использует глобальные классы `ui-*` без слоя. [ADR-034](../../../docs/decisions/034-native-css-architecture.md) оставляет `ui-*`-примитивы в общем слое `primitives`, а unlayered CSS — локальным компонентам. Простое помещение текущего файла в `@layer primitives` уже проверялось на собранной странице: CSS карты загрузился раньше объявления общего порядка слоёв, и позднее правило `reset` обнулило границу и padding. При этом редакционный CSS уже подключается отдельно от foundation, в том числе из клиентского модуля карты.

## Goals / Non-Goals

**Goals:** сохранить явную зависимость обоих представлений от одного файла стилей и прежний вид блока; убрать некорректное имя `ui-*` у feature-owned правил; замкнуть нижние углы панели внутри рамки; объяснить исключение из ADR-034 будущим авторам.

**Non-Goals:** менять общий порядок слоёв, поведение картографического SDK, состав исходных материалов или превращать стиль карты в примитив для любого `figure` сайта.

## Decisions

- Считать рамку и подпись стилем функции «встроенная карта с подписью», а не общесайтовым `ui-*`-примитивом. В `apps/www/src/components/maps/map-frame.css` заменить классы на opt-in `map-frame` и `map-frame__caption`; правила оставить unlayered, но ограничить этими классами. `editorial-map.css` продолжит импортировать файл через CSS `@import`, страница места — через Astro frontmatter. Генератор редакционной карты и разметка места указывают те же классы; их собственные высота, действия, атрибуция и особые стили не переезжают. Разделять общий CSS через Sass-миксин означало бы новую зависимость и повтор скомпилированных правил, а перенос в `global.css` убрал бы видимый импорт и подключил стиль ко всем страницам.
- У `map-frame__caption` скруглить только нижние углы по внутреннему радиусу рамки с учётом границы `1px`. Не переносить локальную обрезку `.place-map` в общий CSS: карточка места уже обрезает фигуру, а редакционная карта не должна рисковать обрезкой доступного фокуса и элементов SDK. Отсутствие подписи сохраняет существующее скругление самой карты.
- Новый ADR-042 зафиксирует узкую границу относительно ADR-034: app-owned feature CSS может быть unlayered, если он явно подключён каждым потребителем, применяется только по opt-in классу и не объявляет reset, общие стили тегов или site-level `ui-*` API. Он намеренно сильнее layered foundation; если блоку потребуются переопределения в глобальных слоях, решение о владении следует пересмотреть, а не наращивать специфичность. ADR-034 получит ссылку на уточнение, индекс ADR — новую запись. Не вводить отдельный `layers.css`: ради одного feature-файла он усложняет граф импортов и увеличивает число копий объявления порядка слоёв в CSS-чанках.
- В архивном `align-place-map-caption/design.md` оставить исходные решения и завершённые задачи как историю, добавив короткую отметку о последующем изменении со ссылкой на новый change/ADR. Не выдавать последующий запрос на переиспользование за часть первоначально согласованного плана. Дизайн-гайд обновить только в части имён общих классов.

## Risks / Trade-offs

- **Unlayered feature-правила приоритетнее всех layered правил** → сохранить узкие opt-in селекторы; местные отличия задавать владельцам карт, а не неявными overrides в `content` или `primitives`. Новое исключение не распространяется на общесайтовый CSS.
- **CSS импортируется двумя путями и может повториться в итоговых чанках** → сравнить актуальные YAML-отчёты бандлов и сетевые запросы ключевых страниц до/после; не добавлять зависимость только ради дедупликации нескольких деклараций.
- **Изменение радиуса способно затронуть подпись-ссылку и углы без подписи** → проверить в браузере собранные карточки с адресом и без, новость и KB с редакционной картой, узкую и широкую ширину, состояние без JavaScript, видимый фокус, высоту карты и атрибуцию. Сверить рассчитанные стили, а не считать успешную сборку визуальной приёмкой.
