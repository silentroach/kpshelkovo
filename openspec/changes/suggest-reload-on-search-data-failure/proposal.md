# Proposal

## Why

После сетевого отказа данных Pagefind кнопка «Повторить» может оставаться бесполезной даже при восстановленной сети: движок сохраняет неуспешную загрузку в своём кеше. В [#899](https://github.com/silentroach/kpshelkovo/issues/899) владелец выбрал для этого редкого случая понятную подсказку обновить страницу вместо усложнения восстановления.

## What Changes

- При ошибке первой выдачи и догрузки результатов показывать сообщение об ошибке с предложением обновить страницу средствами браузера; убрать обе кнопки «Повторить».
- При отказе догрузки сохранять уже показанные результаты и доступные ссылки.
- Объявлять подсказку вспомогательным технологиям и сохранять закрытие диалога с возвратом фокуса.
- После восстановления сети и обычного обновления страницы поиск должен работать при новом открытии. Отдельная кнопка обновления, автоматическая перезагрузка и сохранение запроса между обновлениями не требуются.
- Уточнить контракт восстановления и заменить проверки, обещающие локальный повтор поисковой операции.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `client-load-recovery`: восстановление поиска после отказа данных через обычное обновление страницы; локальный повтор данных сравнения и API карты сохраняется.

## Impact

- Основная правка — [SearchDialog.svelte](/apps/www/src/components/search/SearchDialog.svelte) и его [компонентные тесты](/apps/www/src/components/search/tests/SearchDialog.test.ts).
- Проверка настоящего сетевого отказа fragments и последующего восстановления — на локальной production-сборке с настоящим индексом Pagefind. Приёмка после публикации на production не требуется.
- Изменение ограничено состояниями ошибок поисковых данных. Движок, его версия, кеши, правила индексирования и релевантность, обработка ошибки загрузки самого интерфейса, сравнение и карта не меняются.
