# Design

## Context

Мотивация и уточнённый объём — в [proposal](/openspec/changes/remove-legacy-compare-host/proposal.md). [ADR-033](/docs/decisions/033-integrated-tariff-comparison-section.md) закрепляет сравнение как часть единого приложения с общей публикацией.

В текущем дереве CI загружает и устанавливает третий site-конфиг. Он содержит редиректы сравнения, использует отдельный ACME webroot и общий сертификат основного сайта. Специализированный скрипт установки уже не вызывается workflow, но остаётся в репозитории. Разрешение установки через общий helper сохранено в sudoers, адрес — в job summary; README описывает редиректы как действующие.

Владелец сообщил, что production-сервер очищен, и исключил DNS из задачи. Это исходные условия плана; агент не проверял состояние сервера.

## Goals / Non-Goals

**Goals:**

- Следующий deploy устанавливает только конфиги основного сайта и media; `www`-алиас остаётся частью основного конфига.
- Исходники и документация больше не содержат прежнего доменного имени в кириллице или punycode.

**Non-Goals:**

- Управление DNS, сертификатами и файлами production-сервера, изменение приложения сравнения и общей политики обработки неизвестных хостов.

## Decisions

### Удалить поддержку из существующего deploy-потока

Удалить `/ops/nginx/sravni-shelkovo.conf` и `/ops/nginx/deploy-sravni-shelkovo.sh`. Из `/.github/workflows/ci.yml` убрать загрузку конфига, установку, его временный файл в `trap` и прежний адрес в summary. Из `/ops/nginx/deploy-nginx.sudoers` убрать только разрешение установки этого site-конфига.

Существующие общие helpers остаются способом установки основных конфигов: они уже выполняют `nginx -t` перед reload. Полный отказ от старого site-конфига соответствует решению владельца; сохранение конфигурации ради редиректа или заглушки продолжило бы обслуживание отдельного домена. Одноразовый автоматический механизм очистки не нужен: сервер очищен владельцем.

### Описать действующие адреса

В разделе деплоя `/README.md` перечислить основной сайт, `www.kpshelkovo.online` как редирект на него и media-origin. В результате CI оставить основной сайт и media-origin как самостоятельные точки входа. Сравнение относится к основному сайту по действующему адресу.

Поиск по всему отслеживаемому дереву на этапе планирования нашёл прежнее доменное имя только в удаляемом nginx-конфиге и summary workflow. В README найдено описание старого compare-домена без адреса. Проверка после правок должна подтвердить отсутствие обеих форм доменного имени во всём итоговом дереве. План содержит пути удаляемых файлов, но не воспроизводит доменное имя. Историю Git переписывать не требуется.

### Проверить изменённый deploy и сохранность раздела

Разобрать YAML workflow и проверить shell-синтаксис изменённого шага; сверить оставшиеся привилегированные команды с sudoers. По diff подтвердить, что конфиги оставшихся хостов и общий deploy-helper сохранены, включая проверку nginx перед reload. Локальные `nginx`, `actionlint` и `shellcheck` при подготовке плана не обнаружены; production-доступ для их запуска не требуется и не запрашивается.

Выполнить `pnpm build` и разово проверить в результате HTML, Markdown и JSON сравнения по существующим путям под `/815/compare/`. Новые постоянные smoke-тесты не нужны. Структуру документов проверяет `pnpm openspec:validate`; итоговый diff проходит проектное ревью.

## Risks / Trade-offs

- Следующий deploy может восстановить удалённый на сервере сайт, если останется его установка в CI → удалить загрузку и вызов helper одновременно с конфигом и разрешением sudo.
- Общий сертификат нужен оставшимся хостам → изменение ограничено репозиторием, ссылки на сертификат в действующих конфигах сохраняются.
- Возврат всей прежней версии workflow снова включит старый site-конфиг → при возможном откате сохранять исключение этого шага; повторное подключение домена требует отдельного решения владельца.

## Migration Plan

После согласования сохранить артефакты в рабочей ветке и связать change с issue. Выполнить правки и локальную приёмку, синхронизировать основную спецификацию и архивировать change, затем открыть PR с `Closes #1141`. После merge обычный CI использует сокращённый список конфигов. Дополнительная серверная миграция не требуется по сообщению владельца.
