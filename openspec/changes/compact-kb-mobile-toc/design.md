# Design

## Context

Причина изменения и согласованный охват описаны в [proposal](/openspec/changes/compact-kb-mobile-toc/proposal.md). [Выбранная примерка](/openspec/changes/compact-kb-mobile-toc/preview/README.md) сохраняет реальную страницу и меняет только оболочку TOC.

Общий пакет строит оглавление из заголовков в `/packages/markdown/src/toc.ts`. Затем app-level `transform` в `/apps/www/src/lib/markdown/render.ts` получает подготовленное дерево. Страница `/apps/www/src/pages/kb/[...slug].astro` владеет оформлением KB; её текущий breakpoint двух колонок — `48rem`.

Действующие [knowledge-base](/openspec/specs/knowledge-base/spec.md) и [дизайн-гайд](/docs/design/design-code-shelkovo.md#оглавление-базы-знаний) требуют всегда открытого оглавления. Владелец разрешил пересмотреть это правило и выбрал новую мобильную композицию. Требование заменяет delta этого change; гайд обновляется при реализации.

Границы слоёв сохраняют [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md), [ADR-034](/docs/decisions/034-native-css-architecture.md) и [ADR-043](/docs/decisions/043-author-controlled-markdown-toc.md).

## Goals / Non-Goals

**Goals:**

- Выдать правильное начальное состояние статическим HTML/CSS, без перескока от длинного списка к короткой строке после загрузки JavaScript.
- Использовать готовое дерево оглавления, сохранив один редакционный источник ссылок и заголовков.
- Сохранить нативную клавиатурную семантику раскрытия и работу прямых якорей.

**Non-Goals:**

- Прилипающая навигация, плавающая кнопка возврата, автоматическое сворачивание после перехода и хранение состояния между страницами.
- Новый синтаксис Markdown, ручные оглавления или порог длины для отдельных документов.
- Изменение шрифтов сайта, заголовков документа, хлебных крошек и текста источников.

## Decisions

### 1. Компактная строка на всех страницах KB

До `48rem` используется выбранная композиция:

- Отступы слева и справа совпадают с полями текста. Фон прозрачный; верхняя и нижняя границы по 1 px используют `border`.
- Вертикальные поля — `0.5rem`; нажимаемая область строки — не менее `2.75rem`. При обычном размере текста общая высота закрытого блока получается 62 px; это следствие отступов, а не фиксированная высота.
- «Содержание»: Fira Sans 600, `1.0625rem`, line-height `1.5`, основной цвет текста.
- «Показать» / «Скрыть»: Fira Sans 400, `0.875rem`, line-height `1.5`, цвет `primary`, рядом небольшой шеврон состояния.
- Вся строка является одним управлением. Шеврон декоративный; доступное состояние обеспечивает нативное раскрытие. Фокус виден вокруг строки, скрытая подпись действия не озвучивается.
- Раскрытый список находится в тех же полях, сохраняет авторские группы и текущую плотность пунктов. Дополнительной анимации нет.

От `48rem` в браузерах с поддержкой `::details-content` сохраняется открытый полноширинный TOC и существующая сетка групп. Без этой поддержки остаётся раскрываемая строка; такой запасной вариант на компьютере согласован владельцем. На телефоне начальное состояние всегда свёрнутое. Размеры задаются в `rem`, чтобы строка могла расти с текстом.

После замечания владельца о первом свёрнутом варианте выбранная строка заменила серую плашку с подстрочником «Договор и приложения». Новая строка подчёркивает действие словом «Показать».

### 2. Представление принадлежит приложению

В `/apps/www/src/lib/markdown/` добавить небольшое HTML-only AST-преобразование, подключаемое явной опцией `RenderSiteMarkdownOptions` только из KB. Оно работает с готовым узлом TOC после пакетного построения, до сериализации HTML.

Общий пакет продолжает определять состав и структуру оглавления. Преобразование не ищет заголовки повторно, не разбирает HTML-строку и не распознаёт оферты по URL или словам. Companions и другие HTML-потребители не включают эту опцию.

Новый ADR не нужен: это применение существующей границы app-level представления из ADR-003/034/043.

### 3. Нативное раскрытие без клиентского переключателя

Внешний `nav.ui-markdown-toc` сохраняется. Внутри один изначально закрытый `<details>`, один `<summary>` и один полный список из готового AST. Мобильные подписи действий переключаются CSS по `[open]`; вручную заданный `aria-expanded` и клиентская синхронизация не нужны.

Внутри `@supports selector(::details-content)` и media query от `48rem` содержимое `<details>` получает `content-visibility: visible`, а `<summary>` скрывается через `display: none`. В содержимом остаётся отдельная обычная подпись «Содержание» для desktop; на мобильном её роль выполняет summary. Скрытое управление не получает фокус и не сообщает закрытое состояние над видимым списком.

Без поддержки псевдоэлемента эти переопределения не применяются: на любой ширине работают нативное раскрытие и полные ссылки. На компьютере такой fallback согласован владельцем. Признак поддержки нельзя заменять предположением о ширине или вручную выбранной версии браузера.

По [MDN browser compatibility data](https://github.com/mdn/browser-compat-data/blob/main/css/selectors/details-content.json) поддержка начинается с Chrome 131, Firefox 143 и Safari 18.4. Механизм определён в [CSS Pseudo-Elements](https://drafts.csswg.org/css-pseudo-4/#details-content-pseudo). Советник проверил в Chromium 147 видимость ссылок в accessibility tree и Tab-навигацию при скрытом summary. Firefox, Safari и скринридер остаются частью приёмки реализации; см. [вопрос CSSWG о состоянии раскрытия](https://github.com/w3c/csswg-drafts/issues/13096).

Оглавление и заголовки документа не дублируются. Новые подписи управления не должны попадать в индекс как содержание справки; существующие правила исключения навигации сохраняются.

Альтернативы:

- Оставить список всегда открытым: сохраняет проблему, ради которой подготовлена примерка.
- Менять `open` через клиентский `matchMedia`: требует JS для начального выбора режима и может сдвинуть текст после входа по якорю.
- Создать отдельные desktop- и mobile-копии TOC: позволяет держать desktop открытым и в старых браузерах, но дублирует HTML и проверки. После согласования fallback эта цена не нужна.

### 4. Обычная навигация по якорям

Ссылки ведут к существующим заголовкам вне закрытого блока. Прямой вход на мобильном сохраняет закрытый TOC и сразу показывает целевой раздел. Выбор ссылки не сворачивает оглавление: это сохраняет геометрию во время перехода.

Вернуться можно обычной прокруткой к началу или историей браузера после перехода по якорю. На одной странице раскрытое мобильное состояние сохраняется при смене ширины, поскольку CSS не меняет `open` и не пересоздаёт узлы; на новой странице действует начальное состояние. Печать скрывает TOC существующим правилом навигации.

## Risks / Trade-offs

- В старых desktop-браузерах список требует раскрытия → согласованный нативный fallback сохраняет видимое управление и все ссылки; скрывать summary можно только вместе с поддерживаемым постоянным показом содержимого.
- CSS-видимость может расходиться с нативной семантикой → скрывать summary на desktop и проверять реальную доступность ссылок в Chromium, Firefox и WebKit, отдельно проверить чтение скринридером.
- Изменение оболочки затрагивает CSS дочерних списков → сохранить проверку плоского и вложенного оглавления, добавить короткое обычное оглавление без групп.
- Ошибка работы с якорями может быть незаметна на снимке → проверить прямую загрузку с hash, клавиатурный переход и возврат через историю на собранной странице.
- Обновление снимков может скрыть регрессию → просмотреть закрытое и раскрытое состояния и сохранить существующие проверки состава ссылок, видимости цели и компактных промежутков.

## Migration Plan

Изменение включается на всех KB-страницах одним opt-in шаблона. Перенос редакционных файлов и данных не требуется. Реализация, обновлённый гайд, основные specs и архив change входят в один PR. Откат возвращает PR целиком.
