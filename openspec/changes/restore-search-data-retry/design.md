# Design

## Context

Причина и общий тикет описаны в [proposal](/openspec/changes/restore-search-data-retry/proposal.md). Действуют [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md) и [ADR-002](/docs/decisions/002-client-transitions-prefetch-cache.md); пользовательский контракт восстановления принадлежит [client-load-recovery](/openspec/specs/client-load-recovery/spec.md).

В [SearchDialog](/apps/www/src/components/search/SearchDialog.svelte) различаются ошибка первой выдачи и `loadMoreFailed`; при второй уже показанные ссылки сохраняются. Кеш клиента удаляет отклонённые promises. Pagefind 1.6.0 делает то же для fragments, но не исправляет все виды отказов. [Исследование](/docs/research/pagefind-1.6.0-upstream.md) и консультация `advisor` определили границу пригодного повтора.

## Goals / Non-Goals

**Goals:**

- Повторять наблюдаемый отказ чтения найденного результата на том же клиенте.
- Сохранять запрос, успешно показанную порцию и точный предел неудавшейся догрузки.
- Различать ошибки по месту возникновения, а не по тексту стороннего исключения.

**Non-Goals:**

- Обнаружение всех скрытых отказов чанков индекса и фильтров, автоматический retry или гарантия успешности каждой повторной попытки.
- Перезапуск движка, подмена fetch, cache-busting импорты, vendor patch и общий recovery-framework.
- Изменение восстановления сравнения или восстановления запроса после полной перезагрузки документа.

## Decisions

### 1. Повторяемой считается только ошибка `reference.data()`

Ввести одну локальную маркированную ошибку чтения результата и helper, оборачивающий только вызов `reference.data()`. Использовать его в двух местах [client.ts](/apps/www/src/lib/search/client.ts): обычная материализация результата и чтение первого результата при проверке inverse-prefix. Нормализация ответа выполняется вне этой обёртки, чтобы ошибки нашего кода не выдавались за повторяемую загрузку.

Ошибки импорта, `options`, `init`, broad/exact `search()` и неизвестные ошибки сохраняют reload-подсказку. Успешный `await pagefind.init()` не использовать как доказательство готовности: [публичный API создаёт wrapper](https://github.com/Pagefind/pagefind/blob/v1.6.0/pagefind_web_js/lib/public_search_api.ts), а ошибка фактической инициализации может проявиться позже в `search()`.

Маркировка определяет стадию отказа, а не его сетевую причину. Повреждённый fragment или отказ worker тоже могут отклонить `data()`; пользователь сможет повторить, но без обещания успеха. Строки чужих ошибок не разбираются.

### 2. Повтор использует существующий клиент и кеши

Обработчик вызывает `client.search(query, limit)` на том же экземпляре. Успешные результаты сохраняются в действующем кеше; rejected entries удаляют клиент и Pagefind. Предварительный отказ inverse-prefix также повторяется через тот же helper.

При догрузке хранить последний успешно показанный `requestedLimit` и не увеличивать его из-за неудачной попытки. Повтор запрашивает прежний неудавшийся предел, вычисленный из последнего успеха, вместо добавления ещё одной порции. Не заменять `Promise.all` новым механизмом частичного результата: сохраняется уже показанная порция, новая применяется после полного успеха.

Альтернатива пересоздать весь движок избыточна для исправленного кеша fragments и затрагивает browser module map. Удаление всех успешных кешей ухудшает повторную загрузку без подтверждённой пользы.

### 3. UI сохраняет доступность и управление попыткой

Для маркированного отказа показывать сообщение «Не удалось загрузить результаты поиска.» и кнопку «Повторить». При ошибке догрузки кнопка располагается после сохранённых результатов. Для остальных ошибок оставить «Поиск не работает. Попробуйте обновить страницу.».

Во время попытки блокировать повторную активацию и объявлять загрузку. После нового отказа сохранять сообщение и кнопку. После успешной первой выдачи переводить фокус на первый результат, если он оставался на кнопке повтора; после успешной догрузки аналогично переводить его на первый добавленный результат. Не перехватывать фокус, если пользователь уже ушёл с кнопки. Закрытие по Escape и возврат к opener сохраняются.

Автодогрузка не запускает новые попытки после отказа без действия пользователя. Существующие request IDs и проверки открытого диалога защищают от позднего ответа после смены запроса, закрытия или нового открытия. Новый текст проходит `humanizer-ru` и обязательный `editorial-reviewer` при реализации.

### 4. Границы upstream фиксируются явно

[`loadChunk` и `loadFilterChunk`](https://github.com/Pagefind/pagefind/blob/v1.6.0/pagefind_web_js/lib/coupled_search.ts#L387-L418) удаляют отказ из кеша, но подавляют исключение. Поиск может вернуть пустой или неполный результат без сигнала UI. Наш `exactSearchPromise` может кешировать такой формально успешный ответ. Этот change не обещает обнаружить или исправить скрытый отказ чанка повтором того же запроса.

Гарантия ограничена отказом чтения содержимого результатов, дошедшим до приложения. При необходимости исправлять молча потерянные совпадения требуется отдельное решение с upstream; здесь оно не маскируется автоматической перезагрузкой.

### 5. Настоящий отказ проверяется на production-индексе

Компонентные fixtures подтверждают состояние интерфейса, но не исправление Pagefind. На production-сборке блокировать новые `/search/fragment/*` до первой выдачи и отдельно после успешной порции. Затем снять блокировку и нажать «Повторить» на том же клиенте: запрос и предел сохраняются, результат доступен, документ/entry/WASM не загружаются заново. Повторный отказ также проверяется.

Отдельно завершить запрос entry/WASM/meta сетевой или HTTP-ошибкой и проверить reload-подсказку без локального повтора. Повторная консультация проверила этот путь: для entry/WASM исключение сохраняется в `initError`; после отказа meta декодирование возвращает нулевой указатель, который [getPtr](https://github.com/Pagefind/pagefind/blob/v1.6.0/pagefind_web_js/lib/coupled_search.ts#L540-L551) превращает в ошибку. Бесконечно ожидающий fetch не покрывается этим сценарием и не требует нового watchdog. Действующий [search-recovery.browser.spec.ts](/apps/www/tests/search-recovery.browser.spec.ts) проверяет lazy JS без готового индекса; его успех не заменяет эти сценарии. Короткие сетевые сценарии с индексом включить в существующий production search-quality suite без нового универсального smoke-обхода сайта.

## Risks / Trade-offs

- Повторяемая стадия не гарантирует исправимую причину. Повтор остаётся ручным, повторный отказ явно показан и не стирает данные.
- Инициализация Pagefind отложена. Классифицировать по `data()`, а не по возврату `init()`.
- Изменение лимита после отказа может пропустить порцию. Проверить точные аргументы последовательных попыток и отсутствие дублей.
- Удаление кнопки после успеха может потерять клавиатурный фокус. Управлять им только для пользователя, который оставался на действии повтора.

## Migration Plan

Выполнить после обновления до 1.6.0 и явных секций в общей ветке. Положительный сетевой прогон служит основанием для выпуска кнопки. Если повтор fragments не работает без дополнительного механизма, остановить этот этап и согласовать дальнейший объём с владельцем. Общая приёмка, sync/archive, один PR и откат описаны в [первом change](/openspec/changes/add-search-excerpt-ellipsis/design.md#migration-plan).
