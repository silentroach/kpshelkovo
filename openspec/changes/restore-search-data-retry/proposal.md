# Proposal

## Why

После временного отказа поисковых данных пользователь сейчас должен обновить страницу и ввести запрос заново. Pagefind 1.6.0 удаляет неудачные загрузки fragments из кеша, поэтому можно проверить и вернуть локальный повтор без потери уже показанной выдачи.

Общий тикет: [#1263](https://github.com/silentroach/kpshelkovo/issues/1263). Прежняя проблема описана в [#899](https://github.com/silentroach/kpshelkovo/issues/899) и [архивном решении](/openspec/changes/archive/2026-10-29-suggest-reload-on-search-data-failure/design.md); границы upstream-исправления проверены в [исследовании](/docs/research/pagefind-1.6.0-upstream.md).

## What Changes

- Вернуть доступное действие «Повторить» для ошибок загрузки результатов после успешной инициализации движка.
- Повторять текущий запрос с сохранением нужного объёма выдачи; при отказе догрузки сохранять уже показанные результаты и ссылки.
- Сохранять совет обновить страницу для ошибок загрузки кода и инициализации движка, для которых локальное восстановление не подтверждено.
- Проверить повтор на настоящих сетевых отказах первой выдачи и догрузки до принятия реализации.

## Capabilities

### New Capabilities

Новых областей нет.

### Modified Capabilities

- `client-load-recovery`: различать локальный повтор загрузки результатов и восстановление инициализации через обновление страницы.

## Impact

Затронуты [поисковый клиент](/apps/www/src/lib/search/client.ts), его типы ошибок, [SearchDialog](/apps/www/src/components/search/SearchDialog.svelte), компонентные и браузерные проверки. Сохраняются защита от устаревших ответов, клавиатурная работа диалога и отсутствие автоматического повтора. Общий механизм восстановления сравнения не меняется.

Зависит от обновления Pagefind в [первом change](/openspec/changes/add-search-excerpt-ellipsis/proposal.md). Выполняется после [явных секций](/openspec/changes/add-explicit-search-sections/proposal.md) в общей ветке `feat/pagefind-1.6-search`; PR один. Код меняется после апрува. Проверки настоящего отказа выполняются до PR на локальной production-сборке; отдельная production-приёмка не требуется.
