# Spec Delta

## ADDED Requirements

### Requirement: Отзыв из соседнего чата имеет компактную подпись

HTML-карточка SHALL обозначать соседний чат рядом с датой соответствующего отзыва. Дата и подпись SHALL использовать обычное начертание и приглушённое оформление без отдельного блока источника. У отзывов из чата Шелково дополнительное название чата SHALL отсутствовать. Подпись SHALL обозначать происхождение сообщения, не приписывая автору место жительства или место выполнения заказа.

#### Scenario: Рядом опубликованы местный и соседний отзывы

- **WHEN** карточка содержит отзывы из чата Шелково и соседнего посёлка
- **THEN** название соседнего чата видно только у соответствующего отзыва, рядом с датой
- **AND** переход по каждому отзыву открывает его собственное исходное сообщение
- **AND** доступное имя ссылки соседнего отзыва включает дату и подпись чата

#### Scenario: Длинное название на узком экране

- **WHEN** дата и название чата не помещаются в одну строку
- **THEN** метаданные переносятся с сохранением полного текста и читаемости
- **AND** подпись не создаёт отдельного интерактивного элемента внутри ссылки отзыва

### Requirement: Markdown сохраняет подпись источника отзыва

Markdown-карточка SHALL передавать подпись соседнего чата в необязательном поле `reviews[].sourceLabel` вместе с исходным URL отзыва. Значение SHALL совпадать с подписью в HTML. Действующие поля отзывов и их смысл SHALL сохраняться.

#### Scenario: Чтение соседнего отзыва в Markdown

- **WHEN** потребитель читает Markdown-карточку с отзывом из соседнего чата
- **THEN** запись содержит `sourceLabel` с названием источника и `url` исходного сообщения

#### Scenario: Отзыв без дополнительной подписи

- **WHEN** у отзыва нет дополнительной подписи источника
- **THEN** поле `sourceLabel` отсутствует в Markdown
- **AND** источник остаётся доступен по `url`, без подставного названия чата

### Requirement: Происхождение отзыва не меняет учёт для звезды

Отзывы из местного и соседних чатов SHALL участвовать в действующем расчёте звезды на равных основаниях независимо от наличия подписи источника. Повторные описания одного заказа SHALL объединяться редакционно, в том числе при публикации в разных чатах.

#### Scenario: Порог набран отзывами из разных чатов

- **WHEN** положительные отзывы из местного и соседних чатов вместе удовлетворяют действующим условиям звезды
- **THEN** звезда показывается без отдельного порога или веса для соседних чатов

#### Scenario: Отрицательный отзыв опубликован в соседнем чате

- **WHEN** в расчётное окно попадает отрицательный отзыв из соседнего чата
- **THEN** он влияет на отсчёт положительных отзывов по тому же правилу, что и местный

#### Scenario: Один заказ описан в двух чатах

- **WHEN** редактор подтвердил, что сообщения в разных чатах повторяют опыт одного заказа
- **THEN** в каталоге остаётся одна запись об этом заказе и она учитывается один раз
