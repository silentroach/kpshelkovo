# Design

## Context

Мотивация и согласованная уступка описаны в [proposal.md](proposal.md). Сейчас две интеграции собирают самодостаточные JS-файлы с Svelte runtime, публикуют virtual module с URL и обслуживают отдельные dev endpoints. Клиент после отказа меняет query-параметр URL. Минификатор `minify-standalone-graph.ts` обслуживает эти сборки.

Поиск открывает серверную оболочку и фокусирует поле до асинхронной загрузки. `site-runtime.ts` защищает её от устаревшего результата после закрытия и перехода. Сравнение параллельно загружает компонент и `explorer.json`, но общий `catch` сейчас не различает причины отказа. Стили обоих компонентов уже участвуют в SSR-сборке.

Действующий [ADR-002](../../../docs/decisions/002-client-transitions-prefetch-cache.md) сохраняет Astro ClientRouter и требования к жизненному циклу скриптов. При реализации дополнить его причиной полного обновления документа на границе отказа JS: новый документ сбрасывает browser module map, обычный клиентский переход этого не гарантирует. Общая стратегия навигации не меняется.

## Goals / Non-Goals

- Использовать один штатный pipeline сборки, разрешения импортов, окружения и CSS.
- Разделять отказ кода и данных в месте их загрузки, без эвристик по тексту браузерной ошибки и без универсального framework ошибок.
- Не возвращать сериализацию dataset в island props и не делать тяжёлый поиск eagerly loaded.
- Не добавлять service worker, автоматическое обновление, хранение поискового запроса в storage или новые политики HTTP-кеша.

## Decisions

### Обычные статически анализируемые динамические импорты

Использовать существующие entrypoints `components/search/lazy.ts` и `compare/client/explorer-component.ts` через обычные `import()` с литеральным путём. Удалить imports virtual modules, ручную сборку URL, `@vite-ignore` для этих entrypoints, счётчики повторов и регистрации standalone-плагинов. Удалять минификатор и типы только после проверки оставшихся потребителей.

Vite получает возможность штатно разделять чанки; точные имена и число JS-файлов больше не являются условиями тестов. Доступность Pagefind в dev продолжает задавать существующая интеграция `pagefind-dev-snapshot`, теперь через общую конфигурацию приложения.

Альтернатива — общая фабрика автономных графов — сократила бы дублирование, но сохранила второй pipeline и его сопровождение. Eager import ухудшил бы начальную загрузку ради сценария ошибки.

### Ошибка кода подсказывает обновить страницу средствами браузера

В поисковой оболочке удалить локальный retry модуля. Показать согласованный текст: «Поиск не загрузился. Попробуйте обновить страницу». Сохранить доступное объявление ошибки, закрытие диалога и возврат фокуса, защиту от устаревших async-результатов. Отдельную кнопку обновления и обработчик `location.reload()` не добавлять. Не восстанавливать диалог и запрос автоматически после обновления средствами браузера.

В сравнении при отказе загрузки компонента показать согласованный текст: «Фильтры и сортировка недоступны. Попробуйте обновить страницу». Кнопку локального повтора при отказе кода скрыть. Ошибку hydration безопасно считать невосстановимой локально и показывать ту же подсказку, а не повторно гидратировать потенциально частично изменённый DOM. Обновление средствами браузера не гарантирует успешную работу при продолжающейся сетевой или программной ошибке.

Альтернатива — повтор того же `import()` — не гарантирует восстановления после закешированного отказа. Автоматическая перезагрузка скрывает причину и может зациклиться.

### Данные сохраняют локальное восстановление

Загрузка компонента и JSON сравнения остаётся параллельной. В bootstrap различать результаты этих двух операций и ошибку hydration. Если отказал JS, подсказка обновить страницу без кнопки повтора имеет приоритет, даже если одновременно отказал JSON. Если JS успешно загружен, а отказал только JSON, существующая кнопка повтора повторяет запрос данных без перезагрузки документа и без повторной загрузки компонента. Ожидание и завершение операций не должны приводить к необработанным rejection или гидрации отсоединённого root.

Это небольшое разделение состояния внутри explorer bootstrap, а не общий recovery-manager. Локальное восстановление Pagefind в загруженном поиске и ошибки API карты остаются у их существующих владельцев.

## Risks / Trade-offs

- Потеря введённого запроса после обновления → принята владельцем; сообщение подсказывает обновить страницу средствами браузера.
- Иное разделение чанков или выдача CSS → проверить production-сборку, загрузку с холодным кешем, внешний вид, отсутствие hydration warnings и набор/суммарный размер загруженного JS до и после.
- Удаление специальных тестовых URL может сделать fault injection нерабочим → browser-тест должен доказать, что блокируется именно отложенный модуль, bootstrap продолжает работать и ошибка видна. Не подменять проверку реального импорта mock-ответом runtime.
- Ошибка JSON раньше отказа JS может ошибочно предложить бесполезный локальный retry → проверить оба порядка завершения и приоритет отказа компонента.
- Неверное окружение поиска в dev → проверить с локальным Pagefind snapshot и без него; обычный запуск dev-сервера выполнять только с отдельным разрешением владельца, иначе проверять через ограниченный тестовый harness и отмечать непроверенное.
- Отсутствие production-статистики отказов → не заявлять доказанную редкость сценария или количественный выигрыш до замеров.

## Migration Plan

1. После разрешения реализации снять baseline сборки и поиска, затем изменить загрузчики и удалить standalone-путь в одной ветке.
2. Адаптировать существующие unit/browser-тесты, выполнить typecheck, тесты, production build и сравнение загрузки. Браузерная приёмка — на локальной production-сборке; обязательная проверка после production deploy не требуется.
3. Дополнить ADR-002, синхронизировать spec и архивировать change после проверок. Issue #743 должен отражать удаление, а не объединение механизма; при разрешённой публикации связать его с артефактами и PR.
4. Развернуть как обычную статическую сборку. Откат возвращает весь PR с загрузчиками, конфигурацией и тестами; миграции данных нет.
