# Design

## Context

Мотивация — в [proposal](/openspec/changes/respect-compare-map-reduced-motion/proposal.md). Autofit в `SettlementMap` передаёт фиксированные `250` мс. Первоначальное вписывание уже мгновенное. `fitRevision` отделяет фильтрацию от сортировки; действующая синхронизация учитывает позднюю инициализацию и более новые запросы.

## Goals / Non-Goals

**Goals:** выбирать длительность по актуальной настройке перед отправкой camera update и сохранить синхронизацию.

**Non-Goals:** автоматически двигать карту при смене media preference, останавливать уже запущенный переход только из-за смены настройки, добавлять motion-эффекты, подписки, состояние или менять родительский компонент.

## Decisions

- Читать `window.matchMedia('(prefers-reduced-motion: reduce)')` непосредственно перед каждым autofit, после возможного ожидания инициализации. При reduce — `0`, иначе — существующие `250` мс; отсутствие API сохраняет обычное поведение. Аналогичный подход уже есть в `PlaceMap`.
- Не добавлять реактивную подписку: контракт требует учесть настройку при следующем действии, а не инициировать самостоятельный camera update. Подписка и новое состояние здесь только усложнили бы lifecycle.
- Не менять `fitRevision`, отмену устаревшего attachment и защиту новых pending-запросов. Если проверки обнаружат необходимость отдельного механизма, вернуть вопрос оркестратору до реализации и применить консультацию advisor.
- Renderer продолжает владеть кадром по [ADR-039](/docs/decisions/039-shared-yandex-maps-runtime-and-preview.md). Нового ADR и клиентского импорта нет, анализ бандлов не требуется.

## Risks / Trade-offs

- Настройка меняется во время ожидания SDK → читать её после ожидания и проверить последующие действия на том же mount.
- Mock не доказывает реальную камеру → ручная проверка с настоящим SDK в обычном и reduced motion режиме.
- Поздний старый запрос возвращает прежний кадр → проверить быстрые revisions и задержанную инициализацию, не перестраивая sync заранее.

## Ownership and Verification

- Исполнитель меняет только `/apps/www/src/compare/components/SettlementMap.svelte` и `/apps/www/src/compare/components/SettlementMap.svelte.test.ts`.
- `SettlementsExplorer`, `PlaceMap`, runtime, shared стили и общий compare-controls browser suite остаются без правок. Артефакты и sync/archive ведёт оркестратор.
- При реализации обязательны Svelte skills, официальный MCP/autofixer после правки и `animate`; существующая анимация сохраняется только без reduce.
- Проверить `250 → 0 → 250` на одном mount, отсутствие update при одной смене настройки или сортировке, финальный набор быстрого переключения и прежние map tests.
- Настоящая карта: первое раскрытие, фильтрация, быстрые смены, сортировка после pan/zoom, desktop/mobile, клавиатура и popup. Проверки организуются на production-preview без `pnpm dev` и с отдельной браузерной сессией.
- Приёмка: component tests, typecheck, сборка, валидация OpenSpec, браузер и reviewer всего diff. Обычный деплой; откат возвращает change целиком.
