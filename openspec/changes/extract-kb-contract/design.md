# Design

## Context

См. [proposal.md](proposal.md). [ADR-015](../../../docs/decisions/015-markdown-first-knowledge-base.md) сейчас одновременно объясняет выбор редакционной модели и перечисляет правила KB. Реализация и проверки разделены между `apps/www/src/lib/kb/`, маршрутами `apps/www/src/pages/kb/`, sitemap и редакционными инструкциями `apps/www/src/data/kb/AGENTS.md`. `openspec/specs/search/spec.md` описывает общий поиск и подписи карт, но не маршруты и навигацию KB.

## Goals / Non-Goals

**Goals:** закрепить поведение KB в `knowledge-base`, оставив у каждого правила одного понятного владельца; привести объяснение исходного выбора в ADR-015 в соответствие с действующим разделом.

**Non-Goals:** менять исходные статьи и сканы, код маршрутизации, структуру frontmatter или правила Pagefind для других разделов.

## Decisions

### Один контракт KB, остальные области — по ссылке

Создать отдельную spec `knowledge-base` для специфичных для раздела публичных URL, страниц-разделов, breadcrumbs, авторских ссылок, флагов KB и пары HTML/Markdown. Не расширять `search`: правила KB читаются вместе с их навигацией, а общий поиск и карты уже принадлежат `search`, [ADR-025](../../../docs/decisions/025-static-full-text-search-with-pagefind.md) и [ADR-035](../../../docs/decisions/035-status-search-indexing.md). Правила HTTP negotiation и MIME остаются у [ADR-009](../../../docs/decisions/009-markdown-accept-negotiation.md), регистрация поверхностей — у [ADR-011](../../../docs/decisions/011-public-surface-registry.md), рендер и генерация Markdown — у [ADR-003](../../../docs/decisions/003-markdown-pipeline-layering.md) и [ADR-008](../../../docs/decisions/008-markdown-ast-generation.md). Альтернатива — перенести все эти подробности в новую spec — породила бы расходящиеся копии общего контракта.

### Развести смысл двух флагов без изменения правила KB

У `noindex` внешнее назначение (robots и sitemap); в KB такие страницы также не участвуют во внутреннем поиске. `exclude-from-site-search` влияет только на внутренний поиск и не закрывает внешнюю индексацию. Это подтверждают `kb/search.ts`, `kb/load.ts`, `sitemap-data.ts` и тесты. Формула «каждый флаг управляет только своим индексом» неверно описывала бы действующий KB и исключение статуса из ADR-035. В delta spec прямо назвать все наблюдаемые эффекты, не объявляя флаги полностью независимыми переключателями.

### Отделить редакционные инструкции от публичного договора

В ADR-015 сохранить причины выбора Markdown-файлов, авторских ссылок и отсутствия второй карты навигации. Ранние «не вводим поле» и «поиск потом» заменить коротким указанием на текущую модель: схема `kb/raw-schema.ts` проверяет frontmatter, `apps/www/src/data/kb/AGENTS.md` объясняет редактору использование `sources` и SEO. Не копировать в spec перечень допустимых и запрещённых полей. Уточнить ссылки из локального AGENTS.md и индекса ADR, не превращая ADR в руководство по редактированию. Альтернатива — оставить в ADR весь старый список с примечаниями об исключениях — затруднит поддержку при следующем расширении модели.

## Risks / Trade-offs

- Неполный перенос важного правила из ADR → сверить по пунктам требования и сценарии с ADR-015, реальными маршрутами и существующими проверками до сокращения.
- Документация может создать ложное обещание о независимости `noindex` и Pagefind → явно указать исключение KB из поиска и отдельно зафиксировать эффект второго флага.
- Ссылки на старый ADR могут подразумевать несуществующее руководство по frontmatter → обновить локальные инструкции и индекс, проверить действующие ссылки поиском по репозиторию.

## Migration Plan

После разрешения согласованно обновить ADR-015, индекс и редакционную ссылку в той же ветке; сверить существующие тесты путей, breadcrumbs, Markdown companions, sitemap и поиска. Синхронизировать основную spec, архивировать change и включить документацию в один PR. Откат — обратный коммит документации; данных и публичных URL мигрировать не нужно.
