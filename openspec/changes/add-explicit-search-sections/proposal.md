# Proposal

## Why

Подпись Markdown-карты сейчас оформлена заголовком `h3` ради поисковой секции. Выжимки отзывов «Сарафана» уже участвуют в поиске, но у них нет отдельных целей перехода. Явные секции Pagefind позволяют адресовать эти блоки по их смыслу и HTML-структуре.

Общий тикет: [#1263](https://github.com/silentroach/kpshelkovo/issues/1263). Основание: [исследование Pagefind 1.6.0](/docs/research/pagefind-1.6.0-upstream.md).

## What Changes

- Сделать именованную Markdown-карту явной поисковой секцией на `figure`, сохранив её существующий ID и переход к началу карты.
- Оставить название видимой подписью без искусственного heading-элемента и убрать связанный с высотой карты обход для прокрутки.
- Добавить устойчивые якоря и названия поисковых секций для выжимок отзывов в «Сарафане».
- При совпадении основного excerpt с секцией отзыва направлять результат карточки контакта к этому отзыву; использовать общий выбор секции и canonical fallback.

## Capabilities

### New Capabilities

Новых областей нет.

### Modified Capabilities

- `search`: переход к найденному отзыву в карточке «Сарафана» и устойчивость этой цели при перестановке отзывов.

## Impact

Затронуты [рендер Markdown-карт](/apps/www/src/lib/markdown/editorial-maps-html.ts), стили их подписи и прокрутки, [модель контактов](/apps/www/src/lib/contacts/types.ts), mapper и raw-валидация отзывов, [ContactReviews](/apps/www/src/components/contacts/ContactReviews.astro) и связанные тесты. Формат публичных Markdown-документов не получает поисковые служебные атрибуты. Существующий контракт поиска карт выполняется новой разметкой и не требует второй копии требований.

Зависит от [обновления и многоточий](/openspec/changes/add-search-excerpt-ellipsis/proposal.md). Ветка `feat/pagefind-1.6-search` и итоговый PR общие с двумя другими change. Код меняется после апрува. Приёмка поиска проводится на production-индексе до PR; проверка настоящих карт через `pnpm dev` требует отдельного разрешения владельца по правилам проекта.
