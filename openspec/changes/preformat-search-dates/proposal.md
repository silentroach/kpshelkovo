# Proposal

## Why

При первом открытии поиска браузер загружает Luxon только ради подписи календарной даты под результатом. Дата известна при сборке, поэтому её готовую подпись можно передать в индексе и убрать тяжёлую клиентскую зависимость без изменения вида дат и поискового поведения.

Связанная задача: [#875](https://github.com/silentroach/kpshelkovo/issues/875).

## What Changes

- Готовить подпись даты в общем серверном слое поисковой разметки существующим `formatDate` и сохранять её в metadata Pagefind.
- Сохранять исходный `publishedAt` для возрастного ранжирования и `<time datetime>`; готовую подпись использовать только для показа.
- Убрать клиентский вызов `formatDate` и загрузку Luxon из поиска, не заменяя их новым клиентским форматтером.
- Сохранить русский формат даты, календарный день материала независимо от таймзоны посетителя, результаты без даты, порядок выдачи и ленивую загрузку поиска.
- Проверить полный баланс: уменьшение загружаемого JavaScript, рост всех частей индекса и трафик первой порции результатов на одинаковом корпусе.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет. Меняется реализация передачи подписи, а не поведение продукта. Требования [search](/openspec/specs/search/spec.md) и [client-load-recovery](/openspec/specs/client-load-recovery/spec.md) сохраняются; delta specs пропущены через `skip_specs: true`.

## Impact

- Затронуты серверная разметка `BaseLayout`, адаптер и типы поискового результата, `SearchDialog`, их проверки и отчёты [клиентских бандлов](/docs/development.md#анализ-клиентских-бандлов).
- Добавляется внутреннее поле metadata индекса. Публичные URL, JSON/Markdown-представления, версия Pagefind, правила корпуса и существующие поисковые веса не меняются. Новая подпись получает нулевой поисковый вес.
- Общий `formatDate`, серверный Luxon и остальные потребители пакета `@shelkovo/format` остаются без изменений. Новых зависимостей, внешних запросов и deploy-настроек нет.
- Приёмка проводится на согласованной production-сборке и включает браузерную проверку. Отдельная приёмка после деплоя не требуется; после реализации и проверок change архивируется по обычному workflow.
- Сейчас разрешены только подготовка ветки `perf/preformat-search-dates`, коммит и публикация планового draft PR. Реализация продолжится в этой же ветке и PR после отдельного запроса владельца в следующей сессии; текущая публикация не разрешает менять код.
