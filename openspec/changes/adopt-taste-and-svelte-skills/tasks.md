# Tasks

## 1. Подключение и правила применения

- [ ] 1.1 Добавить три закреплённые записи по design через штатный CLI во временном проекте с изолированным профилем; сверить реальные `skillPath`, supporting files и хеши, установить набор через `pnpm skills:install` и подтвердить `pnpm skills:check`. В diff lock должны быть только новые записи.
- [ ] 1.2 Уточнить условия подключения и приоритеты в корневом и локальном `AGENTS.md` по design; вручную проверить решения для русской статьи с цитатой и датами, плотной тарифной таблицы и Svelte-раскрытия. Проверить, что правила позволяют улучшать существующий гайд, сохраняют проектный стек и владельцев решений, разрешают конфликты Taste/animate без правок upstream.

## 2. Общая приёмка

- [ ] 2.1 Подтвердить восстановление полного набора из нового lock в чистой временной копии проекта с изолированным HOME без изменения отслеживаемых файлов и глобальных skills; выполнить `pnpm skills:check`, `pnpm test:agent-tooling` и `pnpm openspec:validate`, сохранить результаты для PR.
- [ ] 2.2 Вызвать `reviewer` для всего diff относительно точного SHA базы `origin/master`, включая staged, unstaged и новые файлы, с issue, change, spec `agent-tooling` и результатами проверок; разобрать замечания и выполнить адресный повтор после исправлений по [инструкции](/docs/development.md#ревью-изменения-в-opencode). При недоступности reviewer провести оба прохода самостоятельно и явно указать ограничение.
