# Proposal

## Why

[Задача #789](https://github.com/silentroach/kpshelkovo/issues/789), часть [инициативы #776](https://github.com/silentroach/kpshelkovo/issues/776): ADR-030 смешивает причины нормализации источников с публичным контрактом и отчётом о переходе на v2. Потребителю нужно однозначное описание разрешения ссылок и границ стабильности ID, а разработчику — один владелец этих требований.

## What Changes

- Выделить действующий контракт источников детальной сметы в `estimate-detail-sources`: явная версия, нормализованный реестр, разрешимость ссылок, трассируемость, локальность ID и повторяемость генерации.
- Сократить ADR-030 до причин нормализации, выбора коротких ID и исторического решения о переходе на v2; подробные измерения заменить ссылкой на исходный PR.
- Связать ADR и индекс решений с основной spec и существующими публичными JSON Schema/OpenAPI. В описании операции detail OpenAPI пояснить разрешение `source_refs` через `sources` того же ответа.

## Capabilities

### New Capabilities

- `estimate-detail-sources`: перенос существующих обязательств публичного `/815/regulation/data/estimate-details-2026.json` из ADR в OpenSpec без изменения формата данных.

### Modified Capabilities

Нет. Основные specs пока не описывают источники детальной сметы.

## Impact

- Документация: ADR-030, `docs/decisions/README.md`, новая основная spec после синхронизации.
- Публичное описание: только текст операции detail OpenAPI в `apps/www/src/lib/reglament/discovery.ts`.
- JSON версии 2, URL, схемы валидации и алгоритм сериализации сохраняются. Миграция других публичных схем из #480 и проверки связей ресурсов из #291 остаются самостоятельными задачами.
