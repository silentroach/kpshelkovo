# Spec Delta

## ADDED Requirements

### Requirement: Редакторское закрытие сохраняет источник расписания

При `availability: closed` исходное `opening_hours` SHALL сохраняться и проходить обычную проверку, но SHALL NOT публиковаться в HTML, Markdown или JSON и участвовать в расчёте открытости. После ручного снятия закрытия и пересборки сохранённое расписание SHALL снова использоваться без восстановления удалённых интервалов. Отметки закрытия определяются `place-availability`.

#### Scenario: Включение и снятие закрытия

- **WHEN** редактор включает закрытие у места с недельным расписанием, а затем снимает его
- **THEN** исходные интервалы и пояснение сохраняются на обоих шагах
- **AND** во время закрытия часы не публикуются и не влияют на доступность, после снятия снова действуют

## MODIFIED Requirements

### Requirement: Необязательное расписание определяется интервалами

`opening_hours` SHALL быть необязательным. При отсутствии редакционного закрытия HTML SHALL показывать полную неделю из `opening_hours.periods` без JavaScript и раскрытия блока, независимо от общей карты. Markdown SHALL передавать те же интервалы во frontmatter `opening_hours.periods` (`days`, `opens_at`, `closes_at`) и `opening_hours.timezone: Europe/Moscow`, без generated-печатной недели и текущего статуса. Дни `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` без интервалов SHALL означать выходные, не неизвестные часы.

#### Scenario: Чтение без JavaScript

- **WHEN** пользователь открывает карточку места с расписанием без редакционного закрытия при отключённом JavaScript
- **THEN** вся неделя и рабочие интервалы доступны в HTML, даже если место скрыто с общей карты
- **AND** Markdown-карточка передаёт те же дни и интервалы во frontmatter вместе с `timezone: Europe/Moscow`, без печатного расписания в body

#### Scenario: Место без расписания

- **WHEN** у места отсутствуют `opening_hours` и редакционное закрытие
- **THEN** HTML- и Markdown-карточки не содержат блока часов, статуса работы или заглушки об отсутствии расписания, а frontmatter Markdown не содержит `opening_hours`
- **AND** подписи на общей карте не содержат сведений о часах или статусе работы и заглушек на эту тему

### Requirement: Пояснение дополняет расписание

`opening_hours.description` SHALL быть необязательным пояснением действующего расписания, которое HTML-карточка показывает отдельно под часами, а Markdown-карточка передаёт только в одноимённом поле frontmatter. При отсутствии пояснения Markdown SHALL не публиковать это поле и не подставлять печатное расписание, пустую строку или `null`. Пояснение SHALL не заменять автоматически полученные часы и не участвовать в вычислении статуса работы.

#### Scenario: Расписание без пояснения

- **WHEN** у места без редакционного закрытия есть `periods`, но отсутствует `description`
- **THEN** HTML-карточка показывает полное расписание без пустого пояснения, а статус работы доступен по интервалам
- **AND** Markdown frontmatter содержит интервалы и часовой пояс без ключа `opening_hours.description`

#### Scenario: Расписание с пояснением

- **WHEN** у места без редакционного закрытия вместе с `periods` заполнено пояснение
- **THEN** HTML-карточка показывает его под расписанием, Markdown-карточка передаёт его в `opening_hours.description` без generated-дублирования в body
- **AND** смена текста пояснения не изменяет часы и статус

### Requirement: Статус использует те же часы по московскому времени

Без редакционного закрытия статус в карточке и на общей карте SHALL вычисляться по тем же `periods`, которые определяют видимое расписание, в часовом поясе `Europe/Moscow` независимо от часового пояса устройства. Начало интервала SHALL включаться во время работы, конец SHALL исключаться. При наличии расписания перерыв и день без интервалов SHALL означать закрытие; время «открыто до» SHALL соответствовать концу текущего интервала.

#### Scenario: Границы интервала и перерыв

- **WHEN** у места без редакционного закрытия день содержит 09:00–13:00 и 14:00–18:00
- **THEN** статус по московскому времени означает открытие в 09:00 и 14:00, закрытие с 13:00 до 14:00 и с 18:00
- **AND** время закрытия в первом интервале равно 13:00, во втором — 18:00

#### Scenario: Другой часовой пояс устройства

- **WHEN** пользователь смотрит статус места без редакционного закрытия с устройства в другом часовом поясе, а по московскому времени у места выходной
- **THEN** карточка и общая карта показывают закрытие по московскому дню недели

### Requirement: JSON публикует интервалы и необязательное пояснение

Для мест без редакционного закрытия в `/map/data/places.json` объект `opening_hours` SHALL передавать структурированные `periods` с полями `days`, `opens_at` и `closes_at`. Поле `description` SHALL присутствовать только при наличии пояснения и содержать это пояснение. Публичный JSON SHALL не подставлять вместо отсутствующего пояснения готовое расписание, пустую строку или `null`.

#### Scenario: Экспорт без пояснения

- **WHEN** в набор общей карты входит место без редакционного закрытия с интервалами и без пояснения
- **THEN** его JSON содержит `opening_hours.periods` с днями и часами и не содержит ключ `opening_hours.description`

#### Scenario: Экспорт с пояснением

- **WHEN** в набор общей карты входит место без редакционного закрытия с интервалами и пояснением
- **THEN** его JSON передаёт интервалы в `periods`, а пояснение — в `description`
