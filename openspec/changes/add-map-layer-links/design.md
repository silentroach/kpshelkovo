# Design

## Context

Мотивация и границы — в [proposal](/openspec/changes/add-map-layer-links/proposal.md). Карта использует один `PlaceMap` на узком и широком экране. Четыре части участков и инфраструктура изначально выключены; обычные места показываются всегда. `p`, `h`, `set` уже включают необходимые слои; ручное выключение отменяет позднее включение и ожидающую камеру.

URL-helper сохраняет чужие query-параметры, их исходное кодирование, hash и history state. Параметры читаются при монтировании; постоянной синхронизации слоёв с URL и обработчика `popstate` нет.

В [схеме мест](/apps/www/src/lib/places/schema.ts) строка `infrastructure` обозначает две разные вещи: категорию и слой. Raw/public схемы слоя используют общий список допустимых значений, mapper и публичный адаптер передают значение без преобразования. Сохраняем границы [ADR-013](/docs/decisions/013-raw-domain-public-data-boundary.md); нового архитектурного решения не требуется.

## Goals / Non-Goals

**Goals:**

- Применить стартовые слои через существующий путь загрузки и отображения, не создавать второй механизм включения частей.
- Отличать независимый запрос слоя от временного включения для проверки `p`, чтобы неизвестная цель не скрыла запрошенную часть.
- Сохранить текущие приоритеты камеры, отмены и повторное использование запросов.

**Non-Goals:**

- Полный реестр состояния карты, двусторонняя синхронизация URL, новые элементы управления и изменение внутренних имён ради сокращения.
- Изменение категорий, URL карточек, идентификаторов наборов или архивных change.

## Decisions

### Одноразовый разбор `l`

Добавить небольшой чистый helper рядом с существующим [URL-helper](/apps/www/src/components/places/place-map-url.ts). Он читает все значения `l`, разделяет по запятой, оставляет известные идентификаторы и объединяет повторы. Идентификаторы распознаются в точном нижнем регистре; прочие варианты игнорируются как неизвестные. `parcels` раскрывается в существующий набор частей. Не добавлять отдельную настройку обычных мест.

Helper только читает URL. Использование `URLSearchParams` для чтения не требует сериализации и не должно менять исходное кодирование. Альтернатива с канонизацией или двусторонней синхронизацией отвергнута по согласованному контракту: ссылка задаёт лишь старт.

### Включение через существующее состояние

Прочитать запрос при монтировании вместе с прямыми целями и применить его до их асинхронного разрешения. Инфраструктура включается тем же состоянием, что и переключатель; части используют существующую отложенную загрузку. При отсутствии распознанных частей не импортировать геометрию и не запрашивать части ради `l`.

Начальный запрос не должен многократно применяться реактивно. После применения актуальные состояния переключателей управляют отображением; флаги ручного выключения и существующая защита от поздних ответов сохраняются. При неизвестном `p` учитывать начальное независимое включение части через `l`, не выключая её вместе с временным запросом прямой цели. Это дополнительное основание сохранения слоя, а не запрет пользователю выключить его.

Вариант «`l` задаёт точную маску и запрещает остальные слои» отвергнут: он конфликтовал бы с `p`, `h`, `set` и будущими слоями по умолчанию. Никакого нового вызова камеры для `l` не нужно; дополнительные объекты не входят в bounds набора.

### Переименование только идентификатора слоя

Заменить значение в `PLACE_MAP_LAYERS`, полях `map_layer` восьми записей КТП, проверках принадлежности слоя и fixtures. Общие raw/public схемы получат новый enum; публичный адаптер отдаст `mapLayer: infra`. Имена полей остаются прежними, как и `category: infrastructure`, подпись «Инфраструктура» и внутренние переменные `infrastructureEnabled` и аналогичные.

Обновить локальную инструкцию мест и текущую спецификацию через delta. Исторические архивы не переписывать. Альтернатива с URL-псевдонимом при старом значении данных отвергнута владельцем: согласовано единое короткое имя без обратной совместимости.

## Risks / Trade-offs

- Старый клиент и новый JSON по-разному понимают слой → публиковать код, данные и схемы одной сборкой; не вводить временное двойное значение.
- Поздний ответ набора или части может вернуть ручное выключение → проверить существующие защитные флаги на URL-включённых слоях, включая общий переключатель участков.
- Неизвестный `p` может выключить независимо запрошенную часть → адресная регрессия для совместного запроса.
- Ручное состояние не отражено в скопированной ссылке → это согласованная цена одноразовой настройки; перезагрузка повторяет первоначальный запрос.
- Игнорирование неизвестного значения не должно скрыть сетевой сбой известной части → ошибки загрузки и повтор остаются штатными по `parcel-map`.

## Migration Plan

1. После разрешения реализации обновить идентификатор в коде, данных, схемах, тестах и локальных инструкциях в одной ветке. Старое значение не поддерживать.
2. Добавить чтение `l` и покрыть совместное применение с прямыми целями и отменами. Обновить связанные agent-facing документы, если они описывают значение слоя или параметры общей карты.
3. Выполнить адресные тесты, typecheck и сборку. При изменении клиентских импортов или условий загрузки сравнить бандлы и сохранить актуальные YAML-отчёты по [инструкции](/docs/development.md#анализ-клиентских-бандлов).
4. После приёмки синхронизировать specs, архивировать change и подготовить единый PR. Откат — весь PR целиком, включая данные и клиент; отдельная production-приёмка не требуется.
