# Proposal

## Why

Перед PR требуется проверить всё изменение, но отдельного повторяемого режима ревью сейчас нет: агент может пропустить коммиты ветки или незакоммиченные файлы и смешать поиск регрессий с упрощением кода. [Issue #840](https://github.com/silentroach/kpshelkovo/issues/840) предлагает независимого reviewer, который возвращает обоснованные замечания автору.

## What Changes

- Добавить проектного OpenCode V2 subagent `reviewer`, вызываемого из основной сессии. Он проверяет корректность и регрессии, затем отдельным проходом подключает `ponytail-review`.
- Учитывать всё изменение относительно явно переданной базы: коммиты ветки, staged, unstaged и новые файлы. Сверять результат с задачей, согласованным change, применимыми основными specs и профильными правилами.
- Возвращать замечания по важности с местом, условием проявления, последствием и рекомендацией; отдельно показывать вопросы, риски, упрощения и непроверенное.
- Запретить инструменты редактирования через permissions. Инструкцией запретить любые изменения файлов проекта, коммиты и публикацию через остальные инструменты. Сохранить доступ к обычным инструментам в пределах разрешений среды; тесты и сборку выполняет основной агент.
- Включить вызов reviewer в приёмку OpenSpec-изменений через `openspec/config.yaml`. После исправлений повторно проверять изменившийся результат; при недоступности reviewer основной агент проводит оба прохода сам и явно отмечает fallback.
- Документировать вызов, передачу контекста и границы автоматического ревью в `docs/development.md`. Для короткого пути reviewer доступен по запросу; человеческое ревью и merge остаются у владельца.

Уточнения к исходному issue согласованы при обсуждении: вместо узкого shell allowlist выбран широкий доступ с техническим запретом `edit` и поведенческим запретом остальных способов записи; допускается явно обозначенная самопроверка при недоступности reviewer. Техническая изоляция всех каналов записи не входит в контракт.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `agent-tooling`: доступный из основной сессии reviewer с ограниченной ролью, полным охватом изменения и проверяемым отчётом; его применение в OpenSpec-приёмке с повторной проверкой исправлений и явным fallback.

## Impact

- Новый файл `.opencode/agents/reviewer.md`; изменения `openspec/config.yaml` и `docs/development.md`.
- Узкая delta к `openspec/specs/agent-tooling/spec.md`; технические детали профиля и пробных прогонов остаются в design/tasks.
- Решение следует ADR-038 и использует штатные возможности OpenCode V2. Новые зависимости, плагины, собственный runner и отдельная slash-команда не требуются.
- Приёмка включает реальный вызов агента, проверку запрета редактора, неизменности проекта и охвата разных слоёв diff, а также небольшой чистый пример. Существующие проверки agent tooling дополняют эти прогоны, но не заменяют их.
- Production-приёмка не требуется. После реализации и приёмки specs синхронизируются, change архивируется в той же ветке; PR закрывает #840 по обычному процессу.
- Этот этап создаёт только плановые артефакты. Разрешение на реализацию необходимо получить отдельным запросом после их ревью.
