# Tasks

План зафиксирован для отдельной сессии реализации в ветке `feat/1121-map-selection-sets`. Все чекбоксы ниже относятся к будущей реализации, а не к подготовке этого draft PR. Состав первого набора и контекст продолжения — в [design](/openspec/changes/add-map-selection-sets/design.md).

## 1. Данные набора и статическая выдача

- [ ] 1.1 Добавить источники JSON и app-owned raw schema → domain → public adapter с разрешением кодов/алиасов и проверкой `show_on_map`; адресными тестами подтвердить целые составные позиции, удаление повторов, неизвестные ссылки, скрытые места и отказ пустого набора.
- [ ] 1.2 Выпускать компактные `/map/data/selection-sets/<id>.json` с проверкой конечного DTO до сериализации; тестом адаптера подтвердить canonical-состав без координат и отделение public DTO, разовой проверкой сборки — фактическую выдачу файла. В [документации карт](/docs/editorial-maps.md) описать формат, текущую версию по стабильной ссылке и исключение runtime-артефакта из discovery по ADR-011.
- [ ] 1.3 Добавить `first-selection.json` из design с включённой обводкой; разово сверить все 67 canonical-позиций, 34 в Парке и 33 в Вилладже, отсутствие отдельного B43 и согласованное включение B42/B43/B44 целиком. Не превращать текущее количество записей в постоянный тест формата.

## 2. Подсветка участков и геометрия обводки

- [ ] 2.1 Разделить membership и одиночный выбор в parcel renderer; в существующих `parcel-layer` тестах подтвердить приоритет одиночного выбора, возврат подсветки набора после его снятия, сохранение межей и восстановление оформления после disable/enable.
- [ ] 2.2 Добавить чистый union-helper в `@shelkovo/geo` и тесты общей стороны, касания углом, зазора, отверстия и MultiPolygon; результат сохраняет кольца и раздельные области без буферизации и изменения исходных координат. Проверить экспорт и декларацию `sideEffects` пакета.
- [ ] 2.3 Подключить неинтерактивную обводку лениво только для `outline: true`, пересчитывая её по видимым участникам при смене состава/частей. Тестами подтвердить восстановление общей прежде границы при выключении соседней части, удаление последнего контура, отсутствие union на pan/zoom/смене `p` и отмену позднего импорта после снятия набора.

## 3. Ссылки, места и жизненный цикл карты

- [ ] 3.2 Поддержать основной маркер и всю дополнительную геометрию мест набора независимо от hover/focus/таймера `h`, с видимой подсветкой при соседних местах и обычными ссылками на карточки; тестами на базе `place-map-geometry` подтвердить восстановление обычной кластеризации и условий раскрытия после снятия набора, без дублей маркеров.
- [ ] 3.3 Добавить доступное действие снятия набора и обработку неизвестного имени, ошибки определения/обводки и неудачной части. Интеграционными тестами подтвердить снятие во время загрузки, сохранение камеры/слоёв/самостоятельного `p`, частичную ошибку без ложного полного fit, штатный повтор части, быстрые выключения/включения и отсутствие возврата отменённого состояния. Новые русские UI-тексты отредактировать по `humanizer-ru`.
- [ ] 3.4 Проверить оформление подсветки и обводки относительно обычных статусов, отдельного выбора и подложки; записать выбранные визуальные правила в существующий дизайн-гайд, если они его дополняют. Проверить читаемость номеров, доступность снятия набора и независимый от цвета признак выделения.

## Workflow follow-up

- После реализации и приёмки выполнить штатные sync/archive в этой же ветке; основные specs и архив входят в существующий PR вместе с кодом. До этого change остаётся активным.
- Повторить `pnpm openspec:validate` и адресное ревью изменений sync/archive по [инструкции](/docs/development.md#ревью-изменения-в-opencode).
- Обновить ссылку issue на архив, результаты и оставшуюся ручную приёмку в текущем PR. Когда критерии #1121 выполнены, снять draft и заменить `Refs #1121` на `Closes #1121`; человеческое ревью и merge оставить владельцу.
