## Why

На `/news/` браузер загружает восемь блокирующих CSS-файлов, семь из которых вместе занимают 5,95 КБ до сжатия. В [#629](https://github.com/silentroach/kpshelkovo/issues/629) уже зафиксирована связанная регрессия FCP/LCP новостей и статуса сервисов. Цель — воспроизводимо улучшить загрузку и Lighthouse Performance во всём сайте, сохранив CSS/JS внешними и выбрав простую упаковку по результатам экспериментов.

## What Changes

- Исследовать доставку CSS всех корневых разделов: `news`, `status`, `kb`, `map`, `sarafan`, `reviews`, `people`, `meetings`, `815`, а также главной и 404.
- Начать со схемы «общий CSS + CSS раздела», включая один исходный пакет `/815` для Compare и регламента. Сравнить её с исходной сборкой и при необходимости с более выборочной группировкой; окончательное число пакетов выбрать по измерениям, а не закреплять заранее.
- Сохранить scoped стили у компонентов; группировка меняет только выходные ресурсы.
- Проверить выделение vendor JS из обычного клиентского графа Astro с учётом реальных потребителей. Сохранить отдельное кеширование библиотек и отложенную загрузку; число vendor-файлов определяется реальным графом.
- Использовать штатные возможности Astro/Vite/Rolldown. Предпочтительный механизм — `codeSplitting.groups`; собственный сборочный слой и длинные списки исключений не входят в объём.
- Не встраивать оптимизируемые CSS/JS в HTML ради балла. По уточнению владельца существующие служебные вставки Astro сохраняются; их удаление не входит в задачу.
- Принимать результат по повторным A/B-прогонам Lighthouse Performance, FCP/LCP, TBT/CLS, объёму передачи и повторным переходам. Уменьшения числа файлов без измеримого эффекта недостаточно; при потолке или округлении балла допускается улучшение реальных метрик.

## Capabilities

### New Capabilities

- `asset-delivery`: измеримо более быстрая доставка внешних CSS/JS с кешированием и сохранением оформления и границ загрузки интерактивности.

### Modified Capabilities

Нет.

## Impact

- Основное ожидаемое изменение приложения: `apps/www/astro.config.ts`; конкретная конфигурация определяется ограниченной серией экспериментов.
- Упаковка ресурсов затрагивает все разделы `apps/www`; приёмка включает прямую загрузку, клиентские переходы и отложенную интерактивность.
- Самодостаточные retryable-графы поиска и Compare сохраняют действующий контракт восстановления после неудачной загрузки. Их внутренние библиотеки не выносятся в общий vendor в этом изменении.
- `apps/media`, содержимое новостей, публичные API и инфраструктура доставки не меняются.
- Основа решения — ADR-034 о владении CSS, ADR-017 о внешнем исполняемом коде и ADR-004 о Lighthouse-профиле без аналитики.
- Связанная задача — [#629](https://github.com/silentroach/kpshelkovo/issues/629); прежний вариант с inline заменяется текущим change. Постоянные route-level бюджеты CI остаются отдельной задачей [#392](https://github.com/silentroach/kpshelkovo/issues/392).
- Владелец разрешил обновить issue и опубликовать draft PR с планом. Реализация ожидает отдельного согласования обновлённого change и затем войдёт в тот же PR.
