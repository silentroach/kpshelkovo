# Proposal

## Why

Исходники мероприятий лежат одним плоским списком, хотя владелец ожидает группировку по году и месяцу также в репозитории. Это уточнение задачи [#224](https://github.com/silentroach/kpshelkovo/issues/224) в [PR #748](https://github.com/silentroach/kpshelkovo/pull/748), продолжение [обсуждения структуры файлов](https://github.com/silentroach/kpshelkovo/pull/748#discussion_r4054864858).

## What Changes

- Хранить записи в `apps/www/src/data/events/YYYY/MM/<event-id>.md`, по московскому году и месяцу начала мероприятия.
- Сохранить существующие имена файлов как стабильные ID, отдельные от публичного `slug`. Например, `apple-garden-2026.md` переедет в `2026/05/apple-garden-2026.md`.
- **BREAKING для редакторского формата:** плоское размещение записей больше не принимается; при переносе начала в другой месяц редактор переносит исходник в соответствующую папку.
- Проверять соответствие папки дате и обнаруживать повтор одного стабильного ID в разных папках без потери записи при загрузке.
- Перенести существующие записи, обновить загрузку, предметные тесты и действующие редакторские инструкции. Сохранить публичные URL, ссылки новостей, JSON ID, DOM-якоря, ICS-адреса и UID при переносе файлов без изменения данных.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `events-calendar`: редактор хранит исходники по месяцу начала; структура проверяется при публикации и не меняет стабильную идентичность мероприятия.

## Impact

- Коллекция `events` в `apps/www/src/content.config.ts`, загрузка и проверка источников в `apps/www/src/lib/events/`.
- Исходники `apps/www/src/data/events/`, интеграционные тесты, читающие эти файлы напрямую.
- `AGENTS.md`, локальные инструкции мероприятий, `.agents/skills/news-maker/SKILL.md` и `docs/news.md`.
- Реализация продолжает существующие issue и PR в ветке `feat/224-events-calendar`. Новые зависимости и инфраструктура не требуются.
