# Design

## Context

Мотивация и границы — в [proposal.md](proposal.md). В текущей ветке `d0e31e62` семь мероприятий лежат в корне `src/data/events`. Коллекция читает `*.md`, а `generateId` получает стабильный ID из имени файла. `mapRawEvent` использует этот ID для JSON, якорей, самостоятельного ICS и UID; публичный URL отдельно строится из московского начала и frontmatter `slug`.

`news/source.ts` и `status/source.ts` уже проверяют соответствие месячных папок дате. Общие `trimMarkdown`, `rawMarkdownBody` и разбор дат доступны для повторного использования. `news/tests/events-integration.test.ts` напрямую читает плоские пути пяти перенесённых из новостей записей.

Применим [ADR-013](../../../docs/decisions/013-raw-domain-public-data-boundary.md): путь коллекции относится к входной границе, а доменные и публичные идентификаторы сохраняют собственный контракт. Нового архитектурного слоя или ADR этот перенос не требует.

## Goals / Non-Goals

**Goals:**

- Раскладывать исходники по месяцу начала с проверкой согласованности пути и даты.
- Сохранить доменную модель и опубликованные идентификаторы при организационном переносе файлов.

**Non-Goals:**

- Переименование стабильных ID или привязка ICS к текущему месяцу.
- Новые поля frontmatter, правка содержания мероприятий, перенос UI, изменение поиска или схем публичных данных.

## Decisions

### Папки по началу, существующие имена файлов

Новый путь — `YYYY/MM/<event-id>.md`. Сохранить basename каждого существующего файла; `slug` продолжает определять публичное название пути. Это минимальный перенос: он не требует нового поля `id`, миграции идентификаторов или алиасов.

При изменении месяца начала перемещать файл; смена только публичного `slug` не требует переименовывать файл. Период через несколько месяцев хранить по началу. Альтернатива `YYYY/MM/<public-slug>.md` потребовала бы отдельного сохранения прежнего ID при каждом переименовании; в этом изменении она не используется.

### Проверка на границе источников

Использовать рекурсивный glob `**/*.md` с исключением `AGENTS.md` на всех уровнях. Узкий glob ровно двух папок скрывал бы ошибочно размещённые записи, поэтому форму пути проверять явно через Zod в предметном `events/source.ts`, по образцу соседних разделов. Сверять год и месяц с существующим разбором `starts_at`, включая московскую дату на границе UTC-месяца. Сохранить обязательную проверку непустого body.

Внутренний ключ Astro-коллекции содержит полный относительный путь без `.md`. Перед `buildEventsDataset` загрузчик переводит его в стабильный ID из basename; остальные данные поступают в существующий mapper. Полный ключ коллекции нужен, чтобы две копии с одинаковым basename в разных месяцах дошли до существующей проверки дубликатов `EventRoutesSchema`, а не перезаписали друг друга в хранилище коллекции. Путь коллекции не выходит в публичные ID и ICS.

Доменные fixtures могут по-прежнему использовать нормализованные `EventEntry`; тесты загрузочной границы должны отдельно покрыть преобразование ключа коллекции и обнаружение повторного ID между папками.

### Действующие инструкции

Обновить корневой `AGENTS.md`, `src/data/events/AGENTS.md`, `.agents/skills/news-maker/SKILL.md` и `docs/news.md`. Закрепить месячные папки, сохранение basename при переносе и различие стабильного ID с публичным `slug`. Архивы прежних решений остаются историей; новый change заменяет прежнее решение о плоском хранении.

## Risks / Trade-offs

- Папки случайно станут частью публичного ID → нормализовать ключ на входе, проверить прежние JSON ID, якоря, оба ICS-адреса и UID.
- Рекурсивный glob пропустит неправильное размещение или загрузит инструкцию → проверять путь каждого найденного материала, исключить `AGENTS.md` на любой глубине.
- Одинаковые basename в разных папках скроют одну запись → использовать разные ключи коллекции до доменной проверки дубликатов.
- Дата перемещена без исходника или ссылок новостей → проверка папки и существующая проверка редакторских ссылок останавливают сборку с понятной ошибкой.

## Migration Plan

1. После согласования сохранить артефакты и отметить разрешение в #224 по корневому процессу; продолжать в ветке PR #748.
2. Зафиксировать публичные ID, URL, календарные адреса и UID текущих записей для разового сравнения.
3. В одном изменении обновить загрузку, перенести семь файлов без изменения frontmatter/body и поправить прямые пути интеграционных fixtures:
   - `2026/05/`: `apple-garden-2026.md`, `victory-day-greenwood-march-2026.md`, `victory-day-greenwood-2026.md`, `victory-day-shelkovo-memorial-2026.md`.
   - `2026/06/`: `ok-meeting-june-2026.md`.
   - `2026/09/`: обе записи `green-dreams-*-cinema-quiz-2026-09-19.md`.
4. Обновить инструкции, проверить source-границу, существующие интеграции, typecheck и сборку. Разово сверить публичные данные и календарные ссылки с исходным состоянием; не добавлять постоянный обход артефактов в CI.
5. Синхронизировать основную spec, архивировать change и отправить результат в тот же PR. Обязательной production-приёмки нет; достаточны локальная сборка, проверки и человеческое ревью. Откат возвращает перенос, загрузку и документацию вместе.
