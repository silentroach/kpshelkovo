# Design

## Context

Мотивация — в [proposal](/openspec/changes/external-fontsource-css/proposal.md). `/packages/ui/fonts.ts` разрешает Fontsource 5.3.0 через Astro local provider. `/packages/ui/src/Fonts.astro` выводит два `<Font />`: www и стенды используют `optimizedFallbacks: true`, media — прежние два Cyrillic face без подгонки метрик. В установленном Astro 7.3.5 `<Font />` непосредственно выводит `<style set:html={data.css}>`; обычный `build.inlineStylesheets` его не выносит.

В www уже установлено `vite.build.assetsInlineLimit: 0`. CSS Fontsource по весам содержит `unicode-range`, `swap`, WOFF2 и запасной WOFF. Отдельный `latin-400.css` диапазона не содержит: набор таких импортов с одинаковым family/weight не заменяет штатный CSS по весу.

Применимые решения: [ADR-020](/docs/decisions/020-separate-media-error-app.md) сохраняет независимую media-404; [ADR-034](/docs/decisions/034-native-css-architecture.md) оставляет семантические роли у хоста и допускает CSS реально переиспользуемых package-компонентов. Новый ADR не нужен: обычная CSS-сборка заменяет способ подключения, без новой архитектуры доставки.

## Goals / Non-Goals

**Goals:**

- Проверить переиспользование внешнего CSS между страницами и влияние утраты metric fallback до выбора production-результата.
- Использовать только поддерживаемые импорты пакета и обычный CSS pipeline, сохранив бинарные файлы шрифтов.

**Non-Goals:**

- Merge, subset, конвертация и переименование шрифтов; отдельный набор для `₽`.
- Внутренние virtual modules Astro, постобработка HTML, собственный генератор `@font-face`, ручная таблица font metrics.
- Новые зависимости, JS-загрузчик шрифтов, preload, внешние origins, смена семейств или весов.
- Перенос media-404 на CSS Fontsource или постоянный smoke-обход сайта в CI.

## Decisions

### 1. Три штатных CSS-импорта по весам

Импортировать `@fontsource/fira-sans/400.css`, `@fontsource/fira-sans/600.css` и `@fontsource/pt-serif/700.css` в небольшой shared font stylesheet. Он задаёт только семейства через прежние `--font-fira-sans` и `--font-pt-serif`, с цепочками `system-ui` и `Georgia, serif`. Роли `--font-body` и `--font-heading` остаются у www и визуальных стендов.

Не переписывать declarations пакета и не собирать CSS из отдельных subset-файлов. Native CSS объявляет дополнительные поддерживаемые алфавиты и запасной WOFF, но браузер получает только подходящие символам страницы face и предпочитает WOFF2. Font Budget документирует этот WOFF fallback и дополнительные наборы; новые веса не добавляются. Размер опубликованных, но не загруженных файлов учитывать отдельно от cold bytes страницы.

### 2. Общее внешнее CSS через обычную сборку Astro

www и его визуальные стенды используют head-компонент с импортом stylesheet, без Fonts API для этих хостов. Удалить неиспользуемые `wwwFonts`/provider definitions и связанную с ними guard-проверку, адаптировав адресный Font Budget к активному подключению. Штатная сборка останавливается при отсутствующем CSS или font asset; не создавать заменяющий framework собственный CSS-валидатор.

Объявления могут войти в общий stylesheet вместе с foundation: отдельное имя `fonts.css` не является контрактом. Результат должен быть внешним и общим между страницами. В www этому помогает существующий `assetsInlineLimit: 0`; для визуальных стендов обеспечить тот же способ штатной конфигурацией, не меняя глобально inline-политику остальных styles без необходимости.

`sideEffects` UI уже включает `**/*.css`: проверить удержание нового CSS и отсутствие ненужных импортов в production, обновить exports и sideEffects только при реальной необходимости. Хешированные CSS/fonts остаются внутри `/static/` и используют действующий production-кеш 30 дней; менять nginx или CSP не требуется.

### 3. Отделить прежнее media-подключение

Самостоятельная media-404 продолжает использовать Astro local provider и guard обязательных media faces. Разделить head-компоненты так, чтобы CSS www не импортировался в media. Удаление www-конфигурации не должно менять оригинальные media-семейства, две font URL, бинарные данные, `swap`, fallback или отсутствие preload. Проверить это сравнением готового media-артефакта.

### 4. Проверить компромисс до публикации

Внешний CSS кешируется, но холодная загрузка получает дополнительную зависимость до обнаружения fonts. Утрата metric fallback может изменить переносы и увеличить font-induced CLS. Это гипотезы, не заранее принятие ухудшения.

Сохранить baseline обычной реализации из свежей production-сборки, не использовать устаревший `dist` от отменённых экспериментов. Сравнить главную, `/815/regulation/` и длинный `/kb` на desktop/mobile: одинаковые браузер, viewport, CPU/network, cold/warm cache и задержка fonts. Записать HTML/font CSS/font bytes, FCP, LCP, CLS, строки/геометрию выбранных текстов; если вывод зависит от временных метрик, использовать не менее трёх одинаковых навигаций и медиану/диапазон.

Проверить loaded/delay/fail, `₽`, кириллицу, латиницу, клавиатурные подписи и переход между страницами с кешем. Обычные страницы должны получать те же нужные WOFF2-наборы; дополнительные alphabets и WOFF считать запросами только если они реально понадобились. Вынос CSS сам по себе не гарантирует ускорение.

Если обнаружены новые обрезания/перекрытия, заметные проблемы первого рендера или font-induced сдвиги, которые ухудшают чтение, остановиться и показать владельцу сравнение. Не возвращать metric fallback собственным генератором и не ослаблять приёмку ради выбранного подхода. После успешной локальной приёмки — проверки, reviewer и обычный PR.

## Risks / Trade-offs

- [Кешируемость против раннего обнаружения fonts] → сопоставить cold и warm в одинаковых условиях, не обещать ускорение до измерений.
- [Переносы без подгонки метрик] → сравнение delay/fail и CLS, возврат результата владельцу при существенной регрессии.
- [Native CSS содержит больше объявлений и форматов] → сохранять upstream без парсера/переписывания, различать объём артефактов и реальные запросы.
- [Общий компонент случайно подключит CSS www на media] → отдельный media-вход и проверка неизменности артефакта.

## Migration Plan

Сначала baseline, затем локальное переключение и browser comparison. Документация и проверки меняются вместе с принятым подключением; до положительной приёмки нет PR или деплоя. Откат — весь diff этого change, не бинарные эксперименты #1034. Production-проверка после merge не является условием завершения.
