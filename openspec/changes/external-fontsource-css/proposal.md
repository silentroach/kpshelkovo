# Proposal

## Why

Astro `<Font />` повторяет одни и те же объявления шрифтов и метрических fallback внутри HTML каждой страницы. Владелец хочет проверить обычный внешний CSS, который браузер сможет переиспользовать между страницами, без изменения бинарных шрифтов и собственного генератора.

Issue: [#1035](https://github.com/silentroach/kpshelkovo/issues/1035). Отменённое объединение subsets из #1034 в этот change не входит.

## What Changes

- Основной сайт и его визуальные стенды подключают стандартный CSS Fontsource для Fira Sans 400/600 и PT Serif 700 через обычную CSS-сборку Astro.
- Версии шрифтов, рисунок, веса, семантические CSS-переменные, локальная доставка, `swap` и отсутствие preload сохраняются.
- Объявления шрифтов становятся частью общего внешнего кешируемого CSS, а не отдельным inline-блоком в каждом HTML.
- Системные fallback используются без автоматической метрической подгонки Astro; влияние на переносы и сдвиги сначала проверяется локально на production-сборке.
- Используются готовые CSS по весам с `unicode-range` и стандартным WOFF fallback. Subsets не склеиваются и не редактируются вручную.
- Самостоятельная media-404 сохраняет прежний local provider, два Cyrillic WOFF2 и собственную доставку.
- Если локальное сравнение показывает существенное ухудшение первого рендера, переносов или font-induced CLS, реализация останавливается для решения владельца. Собственный генератор или экстрактор CSS не добавляется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `web-font-loading`: внешний переиспользуемый font CSS основного сайта и обычный системный fallback вместо обязательной подгонки метрик.

## Impact

- Shared head-компоненты и CSS `/packages/ui`, конфигурации www и визуальных стендов, адресные проверки Font Budget. Подключение media отделяется без изменения её результата.
- [Font Budget](/docs/design/design-code-shelkovo.md#font-budget) и [инструкция шрифтов](/docs/development.md#шрифты-при-сборке).
- Нативный CSS Fontsource объявляет все поддерживаемые наборы выбранных весов и резервный WOFF; браузер загружает только нужные тексту наборы, предпочитая WOFF2. Дополнительные файлы сборки учитываются в приёмке.
- Новых зависимостей, внешних browser-origin, Python-подготовки и изменений CSP или nginx не требуется.
- Приёмка проводится локально до PR: сравнение холодной/повторной навигации, первого рендера и loaded/delay/fail на mobile/desktop. Отдельная production-приёмка не требуется; успешно принятый PR закрывает issue.
