# Proposal

## Why

В workspace есть форматирование, typecheck и тесты, но нет отдельной быстрой lint-проверки. Из-за этого подозрительные конструкции и ошибки в исходном коде могут впервые обнаружиться только при ревью.

Связанная задача: [#864 — Подключить oxlint к проверкам кода](https://github.com/silentroach/kpshelkovo/issues/864).

## What Changes

- Добавить Oxlint как локальную dev-зависимость и команду `pnpm lint`, проверяющую поддерживаемый исходный код всего workspace, включая скриптовые блоки Astro и Svelte.
- Запускать lint в существующем CI при PR, push и плановых пересборках; ошибки и предупреждения останавливают проверку и, соответственно, деплой. Typecheck и тесты остаются отдельными проверками.
- Запускать на staged-файлах через существующий pre-commit `lint-staged` безопасное автоисправление Oxlint (`--fix`); оставшиеся замечания блокируют коммит. Форматирование и lint не должны одновременно записывать один файл.
- Подобрать правила для нынешнего кода, разобрать находки без массового изменения поведения и описать команды разработчику.

## Capabilities

### New Capabilities

Нет: это внутренний инструмент разработки, а не долгоживущий продуктовый, редакционный или публичный контракт.

### Modified Capabilities

Нет. Spec `agent-tooling` описывает восстановление агентской интеграции и не является контрактом для lint приложения.

## Impact

- Корневой `package.json`, `pnpm-lock.yaml`, настройки Oxlint и `lint-staged`, `.github/workflows/ci.yml`, документация разработки и файлы, в которых подтвердятся находки lint.
- Pre-commit и CI становятся строже для исходного кода; публикация по расписанию тоже зависит от успешной lint-проверки. Новых публичных API и изменений поведения сайта не планируется.
- Production-приёмка не требуется: результат проверяется локально и в CI до merge. Этот PR содержит только план; реализация и проверки продолжатся в той же ветке после ревью владельца.
