# Design

## Context

Мотивация и объём — в [proposal](/openspec/changes/combine-web-font-subsets/proposal.md). Сейчас `/packages/ui/fonts.ts` строит локальные варианты из Fontsource 5.3.0: три subsets на начертание www и отдельный кириллический набор media. Guard и тесты предполагают один файл на subset.

В изолированном эксперименте сумма Latin+Cyrillic для трёх начертаний составила 121 608 байт, объединённые файлы — около 90,5 КБ. Эти результаты не являются целевым бюджетом: FontTools Merger сохраняет hinting только первого входа, поэтому кириллица потеряла инструкции. Контуры и ширины сохранились, но этого недостаточно для эквивалентного отображения.

В тексте 371 HTML-страницы текущей сборки единственный дополнительный символ `latin-ext` — `₽`, встречающийся на 100 страницах. Это основание состава набора, а не зависимость генерации от текущего контента.

Полные TTF из `google/fonts/main` проверены advisor: Fira Sans Regular/SemiBold 4.203 и PT Serif Bold 1.000W OFL содержат `₽`; их декомпозированные контуры и горизонтальные метрики для всех cmap-символов используемых Fontsource subsets совпали. Перед подготовкой нужно закрепить immutable revision и повторить это сравнение. Источники:

- `ofl/firasans/FiraSans-Regular.ttf`, SHA-256 `c29556a2719bf613ef3d5e070e40d903a8965d9c081beca1375dc1e6e0f93c23`.
- `ofl/firasans/FiraSans-SemiBold.ttf`, SHA-256 `db0321f83eb3e9f527b8af384a1b3fefdc1039cf2b06fd39b3f61492bda9561c`.
- `ofl/ptserif/PT_Serif-Web-Bold.ttf`, SHA-256 `038ba7336bd7ea14f12ad155bed51a4345cac5153275d521dec3ba04021c526e`.
- OFL и copyright notices из соответствующих каталогов и бинарных name records, а не только package metadata.

Действующие решения: [ADR-020](/docs/decisions/020-separate-media-error-app.md) сохраняет независимую media-404, [ADR-034](/docs/decisions/034-native-css-architecture.md) оставляет семантические роли и tokens у приложения. Новый архитектурный ADR не нужен: доставка остаётся штатной локальной Astro Fonts API.

## Goals / Non-Goals

**Goals:**

- Сохранить рисунок, метрики, hinting и используемые layout features при сокращении набора символов.
- Сделать обновление трёх файлов явной воспроизводимой операцией, независимой от обычной сборки.
- Измерить настоящий размер нового набора с `₽` и полную стоимость подключения, включая встроенный font CSS.

**Non-Goals:**

- Variable fonts, новые веса, изменение композиции или CSS-ролей.
- Собственный font provider, runtime-загрузчик, восстановление повреждённых font tables, генерация по символам текущих страниц.
- Python в install/build/CI, изменение media-ресурсов или инфраструктуры доставки.

## Decisions

### 1. Subset полных TTF вместо merge готовых subsets

Использовать штатный FontTools subsetter с явным сохранением hinting, `layout-features='*'` и включённым glyph closure. Стандартный список features не включает `tnum`, поэтому полагаться на defaults нельзя. Целевой набор codepoints — объединение cmap действующих Latin и Cyrillic файлов плюс `U+20BD`. Layout-альтернативы и компоненты сохраняются через closure; это не означает подключение полного `latin-ext`.

Merge готовых Fontsource-файлов отвергнут из-за подтверждённой потери hinting. Восстанавливать bytecode, CVT и layout вручную несоразмерно. Полный TTF без subset сохранял бы исключённые алфавиты и лишний объём.

### 2. Предгенерированные WOFF2 и отдельный рецепт подготовки

Три WOFF2 хранить в `/packages/ui` вне `public`, рядом со сведениями о происхождении и полными лицензиями. Один небольшой preparation-script и отдельное Python-окружение с FontTools 4.66.1 и Brotli 1.2.0 запускаются только вручную при обновлении шрифтов. Версии инструментов, immutable Git revision, SHA-256 входов и выходов, состав codepoints и политика timestamps фиксируются вместе с рецептом.

Исходные TTF можно загрузить во временный каталог при явной подготовке, после проверки хешей. Не добавлять их в Git и не скачивать при импорте `fonts.ts`, установке зависимостей, тестах или сборке. Воспроизводимость подтвердить двумя независимыми генерациями с одинаковыми входами и инструментами. Обновление Fontsource для media не должно незаметно менять готовые www-файлы.

### 3. Лицензионное техническое имя производного PT Serif

[Исходный OFL PT Serif](https://github.com/google/fonts/blob/main/ofl/ptserif/OFL.txt) резервирует имена «PT Sans», «PT Serif» и «ParaType». Для заранее подготовленного изменённого subset использовать family name `Shelkovo Editorial Serif`, full name `Shelkovo Editorial Serif Bold` и PostScript name `ShelkovoEditorialSerif-Bold`; удалить использование Reserved Font Names как имени производного шрифта, сохранив требуемые copyright и license notices. Проверить связанные name records и соответствие имени в Astro definition.

CSS-переменная `--font-pt-serif`, роль заголовков и рисунок остаются прежними. В документации указать происхождение от PT Serif. Это не новый визуальный выбор семейства. Для Fira Sans сохранить фактические copyright notices Mozilla Foundation и Telefonica и исходный OFL; атрибуция package metadata недостаточна.

### 4. Штатный Astro local provider и явная матрица faces

Для www задавать один `options.variants` на weight/style без `unicodeRange`. Официальный local provider допускает такое подключение; новый provider не требуется. Media сохраняет текущие Fontsource Cyrillic варианты с диапазонами. Разделить сборку этих двух наборов без новой универсальной системы подготовки шрифтов.

Guard проверяет обязательные weight/style и число уникальных файлов по ожидаемым вариантам соответствующего хоста, а не числу subsets. Сохранить диагностику отсутствующего и дублированного face; отсутствие `unicodeRange` у www не должно ослабить проверку media. Сохранить `swap`, optimized fallback для www, прежний fallback media и запрет preload.

### 5. Проверки без постоянного обхода сайта

Короткие unit-тесты проверяют состав вариантов и ошибки guard. Подготовка подтверждает cmap, `₽`, контуры, метрики и сохранность hinting всех retained glyphs, включая компоненты и GSUB-альтернативы; проверяются `cvt/fpgm/prep` и применимые настройки `gasp`. Не сравнивать GSUB/GPOS побайтно и не писать собственный универсальный font validator.

Однократная приёмка production-сборки в браузере: главная, длинный KB, тарифные цифры/`₽`, media-404, mobile/desktop. Проверить реальные faces, смешанный текст, кернинг/лигатуры и табличные цифры, loaded/задержанные/ошибочные шрифтовые ответы. Записать холодные и повторные запросы, размеры WOFF2, встроенного font CSS и сжатого HTML до/после в одинаковых условиях. На страницах с тремя начертаниями — три same-origin WOFF2 вместо шести базовых или дополнительных `latin-ext`; media — прежние два файла. Сравнить bundle-отчёты по проектному правилу при изменении сборки.

## Risks / Trade-offs

- [Merge-оценка завысила экономию] → измерить результат subset с сохранённым hinting и `₽`, не обещать прежние 26%.
- [Shaping смешанного текста может измениться после объединения] → сохранить все layout features и closure, проверить короткие примеры и реальные страницы.
- [Расширенная латиница перестаёт использовать веб-шрифт] → явно зафиксировать системный fallback для символов вне целевого набора; это согласованное ограничение.
- [Полные upstream TTF и Fontsource могут разойтись при обновлении] → закреплять и проверять источники, повторять сравнение при явной регенерации.
- [Подготовленные файлы требуют редкого отдельного Python-шага] → маленький рецепт без интеграции в штатную pnpm-сборку; инструменты нужны только редактору шрифтов.
- [Техническое переименование затрагивает font metadata] → проверка name records и лицензий, стабильные semantic CSS variables; визуальные роли остаются прежними.

## Migration Plan

Подготовить и проверить три файла, затем одной правкой подключить их через Astro и обновить guard, тесты и документацию. Приёмку выполнить до PR. Откат — весь PR, включая файлы, определения, Font Budget и specs; отдельная миграция данных или production-приёмка не нужна.
