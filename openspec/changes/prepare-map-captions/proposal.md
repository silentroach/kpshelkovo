# Proposal

## Why

Ради подписей редакционных карт браузер загружает Typograf и часть YAML-библиотеки, хотя текст известен при сборке (#845). Новости и страницы базы знаний без карт также загружают код редакционной карты (#841). Нужен один ограниченный change, который уберёт подготовку статического текста из браузера и подключит карты только там, где они действительно есть.

## What Changes

- Готовить текстовые `iconCaption` по действующим правилам типографики сайта до публикации HTML-карт, превью места и `/map/data/places.json`; общий клиентский renderer выводит только готовый обычный текст, не исполняя HTML и не разбирая Markdown.
- **BREAKING:** в публичной геометрии `/map/data/places.json` существующий `properties.iconCaption` будет содержать подготовленный для показа текст вместо точной исходной строки. Исходный редакционный GeoJSON и блоки `map` в Markdown companion остаются без изменений. Нового поля и отдельной агентской выдачи в этом change нет.
- Убрать оставшиеся клиентские зависимости Typograf/YAML на задействованных картах, если после переноса подписей их продолжает притягивать путь импортов. Не переносить другие статические текстовые преобразования в браузер ради этой оптимизации.
- Не загружать код редакционных карт на страницах новостей и базы знаний без блока карты; на материалах с картами сохранить их запуск, печать, ошибки и работу после клиентской навигации.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `map-geodata`: разграничить исходные строки и подготовленные подписи в HTML и публичной геометрии мест, сохранив безопасный вывод и исходник редакционного материала.
- `site-maps`: ограничить загрузку кода Markdown-карты материалами, которые действительно содержат карту, без изменения её поведения и жизненного цикла.

## Impact

- План затрагивает `@shelkovo/markdown`, подготовку редакционной геометрии в `apps/www`, адаптер публичного JSON мест, общий renderer трёх поверхностей карты и шаблоны новостей/KB. Клиентские импорты и размеры сборки нужно сравнить по `docs/development.md#анализ-клиентских-бандлов` с обновлением YAML-отчётов.
- Изменение значения `properties.iconCaption` у существующего публичного URL согласовано как часть перехода к подготовленным данным карты; потребители, которым важна буквальная исходная строка, должны читать редакционный источник, а не интерпретировать отображаемый payload как его точную копию.
- Послойная доставка карты и судьба агентской навигации рассматриваются отдельно в #858 и #859. Разделение простого превью по возможностям (#847), скрытые мобильные превью (#844), первый экран `/map/` (#393) и общая переработка данных мест в этот change не входят. Нужна проверка сборки и браузерных сценариев до обычного PR; отдельная production-приёмка для этих двух задач не согласована.
