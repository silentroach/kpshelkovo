# Design

## Context

Мотивация и границы — в [proposal.md](proposal.md). `PlacePreview.astro` уже использует общий `MapPreview` и встречается только на `/map/<slug>/`. Его контейнер имеет высоту `15rem`, от `60rem` — `20rem`, рамку 1 px и ширину существующей колонки. `MapCardShell` события оформлен зеленоватой рамкой, радиусом `1rem` и тенью `0 0.65rem 1.55rem var(--color-shadow)`.

Общий `MapPreviewElement` создаёт Яндекс Карту с `behaviors: []`. В `MapPreview.astro` и canvas, и внутренний SDK-контейнер получают `touch-action: pan-y`. Runtime общий с фоновыми картами события и поселка. Изменение дефолтных жестов затронуло бы все эти размещения.

Применимы [ADR-028](../../../docs/decisions/028-markdown-first-places-map.md), [ADR-034](../../../docs/decisions/034-native-css-architecture.md) и [ADR-039](../../../docs/decisions/039-shared-yandex-maps-runtime-and-preview.md). ADR-028/039 и основной `place-card-presentation` сейчас явно запрещают зум превью; новый контракт заменяет этот запрет только для карты места. Отдельный runtime или новая архитектура не нужны: существующие ADR дополняются этим исключением.

## Goals / Non-Goals

**Goals:**

- Сохранить существующие размеры и общую реализацию превью, включив зум явно в адаптере места.
- Использовать возможности установленного SDK и минимальный браузерный адаптер там, где сенсорный и трекпадный pinch приходят разными событиями.

**Non-Goals:**

- Полноэкранный renderer, фильтры, кластеры, перетаскивание, вращение, отдельное хранение камеры и масштабирование фоновых карт.
- Обобщённый конфиг произвольных жестов, новая библиотека жестов или новый пакет UI ради рамки.

## Decisions

### Оформление принадлежит адаптеру места

В scoped CSS `PlacePreview.astro` применить те же значения рамки, радиуса и тени, что у `MapCardShell`. Высоты `15rem`/`20rem`, breakpoint `60rem`, толщину рамки 1 px и геометрию колонки сохранить. Скруглить подложку внутри имеющегося контейнера без новых отступов. Адрес остаётся подписью снаружи карты.

Переиспользование самого `MapCardShell` не подходит: он создаёт фоновую карту с наложенным содержимым и другим кадрированием. Короткая локальная правка оформления проще, чем добавление ему несвязанного режима.

### Логотип и копирайт справа внизу

По дополнительному запросу владельца использовать разрешённый вариант совместного перемещения блока. Адаптер места передаёт существующее `copyrightsPosition: 'bottom right'`; общий runtime уже передаёт параметр в `YMap`. Это тот же штатный способ, который используется в виджете события. Отдельную CSS-перестановку логотипа и копирайта не добавлять. Сохранить ссылки, читаемость и клавиатурный доступ; на узком экране проверить совместное размещение со штатным действием карты и скруглённым краем.

### Явное включение pinch-зума

Добавить в данные общего превью один optional readonly-флаг разрешения pinch-зума. Только `PlacePreview` передаёт его; отсутствие флага сохраняет неподвижный режим. DOM-признак того же режима ограничивает изменения touch-поведения соответствующим экземпляром.

Начать со штатного `pinchZoom` SDK. [Документация Яндекс Карт v3](https://yandex.com/maps-api/docs/js-api/map/index.html) подтверждает отдельные `pinchZoom` и `scrollZoom`, но не гарантирует одинаковую обработку сенсорного и трекпадного жеста. Поэтому до завершения runtime-правки проверить оба пути с настоящим SDK.

Обычный `scrollZoom` не включать постоянно. Если трекпадный pinch не обрабатывается штатным `pinchZoom`, добавить локальную обработку его браузерного сигнала масштабирования, например cancelable `wheel` с `ctrlKey` в Chromium, и передавать изменение камеры в API карты. Обычные wheel-события не отменять. Не дублировать обработку одного жеста браузерным адаптером и SDK; слушатели освобождать при уничтожении экземпляра.

Проверить взаимодействие SDK с `touch-action` и отменой событий: один палец прокручивает страницу, два меняют масштаб карты, сама страница при pinch над готовой картой не масштабируется. Не снимать ограничение жестов глобально. Начальный fit и повторный fit после изменения размера сохраняют точку и все контуры; изменение камеры пользователем не меняет географические данные.

### Приёмка

До изменения сохранить размеры карты на одинаковых страницах и viewport. После изменения сравнить размеры и положение адреса при 1440, 390 и 320 px, загрузке, ошибке и готовой карте. Проверить точку и MultiPolygon, скругление, фокус и видимость атрибуции.

Существующие компонентные тесты проверяют включение режима только в адаптере места, неподвижные фоновые карты, lifecycle и резервную ссылку. Жесты проверяются браузером с настоящим SDK: touch pinch, трекпадный сигнал масштабирования, обычное колесо, свайп и прокрутка трекпада. Mock успешного вызова SDK не считается доказательством работы жестов. Если настоящий SDK в локальной среде недоступен, этот пункт приёмки остаётся открытым до проверки на доступной среде.

Обязательная приёмка после публикации в production не предусмотрена. Проверка физического трекпада и телефона при человеческом ревью дополняет воспроизводимую браузерную проверку.

## Risks / Trade-offs

- Браузер может забрать pinch для масштаба страницы или отменить его как прокрутку → проверить фактические события и CSS с настоящим SDK, ограничить перехват жестом масштабирования над готовой картой места.
- Скругление может обрезать действия и фокус у края → проверить атрибуцию и штатную кнопку на узком экране; сохранить место под них.
- Общий компонент обслуживает несколько разделов → включать режим только через адаптер места и проверить неподвижные фоновые карты.

## Migration Plan

1. Получить разрешение реализации этих артефактов. Ранее согласован способ управления, но не подготовленный change.
2. Внести оформление и локальный режим жестов, обновить тесты, дизайн-гайд и пояснения ADR-028/039.
3. Выполнить проверки и ревью diff, синхронизировать основные specs, завершить change по проектному workflow. Не архивировать связанный `add-events-calendar`, для которого владелец отдельно отложил архивирование.
4. Откат возвращает оформление, режим жестов и соответствующие документы вместе; миграции данных нет.
