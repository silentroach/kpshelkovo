# Design

## Context

Мотивация и границы согласованного результата описаны в [proposal](/openspec/changes/improve-search-empty-state/proposal.md), поведение в [delta spec](/openspec/changes/improve-search-empty-state/specs/search/spec.md).

[SearchDialog](/apps/www/src/components/search/SearchDialog.svelte) уже различает начальное состояние, загрузку, результаты, пустую выдачу, ошибку и недоступный dev-индекс. Состояние `empty` устанавливается после актуального успешного ответа с нулевым `total`. Видимое сообщение и текст `announcement` сейчас заданы отдельно. `query` хранит ввод пользователя; клиент может нормализовать поисковую формулировку независимо от него.

Решение следует [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md): интерфейс остаётся владельцем представления результатов. Локальное оформление принадлежит компоненту по [ADR-034](/docs/decisions/034-native-css-architecture.md).

## Goals / Non-Goals

**Goals:**

- Вычислять одну актуальную строку для видимого сообщения и существующего `aria-live`, сохраняя модель состояний диалога.

**Non-Goals:**

- Изменение поискового клиента, нормализации запроса, корпуса, ранжирования, загрузки или интерфейсов данных.
- Дополнительные ссылки, кнопки, видимый заголовок поля и отдельный компонент подсказок. Связанные продуктовые идеи перечислены в proposal.

## Decisions

### Длина введённого запроса

Вычислять сообщение через `$derived` от `query`, используя условие `query.trim().length > 30`. Внутренние пробелы, включая повторные, учитываются; исходное значение поля не переписывается. Для длины используется обычная длина JS-строки, как в существующем ограничении `maxlength`.

Длина относится к вводу пользователя. Подсчёт по нормализованному запросу клиента мог бы убрать служебные слова или пробелы и изменить согласованную границу. Отдельные `$state`, `$effect`, таймеры и модуль вычисления для этой строки не нужны.

### Одна строка для двух представлений

Подставлять выбранную строку в существующий `<p class="state-message">` ветки `empty` и возвращать её из соответствующей ветки `announcement`:

- до 30 символов включительно: «Ничего не нашли. Попробуйте другие слова»;
- более 30 символов: «Ничего не нашли. Попробуйте другие слова или сократите запрос».

Это оставляет одно место выбора текста и даёт ту же помощь пользователю скринридера. Строка выводится обычным текстом Svelte. Существующие переносы и оформление `state-message` подходят для двух предложений; новое оформление в дизайн-гайде не требуется.

Показ привязан к `empty`. При редактировании пустой выдачи `beginSearch` переводит её в загрузку; очистка поля возвращает `initial`. Уже существующая проверка актуальности ответа защищает подсказку от устаревшего запроса. Новые обработчики переходов не добавляются.

### Соразмерная проверка

Использовать существующие тесты [SearchDialog](/apps/www/src/components/search/tests/SearchDialog.test.ts), проверку типов и production-сборку. Границу 30/31, пробелы и смену вариантов проверить разовым браузерным сценарием на этой сборке. Для небольшой текстовой ветки новые постоянные тесты и снимки точных строк не нужны.

Браузерный сценарий охватывает короткий запрос без результатов, ровно 30 и 31 символ, внешние и внутренние пробелы, возврат с длинного запроса к короткому, очистку поля и запрос с результатами. Проверить видимый текст, содержимое существующего `aria-live`, сохранность введённого значения и перенос длинной подсказки на узком экране. Точный ввод для пустой выдачи выбрать на проверяемой сборке; пример `телепортация` из issue не становится постоянной поисковой фикстурой.

## Risks / Trade-offs

- Длина запроса не объясняет причину отсутствия результатов. Порог 30 служит согласованным условием полезности совета; текст предлагает действие, не утверждая причину неудачи.
- Отдельное вычисление видимой и объявляемой строк могло бы дать разные советы. Общая вычисляемая строка устраняет это расхождение.
- Дополнительный текст увеличивает высоту пустой выдачи. Проверить естественный перенос на ширине 390 px и при увеличении текста; использовать существующую прокрутку области результатов.

## Migration Plan

После разрешения реализации изменить компонент и выполнить приёмку из [tasks](/openspec/changes/improve-search-empty-state/tasks.md). Публикация проходит обычной сборкой сайта; данные и индекс не требуют миграции. Откат возвращает изменение компонента вместе с сопровождающими specs.
