# Design

## Context

Мотивация — в [proposal.md](proposal.md); контракт — в [specs/parcel-map/spec.md](specs/parcel-map/spec.md). Сейчас `details-public.ts` строит JSON из доменной записи, `details-public-schema.ts` проверяет его при сборке, а `PlaceMap.svelte` читает `response.json()` и отображает последнюю цену из `priceHistory`. Архивированный `add-parcel-details-popup` фиксирует прежнюю форму DTO; этот change — отдельное, запрошенное владельцем изменение формата до слияния PR #879.

Решение опирается на [ADR-013](../../../docs/decisions/013-raw-domain-public-data-boundary.md): внутренние `areaM2` и `priceHistory` не переименовываем ради опубликованного представления. [ADR-041](../../../docs/decisions/041-parcel-records-and-exact-search.md) сохраняет отдельный статический файл сведений и отложенную загрузку.

## Goals / Non-Goals

**Goals:**

- Переименовать и упаковать только публичные поля, оставив смысл площади (м²) и цены (рубли) неизменным.
- Сохранить проверку всего создаваемого файла на этапе сборки и лёгкий клиент без Zod.
- Сохранить читаемость карты рядом с выбранной позицией и компактную видимую реакцию закрытия без уменьшения удобной области нажатия.

**Non-Goals:**

- Менять редакционные записи, доменную модель, геометрические файлы или поиск.
- Публиковать историю в интерфейсе либо поддерживать два формата JSON в клиенте: первоначальный файл ещё не вошёл в основную ветку.
- Проецировать все вершины кадастровой геометрии в пиксели ради точной проверки пересечения попапа с полигоном: владелец согласовал выбор свободной стороны с отступом и fallback у краёв карты.

## Decisions

### Публичный адаптер отвечает за изменение формы

В `details-public.ts` собирать из доменной записи `code`, `status`, `area: parcel.areaM2` и `price`: `history` строить из каждого наблюдения как `[on, price]` без сортировки, `last` брать из последнего наблюдения и не добавлять при пустой истории. Публичная Zod-схема проверяет выход (включая даты и суммы в каждой паре); объект `price` существует и при пустой истории. В готовом JSON необязательные значения отсутствуют, `null` не используется. `part` не передаётся: `selectedParcel.part` уже доступно карте.

Альтернатива — переименовать доменные `areaM2` и `priceHistory` или использовать их без адаптера. Это распространило бы изменение публичного формата на загрузчик, обновлятор и другие потребители доменной модели вопреки ADR-013. Пара `price.last`/`price.history` намеренно дублирует последнюю сумму ради прямого чтения; тест публичного адаптера защищает их согласованность.

### Клиент читает обычный JSON

`PlaceMap.svelte` продолжает вызывать `response.json()` и импортировать только TypeScript-тип DTO. Небольшая проверка полей, нужных попапу (`code`, необязательная `area`, необязательная `price.last` и наличие массива `price.history`), сохраняет уже существующее поведение ошибки и повтора; полную историю проверяет Zod при сборке. Попап использует `price.last`, а название части — из `selectedParcel`. Не добавлять runtime-импорт публичной схемы, Zod или универсальный парсер.

### Локальная поверхность и размещение попапа

Для участка уменьшить предел ширины с `16rem` до `15rem`, использовать слегка прозрачный фон панели, но оставить текст, границу и контраст фокуса непрозрачными. При вычислении положения от опорного маркера использовать фактическую ширину панели (в том числе при увеличенном базовом шрифте), предпочитать сторону с достаточным пространством и отступом, при нехватке места переходить на другую сторону или применять существующий clamp в карте. Проверять стрелку после позиционирования: она остаётся только при реальном направлении к опорной точке. Приближение не обещает точной проверки пересечения с каждым сегментом полигона — размер участка и форма могут быть произвольными.

Крестики обоих попапов продолжают иметь кликабельную область `44 × 44 px`; на hover показывать компактную подложку вокруг иконки, а не заливку всей области. Сохранять заметный keyboard focus на прежнем контуре кнопки и согласовать общее правило в дизайн-гайде. Вариант уменьшить саму кнопку отвергнут: тач-цель станет хуже ради визуального эффекта.

## Risks / Trade-offs

- Дублированная `last` может разойтись с последней парой истории → получать оба значения из одной доменной записи и проверять согласованность тестом, в том числе при снижении цены и пустой истории.
- Клиент не проверяет каждую пару при получении JSON → исходный статический артефакт целиком проверен при сборке; повреждённые поля попапа дают локальную ошибку с повтором, а схема не увеличивает клиентский бандл.
- Без точной проекции большой или сложный контур всё же может попасть под карточку → выбирать свободную сторону и больший отступ, приоритет отдавать размещению внутри карты и сохранению кликабельного закрытия.

## Migration Plan

В той же ветке и PR #879 изменить публичную схему, адаптер, клиент, локальные стили двух попапов и тесты одной сборкой, обновить дизайн-гайд и отчёты бандлов при изменении клиентского кода, затем синхронизировать основной `parcel-map` spec. PR ещё не слит, поэтому production-миграция предыдущего JSON не требуется. Откат — вернуть прежнюю форму в адаптере и схеме одновременно с потребителем; UI-правки откатываются в том же PR.
