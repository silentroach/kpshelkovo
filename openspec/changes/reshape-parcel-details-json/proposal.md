# Proposal

## Why

Файл сведений участка из PR #879 дублирует часть посёлка, которую карта уже знает, а площадь и история цен представлены неудобно для чтения клиентом и других потребителей JSON. До слияния PR стоит закрепить запрошенный владельцем компактный формат и согласовать его с попапом.

## What Changes

- **BREAKING:** в `/map/data/parcels/details/<основной-код>.json` удалить `part`, переименовать `areaM2` в `area` без изменения единиц измерения (м²).
- **BREAKING:** заменить `priceHistory` на `price`: необязательная последняя сумма `last` и полная `history` как упорядоченный массив пар `[дата наблюдения, полная цена в рублях]`. При пустой истории `price.history` остаётся `[]`, а `last` отсутствует.
- Обновить сборку и потребителя JSON без Zod в клиентском JavaScript. Не менять доменную модель, поведение выбора участка и видимые формулировки попапа.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `parcel-map`: публичный контракт файла сведений, из которого попап берёт площадь и последнюю цену.

## Impact

- Связанная задача: [#861](https://github.com/silentroach/kpshelkovo/issues/861), незавершённый [PR #879](https://github.com/silentroach/kpshelkovo/pull/879); изменение планируется в той же ветке и PR. Предыдущий change `add-parcel-details-popup` уже архивирован и не переписывается.
- Затронуты Public DTO и его Zod-схема на этапе сборки, адаптер, `PlaceMap.svelte`, тесты JSON и попапа. Поля `code` и `status`, маршрут, правила публикации, исходные редакционные записи и доменная модель остаются прежними.
- Существующие потребители старых имён полей должны перейти на новый формат в одной сборке. Отдельная production-приёмка и миграция сохранённых данных не нужны: изменение вносим до слияния PR с первоначальной публикацией этого маршрута.
