# Proposal

## Why

Перечень услуг из приложения № 1 повторяется в шести офертах, но для его просмотра приходится открывать полный договор. В [задаче #1360](https://github.com/silentroach/kpshelkovo/issues/1360) владелец просит отдельную таблицу и обновление промпта оферт; распознанный текст документа должен сохраниться.

## What Changes

- Добавить `/kb/ok/service-list/` с перечнем услуг: колонки «№», «Перечень и состав услуг», «Периодичность», сезонные группы и исходная нумерация.
- Сохранить формулировки распознанного документа без редакторского пересказа. По уточнениям владельца убрать повторный внутренний заголовок и конечные точки периодичности; жёлтое пояснение о приложении № 1 связывает слова «публичным договорам» с `/kb/ok/#публичные-оферты`, затем следует `[TOC]`. Вместо отдельного блока PDF оригиналы доступны через договоры, источники учитываются в `sources`. Добавить ссылку на страницу из раздела ОК Комфорт.
- Разрешить обычные GFM-таблицы в HTML базы знаний через явное включение в её рендере. Публичный Markdown строить из того же содержимого списками. Это изменение действующего ограничения требует согласования.
- Дополнить `/prompts/oferta.md`: сверять приложения всех оферт и синхронно обновлять отдельный перечень, сохраняя текст документа. При различиях приложений остановиться и сообщить владельцу.
- Полные оферты сохраняют свои приложения. Их обновление, новая редакция PDF, интерактивные таблицы и переработка перечня в объём не входят.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `knowledge-base`: табличное представление редакционного источника в HTML с сохранением данных в списочном Markdown companion.

## Impact

- Общий Markdown-пакет: явное разрешение таблиц при HTML-рендере и AST-преобразование таблиц в списки.
- Приложение: общая Markdown-обёртка, HTML и companion KB, локальное оформление таблиц.
- Материалы и инструкции: новая KB-страница, индекс ОК Комфорт, промпт оферт, справочник Markdown, локальные правила KB и дизайн-гайд.
- Новые зависимости, клиентский JavaScript и отдельное хранилище услуг не требуются.
- Приёмка выполняется на локальной production-сборке до PR; отдельная production-приёмка не нужна.

Владелец разрешил реализацию 17 ноября 2026 года и уточнил вводную ссылку на список договоров.
