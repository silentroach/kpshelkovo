# ADR-041: Участки отдельно от мест, точный поиск в Pagefind

## Статус

Принят; дополняет [ADR-013](013-raw-domain-public-data-boundary.md), [ADR-025](025-static-full-text-search-with-pagefind.md), [ADR-028](028-markdown-first-places-map.md) и [ADR-039](039-shared-yandex-maps-runtime-and-preview.md).

## Дата

2026-09-22

## Контекст

Житель ищет номер застройщика и границы нынешнего участка. Место по ADR-028 имеет карточку, маркер и редакционное описание; участок имеет кадастровую геометрию и может объединять несколько обозначений. Pagefind по ADR-025 ищет содержательные HTML-страницы, а отдельные карточки для тысяч участков не нужны.

## Решение

- Хранить нынешние участки в отдельной Markdown-коллекции: один кадастровый контур и одна редакционная запись на участок, основной код и подтверждённые алиасы. Снимки источников и основания соответствий остаются отдельно от записей; неопределённые связи не выводятся из близости меток. Raw-схемы, доменная модель и публичное представление карты следуют ADR-013.
- Добавить выключенный по умолчанию слой к существующей карте Яндекса, не расширяя сущность места, её маршруты и граф упоминаний. Геометрию загружать по запросу; обычные границы показывать одинаково без зависимости от статуса продажи и без его производного признака в картографических данных. Исходный статус продажи, цену и заметки не публиковать; поправку подложки применять при сборке публичного представления карты, не меняя исходный кадастр.
- Добавлять действующие участки непосредственно в Pagefind после индексирования HTML, по одной записи без геометрии на участок. Точный фильтр по полному либо короткому основному коду и алиасам даёт один результат на контур по `/map/?p=<полный-код>` перед текстовыми страницами. Текстовый поиск исключает записи участков фильтром; карта разрешает прямую ссылку по своему геометрическому JSON без поискового индекса.

## Почему так

Помещать участки в places означало бы создавать фиктивные карточки и менять смысл маркеров, видимости и backlinks. Отдельные HTML-страницы участков требовали бы создавать карточки ради поиска и зависели бы от stemming и ранжирования. Custom records и точный фильтр Pagefind сохраняют поиск без геометрии и дополнительного словаря; один публичный JSON карты собирается из того же редакционного хранилища.

## Последствия

- Поиск и карта получают представления одного набора из проверенного геометрического feed при сборке; новый снимок проходит редакционную проверку до публикации. Размер и холодный трафик индекса нужно оценивать вместе с удалённым словарём, а не считать уменьшение числа файлов экономией байтов.
- Участок не получает HTML-карточку и не становится местом. Коммерческие сведения остаются в редакционных данных до отдельного решения об их показе.
