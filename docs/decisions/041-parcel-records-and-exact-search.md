# ADR-041: Участки отдельно от мест, полнотекстовый поиск в Pagefind

## Статус

Принят, уточнён 2026-09-24; дополняет [ADR-013](013-raw-domain-public-data-boundary.md), [ADR-025](025-static-full-text-search-with-pagefind.md), [ADR-028](028-markdown-first-places-map.md) и [ADR-039](039-shared-yandex-maps-runtime-and-preview.md).

## Дата

2026-09-22

## Контекст

Житель ищет номер застройщика и границы нынешнего участка. Место по ADR-028 имеет карточку, маркер и редакционное описание; участок имеет кадастровую геометрию и может объединять несколько обозначений. Pagefind по ADR-025 ищет содержательные HTML-страницы, а отдельные карточки для тысяч участков не нужны. Точный фильтр по номерам участков требовал дополнительного запроса и заметно увеличивал холодный трафик.

## Решение

- Хранить позиции генплана в отдельной Markdown-коллекции: одна редакционная запись с основным кодом и подтверждёнными алиасами может относиться к одному или нескольким самостоятельным нынешним кадастровым участкам. Каждый кадастровый номер, исходный контур и площадь остаются отдельными; карта показывает одну позицию и сохраняет межи. Цена и статус предложения относятся к позиции, не к каждой её кадастровой части. Снимки источников и основания соответствий остаются отдельно от записей; неопределённые связи не выводятся из близости меток. Raw-схемы, доменная модель и публичное представление карты следуют ADR-013.
- Добавить выключенный по умолчанию слой к существующей карте Яндекса, не расширяя сущность места, её маршруты и граф упоминаний. Геометрию загружать по запросу; в публичном представлении карты передавать необязательный исходный статус предложения застройщика для слабой заливки контуров и сероватой капсулы недоступного участка. Свободный и забронированный участки выглядят одинаково, проданный и участок без статуса остаются нейтральными. Цену, признаки и редакционные заметки не публиковать; поправку подложки применять при сборке публичного представления карты, не меняя исходный кадастр.
- Добавлять действующие позиции непосредственно в Pagefind после индексирования HTML, по одной записи без геометрии на позицию. Полный и короткий варианты основного кода и подтверждённых алиасов включать в поисковый текст записи; служебную подпись раздела не индексировать как слово каждой позиции. Для обозначений одного полнотекстового запроса достаточно: позиции возвращаются вместе со страницами в общем порядке без обязательного первенства точных совпадений. Результат ведёт по основному коду на `/map/?p=<полный-код>`, а карта разрешает прямую ссылку по своему геометрическому JSON без поискового индекса.

## Почему так

Помещать участки в places означало бы создавать фиктивные карточки и менять смысл маркеров, видимости и backlinks. Отдельные HTML-страницы участков требовали бы создавать карточки ради поиска. Custom records Pagefind сохраняют поиск без геометрии и дополнительного словаря; короткие обозначения индексируются явно, потому что токенизация полного кода не обеспечивает их поиск. Отказ от отдельного точного фильтра сокращает холодную загрузку индекса. Один публичный JSON карты собирается из того же редакционного хранилища.

## Последствия

- Поиск и карта получают представления одного набора из проверенного геометрического feed при сборке; новый снимок проходит редакционную проверку до публикации. Размер и холодный трафик индекса нужно оценивать вместе с удалённым словарём, а не считать уменьшение числа файлов экономией байтов.
- Префиксы и цифровые фрагменты могут находить несколько участков по обычной релевантности Pagefind; они не расширяются отдельным правилом точного поиска. Подтверждённые алиасы остаются в доменной модели и поясняются при совпадении с запросом.
- Участок не получает HTML-карточку и не становится местом. Цены, признаки и заметки остаются в редакционных данных до отдельного решения об их показе.
- Окраска остаётся второстепенной подсказкой из сохранённого снимка: она не подтверждает собственность и актуальную доступность сделки. Отсутствие статуса нельзя принять за продажу; карта не даёт ответа по цвету без проверки первоисточника.
