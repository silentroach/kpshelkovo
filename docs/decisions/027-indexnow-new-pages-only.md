# ADR-027: IndexNow только для новых страниц

## Статус

Принят, заменяет ADR-026

## Дата

2026-08-16

## Контекст

ADR-026 использовал checksum-diff готового сайта и отправлял в IndexNow добавленные, изменённые и удалённые HTML-маршруты. Это соответствует возможностям протокола, но не различает содержательные и технические изменения страницы.

Общий Astro layout подключает клиентские компоненты на всех страницах. Изменение такого компонента меняет хеш его бандла и ссылку на этот бандл почти во всех HTML-файлах. В результате небольшой UI-релиз может без пользы отправить в IndexNow почти весь сайт и потратить crawl quota.

Для проекта важна быстрая индексация новых страниц. Обычные изменения и удаления допустимо обнаруживать через регулярный обход и sitemap.

## Решение

Отправлять в IndexNow только канонические индексируемые маршруты, для которых `rsync --itemize-changes` вернул маркер нового обычного файла `<f+++++++++` для `index.html`. Знак `<` означает отправку локального файла на удалённый сервер.

Изменённые и удалённые HTML-файлы не отправлять. Assets и маршруты, отсутствующие в приватном URL-манифесте новой сборки, также не отправлять.

До успешного ответа IndexNow продолжать хранить сырой rsync-манифест вне web root. Это сохраняет маркер нового файла при перезапуске job, даже если следующий dry-run уже увидит опубликованный файл как существующий.

## Рассмотренные альтернативы

### Определять содержательные изменения

Можно сравнивать только основной текст, метаданные или доменную дату обновления. Для этого нужен отдельный контракт для разных типов страниц и дополнительное состояние. Такая сложность не нужна, пока проект не стремится ускорять переиндексацию существующих материалов.

### Оставить checksum-diff всех HTML

Это автоматически замечает любые изменения, но массово отправляет страницы после изменения общего layout или клиентского бандла. Для текущей цели этот сигнал слишком шумный.

### Отправлять удаления

Это ускорило бы удаление URL из поиска, но проект не требует такой срочности. Поисковики увидят 404 при обычном обходе.

## Последствия

- Новая индексируемая страница попадает в IndexNow сразу после успешного deploy.
- Изменения общего layout, клиентских компонентов и метаданных существующих страниц не создают массовую отправку.
- Страница, которая уже существовала с `noindex`, а затем стала индексируемой, не считается новой; её обнаружение остаётся задачей sitemap и обычного обхода.
- Удалённые страницы исчезают из индекса без ускорения со стороны IndexNow.
- Повторный deploy после ошибки IndexNow сохраняет новые URL благодаря накопленному rsync-манифесту.
