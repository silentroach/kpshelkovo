# ADR-027: IndexNow только для новых страниц

## Статус

Принят, заменяет [ADR-026](/docs/decisions/026-indexnow-after-static-deploy.md).

## Дата

2026-08-16

## Контекст

Checksum-diff HTML не отличает содержательные изменения от технических: новый хэш общего клиентского бандла может изменить почти все страницы. Для проекта важна быстрая индексация новых материалов; массовые уведомления о таких технических правках расходуют crawl quota без пользы.

## Решение

IndexNow уведомляет только о новых файлах `index.html`, чьи канонические URL входят в отфильтрованный sitemap-манифест текущей сборки. Уведомление следует за публикацией сайта и проверкой публичного key-файла: вызов во время build создал бы гонку с доступностью ключа и страниц.

Изменения и удаления существующих страниц, assets и URL вне манифеста не отправляются. Существовавшая страница с `noindex`, ставшая индексируемой, также не считается новой. Её обнаружение, обновления и удаления остаются обычному обходу и sitemap.

Неотправленные новые URL сохраняются вне web root до успешного завершения отправки; при повторе их снова сверяют с текущим манифестом. Ошибка уведомления делает job неуспешным, но не откатывает уже опубликованный сайт. Порядок действий и восстановление описаны в [deploy-runbook](/README.md#indexnow).

## Почему так

Sitemap уже владеет полным индексируемым набором, а deploy знает, какие файлы добавляются: отдельный сервис или CMS hook не нужен. Анализ основного текста, метаданных или `lastmod` потребовал бы дополнительных правил и состояния для разных страниц, хотя ускорение переиндексации не является целью. Удаления также не требуют срочного уведомления: поисковик увидит 404 при обходе.

Ключ хранится в repository secret и публикуется вместе с артефактом: это позволяет ротировать его без фиксации в истории Git. Запрос выполняет runner, поэтому CSP браузера не расширяется.
