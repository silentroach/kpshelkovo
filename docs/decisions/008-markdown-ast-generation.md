# ADR-008: Генерация Markdown через AST

## Статус

Принят

## Дата

2026-05-14

## Контекст

Сайт публикует Markdown-представления страниц, индексы и агентные путеводители. Генераторы объединяют структурные данные с готовым редакционным Markdown. Ручная сборка строк заставляет каждый генератор заново решать экранирование, вложенность списков, ссылки и сериализацию frontmatter; единый стиль вывода легко расходится между разделами.

В репозитории уже используется экосистема unified/remark и общий пакет `@shelkovo/markdown`. Это позволяет разделить содержание документов, которым владеет приложение, и универсальную сборку Markdown.

## Решение

- Генерировать публичные Markdown-документы, включая Markdown-совместимые `llms.txt`, через mdast. Пакет предоставляет тонкие функции создания узлов, парсинг существующих редакционных фрагментов и единый сериализатор.
- Использовать `mdast-util-to-markdown` напрямую для сериализации и совместимый парсер `mdast-util-from-markdown`. Расширения GFM и frontmatter работают в той же AST-модели; объект frontmatter сериализуется через `yaml`.
- Содержание, выбор публичных полей и доменные преобразования остаются в приложении. Пакет централизует экранирование и стиль вывода, сохраняя Markdown-семантику вставленных редакционных фрагментов.

Генерация Markdown и рендер в HTML — разные операции. Они используют общую инфраструктуру пакета, но доменная обработка сайта остаётся на уровне приложения по [ADR-003](003-markdown-pipeline-layering.md).

## Рассмотренные альтернативы

- **Строковые helpers или шаблоны.** Проще для статичного текста, но оставляют каждому генератору экранирование, необязательные блоки и сочетание frontmatter с редакционным Markdown.
- **`remark-stringify` как основной API.** Уместен в unified-цепочке, но при непосредственной сборке AST добавляет обёртку над тем же `mdast-util-to-markdown`, не устраняя необходимость создавать узлы.
- **Отдельный Markdown DSL.** Может дать компактную запись, но вводит вторую модель разметки и требует отдельно решать совместимость фрагментов, frontmatter и рендера.

## Последствия

AST-код объёмнее простого шаблона, зато экранирование и сериализация поддерживаются в одном месте. Изменение стиля вывода затрагивает общий пакет и его проверки. Тонкие фабрики не заменяют стандартные узлы mdast собственным языком разметки.
