# ADR-042: Общая рамка карты как feature-owned CSS

## Статус

Принят; уточняет [ADR-034](034-native-css-architecture.md) для явно подключаемых стилей функции.

## Дата

2026-09-28

## Контекст

Рамка и подпись встроенной карты нужны редакционным картам и карточкам мест. Их CSS подключается отдельно от глобальной основы сайта и может загрузиться до объявления порядка слоёв. Если поместить правила в `@layer primitives`, последующий `reset` может обнулить границу и отступы; оставлять при этом unlayered классы `ui-*` означало бы выдавать частный стиль за общесайтовый примитив вопреки ADR-034.

## Решение

`apps/www/src/components/maps/map-frame.css` — стиль функции карт, а не примитив дизайн-системы. Каждый потребитель явно импортирует файл и добавляет opt-in классы `map-frame` / `map-frame__caption`. Его unlayered правила относятся только к этой рамке и подписи; они не объявляют reset, стили тегов или site-level `ui-*` API. Размер и поведение каждой карты остаются у её владельца. Для других узких feature-owned стилей такое исключение допустимо только при тех же условиях: явное подключение каждым потребителем и ограничение собственными opt-in классами. В остальном действует порядок слоёв ADR-034.

## Почему так

Глобальный `ui-*`-примитив в `@layer primitives` здесь ненадёжен из-за порядка загрузки CSS; перенос правила в `global.css` заставил бы все страницы получать стили карты и скрыл бы зависимость потребителей. Препроцессор ради повторения нескольких деклараций добавил бы зависимость без новой возможности. Узкий unlayered файл сохраняет прямую связь с картами и заведомо сильнее layered foundation. Если ему понадобятся глобальные переопределения, границу владения надо пересмотреть, а не повышать специфичность.
