# ADR-030: Нормализованные источники детальной сметы

## Статус

Принят

## Дата

2026-08-26

## Контекст

Публичный файл `/815/regulation/data/estimate-details-2026.json` связывает работы, ресурсы и контрольные итоги с фрагментами исходных PDF. В версии 1 массивы `source_refs` повторяли полные объекты источников при каждом упоминании, в том числе внутри `needs_check`. Сжатие уменьшало передачу по сети, но после распаковки клиент всё равно разбирал и хранил эти повторы.

При переходе на v2 нормализация уменьшила несжатый JSON с 847 747 до 335 893 байт (−60,4%), а Brotli-ответ — на 3,5%. Подробные измерения и результаты поиска потребителей сохранены в [PR #278](https://github.com/silentroach/kpshelkovo/pull/278).

## Решение

- Вынести полные источники в корневой реестр `sources`, а в `source_refs` оставить ссылки на него. Это убирает повторные тела источников и сохраняет трассируемость до PDF, страницы, фрагмента и имеющейся цитаты либо её структурированных позиций.
- Использовать короткие последовательные ID вместо хешей содержимого. ID нужны для связей внутри ответа; независимое узнавание источника между обновлениями не требовалось. Порядок первого упоминания даёт повторяемый результат для неизменного упорядоченного набора.
- Сохранить отдельный публичный адаптер по [ADR-013](013-raw-domain-public-data-boundary.md). Внутренняя модель с полными объектами источников удобна для расчётов и Markdown-представлений.

## Рассмотренные альтернативы

- **Полные объекты в каждом `source_refs`.** Сохраняли самодостаточность отдельного факта и формат v1, но оставляли измеренную стоимость повторов после распаковки.
- **Хеши содержимого.** Сохраняли бы ID при перестановке фактов, но добавляли строки с высокой энтропией. Пробный вариант увеличил Brotli-ответ на 5,7% относительно v1; короткие ID оказались компактнее.

## Исторический переход на v2

В PR #278 формат намеренно изменили несовместимо и обозначили `schema_version: "2"`. Поиск по репозиторию и публичному коду GitHub не обнаружил внешних потребителей v1, хотя не исключал частных. Для этого перехода решили не сохранять параллельный endpoint v1: поддержка двух форматов и точек обнаружения не имела подтверждённой пользы. Этот выбор относится к тому переходу, а не задаёт общую политику будущих breaking changes.

## Последствия

- Потребителю нужен реестр из того же ответа, чтобы перейти от факта к источнику; ID нельзя использовать как постоянный ключ между обновлениями.
- Тела источников занимают место по числу уникальных источников, а повторные упоминания добавляют только ссылки.
