# ADR-040: Портреты людей в публичном S3

## Статус

Принят

## Дата

2026-09-22

## Контекст

Портрет в профиле помогает узнать человека в лицо. Внешний сайт может удалить или заменить фотографию, а хранение бинарных копий в Git увеличивает историю репозитория. [ADR-021](/docs/decisions/021-public-section-files-in-s3.md) объясняет выбор общего S3-хранилища, [ADR-023](/docs/decisions/023-news-images-in-public-s3.md) — подготовленного JPEG web-master. Для людей владелец выбрал текущий портрет без истории редакций; действующий контракт этого исключения — [people-photos](/openspec/specs/people-photos/spec.md), общий контракт файлов — [public-media](/openspec/specs/public-media/spec.md).

## Решение

- Разрешить публикацию портретов из публичных источников для профилей людей в `kps-public`. Связь имени с фотографией подтверждать подписью первоисточника.
- Раздел-владелец — `people`; ключ — `people/<slug>.jpeg`. При замене портрета содержимое обновляется по тому же адресу. Датированные редакции не создаются.
- Применять общий [JPEG-профиль runbook](/ops/storage/public-media.md#подготовка-фотографии-новости-иллюстрации-отзыва-или-портрета), сохраняя полный кадр. Удалять встроенные метаданные; GPS для портретов не восстанавливать.
- Во frontmatter хранить канонический media URL, фактические размеры файла и необязательный источник с названием и ссылкой. Организация человека не определяет источник фотографии.
- Доставлять небольшой портрет обычным `<img>` с размерами и альтернативой из имени. Это сохраняет независимость сборки от получения фотографии и не требует производных файлов или клиентского JavaScript.
- Публиковать с коротким кешем без `immutable` по [runbook](/ops/storage/public-media.md). Сначала проверять точный ключ и SHA-256; одинаковый файл использовать повторно, различающийся заменять только в рамках запроса на смену портрета этого человека. После публикации проверять байты, размеры и метаданные через media-origin с учётом короткого кеша.
- При замене синхронно обновлять фактические размеры файла и источник в профиле. Откат Git сам по себе не возвращает прежнюю фотографию в S3.

## Рассмотренные альтернативы

- Внешний JPEG: профиль зависел бы от доступности и изменений первоисточника.
- Датированный ключ `people/<slug>/<snapshot-date>/portrait.jpeg`: сохраняет историю, которая для текущего портрета не нужна, и усложняет адрес.
- Круглый аватар или автоматическая обрезка: теряется часть исходного кадра.
- Astro Image Service: для небольшого портрета добавляет сетевую зависимость сборки и производные файлы без необходимости.

## Последствия

Портреты доступны по стабильным URL независимо от первоисточника. Подготовка и проверка публикации требуют отдельного шага перед добавлением ссылки в профиль. Замена становится видна после истечения proxy cache и клиентского кеша. Откат кода или данных не удаляет опубликованные объекты.
