# ADR-043: Заголовки статических endpoints из ответов Astro

## Статус

Принят, 2026-10-02. Уточняет границу ручного nginx в [ADR-011](/docs/decisions/011-public-surface-registry.md) и [ADR-036](/docs/decisions/036-llms-v2-guides.md).

## Контекст и решение

Astro сохраняет тела prerendered-ответов в файлы, но статическая раздача nginx теряет их HTTP-метаданные. Ручное повторение MIME и discovery-ссылок уже привело к расхождению с обработчиками. Реестр публичных поверхностей не перечисляет все конкретные URL параметризованных endpoints и не знает имена скачиваемых файлов.

Локальная static-only интеграция получает фактические заголовки через `staticHeaders` и генерирует один непубличный nginx-фрагмент с точными locations всех prerendered endpoints. Карта ответов определяет выборку, а список выпущенных Astro-файлов и стабильные API-поверхности помогают обнаружить неполное покрытие. Повторное исполнение обработчиков и runtime-сервер не нужны.

Обработчики владеют объявленными `Content-Type`, `Link`, `Content-Disposition`, `X-Robots-Tag` и `Vary`. Неизвестное application-owned поле останавливает сборку, вместо того чтобы исчезнуть при публикации. Транспортные поля формирует nginx. MIME и параметры передаются через `default_type` и charset-модуль, без второго `Content-Type`; строки проверяются и экранируются для nginx.

Кеширование, логи, security include и существующие дополнения прямого Markdown остаются компактной операционной политикой. Для Markdown без собственных значений сохраняются `noindex, follow`, `Vary: Accept` и ссылка на наиболее конкретный llms из существующего app-helper. Объявленные значения не заменяются ручными копиями.

HTML, согласование Markdown через `Accept`, файлы `public/`, инфраструктура и fallback сохраняемых `/static/` поколений остаются ручными. Генератор не становится реализацией всего реестра или всего nginx. Deploy устанавливает site config и оба include комплектом с проверкой `nginx -t` и восстановлением прежних файлов и enabled-site при ошибке.

## Альтернативы и последствия

- Ручные locations с тестами сохранили бы второй источник метаданных и необходимость обновлять правила для новых URL.
- Генерация из реестра потребовала бы заново получать конкретные пути и заголовки, которые уже есть в ответах Astro.
- Exact locations увеличивают конфиг, зато не требуют сложной группировки regex и сохраняют индивидуальные метаданные. Размер и время проверки измеряются при изменениях.

Пути артефактов, проверки и откат описаны в [окружении разработки](/docs/development.md#метаданные-статических-endpoints). Публичный контракт хранится в OpenSpec, а не в этом историческом обосновании.
