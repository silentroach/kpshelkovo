# ADR-035: Страницы сервисов и свежие события в поиске

## Статус

Принят. Уточняет [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md); действующие требования внутреннего поиска и внешней индексации статуса — [search](/openspec/specs/search/spec.md).

## Дата

2026-09-10

## Контекст

Поиск по сайту индексировал отдельные события с поясняющим текстом, но исключал главную статуса и страницы сервисов. По общим запросам жители получали старые отключения вместо постоянного адреса с состоянием сервиса. Внешние поисковики могли индексировать также историю и календарные журналы.

Полное исключение событий из поиска по сайту лишает жителей возможности найти недавнее отключение по причине, месту или дате. Внешняя выдача обновляется с задержкой, поэтому переключать её правила при каждом начале и окончании события нецелесообразно.

## Решение

Разделить две задачи: внутренний поиск помогает найти текущее состояние и недавнее событие, внешняя выдача ведёт к постоянным точкам входа — главной статуса и страницам сервисов.

Внутренний корпус отбирается при сборке по окончанию события, чтобы длительное действующее ограничение не исчезало из поиска из-за возраста начала. Дополнительное возрастное понижение статуса не нужно: актуальность уже задаёт корпус. Дата начала помогает различать одноимённые события; требование к поисковому заголовку принадлежит [search](/openspec/specs/search/spec.md). Исторические списки остаются доступны читателю, но не возвращают старые события в поиск через родительскую страницу.

Внешний `noindex` события и внутреннее включение в Pagefind независимы. Постоянная внешняя политика для событий, истории и календарей не зависит от частоты обхода роботом. Она исключает отдельные URL, а не все упоминания исторических сведений на индексируемых страницах сервисов. Самостоятельные новости и разборы следуют правилам `/news/`; подробность записи статуса сама по себе не меняет её раздел.

Проверка актуальности использует существующую дату окончания при сборке. Для неё не нужны новые поля материала, клиентский фильтр или отдельный процесс переиндексации. Обновление поиска остаётся частью полной публикации сайта по [ADR-031](/docs/decisions/031-status-incident-lifecycle.md).

## Владельцы действующих правил

- [search](/openspec/specs/search/spec.md) — постоянные точки входа, включительное окно актуальности от окончания, индексируемый текст и внешняя индексация: `noindex, follow`, self-canonical, разрешённый обход и исключение из sitemap/IndexNow.
- [status-lifecycle](/openspec/specs/status-lifecycle/spec.md) — фазы, граница окончания, снимок сборки и свежесть публикации. Расписание задано в [CI/CD](/.github/workflows/ci.yml).
- [ADR-009](/docs/decisions/009-markdown-accept-negotiation.md) и [nginx-конфигурация](/ops/nginx/kpshelkovo-online.conf) — прямые Markdown-версии и content negotiation, включая `X-Robots-Tag`.
- [sitemap](/apps/www/src/lib/sitemap.ts) и [IndexNow](/apps/www/src/lib/indexnow.ts) — отбор внешних URL и отправка после публикации по [ADR-027](/docs/decisions/027-indexnow-new-pages-only.md).

## Рассмотренные альтернативы

- Полностью исключить события из внутреннего поиска: теряется поиск недавних отключений и будущих работ.
- Считать окно от начала: длительные действующие ограничения исчезают из поиска.
- Индексировать только ближайшие будущие события: объявленные заранее работы становятся ненайденными без пользы для читателя.
- Переключать внешнюю индексацию по возрасту: повторный обход не совпадает с жизненным циклом события и добавляет лишнюю политику.
- Индексировать весь текст страниц сервисов: старые события возвращаются в общий поиск через родительскую страницу.

## Последствия

- Постоянные страницы становятся точками входа в статус; недавние события можно найти отдельно.
- Устаревшие события выпадают из внутреннего индекса при следующей опубликованной сборке после истечения срока.
- Удаление URL из внешней выдачи происходит по мере повторного обхода, а не в момент deploy.
- Полный охват публичных JSON, RSS и llms-представлений сохраняется независимо от поискового отбора.
