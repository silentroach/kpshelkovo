# ADR-043: Авторские группы и сокращения автоматического оглавления

## Статус

Принят, 2026-10-16. Дополняет [ADR-003](/docs/decisions/003-markdown-pipeline-layering.md) и [ADR-008](/docs/decisions/008-markdown-ast-generation.md).

## Контекст

В длинном документе разделы и приложения трудно различать в одном списке. При этом ручное оглавление или отдельное название пункта требуют повторять номера и заголовки. Группировка по словам «Договор» и «Приложение» либо по маршруту страницы привязала бы общий рендер к одному виду документов.

## Решение

Автор задаёт границы групп через `::toc-group[Название]` и исключаемые из подписи фрагменты заголовка через `:toc-omit[Фрагмент]`. Полный заголовок остаётся источником ID; короткая подпись используется только в оглавлении. Группа переносит целую ветвь, включая подразделы. Аннотации принадлежат общему Markdown-пакету; полноширинное оформление KB — приложению.

Выбран синтаксис семейства remark/micromark directives с ограниченной проектной семантикой. Совместимость обычных двоеточий, неизвестных директив и упоминаний с падежом сохраняется на границе парсинга. Разные входы разбора используют один контракт. HTML и Markdown companions передают одинаковое содержание, а публичный Markdown выражает оглавление обычными списками без управляющих пометок.

## Почему так

- Отдельный `toc-label` дублировал бы название и мог расходиться с заголовком. Исключаемый фрагмент хранит текст один раз.
- Контейнер `:::…:::` оборачивал бы весь текст разделов и менял дерево документа. Маркер границы не требует такого вмешательства.
- Автоматическое распознавание приложений по словам и маршрутам не выражает намерение автора и не переносится на другие документы.
- Ручной список создавал бы вторую копию структуры и целей переходов.

Цена решения — согласованный разбор и диагностика аннотаций во всех Markdown-входах. Ошибочная граница или пустая подпись останавливают обработку, а не повреждают навигацию. Авторский формат и ограничения описаны в [README пакета](/packages/markdown/README.md); действующие требования — в [markdown-service-blocks](/openspec/specs/markdown-service-blocks/spec.md).
