# ADR-037: Печать справки и новостей через CSS

## Статус

Принят

## Дата

2026-09-13

## Контекст

Жители распечатывают справку и новости для семьи или сохраняют их в телефон. Экранное оформление мешает: в распечатку попадают меню и оглавление, ссылки теряют подчёркивание, а фотографии сохраняют экранное кадрирование.

В [задаче #723](https://github.com/silentroach/kpshelkovo/issues/723) согласовано чистое представление существующей страницы. Отдельная редакция материала для PDF создала бы второй источник содержимого и потребовала бы поддерживать его вместе с HTML.

## Решение

- Использовать штатную печать браузера и `@media print`. Сохранение в PDF выполняют браузер и ОС.
- Применять оформление ко всему `/kb/` и `/news/`: статьям, документам, страницам-разделам, лентам, архивам и тегам.
- Печатать существующий DOM. Сохранять заголовок, текст, списки, телефоны, изображения, подписи, сведения о материале и видимые источники. Списки ссылок на страницах-разделах считаются содержимым.
- Скрывать интерфейс сайта, внутристатейное оглавление вместе с его разделителем, якоря заголовков и декоративные элементы. В карточках событий сохранять дату, время и место, скрывать фоновую карту и действия интерфейса.
- Подчёркивать ссылки на их местах. Не дописывать URL и не собирать отдельный список ссылок.
- Не добавлять кнопку печати, дату печати, адрес страницы и другие служебные подписи. Колонтитулы, которые может добавлять сам браузер, остаются его настройкой.

### Владение стилями

`BaseLayout.astro` по маршруту ставит на `body` класс `site-print-content`. Общий `apps/www/src/styles/print.css` ограничивает все правила этим корнем и `@media print`; именованное правило `@page site-content` задаёт поля только для этих страниц.

Print CSS принадлежит приложению и использует слой `integration` по [ADR-034](034-native-css-architecture.md). Он связывает существующие semantic hooks оболочки, Markdown и новостных компонентов. `!important` применяется к свойствам, которые должны перекрыть unlayered экранные стили компонентов; отдельный слой overrides не вводится.

Для многостраничного содержимого снимаются мешающие разбиению grid/flex-контейнеры и обрезание. Заголовки удерживаются со следующим блоком, фотографии — с подписями. Высота изображений ограничена относительно печатной страницы, пропорции сохраняются. Обложка новости становится обычным изображением без маски и наложенного текста.

## Рассмотренные альтернативы

- Отдельный PDF-генератор, серверный маршрут или копия содержимого: не нужны для согласованного сценария, добавляют второй способ рендера и отдельные зависимости.
- Скрипт `beforeprint`, перестраивающий DOM: создаёт дополнительный жизненный цикл и не нужен для очистки оформления.
- Общие print-правила для всего сайта: у карты, таблиц сравнения и других разделов свои ограничения; расширение охвата требует отдельной проверки.

## Последствия

- Новые страницы внутри `/kb/` и `/news/` автоматически получают print-оформление. Новые типы блоков нужно проверять на разрывах страниц и при выключенной печати фонов.
- Содержимое продолжает поступать из обычного HTML; отдельного PDF-артефакта сборки нет.
- При изменении экранной геометрии новостных компонентов нужно учитывать её print-переопределения.
- Разбиение на страницы зависит от браузера, формата бумаги и масштаба. Критерий качества — читаемость и полнота содержимого, а не одинаковое число страниц.
- Проверка включает короткую инструкцию, длинную справку с подписью к изображению, многостраничный документ, страницу-раздел, новость с фотографиями и ленту. Сохранение в PDF проверяется в Chrome и Safari на компьютере, Safari на iPhone и Chrome на Android; эмуляция размера экрана не заменяет проверку системного сохранения на устройстве.
