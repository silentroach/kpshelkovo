# ADR-017: CSP с inline-исключениями для Astro и Яндекс Карт

## Статус

Принят, заменяет [ADR-005](/docs/decisions/005-csp-inline-script-policy.md).

## Дата

2026-07-01

## Контекст

Вынос проектного JavaScript в обработанные модули не устраняет inline bootstrap и загрузчики Astro islands. Их хэши зависят от сборки: рассинхронизация с nginx ломает клиентскую навигацию или islands. Nonce на каждый ответ потребовал бы изменять статический HTML и CSP при раздаче, усложнив кеширование и deploy, и не решил бы потребность карт в eval.

## Решение

Сохраняем документированные исключения для действующих генераторов и интеграций:

- `script-src 'unsafe-inline'` — для inline bootstrap и загрузчиков Astro islands.
- `script-src 'unsafe-eval'` — для векторного движка JS API Яндекс Карт v3. Этим же разрешением пользуется компиляция WebAssembly в Pagefind; широкий eval самому поиску не нужен.
- `style-src 'unsafe-inline'` — для сгенерированных inline-стилей и стилей сторонних виджетов.

Это принятый компромисс совместимости и защиты от XSS; замечания Lighthouse по этим исключениям остаются ожидаемыми. Отказ от интерактивных карт или аналитики изменил бы продукт, поэтому его нельзя подменять правкой CSP ради оценки аудита.

`script-src-attr 'none'` сохраняет запрет raw inline-обработчиков событий. Правила написания проектного JavaScript, включая обоснованные raw inline-исключения, находятся в [инструкциях приложения](/apps/www/AGENTS.md#клиентский-javascript). Разрешения генераторов не становятся нормой для нового проектного кода.

## Владельцы политики и пересмотр

- Точные заголовки и allowlists принадлежат [security.conf](/ops/nginx/security.conf), причины каждого широкого или стороннего источника — [CSP.md](/ops/nginx/CSP.md). При изменении CSP их обновляют вместе по [локальным правилам](/ops/nginx/AGENTS.md); внешние источники остаются узкими и привязанными к нужным директивам.
- Удаление script `unsafe-inline` требует надёжного разрешения или выноса generated bootstrap без ручной синхронизации хрупких хэшей.
- Удаление `unsafe-eval` требует устранить потребность JS API или подтвердить, что SDK больше не использует eval. Для Pagefind при этом сохраняется только более узкое `wasm-unsafe-eval`, как предусмотрено [ADR-025](/docs/decisions/025-static-full-text-search-with-pagefind.md).
- Ужесточение `style-src` требует отдельной проверки сгенерированных стилей Astro и сторонних виджетов.
