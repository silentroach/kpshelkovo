# ADR-035: Внутренние редакционные источники базы знаний

## Статус

Принят

## Дата

2026-09-06

## Контекст

Страницы `/kb` часто собирают факты из документов, сообщений, реестров и ранее опубликованных материалов сайта. По ADR-015 frontmatter базы знаний намеренно оставался минимальным, а источники сохранялись только ссылками в Markdown body.

Контекстная ссылка полезна читателю, когда помогает открыть документ или проверить конкретное утверждение. Однако редакционный агент может превратить несколько источников в повторяющиеся строки или абзацы `Источник: ...` после каждого фрагмента. Это засоряет текст. Если убрать такие строки без замены, человек или агент, который позже обновляет страницу, теряет журнал происхождения фактов.

Источники нужны в первую очередь редакторам и агентам, работающим с исходниками репозитория. Публичный блок источников пока не нужен.

## Решение

Добавить в raw frontmatter страниц `/kb` опциональный массив `sources`:

```yaml
sources:
  - url: https://example.com/document
    description: Подтверждает размер тарифа и дату его введения
  - url: /news/example/
    description: Содержит последующее подтверждение начала работ
```

Каждый элемент содержит два обязательных непустых поля:

- `url` - публичный абсолютный HTTP(S) URL или внутренний путь сайта от корня;
- `description` - краткое plain-text объяснение, какая информация страницы взята из материала.

`sources` хранит все материалы, из которых автор или редакционный агент взял содержательные факты. Полезные ссылки, действия, навигация и связанные материалы не считаются источниками, если из них не брали факты. Материал остается в `sources`, даже если ссылка на него естественно встроена в основной текст.

Один URL записывается один раз. Если материал подтверждает несколько фактов, они перечисляются в одном `description`. Порядок элементов не имеет договорной семантики.

На первом этапе поле существует только на raw-границе content collection:

- Zod-схема проверяет структуру, допустимые URL, непустые описания и отсутствие точных дублей URL;
- загрузчик не переносит `sources` в доменную модель `KbPage`;
- поле не попадает в HTML, Markdown companion, Pagefind, SEO, JSON-LD или другие публичные поверхности.

В основном тексте нельзя добавлять отдельные строки или абзацы вида `Источник: ...`. Ссылку можно интегрировать в предложение, если она полезна читателю сама по себе. Такое присутствие в тексте не отменяет запись фактического источника во frontmatter.

Существующий корпус не мигрируем массово. `sources` заполняется в новых и существенно редактируемых материалах, если у них есть фактические источники.

## Рассмотренные альтернативы

### Хранить массив URL без описаний

Плюсы:

- меньше frontmatter;
- проще добавлять ссылки.

Минусы:

- по ссылке непонятно, какие факты из нее взяты;
- список быстро превращается в непрозрачный набор URL;
- следующему редактору приходится заново изучать каждый материал.

Отклонено: обязательное описание делает журнал полезным для последующего обновления страницы.

### Оставить источники только в основном тексте

Плюсы:

- источник находится рядом с утверждением;
- не нужно поддерживать второе представление.

Минусы:

- служебные подписи засоряют читательский текст;
- встроенные ссылки смешивают доказательства, навигацию и действия;
- агенту сложнее получить полный список использованных материалов.

Отклонено как единственная модель. Полезные читателю ссылки остаются в тексте, а полный редакционный журнал хранится отдельно.

### Сразу показывать публичный блок источников

Плюсы:

- читатель видит происхождение материала;
- источники доступны внешним агентам через HTML и Markdown companion.

Минусы:

- нужно отдельно решить дизайн, место блока и влияние на поиск;
- неполная миграция старого корпуса создаст разное поведение похожих страниц;
- внутренняя редакционная потребность не требует публичного контракта.

Отклонено для первого этапа. Публичное представление потребует отдельного решения.

### Сделать поле обязательным и мигрировать весь корпус

Плюсы:

- все страницы сразу следуют одному контракту;
- отсутствие источников становится явным.

Минусы:

- страницы-разделы и авторские инструкции могут не иметь внешних источников;
- URL из существующего Markdown нельзя надежно классифицировать автоматически;
- массовая ручная миграция увеличивает объем изменения до проверки пользы модели.

Отклонено: поле остается опциональным, а старые страницы обновляются постепенно.

## Последствия

- Новые и существенно обновляемые страницы могут хранить проверяемое происхождение фактов без служебных абзацев в читательском тексте.
- Строгая raw-схема отклоняет пустые списки, пустые поля, неподдержанные URL и точные дубли.
- Публичное поведение `/kb` не меняется.
- Полнота `sources` гарантируется редакционным процессом только для новых и существенно обновленных материалов; старые страницы могут не иметь журнала.
- Если источники понадобится показать читателю или внешнему агенту, поле нужно будет осознанно перенести в доменную модель и соответствующие публичные DTO.
