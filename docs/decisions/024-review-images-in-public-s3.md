# ADR-024: Иллюстрации отзывов в публичном S3

## Статус

Принят

## Дата

2026-08-10

## Контекст

Авторскому отзыву может понадобиться отдельная иллюстрация или мем внутри повествования. Хранить такие JPEG в Git неудобно, а префикс `news/` не подходит: владельцем файла остается раздел отзывов.

ADR-021 требует отдельного решения для изображений каждого раздела. ADR-023 уже определил безопасный и воспроизводимый профиль подготовки JPEG для новостей, но намеренно не распространил его на остальные материалы.

## Решение

- Хранить подготовленные JPEG-иллюстрации отзывов в бакете `kps-public` под ключами `reviews/YYYY/MM/<review-slug>/<semantic-name>.jpeg`.
- Перед загрузкой применять тот же профиль, что в ADR-023: исправлять ориентацию, не увеличивать изображение, ограничивать длинную сторону 2560 пикселями, переводить в sRGB и сохранять progressive JPEG с quality 90 и субдискретизацией 4:2:0.
- Всегда удалять EXIF, IPTC, XMP, GPS, комментарии, thumbnails и остальные метаданные. Для отзывов координаты не восстанавливать: иллюстрация не должна раскрывать точное место съемки или участок автора.
- Считать опубликованный ключ неизменяемым. Загружать файл с `Content-Type: image/jpeg` и `Cache-Control: public, max-age=31536000, immutable`.
- Публиковать файл только через `https://media.kpshelkovo.online/<key>`.
- Вставлять изображение стандартным Markdown-синтаксисом непосредственно в авторский body, чтобы автор определял его место в повествовании, а HTML и Markdown companion сохраняли одинаковую структуру.
- Обязательно писать содержательный `alt`. Не использовать изображение как обложку, аспект отзыва или отдельное поле frontmatter.
- Не создавать для одиночных иллюстраций отдельную галерею или image-модель. Если отзывам понадобятся наборы фотографий, подписи и адаптивные производные Astro, это потребует отдельного расширения модели.

## Рассмотренные альтернативы

### Использовать префикс `news/`

Отклонено: первый сегмент ключа обозначает раздел-владелец, а иллюстрация принадлежит отзыву.

### Хранить изображение в Git

Отклонено: бинарный файл увеличивает репозиторий и остается в его истории, хотя уже существует публичное объектное хранилище.

### Добавить структурированное поле изображений во frontmatter

Отклонено для одиночной иллюстрации: автору важно поставить ее в конкретное место текста, а отдельная модель потребовала бы синхронизации позиции между HTML и Markdown companion.

## Последствия

- Отзывы могут содержать авторские иллюстрации, не смешивая их с фотографиями новостей.
- Публичный JPEG не содержит координат, данных устройства и других скрытых метаданных.
- Изображение загружается напрямую с media-origin и не получает адаптивных производных Astro; лимит 2560 пикселей ограничивает размер публикационной копии.
- Ключи изображений становятся долгоживущими и не должны перезаписываться.
