# ADR-024: Иллюстрации отзывов в публичном S3

## Статус

Принят

## Дата

2026-08-10

## Контекст

Авторскому отзыву может понадобиться иллюстрация или мем внутри повествования. JPEG в Git увеличивает историю, а префикс `news/` приписал бы файл другому разделу. Профиль подготовки новостных JPEG уже существовал, но требовал отдельного решения для отзывов.

## Решение

Используем тот же подход подготовленного web-master в публичном S3 с владельцем `reviews`. Координаты исключены без новостного opt-in: иллюстрация не должна раскрывать точное место съёмки или участок автора.

Одиночная иллюстрация живёт в авторском Markdown body. Это сохраняет выбранное автором место между абзацами в HTML и Markdown без отдельной галереи, frontmatter image-модели или автоматического назначения обложкой и аспектом.

Действующие требования к позиции, содержательному `alt`, сохранности HTML/Markdown, подготовке JPEG и GPS принадлежат [public-media](/openspec/specs/public-media/spec.md). Порядок публикации и точные параметры — [storage runbook](/ops/storage/public-media.md); вход редактора — [инструкции отзывов](/apps/www/src/data/reviews/AGENTS.md) и skill `public-media-publisher`.

## Рассмотренные альтернативы

- **Префикс `news/`.** Смешал бы владельцев файлов разных разделов.
- **Изображение в Git.** Оставило бы бинарный файл в истории при уже существующем объектном хранилище.
- **Структурированное поле изображений во frontmatter.** Для одиночной иллюстрации потребовало бы отдельной синхронизации позиции между HTML и Markdown.

## Последствия

Иллюстрация загружается напрямую с media-origin без адаптивных производных Astro; профиль web-master ограничивает размер публикационной копии. Наборы фотографий, отдельные подписи и галерея потребуют расширения модели по реальной потребности.
