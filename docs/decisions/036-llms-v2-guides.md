# ADR-036: Короткие путеводители llms.txt v2

## Статус

Принят

## Дата

2026-09-12

## Контекст

Lighthouse не распознавал навигацию в llms: AST сериализовал URL без названий как автоссылки. Короткие и полные файлы дублировали инструкции, содержали изменчивые счётчики и не всегда объясняли полноту источника. Исправление одной ссылки снимало ошибку аудита, но не помогало агенту выбрать данные.

## Решение

В [#712](https://github.com/silentroach/kpshelkovo/issues/712) выбрали самостоятельные короткие путеводители по структуре [llmstxt.org v2](https://llmstxt.org/): название, краткое описание и разделы именованных абсолютных ссылок. Путеводитель помогает выбрать материал, выборку или полный набор; подробные инструкции и сами данные остаются отдельными ресурсами.

Действующий контракт структуры, полноты источников и выбора наиболее конкретного путеводителя с корневым fallback — [public-content-discovery](/openspec/specs/public-content-discovery/spec.md). Он не фиксирует количество файлов. Доставка Markdown принадлежит [public-markdown-delivery](/openspec/specs/public-markdown-delivery/spec.md).

Полные `llms-full.txt` удалены без совместимых копий и специальных редиректов. Это решение проекта: повтор инструкций усложнял сопровождение. Документы `full.md`, `full/*.md` и полные JSON-наборы сохраняют самостоятельное назначение.

Генераторы используют AST API по [корневым правилам](/AGENTS.md#локальные-инструкции). Описательный реестр и ручная доставка nginx сохраняют границы [ADR-011](/docs/decisions/011-public-surface-registry.md).

## Рассмотренные альтернативы

- **Исправить только автоссылки.** Устранило бы симптом аудита, сохранив дублирование и неясную полноту выборок.
- **Оставить короткие и full-путеводители.** Агенту пришлось бы выбирать между похожими инструкциями, а редактору — синхронизировать их.
- **Счётчики и примеры записей в путеводителе.** Требовали бы загрузки изменчивых доменных данных ради навигации; полные наборы лучше получать по именованной ссылке.

## Последствия и проверки

- Общий [layout](/apps/www/src/layouts/BaseLayout.astro) выбирает путеводитель через [реестр](/apps/www/src/lib/public-surface/index.ts); разделовые `location` в [nginx](/ops/nginx/kpshelkovo-online.conf) передают его общему Markdown-обработчику.
- [Регрессионный тест генераторов](/apps/www/src/lib/tests/llms.test.ts) проверяет именованные ссылки. Полноту объяснений и выбор источника проверяют по затронутым сценариям; реальные HTTP-связи — при изменении доставки.
- Разовая проверка ресурсов не создаёт постоянный smoke-обход сборки или отдельный валидатор Markdown. Агентные задания с чистым контекстом помогают проверить, может ли потребитель найти ответ и сверить его с источником.
