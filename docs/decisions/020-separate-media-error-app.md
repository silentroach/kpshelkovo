# ADR-020: Отдельное Astro-приложение для media error pages

## Статус

Принят

## Дата

2026-07-11

## Контекст

Media-origin проксирует S3 и не является разделом основного сайта. Вместо XML-ошибки хранилища читателю нужна локальная фирменная 404.

Страница внутри `apps/www` связала бы media-origin с prefetch, client router, аналитикой, sitemap и общим deploy-root. Готовый HTML в `public` обошёл бы Astro и продублировал визуальный блок, логотип и шрифты.

## Решение

Выделяем статическое `apps/media` с независимым артефактом `dist/media` и deploy-root. Оно собирает страницу ошибки и её assets без клиентского runtime основного сайта. Общий `NotFoundView` и брендовые ресурсы принадлежат `packages/ui`, поэтому страницы ошибок сохраняют общий вид без общей границы развёртывания.

Публичное преобразование ошибок хранилища в локальную 404 принадлежит [public-media](/openspec/specs/public-media/spec.md). Пути, порядок сборки и деплоя — [origin runbook](/ops/nginx/media-kpshelkovo-online.md); ограничения приложения — [apps/media/AGENTS.md](/apps/media/AGENTS.md).

## Рассмотренные альтернативы

- **Страница в `apps/www`.** Получила бы ненужные глобальные возможности или потребовала исключений для runtime и deploy-путей.
- **Готовый HTML в `public`.** Потребовал бы отдельно поддерживать визуальный блок и брендовые assets вне Astro.
- **Встроить логотип и шрифты в HTML.** Увеличило бы каждый ответ на отсутствующий объект, даже когда запрос пришёл из `img`, `video` или ссылки на документ и HTML не будет показан.

## Последствия

Media 404 имеет собственную build/deploy-границу и не зависит от hashed assets `apps/www`. Изменение общего not-found UI затрагивает оба приложения; независимая доставка требует отдельного статического каталога на VPS.
