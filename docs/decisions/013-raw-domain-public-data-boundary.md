# ADR-013: Граница между внешними DTO, доменной моделью и публичными DTO

## Статус

Принят

## Дата

2026-05-20

## Контекст

Когда тип из Zod-схемы исходного YAML или frontmatter становится внутренней моделью приложения, внешний формат определяет язык всего кода: имена полей, строковые значения и форму вложенных объектов. Изменение источника тогда затрагивает вычисления и UI, даже если смысл данных прежний.

Прямая публикация той же модели создаёт вторую связь: внутренний рефакторинг может случайно изменить JSON для внешних потребителей или раскрыть служебные поля. Входной формат, удобное внутреннее представление и опубликованный контракт должны развиваться независимо.

## Решение

- **Raw DTO** описывает источник данных. Его Zod-схема проверяет входной формат и выполняет необходимые для чтения источника нормализации.
- **Доменная модель** описывает внутренний язык приложения. Явно написанные readonly-типы отделены от входной схемы; mapper собирает их из проверенного Raw DTO и переводит представление или смысл значений там, где они различаются.
- **Public DTO** описывает самостоятельный опубликованный формат. Отдельный адаптер выбирает данные из доменной модели, чтобы внутренние изменения не меняли публичный контракт автоматически. Тип Public DTO может выводиться из отдельной публичной Zod-схемы: она описывает выходной формат, а не подменяет raw-схему или доменную модель.

Такое разделение поддерживает подход [ADR-011](011-public-surface-registry.md): публичные представления имеют собственный контракт, а не являются выгрузкой внутреннего состояния приложения.

## Рассмотренные альтернативы

- **Выводить доменную модель из raw-схемы.** Меньше типов, но удобство исходного формата продолжает определять внутреннюю модель.
- **Строить домен через Zod `transform()`.** Сокращает loader, но смешивает проверку источника с доменными преобразованиями и затрудняет их отдельное тестирование.
- **Рекурсивно переводить `snake_case` в `camelCase`.** Меняет написание, но не уточняет смысл полей, не переводит enum-значения и не упрощает неудобную структуру источника.
- **Публиковать доменную модель напрямую.** Убирает адаптер, но связывает внутренний рефакторинг с внешней совместимостью и может раскрыть вычисляемые служебные поля.

## Последствия

Явные типы и преобразования требуют больше кода на границах. Взамен источник можно менять без переноса его формата в UI, а внутреннюю модель — без случайного изменения опубликованных данных. Сохранение прежнего публичного формата остаётся задачей адаптера; намеренное изменение контракта рассматривается отдельно от внутреннего рефакторинга.
