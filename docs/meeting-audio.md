# Как расшифровать запись встречи

Рабочий процесс для Mac с Apple Silicon и Nix: GigaAM распознаёт русскую речь, pyannote Community-1 размечает голоса. Для сравнения на коротком отрывке можно запустить Whisper large-v3 через MLX. Аудио обрабатывается локально. Модели и зависимости скачиваются при первом запуске; для каждого инструмента создаётся отдельное окружение.

## Запись и проба

Из корня проекта открой Bash с инструментами. Для каждой встречи выбери отдельную рабочую папку. Все команды ниже — в этом Bash.

```bash
nix shell nixpkgs#uv nixpkgs#python311 nixpkgs#ffmpeg -c bash
```

```bash
src="$HOME/Meetings/2026-03-20/input.wav"
work="$HOME/Meetings/2026-03-20/work"
ffprobe -v error -show_entries stream=codec_name,sample_rate,channels,duration "$src"
```

Скрипт принимает **моно, 16 кГц, PCM s16 WAV**. Если запись уже такая, используй оригинал. Иначе сделай рабочую копию (`mkdir -p "$work"; ffmpeg -i "$src" -ac 1 -ar 16000 -c:a pcm_s16le "$work/audio.wav"`) и укажи `src="$work/audio.wav"`. Сохрани оригинал, особенно если участники записаны на разных каналах. Не удаляй паузы: ссылки архива должны вести на время исходной записи.

Выбери несколько начал фрагментов **в секундах от начала записи**: тихий вопрос, ответ с терминами или суммой, смену говорящего. Числа ниже — пример для длинной встречи. GigaAM в коротком режиме принимает до 25 секунд; скрипт берёт по 24.

```bash
bash scripts/meetings/audio.sh giga "$src" "$work" 1200 3900
bash scripts/meetings/audio.sh whisper "$src" "$work" 1200 3900
```

В `clip-*.wav` можно прослушать ровно то, что слышала модель. Сравни варианты в соседних JSON: кто кому задаёт вопрос, не исчезли ли «не», суммы, фамилии. На паузе проверь, не добавила ли модель слова. Для мартовской встречи GigaAM лучше передала вопрос о праве собственности; для другой записи выбор стоит перепроверить.

## Голоса и полный текст

Для диаризации прими условия [Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), для полной расшифровки GigaAM — отдельно условия [segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0). Нужен read-токен того же аккаунта с доступом к этим моделям. Скрипт читает сохранённый токен Hugging Face или `HF_TOKEN`, иначе запросит его без эха.

```bash
# Три минуты вокруг знакомого вопроса (начало в секундах).
bash scripts/meetings/audio.sh diarize "$src" "$work" 3840
# После проверки перехода «вопрос → ответ» — вся запись целиком.
bash scripts/meetings/audio.sh diarize "$src" "$work"
# Полный текст GigaAM: штатный transcribe_longform с разбиением по речи.
bash scripts/meetings/audio.sh longform "$src" "$work"
```

На Mac оба полных прогона используют CPU; запускай их последовательно. Можно поставить `caffeinate -i` перед `bash` в команде длительного прогона. Держи крышку открытой. Пилот распознавания и пилот диаризации проверены на мартовской записи; полная расшифровка через [longform GigaAM](https://github.com/salute-developers/GigaAM#model-inference) пока не прошла приёмку на всей встрече.

В `longform` сначала виден прогресс поиска речи. Затем после каждой пачки распознанных фрагментов скрипт выводит их количество, таймкод в оригинале и примерное время до конца распознавания. На длинных паузах таймкод может перепрыгнуть вперёд. Оценка появляется после первой пачки; итоговый JSON сохраняется в конце. При обновлении закреплённой версии GigaAM проверь адаптер прогресса: он наблюдает за разбиением записи и декодированием пачек внутри `transcribe_longform`.

## От JSON до встречи в архиве

- `full.longform.json` содержит текст и время слов. `full.diarize.json` — интервалы говорящих. Все JSON **этих скриптов** используют секунды от начала оригинала, в том числе для пробных фрагментов.
- Для черновика реплик сопоставь слова с интервалами `exclusive` по пересечению времени. Проверь границы коротких вопросов и перебивания по `overlap_aware` и оригиналу. Метки `SPEAKER_*` действуют только внутри одного прогона; привязывай людей к проверенным репликам, а не к номеру из пилота.
- Сверь написание названий с [глоссарием](/GLOSSARY.md). Он помогает исправлять распознавание, но не определяет, какое юрлицо имел в виду говорящий. Для фамилий ищи представление в записи или подтверждение участника. Прослушай спорные отрицания, даты, суммы и ссылки на нормы.
- Сохрани исходные JSON рядом с аудио. Для публикации подготовь полную транскрипцию по [правилам встреч](/apps/www/src/data/meetings/AGENTS.md) и [контракту архива](/openspec/specs/meetings-archive/spec.md). Модели, WAV и черновые расшифровки в каталог сайта не переносятся.
