# News Section Content Rules

Этот файл фиксирует стартовые редакционные правила и seed-контент news-section в `apps/www`.

## Data Location

- authors: `apps/www/src/data/news/authors/*.yaml`
- articles: `apps/www/src/data/news/articles/**`
- yearly summaries: `apps/www/src/data/news/summaries/YYYY/index.md`
- monthly summaries: `apps/www/src/data/news/summaries/YYYY/MM.md`

## Public Navigation

- `/news/` показывает свежие и закрепленные публикации и ведет в архив новостей.
- `/news/archive/` перечисляет доступные годовые архивы.
- `/news/YYYY/` показывает краткую выжимку за год и служит каталогом непустых месяцев от января к декабрю.
- `/news/YYYY/MM/` показывает краткую выжимку и публикации месяца от новых к старым, а также ведет к соседним месяцам, в том числе через границу года.
- HTML и Markdown companions сохраняют одинаковую структуру архива и используют одну выжимку из общего источника.
- Годовые и месячные архивы доступны внешним поисковикам, но не включаются во внутрисайтовый индекс Pagefind.

## Archive Summaries

- Каждый год и месяц с публикациями обязан иметь непустую Markdown-выжимку. Лишний файл без соответствующего архива останавливает сборку.
- Файл содержит только абзацы body Markdown без frontmatter, заголовков, списков и таблиц.
- Месячная выжимка обычно занимает один короткий связный абзац. Второй абзац нужен только для самостоятельной важной темы.
- Годовая выжимка строится из месячных и может быть длиннее, но не повторяет весь архив.
- Ссылки ведут только на важные существующие новости и используют root-relative URL. В годовой выжимке достаточно одной опорной ссылки на каждую главную сюжетную линию.
- Период файла определяется месяцем публикации новости, а не отчетным периодом внутри ее заголовка.

## Events

Новость ссылается на общую запись мероприятия из `apps/www/src/data/events/YYYY/MM/<event-id>.md`:

```yaml
events:
  - event: 2026/06/ok-meeting-june
```

- `event` содержит текущий ключ `YYYY/MM/slug` по московскому месяцу начала мероприятия, без `/events/` и завершающего слеша. Часы, место, описание и состояние хранятся только в общей записи. Неизвестная или устаревшая ссылка останавливает сборку; при изменении адреса связанные новости обновляются вместе с мероприятием.
- Необязательный новостной `slug` задаёт имя ICS-файла и по умолчанию равен `event`. При нескольких мероприятиях у каждого нужен явный уникальный slug. Сохраняй опубликованные новостные slugs: они независимы от slug общей записи.
- Формат общей записи, справочное место `place`, внешние площадки, уточнения встречи и правила экспорта описаны в [редакторской инструкции мероприятий](../apps/www/src/data/events/AGENTS.md). Справочное место доступно в событии независимо от `show_on_map`; его название, адрес и координаты берутся из places при каждой сборке.
- Общий `EventWidget` показывает мероприятие в новости и на его подробной странице. В новости название ведёт на мероприятие, а календарное действие использует прежний новостной ICS-адрес. Фоновые карты работают через общий API Яндекс Карт по [ADR-039](decisions/039-shared-yandex-maps-runtime-and-preview.md).
- `/news/data/articles.json` сохраняет datetime-формат: в `events` входят только записи с точным началом и доступным `ics_url`. Известные сведения о месте передаются через `location`, `coordinates` и `map_url`; справочная связь — через `place_id`, абсолютный `place_url` и `location_details`. Отмена и условный набор указаны в `description`. Все формы мероприятий, включая дату без часов и многодневный период, доступны в `/events/events.json`; связи с новостями находятся в `newsUrls`.
- JSON-LD и оба ICS используют общую запись и актуальные сведения о месте. Новостной ICS сохраняет адрес, имя файла и UID; его `URL` ведёт на новость, самостоятельного ICS — на мероприятие. Отменённая запись скрывает действие скачивания, но её ICS остаётся доступным со статусом отмены.
- Связь с `place` создаёт по одному backlink от мероприятия и каждой связанной статьи. Markdown статьи и RSS не получают отдельного блока событий; полные сведения есть в Markdown мероприятия и JSON-каталоге.

## Editorial Rules

Карты-схемы в body новости оформляй ограждённым блоком `map` по [инструкции редакционных карт](editorial-maps.md#вставка-в-новость-или-справку). Геометрию вставляй прямо в блок, а при необходимости внешней ссылки указывай после `map` голый URL. В Markdown companion остаётся исходный JSON с URL и добавляется подпись; пояснение к схеме пиши обычным текстом статьи. Рабочий процесс публикации самой новости — в skill `news-maker`.

1. Исходная новость не переписывается задним числом без явной причины.
   Если появляются поздние подтвержденные факты, добавить их в основной article body отдельным абзацем с понятной атрибуцией, датой или ссылкой на источник.

2. Тип источника определяется author entry.
   Канонический признак официального источника - `kind: official`. Отдельный boolean `is_official` не используется: если нужен официальный источник, автор должен иметь `kind: official`.

3. `cover`, `photos` и `attachments` имеют разные роли.
   `cover` отвечает за карточку, detail hero и social preview. `photos` идут отдельным photo block и ссылаются на неизменяемые подготовленные JPEG в `media.kpshelkovo.online/news/`; для каждого фото обязательны `width`, `height` и `alt`. Перед загрузкой длинную сторону ограничивают 2560 пикселями без апскейла, сохраняют JPEG с quality 90 и удаляют метаданные. GPS-координаты можно вернуть отдельно, только если место съемки является публичной частью материала. Обложка и все `photos` попадают в `NewsArticle.image` JSON-LD. `attachments` должны вести на стабильные public URL.

4. `tags` остаются короткими и утилитарными.
   Теги не заменяют `areas`; spelling одного и того же тега должен быть единым по всему разделу.

5. `summary` не сокращается ради meta description.
   Если `summary` нужен для карточек, RSS или discovery-данных и получается длиннее 160-170 символов, добавляй `seo.description`: одну-две короткие фразы для поискового сниппета без keyword stuffing.

6. `search_aliases` используются только для подтвержденных вариантов поиска.
   Поле не показывается читателю и по умолчанию отсутствует. Добавляй его, только если воспроизводимый пользовательский запрос не находит подходящую новость. Не переноси в алиасы слова и фразы, уже присутствующие в `title`, `summary`, body или `tags`, и не заполняй поле предполагаемыми SEO-ключами.
