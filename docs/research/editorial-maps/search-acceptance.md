# Поисковая приёмка редакционных карт

23 сентября 2026 года. Сравнение с [исходной выдачей](search-baseline.md) выполнено через действующий поисковый диалог на production-сборке `dist/www` от 22:00:33 (`3058a993`) с Pagefind-индексом. Изолированный Chromium открывал локальный статический сервер по `http://kpshelkovo.online:14349` с host resolver на `127.0.0.1`; сервер не добавлял CSP (проверка SDK с проектным CSP отдельно записана в [интеграционной приёмке](integration-acceptance.md)). В этой сборке находился **непубликуемый** временный материал `/kb/editorial-maps-acceptance/` с тремя картами; его выдача не является результатом будущего релиза. Затем фикстуру удалили и пересобрали сайт; повтор запроса к постоянной новости описан ниже.

## Сравнение запросов через UI

- `схема объезда`: прежде результатов не было; в первой сборке находилась **только временная KB-фикстура**, её ссылка вела к авторскому `#схемы`, snippet «Схемы. Схема 1.» подсвечивал эти слова, а не карту. В настоящую новость затем добавлена фраза «Ниже показана схема объезда из Семеновского». На пересобранном индексе в 22:27, уже без фикстуры, запрос дал **один результат**: `/news/2026/09/alternative-access/#editorial-map-1`. Переход оставил начало карты в поле зрения. Новость и карта остаются публичными.
- `объезд дамбы`: теперь полезная новость `/news/2026/09/alternative-access/#editorial-map-1` имеет snippet «Объезд закрытой дамбы из Семеновского. На воротах технического въезда…» с `<mark>` на «Объезд» и «дамбы». Отдельно появляется временная фикстура с той же подписью и собственным `#editorial-map-1`. Обе прежние страницы — апрельская новость и отзыв — сохранились; раньше они составляли всю выдачу.
- `альтернативный проезд`: та же действующая новость остаётся единственным результатом с `#как-получить-доступ`; snippet по-прежнему показывает блок «Как получить доступ» и подсвеченный «проезд», выбор не перенаправлен принудительно к карте.
- `технический въезд`: та же новость теперь выбирается с `#editorial-map-1` благодаря **тексту после подписи**, а не только названию: snippet начинается с подписи и продолжает «На воротах технического въезда…», подсветка «технического»/«въезда». Раньше ссылка шла к началу новости. Прежний февральский отчёт остался; дополнительно видна новая status-запись о реконструкции.
- `КПП Парка`: карточка `/map/park-checkpoint/` остаётся полезной целью; новость об альтернативном проезде остаётся в выдаче, её snippet теперь показывает контекст въезда и подпись карты. Подсветка в карточке «Парк»/«КПП», в новости «Парк»/«КПП».
- `проезд через КПП 4`: все контрольные status-записи и майская новость остались; новость об альтернативном въезде также осталась (в видимой начальной порции — седьмая строка вместо четвёртой в baseline). Как прежде, однозначный цифровой `4` не входит в `?h=` и не ограничивает результаты. Фиксированный ранг не является критерием.
- `схема проезда`: сохранились те же три новости об асфальте; первый snippet подсвечивает «схема» и «проезд», релевантная схема объезда по этой общей формулировке не выбрана.
- `схема асфальтирования`: KB-план `/kb/ok/asphalt-plan-2026/#как-читать-схемы` остаётся наиболее полезным; подсвечены «схемы», следующие новости об асфальте также сохранились с подсветкой обоих слов. `асфальтирование дорог`: прежняя новость о материалах и KB-план с `#шелково-форест` остаются, snippets и highlights соответствуют тексту про дороги и асфальтирование.
- `Охотничьи пруды` и `карта прудов`: карточка `/map/hunting-ponds/` остаётся полезной целью с прежними подсветками названия/«прудов»; новость о подходе и соседние материалы не исчезли. Новые карты в news/KB не вытеснили карточку места.

## Несколько карт, скрытые данные и переходы

- В одной строке результата временной KB-страницы находятся три карты. Запрос `Без названия` даёт **одну** строку статьи с её настоящим заголовком и snippet «Без названия. Схема 3.»; Pagefind вернул два отдельных `sub_results` с одинаковым названием и URL `#editorial-map-2`, `#editorial-map-3`. UI выбрал `#editorial-map-2` по штатной оценке. Сами заголовки в HTML имеют разные ID `editorial-map-1`, `editorial-map-2`, `editorial-map-3`; напрямую проверены все три цели, включая третью одноимённую. Запросы `Семеновского` и полная подпись первой карты выбирают `#editorial-map-1`; в snippets выделено слово из видимой подписи. Нет требования, чтобы две одноимённые карты по одному запросу получали две строки или по очереди выбирались UI.
- Уникальное `qa-hidden-editorial-ponds-only-61`, находящееся только в `description` GeoJSON третьей карты, даёт «Ничего не нашли». Запросы по словам из `iconCaption` («Съезд в Авдотьино») и скрытого `description` («с внутренним контуром») возвращают другие страницы, но **не** фикстуру: лейблы SDK/геоданные не попали в snippet или поисковый корпус. HTML карты помечен `data-pagefind-ignore="all"`, статическая подпись расположена снаружи.
- При прямом открытии `#editorial-map-1`, `#editorial-map-2`, `#editorial-map-3` на десктопе 1280×577 начало **соответствующей карты**, а не только подпись, находилось в 92 px от верха; sticky-шапка занимала 57 px, подпись начиналась около 456 px. На 320×700 прямой переход к третьей карте также оставлял её начало в поле зрения. Положение проверялось по рамке `figure` и началу `editorial-map`, а не по одному `h3`.
- В отдельной новой сессии загрузчик SDK блокировали **до открытия страницы**. `window.ymaps3` остался `undefined`, карта показала «Карта не загрузилась.», но прямой `#editorial-map-3` на 1280×577 всё равно дал верх рамки 92 px и подпись 456 px. Из `/kb/transport/` через поисковый UI выбрали одноимённую карту: клиентский переход сохранил JS-маркер документа, открыл `#editorial-map-2`, при 320×700 и последующем resize до 320×568 верх выбранной карты оставался в 92 px, подпись — в 456 px. Это проверка доступности якоря без готового SDK, не проверка работающей сцены.
- При работающем SDK на 320×568 выбор из UI по `технический въезд` открывал новость с `#editorial-map-1`, верх карты 92 px, подпись 456 px; в body подсвечено «въезд» (не «техническим»), как и в baseline буквальная подсветка страницы уже отличалась от морфологической подсветки snippet.

Все обязательные сценарии индексирования, разделения подрезультатов и прокрутки по 5.3/6.2 проверены. Значения рангов и количество страниц не закрепляются: они зависят от корпуса. Сценарии нескольких карт проверены на временном материале, удалённом перед повторной сборкой; запрос к постоянной новости повторён на индексе без него. Итоговые `pnpm build` и `test:search-quality` прошли на дереве без фикстуры. Браузерные наблюдения здесь не относятся к печати.
