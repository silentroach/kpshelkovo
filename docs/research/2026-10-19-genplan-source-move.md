# Переезд источника страниц генпланов

Проверено 19 октября 2026 года. Все четыре страницы частей Шелково на официальном сайте встраивают генпланы с `genplan.zmotech.ru`. Формат каталога совместим с действующим импортёром: достаточно заменить четыре URL в [скрипте обновления](/apps/www/scripts/parcels/update.ts).

## Адреса из официального сайта

Адреса взяты из `src` iframe на страницах частей; каждая страница сайта и каждый новый генплан ответили HTTP 200:

- [Шелково Ривер](https://kpshelkovo.ru/shelkovo-river/): `https://dgtime.ru/shr/shr-genplan/` → [genplan.zmotech.ru/shelkovo-river/](https://genplan.zmotech.ru/shelkovo-river/).
- [Шелково Форест](https://kpshelkovo.ru/shelkovo-forest/): `https://dgtime.ru/shf/shf-genplan/` → [genplan.zmotech.ru/shelkovo-forest/](https://genplan.zmotech.ru/shelkovo-forest/).
- [Шелково Парк](https://kpshelkovo.ru/shelkovo-park/): `https://dgtime.ru/shp/shp-genplan/` → [genplan.zmotech.ru/shelkovo-park/](https://genplan.zmotech.ru/shelkovo-park/).
- [Шелково Вилладж](https://kpshelkovo.ru/shelkovo-village/): `https://dgtime.ru/shv/shv-genplan/` → [genplan.zmotech.ru/shelkovo-village/](https://genplan.zmotech.ru/shelkovo-village/).

На всех четырёх страницах есть и второй iframe — `https://genplan.zmotech.ru/location-map/shelkovo-village/`. Это отдельная карта расположения; для импорта использованы перечисленные выше генпланы.

Из текущего окружения все четыре старых URL завершились `UND_ERR_CONNECT_TIMEOUT` при соединении с `dgtime.ru:443`. HTTP-ответ и редирект не получены; это наблюдение не устанавливает точную дату отключения старого хоста.

## Совместимость данных

Все новые HTML-страницы успешно разобраны штатным [parseGenplanPage](/apps/www/src/lib/parcels/genplan-page.ts), который извлекает JSON из единственного `window['houses_data']` и проверяет его [Zod-схемами](/apps/www/src/lib/parcels/source-schemas.ts). Сохранённый формат, статусы и признаки менять не потребовалось. Сырые HTML и персональные поля каталога в репозиторий не сохранялись.

Сравнение сохраняемых полей со снимками от 17 октября, принятыми на начало проверки в [каталоге генпланов](/apps/www/src/data/parcel-sources/genplans/):

- Ривер — 526 позиций; отличается статус K35.
- Форест — 361 позиция; отличий нет.
- Парк — 574 позиции; отличаются статусы A28 и A80 (в исходных ID буква `А` кириллическая).
- Вилладж — 507 позиций; отличий нет.
- Всего 1968 позиций. Добавлений, исчезновений, изменений кадастровых ссылок, признаков и цен не обнаружено.

В браузере [генплан Ривера](https://genplan.zmotech.ru/shelkovo-river/) содержит 526 записей `houses_data` и 526 HTML-меток `data-id`. Рядом доступны `css/positions.css` и подложка `img/genplan.jpg?v=1.46`. Эта проверка подтверждает устройство новой страницы, но не является новой пространственной сверкой с НСПД.

## Границы исправления и проверки

- Правка адресов восстанавливает существующее поведение по [parcel-updates](/openspec/specs/parcel-updates/spec.md): получение четырёх генпланов без НСПД, проверка всей партии до записи и отказ при неизвестном формате. Нового решения о поведении не требуется.
- `page` и `capturedAt` относятся к конкретному получению и сохраняются в снимке. Принятые снимки и исторические основания в [matches.yaml](/apps/www/src/data/parcel-sources/matches.yaml) нельзя механически переименовывать под новый домен. Новые адреса с фактическим временем получения записывает штатный импорт.
- Применимость подтверждений определяется сохранёнными кадастровыми ссылками обозначений по [resolve.ts](/apps/www/src/lib/parcels/resolve.ts), а не доменом страницы. При обнаруженных входах эти ссылки совпадают.
- Для проверки без записи в принятые данные можно вызвать парсер и [reconcileParcels](/apps/www/src/lib/parcels/reconcile.ts) напрямую либо выполнить CLI на временной копии данных. Оба режима CLI, включая `--snapshot`, записывают результат в каталог данных своей копии приложения; `--snapshot` не является dry run.
- Существующие [тесты обновления](/apps/www/src/lib/parcels/tests/update.test.ts) проверяют парсер, ошибки партии, сохранение истории и повторяемость записи. Подмена домена не требует новых тестов, закрепляющих строки URL.

## Результаты проверок

- Исправленный CLI выполнен с живыми источниками на временной копии снимков и Markdown-записей. Получены все четыре генплана; сохранены 1632 записи, без добавлений, удалений, переименований, изменений геометрии и конфликтов.
- В копии изменились только три статуса: SHR-K35 — `reserved` → `available`; SHP-A28 и SHP-A80 — `available` → `reserved`. Заметки и история цен совпали с исходными.
- Повторный запуск `genplans --snapshot` на полученной партии дал нулевые изменения. SHA-256 всех файлов временного каталога данных совпали до и после повтора. На этом этапе проверка выполнялась только во временном каталоге.
- `pnpm --filter @shelkovo/www exec vitest run src/lib/parcels/tests`: 7 файлов, 87 тестов прошли.
- `pnpm openspec:validate`: 51 основная спецификация и 110 архивных изменений прошли проверку.

## Принятие свежих снимков

По дополнительному запросу владельца 19 октября в 14:27 МСК выполнено `pnpm parcels:update genplans` в рабочей копии. Все четыре снимка получили новые URL и фактическое время получения; в Markdown-записях изменились те же три статуса. Отчёт показал 321 несопоставленное обозначение и ноль конфликтов, добавлений, удалений, переименований и изменений геометрии.

Повторный импорт принятых снимков дал нулевые изменения; SHA-256 файлов генпланов и участков совпали до и после повтора. Кадастровый снимок и `matches.yaml` сохранились побайтово. После обновления данных повторно прошли все 87 тестов участков; diff содержит только адреса и время снимков и три смены статуса.
