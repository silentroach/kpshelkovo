# Редакционные карты и геоданные мест

Один формат GeoJSON используется в ограждённых блоках `map` новостей и базы знаний и в соседних файлах геометрии мест. Источник хранится в редакционном материале; при сборке готовятся данные для карты, а в браузере рисуется сама карта. Карта статьи не создаёт место на общей `/map/`.

## Вставка в новость или справку

Поместите полный `FeatureCollection` в Markdown-блок. После `map` можно указать один абсолютный HTTP(S)-адрес внешней схемы: голый URL, без `url=`, кавычек и Markdown-ссылки. Адрес необязателен и не служит источником геометрии.

HTML-преобразование включается опцией `editorialMaps: true` в шаблонах body новостей и KB, которые подключают стили и клиентский код карты. По умолчанию `renderMarkdown` оставляет блоки `map` обычным кодом.

````markdown
```map https://example.com/map
{
  "type": "FeatureCollection",
  "metadata": { "name": "Схема прохода" },
  "features": [
    {
      "type": "Feature",
      "id": 0,
      "properties": { "iconCaption": "Вход", "marker-color": "#217ea3" },
      "geometry": { "type": "Point", "coordinates": [37.75, 55.05] }
    }
  ]
}
```
````

Названная карта получает подпись из `metadata.name`. Если указан URL, название становится ссылкой на него; при URL без названия подпись будет «Открыть карту». Без URL название остаётся текстом; без обоих значений подписи нет. Пояснение для читателя пишите обычным Markdown рядом с блоком. `metadata.description` и `metadata.creator` сохраняются как данные, но не становятся подписью.

В HTML карта использует подготовленную геометрию, а подпись доступна независимо от загрузки SDK. На индексируемой странице название в подписи становится обычным заголовком-секцией; контейнер с данными и элементами SDK исключён из Pagefind. Для перехода к секции CSS резервирует высоту карты над заголовком; фактический переход проверяется отдельно на production-индексе. Markdown companion сохраняет исходный блок, включая URL и исходные значения JSON, и добавляет подпись один раз. Строки GeoJSON не разбираются как Markdown или упоминания `@slug`; они не создают backlinks. Ошибка JSON, неизвестное содержательное поле или неподдерживаемая геометрия останавливают сборку с указанием материала и номера вставки.

## Геометрия места

У места основная точка задаётся в `location.coordinates` Markdown-карточки. Дополнительные объекты храните в соседнем `apps/www/src/data/places/[slug].geojson`: тот же полный `FeatureCollection`, без искусственного `kind: area`. Файл привязывается к существующей карточке по slug; карточка может обойтись без GeoJSON. В превью карточки дополнительные объекты видны вместе с основным маркером, на общей карте их временно раскрывают наведение, фокус и подсветка по `?h=<slug>`. `show_on_map` влияет на общую карту, но не на существование карточки и её превью.

Формат принимает `Point`, `LineString`, `Polygon` с вырезами и `MultiPolygon`; координаты идут в порядке `[долгота, широта]`. Раздельные части составной области оставляйте раздельными. ID feature может быть числом (включая `0`) или строкой. Для точки поддерживаются `marker-color` и текстовый `iconCaption`; для линии и области — `stroke`, `stroke-width`, `stroke-opacity`, `stroke-dasharray`, `fill`, `fill-opacity` по назначению. Числовые строки оформления допускаются и при подготовке становятся числами. Только `iconCaption` точки выводится на самой карте как обычный текст: `description` объекта и метаданные коллекции не становятся попапами, лейблами линий или областей.

`precision: approximate` отмечает приблизительный контур и сам по себе не включает пунктир. Пунктир задаётся отдельно через `stroke-dasharray`, например `[5, 3]`. Для приблизительного `Polygon` или `MultiPolygon` можно указать `outline_expansion_meters`: при сборке каждая внешняя граница расширяется, а вырезы сокращаются. Это изменение координат, а не толщина линии; не подгоняйте вершины вручную по подложке. Исходные данные остаются в файле и, для `map`, в Markdown companion.

`marker-color`, `stroke` и `fill` проверяются как CSS-цвета при чтении источника: например, `#217ea3`, `red` или `rgb(33, 126, 163)`. Опечатка в цвете останавливает сборку с указанием источника, объекта и поля. Ссылки на CSS-переменные через `var(...)` не принимаются: цвет должен быть задан в самих геоданных.

## Публичный JSON общей карты

`/map/data/places.json` содержит `places` только для мест с `show_on_map: true`. У каждой записи основная точка остаётся в `coordinates` (`lat`, `lng`); необязательная `geometry` содержит **подготовленный** GeoJSON `FeatureCollection` с `features` и сохранёнными свойствами и текстом объектов. В JSON координаты приблизительных контуров уже расширены, числовые строки оформления нормализованы, а применённого `outline_expansion_meters` нет. Повторно расширять контур потребителю не нужно. Сохраняются поля маркера, статуса, часов работы и `html_url`; полного текста карточки места в этой выдаче нет. Описания внутри `geometry.features[].properties.description` относятся к геообъектам, а не к тексту карточки.

Точные границы и диапазоны проверяет [raw-схема](../apps/www/src/lib/geometry/editorial-schema.ts); подготовленный выход — [публичная схема](../apps/www/src/lib/geometry/editorial-public-schema.ts). Примеры в `docs/research/editorial-maps/` — сохранённые исследовательские экспорты и контрольные данные, а не новые редакционные материалы.
