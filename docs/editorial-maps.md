# Редакционные карты и геоданные мест

GeoJSON используется в ограждённых блоках `map` новостей и базы знаний и в соседних файлах геометрии мест. Блок `map` также принимает короткое определение со ссылками на наборы, участки и места. При сборке сайт разрешает ссылки и готовит геометрию; браузер рисует готовую схему. Карта статьи не создаёт место на общей `/map/`.

## Вставка в новость или справку

Поместите полный `FeatureCollection` в Markdown-блок. После `map` можно указать один абсолютный HTTP(S)-адрес внешней схемы: голый URL, без `url=`, кавычек и Markdown-ссылки. Адрес необязателен и не служит источником геометрии.

Для уже известных объектов достаточно короткого определения:

````markdown
```map https://kpshelkovo.online/map/?set=2026-10-ae-electro-shp-f
{
  "sets": ["2026-10-ae-electro-shp-f"],
  "metadata": { "name": "Парк: группа F" },
  "outline": true
}
```
````

В одном блоке можно сочетать `sets`, `parcels`, `places` и собственные GeoJSON `features`. `type` и `features` для короткого определения необязательны; итоговый состав должен быть непустым. Например, отдельная позиция и место могут дополнять набор:

````markdown
```map
{
  "sets": ["2026-10-ae-electro-shp-f"],
  "parcels": ["SHP-C34"],
  "places": ["hunting-ponds"],
  "metadata": { "name": "Участки и Охотничьи пруды" },
  "features": [
    {
      "type": "Feature",
      "properties": { "stroke": "#217ea3", "stroke-width": 2 },
      "geometry": { "type": "LineString", "coordinates": [[37.743, 55.059], [37.744, 55.060]] }
    }
  ]
}
```
````

Позиция входит целиком, алиасы разрешаются в основной код, повторные ссылки на позицию или место удаляются. Место включает основную точку и всю дополнительную геометрию; скрытое с общей карты место использовать нельзя. Неизвестная ссылка останавливает сборку с именем материала и номером вставки. Ссылка подписи остаётся явной: сайт не создаёт автоматический URL для смеси нескольких наборов и собственной геометрии.

Настройка `outline` принадлежит самой вставке и по умолчанию выключена. Она не наследуется из наборов. При включении сборка готовит обводку только ссылочных участков, сохраняя межи; места и собственные полигоны в объединение не входят. Во встроенной схеме номера появляются с того же приближения, что на общей карте. Цены, площадь, статусы продажи, переключатели частей и попапы участков не показываются.

HTML-преобразование включается опцией `editorialMaps: true` в шаблонах body новостей и KB. Клиентский код карты подключается только если в готовом HTML есть вставка карты; материал без вставок его не загружает. По умолчанию `renderMarkdown` оставляет блоки `map` обычным кодом.

````markdown
```map https://example.com/map
{
  "type": "FeatureCollection",
  "metadata": { "name": "Схема прохода" },
  "features": [
    {
      "type": "Feature",
      "id": 0,
      "properties": { "iconCaption": "Вход", "iconContent": "1", "marker-color": "#217ea3" },
      "geometry": { "type": "Point", "coordinates": [37.75, 55.05] }
    }
  ]
}
```
````

Названная карта получает подпись из `metadata.name`. Если указан URL, название становится ссылкой на него; при URL без названия подпись будет «Открыть карту». Без URL название остаётся текстом; без обоих значений подписи нет. Пояснение для читателя пишите обычным Markdown рядом с блоком. `metadata.description` и `metadata.creator` сохраняются как данные, но не становятся подписью.

В HTML карта использует подготовленную геометрию, а подпись доступна независимо от загрузки SDK. На индексируемой странице название в подписи становится обычным заголовком-секцией; контейнер с данными и элементами SDK исключён из Pagefind. Для перехода к секции CSS резервирует высоту карты над заголовком; фактический переход проверяется отдельно на production-индексе. Markdown companion сохраняет копию исходного блока и URL, но ограничивает только числовые `geometry.coordinates` восемью знаками после запятой; остальные значения JSON сохраняются, подпись добавляется один раз. Редакционный Markdown остаётся без изменений. Строки GeoJSON не разбираются как Markdown или упоминания `@slug`; они не создают backlinks. Ошибка JSON, неизвестное содержательное поле или неподдерживаемая геометрия останавливают сборку с указанием материала и номера вставки. `iconCaption` точки сохраняет авторские символы без типографики и удаления тегов в HTML-карте и Markdown companion; HTML и Markdown в маркере выводятся буквально как текст.

Для короткого определения companion вместо ссылочных полей содержит обычный самодостаточный GeoJSON `FeatureCollection`: геометрию участников, точки с номерами, собственные features и запрошенную обводку. В редакционном файле остаются короткие ссылки. Импортированные координаты совпадают с общей картой и не готовятся повторно; собственные features сохраняют авторские значения и исходные границы, как в полном GeoJSON-блоке. Структурные ссылки на места и наборы внутри JSON не становятся упоминаниями или backlinks. Полные GeoJSON-блоки сохраняют прежнее поведение.

## Геометрия места

У места основная точка задаётся в `location.coordinates` Markdown-карточки. Дополнительные объекты храните в соседнем `apps/www/src/data/places/[slug].geojson`: тот же полный `FeatureCollection`, без искусственного `kind: area`. Файл привязывается к существующей карточке по slug; карточка может обойтись без GeoJSON. В превью карточки дополнительные объекты видны вместе с основным маркером, на общей карте их временно раскрывают наведение, фокус и подсветка по `?h=<slug>`. При участии места в активном наборе геометрия остаётся раскрытой до снятия набора. `show_on_map` влияет на общую карту, но не на существование карточки и её превью.

Формат принимает `Point`, `LineString`, `Polygon` с вырезами и `MultiPolygon`; координаты идут в порядке `[долгота, широта]`. Раздельные части составной области оставляйте раздельными. ID feature может быть числом (включая `0`) или строкой. Для точки поддерживаются `marker-color`, текстовый `iconCaption` рядом с маркером и `iconContent` внутри кружка. В `iconContent` можно указать только строку из одной цифры `0`–`9`; у линий и областей это поле недопустимо. Цифра и подпись выводятся как обычный текст, без интерпретации HTML и Markdown. Для линии и области поддерживаются `stroke`, `stroke-width`, `stroke-opacity`, `stroke-dasharray`, `fill`, `fill-opacity` по назначению. Числовые строки оформления допускаются и при подготовке становятся числами. `description` объекта и метаданные коллекции не становятся попапами, лейблами линий или областей.

`precision: approximate` отмечает приблизительный контур и сам по себе не включает пунктир. Пунктир задаётся отдельно через `stroke-dasharray`, например `[5, 3]`. Для приблизительного `Polygon` или `MultiPolygon` можно указать `outline_expansion_meters`: при сборке каждая внешняя граница расширяется, а вырезы сокращаются. Это изменение координат, а не толщина линии; не подгоняйте вершины вручную по подложке. Исходные данные остаются в редакционном GeoJSON или Markdown; companion сохраняет границы до расширения, но нормализует числовые координаты публичной копии.

`marker-color`, `stroke` и `fill` проверяются как CSS-цвета при чтении источника: например, `#217ea3`, `red` или `rgb(33, 126, 163)`. Опечатка в цвете останавливает сборку с указанием источника, объекта и поля. Ссылки на CSS-переменные через `var(...)` не принимаются: цвет должен быть задан в самих геоданных.

Чтобы показать только надпись без кружка, задайте точке `captionOnly: true` и непустую `iconCaption`. В этом режиме `iconContent` недопустим, а `marker-color` ничего не рисует. Отсутствие флага или `false` сохраняет обычный маркер. У линий и областей `captionOnly` недопустим. Режим работает в превью места, на общей карте и в Markdown-схемах; публичная геометрия сохраняет `properties.captionOnly`.

## Публичный JSON общей карты

`/map/data/places.json` содержит `places` только для мест с `show_on_map: true`. У каждой записи основная точка остаётся в `coordinates` (`lat`, `lng`); необязательная `geometry` содержит **подготовленный** GeoJSON `FeatureCollection` с `features` и сохранёнными свойствами и текстом объектов. Подготовка меняет геометрию и оформление, но не авторский текст: `geometry.features[].properties.iconCaption` у точек совпадает с исходной строкой соседнего редакционного `.geojson`, включая кавычки, пробелы, HTML-подобный текст и буквальные entity. В JSON координаты ограничены восемью знаками после запятой, приблизительные контуры уже расширены, числовые строки оформления нормализованы, а применённого `outline_expansion_meters` нет. Повторно расширять контур потребителю не нужно. Сохраняются поля маркера, статуса, часов работы и `html_url`; для строящихся и запланированных мест добавлен готовый текст `status_label` при сохранении кода `status`. Полного текста карточки места в этой выдаче нет. Описания внутри `geometry.features[].properties.description` относятся к геообъектам, а не к тексту карточки. Разделение JSON на слои (#858) и отдельная агентская навигация (#859) в этот этап не входят.

## Именованные наборы общей карты

Редакционные наборы хранятся в `apps/www/src/data/map-selection-sets/<id>.json`. Имя файла без расширения служит стабильным ID: строчные латинские буквы и цифры, слова разделены дефисами. `parcels` содержит полные коды позиций генплана, `places` содержит slug опубликованных на общей карте мест, `sets` содержит ID других файлов. Прямые участники и ссылки могут находиться в одном файле. Отсутствующий список считается пустым; состав после разрешения ссылок должен быть непустым. `outline` необязателен и по умолчанию выключен.

Вложенность разрешается при сборке без заданного предела глубины. Общий дочерний набор можно использовать в нескольких ветвях. Сборка разрешает алиасы в основные коды и удаляет повторы во всём составе. Неизвестный код, slug или набор, скрытое место, пустой итог либо цикл останавливают выпуск; для ошибочной ссылки между наборами указывается цепочка. Пустой дочерний файл нельзя использовать даже в непустом родителе.

Сборный файл может содержать только ссылки:

```json
{
  "sets": ["2026-10-ae-electro-shp-f", "2026-10-ae-electro-shv", "2026-10-ae-electro-shp-ab"],
  "outline": true
}
```

Оформление задаёт открываемый файл. `outline` дочерних наборов не наследуется, поэтому флаг нужно явно включить в каждой самостоятельной подборке, где нужна обводка. Читатель видит одно выделение без дерева файлов, отдельных цветов или переключателей групп. Собственные GeoJSON `features` и metadata доступны в Markdown-вставке, а не в файле набора.

Публичное компактное определение доступно по `/map/data/selection-sets/<id>.json` и содержит только `id`, `parcels` с основными кодами, `places` и `outline`, без координат и данных карточек. Ссылка для читателя выглядит как `/map/?set=<id>`; исправление состава под тем же ID меняет актуальный файл, поэтому для отдельной истории создавайте новый ID. Эти JSON служат вспомогательными runtime-артефактами карты и исключены из discovery по [ADR-011](/docs/decisions/011-public-surface-registry.md).

Первый набор: [`2026-10-ae-electro.json`](/apps/www/src/data/map-selection-sets/2026-10-ae-electro.json), определение доступно по `/map/data/selection-sets/2026-10-ae-electro.json`, ссылка на карту: `/map/?set=2026-10-ae-electro`.

Отдельные исходные выделения открываются по `/map/?set=2026-10-ae-electro-shp-f`, `/map/?set=2026-10-ae-electro-shv` и `/map/?set=2026-10-ae-electro-shp-ab`. Общее определение ссылается на эти три файла.

Точные границы и диапазоны проверяет [raw-схема](/apps/www/src/lib/geometry/editorial-schema.ts); подготовленный выход — [публичная схема](/apps/www/src/lib/geometry/editorial-public-schema.ts). Примеры в `docs/research/editorial-maps/` — сохранённые исследовательские экспорты и контрольные данные, а не новые редакционные материалы.
