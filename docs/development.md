# Окружение разработки

Правила работы с задачами находятся в разделе [«Жизненный цикл изменений»](../AGENTS.md#жизненный-цикл-изменений). Этот документ описывает установку и обслуживание инструментов; причины выбора процесса — в [ADR-038](decisions/038-openspec-development-workflow.md).

## Чистый checkout

Нужны Git, Node.js 24+ и pnpm версии из `packageManager` в корневом `package.json`. Поддерживаемые среды проверки — macOS и Linux. Установка внешних skills требует доступа к GitHub.

Из корня репозитория выполни:

```bash
pnpm agents:setup
```

Команда устанавливает зависимости по frozen lock-файлу, восстанавливает проектный набор skills и генерирует интеграцию OpenCode. После установки или изменения инструкций **перезапусти OpenCode**: работающая сессия может хранить прежние skills в памяти.

- Собственные skills хранятся в Git под `.agents/skills/`.
- Внешние skills восстанавливаются в тот же каталог из `skills-lock.json` в исходном upstream-виде. Их версии задаются полными Git SHA в `ref`, содержимое — `computedHash`.
- Штатные skills и команды OpenSpec хранятся в `.opencode/skills/openspec-*/` и `.opencode/commands/opsx-*.md`. OpenCode также обнаруживает общий каталог `.agents/skills/`.
- Личные глобальные skills и их lock-файлы не участвуют в восстановлении. Установщик запускается с временным домашним каталогом, а генератор OpenSpec — с временным профилем.

Ревью, согласование объёма, ведение глоссария и ADR и упрощение собственной реализации выполняются по `AGENTS.md`. По решению владельца все методы, для которых готовились проектные patches, исключены из набора. Установка не изменяет исходники внешних skills.

Переустановка внешнего набора заменяет его проектные копии. Проектные дополнения хранятся в правилах, OpenSpec config и собственных skills. Bootstrap откажется работать, если в проектной установке остались неизвестные каталоги или дубли skills; сначала разбери их содержимое. Новые собственные skills должны быть добавлены в Git и разрешены в `.gitignore`.

### Setup-скрипт внешней среды

Если среда, например Codex, уже подготавливает pnpm через Corepack, её setup может вызывать общий bootstrap:

```bash
set -euxo pipefail
corepack enable
corepack prepare --activate
pnpm agents:setup
```

Запускай его из корня checkout. Он заменяет отдельные `pnpm install --frozen-lockfile` и `pnpm exec skills experimental_install -y`: bootstrap дополнительно проверяет полученный состав и хеши и восстанавливает интеграцию OpenSpec. На этапе #736 штатная OpenSpec-интеграция генерируется для OpenCode; общий каталог `.agents/skills/` доступен и другим поддерживающим его агентам. Штатные OpenSpec workflows для Codex требуют отдельного подключения этого инструмента.

## Проверки

```bash
pnpm openspec:validate
pnpm skills:check
pnpm test:agent-tooling
```

- `openspec:validate` проверяет активные changes и основные specs в строгом режиме, затем завершённость задач архивов.
- `skills:check` напрямую сравнивает исходные хеши установленных внешних skills с lock-файлом. Кеш Python `__pycache__`, создаваемый при работе сканера humanizer, не считается изменением исходников.
- `test:agent-tooling` проверяет независимость генерации OpenSpec от глобального профиля и обнаружение изменённых, отсутствующих и лишних skills.

Набор skills устанавливается сначала во временный каталог. Ошибки штатного установщика, которые он только печатает, обнаруживаются по фактически полученным файлам и хешам. В рабочую копию попадает проверенное содержимое. Git SHA закрепляет восстанавливаемую ревизию; хеш без SHA этого не обеспечивает.

Эти проверки входят в workflow `Agent tooling` для изменений агентской интеграции, правил, скриптов и зависимостей. Проверки приложения выбираются отдельно по затронутой области. Успешная структурная валидация не доказывает выполнение требований change.

## Регенерация OpenSpec

```bash
pnpm openspec:generate
```

Генератор запускает один штатный `pnpm exec openspec init --tools opencode --profile core --no-animation` из локального пакета; параметры закреплены в `scripts/openspec.mjs`. Он создаёт skills и команды со штатной схемой `spec-driven`. Временные `XDG_CONFIG_HOME` и `XDG_DATA_HOME` исключают влияние личного профиля, а после запуска удаляются.

Собственной схемы проекта нет. Сгенерированные файлы сохраняются без ручных правок и исключены из форматирования, включая обработку явно перечисленных staged-файлов. Дополнения живут в `AGENTS.md` и `openspec/config.yaml`.

Все терминальные примеры OpenSpec, включая upstream skills и подсказки CLI, исполняй через `pnpm exec openspec` из корня workspace. Например:

```bash
pnpm exec openspec context --json
pnpm exec openspec list --json
pnpm exec openspec status --change <change> --json
```

## Обновление и откат

### OpenSpec

1. Прочитай [release notes и миграции](https://github.com/Fission-AI/OpenSpec/releases) выбранной версии.
2. Обнови точную версию `@fission-ai/openspec` в корневом `package.json` и `pnpm-lock.yaml` через `pnpm add -DwE @fission-ai/openspec@<version>`.
3. Выполни `pnpm openspec:generate` и просмотри весь generated diff, включая добавленные или удалённые workflows.
4. Проверь совместимость инструкций и конфигурации с действующей политикой `AGENTS.md`, затем выполни проверки из раздела выше и подходящие проверки затронутого кода.
5. Передай изменение владельцу на ревью. Dependabot предлагает OpenSpec отдельно от общей группы dev-зависимостей; обновление пакета само по себе не обновляет инструкции в Git.

Совместимое механическое обновление допускает короткий путь. Изменение процесса требует change. Откат возвращает весь PR обновления: пакет, lock-файл, настройки и инструкции. После отката восстанови окружение через `pnpm agents:setup` и проверь его; отдельно откатывать только npm-пакет нельзя.

### Внешние skills

Обновляй выбранный upstream в отдельном временном проекте штатным `skills` CLI из локально закреплённого пакета. В качестве источника используй `<owner>/<repo>#<full-git-sha>`, указывай `--agent opencode --skill <name> --yes`. Проверь совместимость метода с проектной политикой, сверь полученные `ref`, `skillPath` и `computedHash` и перенеси нужные записи в проектный lock. Затем выполни `pnpm skills:install` и `pnpm skills:check`.

Несовместимый метод исключай из набора по согласованию с владельцем. Для обновления установщика `skills` также сохраняй точную версию и проверяй совместимость lock-формата и алгоритма хеша. Глобальный набор этим способом не обновляется.
