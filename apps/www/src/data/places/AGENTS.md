# Данные мест

- Один Markdown-файл в этой папке равен одному публичному месту с карточкой `/map/<slug>/`.
- Для показа на общей карте явно укажи `show_on_map: true`. Отсутствие поля и `false` скрывают место только с общей карты и её списка; карточка, поиск и упоминания сохраняются.
- Для инженерных объектов слоя «Инфраструктура» укажи `map_layer: infra`, для мест клубной системы посёлков застройщика в слое «Клубные места» укажи `map_layer: club`. Оба слоя по умолчанию выключены; отсутствие поля сохраняет обычный показ. Категория и маркер не определяют слой. Поведение переключателей и прямых ссылок описано в [place-map-visibility](/openspec/specs/place-map-visibility/spec.md); ссылки `?l=infra` и `?l=club` включают соответствующий слой по [map-layer-links](/openspec/specs/map-layer-links/spec.md).
- Имя файла без `.md` задает канонический `slug`; отдельное поле `slug` во frontmatter не нужно.
- Для места в другом посёлке или именованной территории вне Шелково начинай slug с согласованного латинского префикса территории и дефиса перед именем объекта: `greenwood-beach`, `greenforest-squash-time`, `greenwood-green-dreams`. Правило действует независимо от клубного статуса, слоя и `show_on_map`; для одной территории используй одинаковый префикс.
- Обязательные поля: `title`, `category`, `status`, `summary` и `location`.
- `name_cases` — необязательные формы канонического названия для упоминаний `@slug:case`; добавлять только реально нужные падежи `gen`, `dat`, `acc`, `ins` и `prep`.
- В `location` хранить точные `coordinates` с числовыми `lat` и `lng`; `map_url` и понятный `address` необязательны.
- Координаты допустимы в мировых диапазонах: широта `[-90, 90]`, долгота `[-180, 180]`. Разные места могут иметь одинаковые координаты; сущность определяется slug.
- Если `map_url` не указан, ссылка на Яндекс Карты строится из координат. Явный `map_url` должен быть HTTPS-ссылкой вида `https://yandex.ru/maps…` или `https://yandex.ru/navi…`; ссылки на другие продукты и домены не принимаются.
- `location.coordinates` задаёт основную точку места. Дополнительные точки, линии и области хранить в соседнем `[slug].geojson` как `FeatureCollection`, а не во frontmatter; формат, оформление и привязка к месту описаны в [редакторской инструкции](../../../../../docs/editorial-maps.md#геометрия-места).
- Для приблизительных полигонов `outline_expansion_meters` задаёт подготовку контура при сборке; пунктир задавать отдельно через `stroke-dasharray`. Не подгонять отдельные вершины по подложке Яндекс Карт.
- Поддерживаемые категории: `entrance`, `children`, `sport`, `walking`, `food`, `services`, `nature`, `water`, `infrastructure`.
- `marker` — необязательный кастомный маркер. Без него карта рисует стандартную точку; сейчас поддерживаются `apple`, `animals`, `beach`, `foodtruck`, `titanic`, `construction`, `fish`, `kpp`, `ktp`, `park`, `racket` и `vzu`.
- Поддерживаемые статусы: `existing`, `planned`, `underConstruction`.
- Не публиковать точные координаты частных домов и чувствительной инфраструктуры без отдельного редакционного решения.
- `contact` — необязательная ссылка на существующую подробную карточку «Сарафана» в формате `category/slug`. Место остается источником истины для названия, описания, адреса и координат.
- `opening_hours` — необязательное расписание по часовому поясу `Europe/Moscow`. Часы и статус работы определяются только `periods` с днями `mon`–`sun` и временем `HH:mm`; дни без интервалов показываются как выходные.
- `opening_hours.description` — необязательное дополнительное пояснение под расписанием. Часы в нём не дублировать; если пояснения нет, поле опустить.
- Каждый интервал должен начинаться и заканчиваться в пределах одного дня. Пересекающиеся и соприкасающиеся интервалы одного дня, включая полные дубли, запрещены. Непрерывные часы задавать одним интервалом, перерывы — отдельными интервалами.
- Markdown body необязателен; использовать его для подробностей, которых нет в кратком `summary`.
- В Markdown body людей и другие места упоминать через `@slug`, `@slug:case` или `[видимый текст](@slug)`. Место не должно упоминать само себя, а его slug не должен совпадать со slug человека.
- `search_aliases` — необязательный массив подтвержденных поисковых формулировок, которые неуместно добавлять в видимый текст; не дублировать в нем `title`, `summary` или категорию.
