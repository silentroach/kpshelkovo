# Инвентарь «У кого есть»

Перед редактированием прочитай [правила приложения](/apps/www/AGENTS.md). Для видимого русского текста используй `humanizer-ru`; для фотографий — `public-media-publisher` и [storage runbook](/ops/storage/public-media.md).

## Источники и идентификаторы

- Храни владельцев в `owners/<id>.md`, виды — в `kinds/<id>.md`, предложения — в `offers/<id>.md`. Файлы лежат плоско; ID — имя без `.md`, из строчных латинских букв, цифр и одиночных дефисов между частями.
- ID владельца назначай вручную: первая буква имени и фамилия в строчной латинице, например `ikalashnikov`. При совпадении добавляй следующие буквы имени (`igkalashnikov`); если этого недостаточно, выбирай свободный числовой суффикс `-2`, `-3` и далее. Сохраняй ранее назначенные ID; префикс посёлка или участка в них не включай.
- Название вида и его английский slug пиши в единственном числе: «Циркулярная пила», `circular-saw`. Для слов без обычного единственного числа сохраняй естественную форму языка: «Ножницы», `scissors`. Не переименовывай опубликованный slug только из-за редакторской правки названия.
- Сохраняй ID при изменении имени, участка, заголовка, summary, условий, текста и контактов. Страница владельца — `/ukogo/owners/<owner-id>/`, подробное предложение — `/ukogo/<group>/<kind>/<offer-id>/`; companions находятся по тем же путям с `index.md`. Компактная карточка вида сохраняет якорь `/ukogo/<group>/<kind>/#offer-<offer-id>`.
- Группы: `construction` (строительство и ремонт), `garden` (сад и участок), `home` (дом и уборка). Группу указывай только в виде. Перенос опубликованного вида в другую группу меняет URL: сначала согласуй сохранение прежних ссылок.

## Добавление и изменение

1. Проверь согласие владельца на публикацию имени, контактов и участка. Сверь основной код или алиас с [реестром участков](/apps/www/src/data/parcels/). Контакт должен быть подтверждён: не подставляй контакт редактора вместо владельца.
2. Создай или обнови владельца. Обязательны `name`, `parcel` и хотя бы один способ связи в `contacts`: `phone`, `telegram`, `whatsapp`, `email`, `website`. Ссылочные способы связи используют HTTPS; Telegram хранится URL. Создание записи публикует страницу владельца с именем, участком и контактами, даже если предложений ещё нет. Body владельца не публикуется.
3. Создай вид с `title` и `group`. В body пиши пояснения и ручные ссылки на KB; пустой body допустим. Автоматической подборки связанных статей нет.
4. Создай предложение с `title` (включая известную модель), обязательным `summary`, `owner` и `kind`, равными ID записей. Напиши summary вручную обычным текстом без Markdown: коротко укажи главное условие или комплект, чтобы сравнить карточки без перехода к подробностям. Summary не выводится автоматически из body. Body хранит полные характеристики, комплект, расходники, залог и особые условия. Упоминания людей и мест в body следуют общему app-level контракту.
5. Проверь данные и результат в HTML и Markdown. Неизвестные ссылки и повторяющиеся ID останавливают сборку. Контакты владельца обновляются сразу во всех его предложениях.

Пример frontmatter в `owners/asmirnov.md` (данные условные, только для иллюстрации):

```yaml
name: Алексей Смирнов
parcel: SHR-L43
contacts:
  telegram: https://t.me/example
```

Вид в `kinds/angle-grinder.md`:

```yaml
title: Болгарка
group: construction
```

Предложение в `offers/grinder-example.md`:

```yaml
title: Болгарка с диском 125 мм
summary: Диск 125 мм в комплекте, расходники отдельно.
owner: asmirnov
kind: angle-grinder
price:
  value: 500
  period: day
```

`owner` примера требует файла `owners/asmirnov.md`, `kind` — файла `kinds/angle-grinder.md`. Каждый Markdown-файл обрамляет frontmatter строками `---`.

Коллекции `inventoryOwners`, `inventoryKinds`, `inventoryOffers` читают эти файлы напрямую: имя файла определяет ID, frontmatter проверяется raw-схемой, mapper строит общий доменный снимок. Новый вид добавляется файлом, а не отдельным справочником или миграцией. Например, `kinds/circular-saw.md` с `group: construction` задаёт путь `/ukogo/construction/circular-saw/`; предложения ссылаются на `kind: circular-saw`.

## Цена и фотографии

- Положительная сумма в рублях с точностью до копейки: `price: { value: 500, period: day }`. Периоды: `hour`, `day`, `once`.
- Бесплатно: `price: 0`. Договорная цена: поле `price` отсутствует. Ноль внутри объекта и `null` не используются.
- Необязательный непустой `photos` хранит объекты с `url`, фактическими `width`/`height`, содержательным `alt` и необязательной `caption`.
- Новый снимок публикуй по runbook как `ukogo/<offer-id>/<photo-name>.jpeg`; замена получает новый URL. Допустимо переиспользовать опубликованные фото по прежним разрешённым media URL из `news`, `reviews`, `people`, а также изображения `kb` по публикационному пути. URL без query и fragment.
- Сохраняй полный кадр, ориентацию и JPEG-профиль runbook; метаданные и GPS удаляются. Перед реальной публикацией проверь доставку.

## Снятие

Удаляй только файл предложения. Его подробная HTML-страница и companion перестают генерироваться и отвечают обычной 404 без архива и редиректа. Прежняя ссылка-якорь открывает сохранённую страницу вида. Вид сохраняй вместе с его body и ссылками, даже после снятия последнего предложения: его страница остаётся доступной. В оглавлениях исчезнут пустой вид и опустевшая группа. Пока сохранён файл владельца, его страница показывает имя, участок и контакты; без предложений выводится пустое состояние. Удаляй владельца отдельно, после удаления всех ссылающихся на него предложений; его страницы после этого отвечают 404. Снятие не удаляет фотографии из публичного хранилища; их удаление — отдельное согласованное действие.
