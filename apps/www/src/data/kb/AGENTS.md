# AGENTS.md

Короткие правила для `apps/www/src/data/kb`. Подробные решения: `docs/decisions/015-markdown-first-knowledge-base.md` и `docs/decisions/035-internal-kb-editorial-sources.md`.

- Markdown-файлы базы знаний лежат в этой папке; корень раздела — `index.md`.
- В frontmatter разрешены `title`, опциональные `flags`, `seo.description` и `sources`; поддержаны флаги `noindex` и `exclude-from-site-search`.
- `seo.description` использовать только для HTML meta description, когда автоматическая выдержка из Markdown слишком общая, короткая или повторяется на похожих страницах.
- `sources` - внутренний редакционный журнал материалов, из которых взяты содержательные факты страницы. Поле не выводится в HTML, публичный Markdown, поиск или SEO.
- Каждый элемент `sources` содержит обязательные `url` и `description`. В `url` допустимы публичные HTTP(S)-ссылки и внутренние пути сайта от корня; `description` кратко объясняет, какая информация страницы взята из материала.
- Добавляй в `sources` все фактические источники, даже если ссылка уже естественно встроена в текст. Не добавляй туда ссылки для действий, навигации, связанные материалы и другие URL, из которых не брали факты.
- Один URL указывай один раз; если материал подтверждает несколько фактов, объедини их в одном `description`. Порядок элементов значения не имеет.
- Не добавляй отдельные строки или абзацы вида `Источник: ...`. Если ссылка полезна читателю сама по себе, интегрируй ее в предложение; это не отменяет запись материала в `sources`.
- Не мигрируй весь старый корпус ради заполнения `sources`. Заполняй поле в новых и существенно редактируемых материалах, когда у них есть фактические источники.
- `flags: [noindex]` не добавляет страницу в sitemap и ставит на HTML-страницу `robots: noindex, follow`.
- `flags: [exclude-from-site-search]` исключает страницу только из внутрисайтового Pagefind-поиска; HTML остается в sitemap и доступен внешним поисковикам.
- URL строится из пути: `index.md` дает `/kb/`, а `services/internet.md` и `services/internet/index.md` дают `/kb/services/internet/`.
- Корень и страница с хотя бы одним дочерним публичным маршрутом считаются страницами-разделами независимо от имени исходного файла; добавление дочернего маршрута не требует переименовывать родителя в `index.md`.
- Страницы-разделы не входят в Pagefind. Если самостоятельную landing page без дочерних маршрутов тоже нужно исключить, укажи `flags: [exclude-from-site-search]` явно.
- У каждой HTML-страницы есть Markdown companion: `/kb/index.md` для корня и `/kb/<slug>/index.md` для вложенных страниц.
- В Markdown companion внутренние ссылки на `/kb/.../` ведут на соответствующие `.md` companion-страницы.
- Не создавай одновременно `foo.md` и `foo/index.md`: они конфликтуют за один публичный URL.
- Дочерние страницы не выводятся автоматически. Если раздел должен ссылаться на вложенные материалы, добавь ссылки вручную в Markdown.
- Новости и редакционные объявления идут в `/news`; перебои сервисов, аварии и окна работ — в `/status`, не в `/kb`.
- Для публикации файлов KB в `kps-public` используй skill `public-media-publisher`; ключи принадлежат префиксу `kb/`, а материалы должны ссылаться на `media.kpshelkovo.online`.
