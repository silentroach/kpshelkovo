# Как читать новости и события

## Выберите источник по задаче

- Для одной новости найдите ее через [полный архив](https://kpshelkovo.online/news/archive/index.md) или [свежую подборку](https://kpshelkovo.online/news/index.md) и откройте Markdown по опубликованной ссылке.
- Для массовой обработки берите [полную JSON-ленту](https://kpshelkovo.online/news/data/articles.json): в ней есть все статьи, полный `body_markdown`, архивы и теги.
- Для всех мероприятий статьи используйте [полную выдачу событий](https://kpshelkovo.online/events/events.json): найдите записи по URL статьи в `newsUrls`. Поля описаны в [JSON Schema мероприятий](https://kpshelkovo.online/events/schemas/events.schema.json). Для чтения карточек перейдите из [Markdown-индекса событий](https://kpshelkovo.online/events/index.md) к нужному дню.
- [Каталог API новостей](https://kpshelkovo.online/news/.well-known/api-catalog) ведет к JSON Schema и OpenAPI. [Путеводитель](https://kpshelkovo.online/news/llms.txt) описывает входные документы раздела.

## Архивы и полнота

Полный архив охватывает все публикации. Годовой архив ведет к месяцам, месячный — к отдельным статьям. [Индекс тегов](https://kpshelkovo.online/news/tags/index.md) ведет к ограниченным подборкам, поэтому для полного анализа темы используйте архив или JSON-ленту.

В ленте `archives.years[]` содержит годы и месяцы с количеством записей и HTML/Markdown-адресами. У тегов есть русский `label`, нормализованный `key` и ссылки. Списки показывают `summary`, полный текст находится в статье и `body_markdown`. [RSS](https://kpshelkovo.online/news/feed.xml) содержит краткие описания.

## Даты и календарь

- `published_at` — дата публикации статьи. `events[].starts_at` и необязательное `ends_at` — время мероприятия; сохраняйте часовой пояс из данных.
- `events` в новостной ленте сохраняет прежний формат: только события с точным временем начала и обязательным `ics_url`. У события могут быть описание, место, координаты, карта, организатор и исполнитель. Отмена и условный набор указаны в `description`.
- Одна дата без часов и многодневный период доступны в полной выдаче событий и HTML-карточках новости, но не в legacy-массиве `events`. Отсутствие этого массива не означает, что у статьи нет связанных мероприятий.
- В полной выдаче `timePrecision` различает дату и точное время, `through` включает последний день периода, `status` отражает отмену или условный набор. `sourceUrl` ведет к основному источнику, `url` — к карточке на странице дня начала. Многодневное мероприятие представлено один раз. Каталог содержит редакторские публикации, а не весь архив Telegram.
- Берите готовый `icsUrl` из полной выдачи или `events[].ics_url` из новостной ленты. Одна дата без часов не имеет ICS. Прежние календарные URL и UID сохранены; файл отмененного события доступен с `STATUS:CANCELLED`, хотя карточка не предлагает его скачать.
- `generated_at` — время генерации ленты. `updated_at` — самая поздняя дата публикации среди статей, а не время их правки; у пустой ленты оно равно `generated_at`. Эти поля не обозначают даты мероприятий.

## Территории, медиа и источники

- Если исходная статья не указывает `areas`, JSON нормализует ее на все части поселка: `river`, `forest`, `park`, `village`. Это правило охвата публикации, а не отдельное подтверждение фактов по каждой части.
- Структурированные `cover`, `photos` и `attachments` содержат публичные URL медиа. Адреса картинок внутри `body_markdown` не обязательно автоматически заменены на эти URL; для загрузки вложений и фотографий используйте структурированные поля.
- Тип источника указан в `author.kind`; `official` обозначает официальный источник. `source_url` ведет к исходной публикации, дополнительные ссылки и атрибуция сохраняются в `body_markdown`.
