# Скриншотные тесты оглавлений KB

Тест снимает только навигационную полосу на двух настоящих страницах production-сборки:

- `/kb/ok/offer/shelkovo-park/` — вводный пункт, две именованные группы, плоские нумерованные списки и длинные названия приложений;
- `/kb/ok/development-plan-2026/` — две неназванные группы с вложенными списками.

Для каждой страницы сохранены PNG-эталоны на ширинах 320, 390, 768 и 1440 CSS px. Браузер использует DPR 2, снимки сохраняются в масштабе CSS-пикселей. Используются настоящие стили KB, Markdown-рендер и локальные шрифты сайта. Перед снимком тест ждёт загрузки шрифтов.

Дополнительно проверяются отсутствие горизонтальной прокрутки, компактные промежутки между пунктами оферты и переход к последнему разделу с клавиатуры при отключённом JavaScript.

## Запуск

Из корня workspace:

```bash
pnpm --filter @shelkovo/www test:visual:kb-toc
```

Команда сама собирает приложение, поднимает preview на `127.0.0.1:14335` и останавливает его после проверки. Как остальные визуальные наборы проекта, тест запускается локально; в общий `pnpm test` и CI он не входит.

Эталоны находятся в [каталоге снапшотов](/apps/www/tests/kb-toc.visual.local.spec.ts-snapshots/). Они зависят от платформы Chromium: текущие PNG созданы на macOS. Изменение заголовков исходных страниц тоже может потребовать пересмотра снимков.

## Обновление эталонов

```bash
pnpm --filter @shelkovo/www test:visual:kb-toc:update
pnpm --filter @shelkovo/www test:visual:kb-toc
```

Перед сохранением просмотреть все изменённые PNG: плотность плоских списков, иерархию вложенных, перенос длинных названий, номера и переход от одной колонки к двум. Обновление эталона само по себе не подтверждает исправность вёрстки.
