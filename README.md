# Shelkovo Workspace

Монорепозиторий для сайтов и shared-пакетов Шелково.

Это эксперимент, где в проекте **не написано ни строчки кода руками**. Руками редко, но правится только markdown-документы.

## Состав

```text
apps/
  www/       # основное Astro-приложение kpshelkovo.online, включая /815/compare
  media/     # статическая 404 для media.kpshelkovo.online
packages/
  ui/        # shared styles / UI primitives
  url/
  format/
  geo/
docs/        # документация и дизайн-гайды
ops/         # nginx и deploy-конфиги
```

## Команды

Установка окружения разработки из чистого checkout:

```bash
pnpm agents:setup
```

Нужны Git, Node.js 24+ и версия pnpm из `packageManager`. Подробности восстановления skills, генерации OpenSpec, проверок, обновления и отката — в [руководстве разработчика](docs/development.md). После изменения интеграции перезапусти OpenCode.

Работа начинается с обычного запроса. Агент выбирает OpenSpec или короткий путь по разделу [«Жизненный цикл изменений»](AGENTS.md#жизненный-цикл-изменений) — это единый источник политики проекта.

```bash
# основной сайт на :4321 и media app на :4322
pnpm dev

# проверки
pnpm lint
pnpm typecheck
pnpm test

# сборка
pnpm build
```

## Выходы сборки

- `dist/www` — основной сайт `kpshelkovo.online`
- `dist/media` — статическая 404 для `media.kpshelkovo.online`

## Деплой

- `kpshelkovo.online` получает содержимое `dist/www`
- `media.kpshelkovo.online` получает error app из `dist/media`, а остальные запросы проксирует в S3
- старый compare-домен обслуживается nginx-редиректами
- nginx-конфиги лежат в `ops/nginx/`

### IndexNow

Политика «только новые индексируемые страницы» и её причины — в [ADR-027](/docs/decisions/027-indexnow-new-pages-only.md). Порядок production-публикации задаёт [CI/CD workflow](/.github/workflows/ci.yml), подготовку ключа и отправку выполняет [scripts/indexnow.ts](/scripts/indexnow.ts).

1. Build сохраняет URL после sitemap-фильтров в приватный `apps/www/dist/indexnow-urls.json`. Он формируется из того же прохода сериализации, что и sitemap, остаётся вне публичного `dist/www` и не требует обратного чтения XML.
2. Из repository secret `INDEXNOW_KEY` команда `prepare` создаёт UTF-8 файл `dist/www/{key}.txt`. [Helper](/apps/www/src/lib/indexnow.ts) проверяет формат и зарезервированные имена, не перезаписывает уже существующий файл. Ключ не коммитят; при ротации меняют secret, следующий deploy публикует новый файл и удаляет старый через `rsync --delete`.
3. До синхронизации dry-run `rsync` с теми же checksum, delete и filter options записывает itemized changes. Workflow дописывает их в `INDEXNOW_PENDING_PATH` в домашнем каталоге deploy-пользователя на VPS, вне web root, и забирает накопленный файл на runner. Сохранение до deploy удерживает маркер нового файла при сбое и повторном запуске.
4. После публикации сайта команда `submit` выбирает только новые обычные файлы `index.html` с rsync-маркером `<f+++++++++`, пересекает их URL с манифестом текущей сборки и удаляет дубли. Изменения, удаления, assets и отсутствующие в манифесте URL, включая исключённые `noindex`-страницы, не отправляются. Существующая страница, ставшая индексируемой, нового файла не создаёт.
5. `submit` загружает публичный `https://kpshelkovo.online/{key}.txt` без кеша и редиректов и проверяет точное содержимое. Проверка выполняется и при пустом списке URL; в этом случае POST не нужен. Непустой список отправляется в IndexNow пачками в пределах лимита helper-а; только HTTP 200 и 202 считаются успешными ответами. После успешного завершения всей команды workflow удаляет pending-файл на VPS.

#### Сбой и повтор

- При ошибке публичного ключа, сети или ответа IndexNow job завершается ошибкой. Уже опубликованный сайт остаётся доступен, pending сохраняется. Исправь причину по логу шага и повтори deploy job; не удаляй pending вручную ради зелёного статуса.
- Повтор добавляет новый dry-run к сохранённому списку и снова фильтрует его по **текущему** sitemap-манифесту. Уже опубликованные новые страницы сохраняют исходный маркер добавления; URL, переставшие входить в индексируемый набор, отсеиваются.
- Если одна из пачек принята, а следующая завершилась ошибкой, pending остаётся целиком. Повторная отправка уже принятой пачки допустима; отдельного журнала подтверждений по пачкам нет. При успехе сводка job показывает отправленные URL и количество принятых запросов.

Точные пути и rsync-параметры принадлежат workflow, формат ключа, endpoint, лимит пачки и таймаут — [helper-у](/apps/www/src/lib/indexnow.ts). Раздачу key-файла как `text/plain` с `Cache-Control: no-store` задаёт [nginx-конфиг](/ops/nginx/kpshelkovo-online.conf). Отсутствие ключа останавливает подготовку до публикации; доступность его публичной копии проверяется после неё. Справка по настройке secret — [GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

## Автоматическое обновление данных

Часть данных проекта обновляет Hermes Agent, который авторизуется через GitHub App `kpshelkovo-hermes-agent`. Агент создаёт отдельную ветку, запускает проверки и предлагает изменения через pull request — напрямую в `master` данные не записываются.
